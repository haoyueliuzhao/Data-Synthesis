## 新准入条件

| 条件 | 原评估调度 | 本次评估调度 |
| --- | --- | --- |
| 每卡剩余显存 | 至少 76,000 MiB | 至少 77,824 MiB，即 76 GiB |
| GPU 利用率 | 必须为 0% | 不设门槛，包括 100% |
| 物理卡 | 原设备选择规则 | 仅原绑定的八张卡 |
| 同时运行任务数 | 最多八个 | 不变 |
| 同一张卡上的本实验任务 | 最多一个 | 不变 |
| 开发集/确认评估 | 原条件 | 新条件 |
| 有条件触发的 B 组训练 | 原条件 | 不变 |

新门槛比实测最高占用多 2,144 MiB，约 2.1 GiB 余量。这是工程估算，不保证未来
更长会话的峰值或其他进程后续申请显存不会造成不足。`nvidia-smi` 快照不是资源
预留，也不保证启动后的吞吐。其优化在于显存足够时不再被其他低显存作业的
GPU 利用率阻挡，而不是把显存条件降低为不适合现有评估的 32 GiB。

当前八个并发槽位已经全部被自身评估占用，因此这个调度优化不会立即让第九个
评估额外挤到正在使用的卡上，也不声称会加速已在运行的八个任务。第九个仍须
等待本实验槽位和一张显存达标的卡。任何收益估计都必须与这个事实区分。

## 对在途评估的无重跑接续

既有调度器没有资源策略热更新入口，且原 `pending/running` 队列已驻留内存。
直接改磁盘上的原函数既不能使它立即生效，也会破坏冻结源码绑定。
本次新增两个外部脚本，先提交再执行，保留全部冻结 `src` 和现有发布器源文件：

- `scripts/continue_fixed_kernel_evaluation_shared_gpu_20260915.py`：明确记录此次修订，
  复用已有训练报告、A 执行谱系和启动记录，继续评分、原方向选择及有条件确认。
- `scripts/fixed_kernel_evaluation_shared_gpu_scheduler_20260915.py`：接管八个已存在
  的生成进程，按新条件发出尚未启动的第九个任务，处理后续确认评估的同类准入。

切换时仅暂停旧调度器 PID 3381543，记录其启动时刻、命令摘要、原任务登记及
八个子进程身份，不向生成进程或发布器 3370870 发送信号。旧父进程暂时保持停止，
以便子进程完成后保留可证明的真实退出状态。新调度器只有同时看到绑定子进程
的真实零退出状态及实际完整生成报告，才记录对应完成；不能把进程消失当成成功。
只有八个原子进程的退出证据全部记录后，才退役旧父协调器。

原 job 描述的字段集合及已有输出字节不变；资源准入证据写到独立记录，不向
严格封闭的 worker 输入夹带字段。单个任务失败时停止新启动，保留在途任务及
失败记录，不自动重试。已有 A 训练、材料校验、缓存、模型 smoke 均不重跑。
新记录处于原实验输出目录，继续由现有自动归档流程收录。
