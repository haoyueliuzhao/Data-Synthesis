# 实际期间后继版本：固定 A/B 原样材料接口

本文记录新接口的实现边界。本文中的单元控制全部使用 mock callback、合成金额及 mock 编码器；不表示已经执行真实 Teacher 会话、构造真实 tokenizer、训练 Student 或取得效用结果。生产事实以主阶段的冻结记录、真实请求账本及运行报告为准。

## 1. 与既有接口的关系

原 `catalog_bridge.worker.generate` 仍是脚本接口，最多 32 次响应、24 次工具调用，其原始生产 36 个脚本和 167 行编码材料不重新生产，不转为训练材料。

新 `training_runtime.generate` 是单独登记的 `fixed_AB_training_runtime.v2`。限额明确为 32 次响应、32 次工具调用。新系统合同声明该区别，并复用原 worker 的公开来源解析、逻辑金额、精确单位换算与实际计算工具。原公共消息按原字节含义保持为系统指导之后的后缀；实际请求还包含此前完整公开响应和工具观察，不截去格式失败、工具失败或修订历史。

在线输入只有公开消息、五字段任务身份、已登记会话身份和指导条件。私有 TaskBundle、答案、关系证书及参考程序不传给 Provider。控制任务使用独立的 `control` 指导值，其文本与中性指导相同；离线方法归类不读取该指导值作为财务行为证据。

首次解析得到含 `final` 的对象就终止，包括形状不合法或数值错误的 Final。此前的 JSON 格式失败只得到固定格式提醒，没有财务反馈。每次实际来源读取、换算、计算、显式修订以及全量输入历史均保留。

## 2. 可重放不等于真实模型来源

运行时将来源标记为 `live_teacher_callback`，但不会凭 callback 自报 `authentic_model_origin` 就认证训练资格。它保存原始公开响应、SHA、请求上下文和 transport receipt/evidence。`training_runtime.replay` 使用保存字节独立执行全部确定性工具和协议状态，不联网、不产生第二次模型响应，也不把原会话改名为脚本控制。

`transport.verify_receipts` 才负责核对登记会话、真实发送账本、实际保存请求与响应、模型身份、用量、完整公开请求历史和原始内容 SHA。显式 mock sender 不能建立该证据链。普通失败尾请求没有完整对应响应，也不能进入训练包。

原 `catalog_bridge.assessment` 仅作纯函数提取：旧入口仍先调用原脚本 worker 并要求整个 session 精确相等，然后调用提取后的 `assess_replayed_session`。新入口先通过新 32 工具协议的完整独立回放，再调用同一个财务语义主体，避免复制一套逐渐漂移的财务判定。

财务有效、细完整类已映射、真实模型来源已核验，是三个不同条件。细类 `PENDING_REVIEW` 的财务有效轨迹仍保留在完整分母中，但不能先塞进正式八包配额。请求指导与实际 endpoint / movement / control 方法分别保存。

## 3. 固定全量登记与中断规则

`ResearchLedger.register_collection` 在首条 Teacher 输出前登记所有 `(pool, task, guidance, replicate)`。每个双充分候选每池每指导 32 次，每个控制候选每池 24 次。`collection.run` 核对完整笛卡尔登记，没有先拿到八包就提前结束的路径。

默认并行度固定为 8。提交次序为账本的 pool、task、basis、replicate 顺序；线程完成先后不改变保存的材料顺序。每次会话先调用公开 reader 和 Provider，结束后才调用离线 reader。

- 普通超时、HTTP/公开响应缺失等传输失败：该会话结束，不重试，保留请求和保守扣账，继续下一个已登记会话。
- `FatalStudyError`、`BudgetRejected`、账本完整性失败：停止继续启动会话；已在途会话保留其结果，完整未完成登记表继续存在。
- 未完成全量采集：`population_selection_allowed=false`。没有从已完成前缀挑一个看似足够的 180 题总体的路径。

集合报告同时固定完整来源任务顺序，后续物化必须与该顺序、原始 A/B 登记及所有会话分母精确一致；不能将输入列表换成有利子集，也不能换池或按观察到的质量重新排序。

## 4. 原样整包与一次 CPU 物化

`materials.run` 只有在报告及账本都证明全部登记会话已经终止时才能进入。它重新核验真实 transport receipts，然后为财务有效且细类已映射的会话建立原包。每个正训练响应行是原始成功工具调用响应或首次 Final，保留它当时的全部输入消息；所有原始失败响应另外完整保存，并继续存在于后继行的实际输入历史中。

只登记一次 CPU tokenizer 构造，沿用已经核验的 24,576 上限，不沿用废弃的 49,152 开发设置，也不自动提升为模型配置的 32,768 上限。每行调用原 `encode_original_candidate`，核对模板拼接、原始目标字节解码、偏移、因果 mask、labels 与长度。某行不合格或超长，整包不具备可消费资格；不截断、不改写、不删除失败历史、不以另一条短轨迹替换该包。

一次物化面向全部符合前述条件的完整原包，不在看到前十个合格包后停止编码。所有不合格原因和多余原包继续保存。

## 5. 共同就绪与八加二材料核

实际方法在 A/B 两池分别统计。只有两池对每个实际方法都至少有十个财务有效、细类已映射、可原样消费的真实原包，任务才共同就绪。控制组只需各池一个 control 方法层，双充分组需 endpoint 和 movement 两层。

各层按已经登记的会话顺序取前十包，前八包训练、后两包封存。这里没有按指导名称冒认方法，也没有按长度、得分或细类频率排序。先在完整候选总体上计算共同就绪，再复用原 `design.choose_population` 的来源顺序，保持三类双充分等额及控制双倍，接受原方案 180—200 题范围。共同就绪不足 180 就停止；不补来源、不改配比、不再采样补包。

材料 manifest 即使就绪也明确 `training_started=false`；它不是已经完成的 Student 实验。

## 6. 真正的原包 consumer

`materials.update_examples` 接收一个原计划的五题更新：三种双充分各一题及两个控制。它仅加载指定池和 `train` 角色的八包层，共 64 包，禁止读入封存包、另一池、错误任务或错方法层的编码。

每包重新核对保存 SHA、内容身份、完整目标 Token 数、24,576 上限、原始 `input_ids / target_mask / labels`。输出每个完整原包的数组和逐目标 Token 系数：

\[
\alpha(m\mid x)/(40L_\tau).
\]

控制为 \(1/(40L_\tau)\)。\(L_\tau\) 是整包所有正响应行的目标 Token 总数，而不是某一行长度。没有额外全局任务数、微批数、行数或整个更新总 Token 的除法。函数不进行优化器更新；实际训练仍须在主阶段全部准入条件成立并冻结材料之后执行。

## 7. 开发控制范围

新增控制覆盖：三类双充分、两种数量、两种实际方法；超过旧 24 工具但不超过新限额的回放；首次错误 Final；格式错误历史保留；普通传输终止与全局预算停止；完整 48 会话合成控制登记不提前取八包；未完成登记禁止 tokenizer 构造；mock 来源不能训练化；一次 mock 构造与无截断物化；三臂实际 64 包 consumer 及整包系数。

这些控制验证接口、约束和纯算术，不估计真实模型成功率，不构成 A/B 材料产率估计，也不构成任何正负效用结论。
