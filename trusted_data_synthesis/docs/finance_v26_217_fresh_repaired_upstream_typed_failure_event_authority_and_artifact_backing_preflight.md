## Audited Root Cause

v26.216's `AuthoritativeUpstreamFailureProducer.create_failure` accepted three caller inputs:

```text
terminal_kind
reason
source_event_id
```

It then looked up any of the sixteen reachable v26.195 terminal policies and converted those
labels into an in-memory observation. This made it possible to produce a self-consistent E2
`completed_qualified` exception despite absent response parsing and absent Runtime completion.
The upstream observation was also absent as an independent artifact: `SourceExitProof` stored
only its identity and the dispatcher depended on a process-local dictionary.

The first failed Gate was therefore v26.216 R2, not its five-exit AST enumeration. The repair must
remove caller terminal authority and persist the actual event-to-observation parent chain before
E2 proof construction.
