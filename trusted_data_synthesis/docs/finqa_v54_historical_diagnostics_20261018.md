## 2. 定性阅读：先封存候选，实际读取 18 例

自动分类之后，先按类别字母顺序轮转、类别内按 episode SHA256 升序，为每模型登记最多 10 条，共 90 条候选。实际深入阅读固定取每模型已登记名单的前两条，共 18 条；完整读取了这些条目的原始 response 各 turn 和真实工具事件。其余 72 条没有被称为已完成人工阅读。原方案的上限是每模型 10 条、合计 90 条，本次没有达到或超过该上限。

逐例观察及原文件绑定见 [manual_reading/record.json](../artifacts/finance_research_20260928/finqa_v6_01/v18_researcher_continuation_01/v25_training_replication_01/v54_historical_diagnostics_01/manual_reading/record.json)。这是一组按失败类别选取的解释样本，不能用其比例估计总体发生率。

18 例中直接观察到以下不同现象：

- 有的轨迹已经成功调用 `run_program` 并获得有限数值，随后仅文字说明结果、或以普通 `Program: submit_program(...)` 文字表达提交意图，实际 EOS 前没有提交封套。工具执行成功不等于完成原生提交，也不保证该数值符合题目参考答案。
- 有的首调用只产生 R/U/Q 说明和普通 Program 文字，随后实际 EOS；另有两个样本不断重复计算/执行/提交意图直到 2,048 token 上限。后者不能证明增加长度会解决问题。
- 三个缺关闭封套样本已经生成提交 JSON，却在 `</tool_call>` 前实际 EOS。没有尝试补标签；其程序内容是否合法、补标签后能否正确，均没有据此验证。
- 四个“封套后夹杂内容”的全集样本均在合法封套后继续生成角色标记或伪工具响应。C-only251 的 CME 样本此前两次真实 `run_program` 均报错，后续模型自行写出的成功工具消息并非真实工具结果。原 parser 拒绝整段符合其既定规则。
- 一个 JSON 异常样本在首个开始封套后直接出现大量角色标记，严格 JSON 解码首先失败；后面的其他对象没有被挽救。
- Full389 的一个提交封套确实被 parser 接受，但程序字符串为自然语言，原评分仍 invalid。此例属于原生提交/执行失败，不能归为 parser 格式拒绝。

这些观察解释了格式、交付和执行层面的失效形态；没有推断它们全部由同一个训练机制导致，也没有把失败轨迹中看似合理的文本重新算作正确答案。

## 3. 24 个 outer：原 RMS floor 未激活

本次直接读取已提交 outer 的 JSON 中保存的 C、各任务旧 π、先验 r、新 q、温度与分布诊断，并结合各自原始 700 条冻结奖励统计成功覆盖。没有重新估计 C、改变 RMS 或恢复 GPU 反传。

原实现的 RMS 是：

`sqrt(sum_noncontrol mu*pi*(C/mu)^2 / sum_noncontrol mu)`。

C 已含任务边际 μ。它不同于不加权的原始 C 元素 RMS。报告同时保存这两个量，并明确分位数是优化支持上的不加权 `(task,state)` 分位数、排除 singleton control；没有用原始幅度代替实际分布更新强度。

| 原始 C 的活动状态不加权 RMS | 0.000011227741 | 0.000029566218 |

## 5. 保留的证据缺口与实现核验

已提交 outer 记录没有直接保存独立 draw 的 gJ/C；本次没有额外反传，也没有从累计梯度检查点另行拆出 draw 方向，因此方向一致性记 NA。两个 draw 的成功数可以读取，但不能代替梯度方向一致性。

现成 outer/package 摘要没有 reason/tool/final 分段监督系数归因。严谨拆分需要原监督 span/encoding；本次没有重复加载整套训练材料重做该归因，系数质量记 NA。更没有保存分段 NLL 或梯度归因，因此实际 loss/gradient 贡献也记 NA，不能用输出长度、概率质量或 package loss 代替。

分类与抽样实现的 11 项必要 CPU 测试通过（0.19 秒）：覆盖原 parser 各类拒绝、允许的前置说明、字符串内部工具标签、合法前缀后仍拒绝整段，以及类别/摘要固定抽样上限。自动诊断执行和补充记录均未触发 GPU、provider、optimizer 或评分调用。
