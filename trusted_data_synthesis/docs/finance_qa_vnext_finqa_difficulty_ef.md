## v2 有限工具及验证责任

版本：`finqa_source_numeric_h2.v2`。新建模块，不修改旧 H2。
通用工具为 read、add、subtract、multiply、divide、sum、average、minimum、maximum、absolute。
没有本题答案专用工具，没有任意代码执行、联网检索或 exp。sum/average/min/max 需要模型逐一列出
2—8 个已接受标量输入；Host 不替模型挑一行或确定聚合成员。
自由常量固定为 1、2、3、4、5、100、1000、1000000，不能把来源里的某个数冒充常量。

F 公开完整原表／前后文本，并对所有数字做相同词法索引；包括年份、页码、OCR 噪声，
不添加正确指标、分子／分母或计划标签。索引是检索坐标辅助，不是 OCR 原图任务。
read 选择一个 source ID，产生真实来源数值 Observation。百分数字面值按比率读取；
FinQA 的 `-6.3 ( 6.3 )` 只提供 -6.3 一个带符号数字，不伪造正数候选。
单位尺度保留在原文，read 不自动做百万／十亿换算。

Action 的子目标、reason、operation、inputs、parameters 均由模型提交。
Update 必须由模型明确 accept/reject 当前 Observation；未接受的观察和其它会话 Claim 不可消费。
实际执行次数与提交次数分开计量，拒绝仍消耗一次提交与一次真实 Provider 请求。
沿用 reason≤480、subgoal≤240 字符，不截短或重写原始响应，不单独优化提前 Final 反馈。

一个有意公开的语义变化是：**本版本中间 Claim 是来源绑定的数值推导，不是已认证财务角色的事实。**
加减乘除入口只验证有限标量类型、来源、零分母及执行结果；因此模型选错指标的运算仍能如实执行。
这不等于给错财务结论盖章：Final 才认证原题财务目标，必须满足来源符号表达式等价、
独立数值、单位、实际 lineage 引用和接受生命周期。对比旧 H2 时，这是工具与验证责任变更，
不能把新旧差别归因于单个“证据难度”因素。E/F 内该规则完全相同。

Final 不仅比数字：不同期间／行的两个巧合相等数值不会自动合并为一个事实。
采用从实际工具树构建的 SymPy 符号式进行终局等价检查，容许交换／结合、sum 与逐项 add、
average 与 sum/n 等表达，不在操作准入阶段遍历参考节点。
实现只使用有限工具构造树，不解析执行模型提供的代码或 SymPy 字符串。
[符号化简的官方说明](https://docs.sympy.org/latest/tutorials/intro-tutorial/simplification.html)。

另外登记并核验了 C1 的期初加各项变动等于期末、C2/M3 的货运组成求和与经营总额关系、
M1 的期末减期初等于年度净变动，允许这些真实替代依据。来源正负号也用于认证绝对值与幅度写法。
这些关系仅用于终局检查，不形成模型可见计划，不在 Action 准入时挑选下一步。

此 oracle 仍有范围限制：它认证已核对来源事实及上述来源恒等式上的代数等价，不承诺覆盖所有财报中
不同披露间的语义等价关系、约数精度区间或所有替代充分依据。
例如用其它科目重建相同财务总额，若来源等式尚未登记，可能不被终局符号检查认证。
此类轨迹应标为 oracle 范围问题／尚未认证，不能简单断言模型财务推理错。
这是有限可表达挑战集，不是一般金融定理证明器或穷尽合法解法的行为商。

百分比题要求模型实际产生乘 100 后的 Claim，再用 `percent` 发布。
Final 值必须是数值字符串且距选定 Claim 不超过 0.00001（绝对发布误差），
不得只在 Final 中改变数值／符号／单位来绕过未执行步骤。单位不含答案数值。
各题原问题、来源和目标意义不变；这是统一新增的可执行输出契约，不能把新增协议负担混称原 benchmark 的自然难度。

## E/F 信息条件与在线登记

E：预定位相关数字、其原始片段及必要上下文，无方法计划。
F：完整原表与完整 pre/post_text，所有数字候选均匀索引，不突出相关项。
这里的“完整”指该 FinQA 条目保存的表格和前后文，不是整份年报或 PDF 原图。
E 的预定位本身就是强辅助；这一设计包也包含候选集大小和片段组织差别，
不是单一检索机制的纯因果实验。两条件都必须实际 read/accept，E 不获已接受的中间计算。

同题 E/F 使用相同问题、工具、数值和单位语义、输出规则、模型参数与预算。
每单元一个独立新会话，共 24 个；每条件分母 12，每层分母 3，不估计稳定成功概率。
静态见证不进入在线分母，也不计作模型样本。

生成配置沿用 deepseek-v4-pro（允许响应标识 v4-pro / v4-pro-0813）、temperature=0.7、top_p=1、
thinking disabled、JSON object、max_tokens=8192、中性 SYSTEM 原样沿用前轮。
每会话 12 次实际操作、32 次提交／请求；全局最多 768 次请求、82,575,360 预留 Token 上界。
请求体实际字节上限 98,304；这不是精确 tokenizer 输入测量。
每次请求仍保留完整 HTTP body、响应 envelope、模型原始内容、reservation、usage、状态绑定和执行事件。
缺失 reasoning usage 保留 unknown，不填零。不进行本轮新 tokenizer 监督导出或训练权重赋值。

登记顺序为 C1/C2/C3/E1/E2/E3/M1/M2/M3/J1/J2/J3，各题 E 后 F，分三波各八会话；
波内最多八并行。没有自动重试、fallback、resume、换题或补样到成功。
错误结果保留原分母；完整性或生成条件异常时停止后续波，未启动也保留在 24 分母中。

## 测量与结束标准

主表逐题逐条件报告完整有效、失败／未知、请求／提交、实际操作、拒绝、全部 usage 和预算余量。
状态为完整有效并不意味着中间没有错误；拒绝和未使用工作仍计成本。
数值执行由工具承担，不把工具正确算术当成模型自身算术能力。

逐轮独立检查包括：原始 Provider 内容与 Runtime 字节一致、实际请求绑定、已接受才消费、
真实运算树而非参考树替换、独立 Fraction 计算、实际 lineage、模型明确 Update 和 Final。
同时做纯本地确定性转移重放；不是调用 Provider 重跑。

自动计数的 `off_reference_source_ids` 只是非预选读取，**不自动等于证据错误**。
人工轨迹复核再区分：错误指标／期间／单位／主体、正确事实上的方法错误、提前结束、
接口或长度问题，以及 oracle 不支持的潜在合法依据。E 成功 F 失败仅提供线索，不自动给出因果结论。

不要求 24/24 成功才结束。结束条件是：统计完成、十二题合法构建、冻结条件实际执行、
原分母和失败完整保留、来源／方法／终局问题可追查、成本闭合、文档与 Git 交付。

### 主要结论与 Gate

**全量画像、十二原题合法构建和线上执行证据已经完成；但本批不支持用 E/F 通过率估计证据难度效应。**
新 v2 的公开 Update schema 把 `observation` 声明为无说明的 string，未明确告诉模型该字段必须填写
`state.pending_observation.id`。实际大量响应把它理解为接受观察的自然语言说明。
这是本轮新实现的公开契约表达缺口，不能归咎为模型不懂金融推理，也不能掩盖为“难题失败”。

冻结原结果为 E 2/12、F 7/12。F 高于 E **不证明完整来源更容易，也不证明证据预选有害**。
每题每条件只有一次会话，且接口错误主导了大量预算损失。本批的价值是完整揭示了这个问题，
同时留下几类可定位的财务语义／输入组合错误，而不是给出稳定能力排名。

### 拒绝是什么，不是什么

| 冻结错误码 | 次数 | 解释 |
| --- | ---: | --- |
| lifecycle.observation_binding | 410 | Update 没有填写观察 ID，公开字段说明缺口最突出 |
| final.target_not_established | 22 | 16 次来自 E1_F 缺尺度转换；6 次来自 J1_E 未构建税后口径 |
| lifecycle.accepted_claim_input_only | 6 | 使用尚非当前已接受 Claim 的操作输入 |
| numeric.arity | 5 | read 等输入个数不符合冻结单项读取工具约定 |
| schema.invalid_submission | 3 | 原始提交结构／字段不符合公开 schema |
| final.citations | 2 | 发布引用不符合实际 lineage |
| final.accepted_answer_required | 1 | 发布对象不是已接受答案 Claim |

410/449（91.31%）的拒绝是 Observation 引用问题，且 410 个错误字段均不是 observation ID 格式；
不是 410 个长哈希抄错。没有记录到 `lifecycle.state_binding` 拒绝，因此不能笼统归因为模型不会复制长 ID。
这些拒绝分布在全部 24 个会话，E 282 次、F 128 次。输入条件与重复错误的关联是观察事实，
本样本不能解释为什么两组复发程度不同，更不能证明新说明一定能消除它们。

最直接的反例是 **M1_E**：第 14 次提交已经真实执行三年均值 3297.666…，
随后 18 次 Update 仍把 observation 写成说明文字，直到提交预算耗尽；正确结果始终未被接受。
因此该单元完整有效为 0，不能被描述成“模型不会平均值”或“深计算失败”。
C1_E 甚至已把两个正确数值接受完毕，只是没有剩余提交进行减法。

### 逐轨迹确认的财务与组合问题

除了接口损耗，记录也包含以下实质性诊断。它们不是互斥错误率，不能相加作为失败总数。

- **尺度：E1_E / E1_F。** 选择的是正确的 15.3 百万元与 139549 千元，
  但真实操作直接相除；F 之后乘 100 得 0.01096389…%，没有执行千／百万转换。
  F 的短理由有时已经写出“139.549 million”，但实际输入并未完成换算。
  不能把正确文字解释当成正确执行；16 次目标未成立的 Final 也未修复数值语义。
- **期间集合：M3_F。** 只用 2016 年煤炭与经营收入计算了 12.236096…%，
  原题要求 2014—2016 的汇总占比。读取的两个数字都来自预选支持集合，
  因而“没有 off-reference 读取”并不代表期间范围正确。
- **财务定义：J1_E。** 先把税前 share-based compensation cost 直接做增长率，得到 23.9726…%，
  忽略已提供的两个税收利益；六次目标拒绝后才开始读取一个税收利益。J1_F 则实际读齐四数，
  并正确算出 2010 税后成本 11.8，但停在接受阶段，不能从其最终失败推断不会构造税后公式。
- **跨期配对：J2_F。** 四个必要事实都已找到，后续却把 2016 股数 13 与 2017 单价 33.32 相乘，
  得 433.16；正确 2017 配对应为 11×33.32。问题在输入期间配对，不是单纯找不到四个数。
- **数字定位及恢复：J3_F。** 一次 read 选中了年份 2018，而理由期望付款 22.3；
  随后模型选择正确坐标并完成五项求和 100.9。年份 Claim 没有被删除，也未进入有效 Final 的 lineage。

另 **E3_F** 已实际完成 7×1000=7000 和 997/7000 的正确比率，在接受比率后耗尽提交预算，
还没执行转百分比与 Final。更早的 997/1000=0.997 本身可以是合法的单位换算中间量，
不能只因它与预选解法顺序不同就标错。

这些结果支持继续关注单位、期间集合和输入语义绑定，**不支持继续用无关运算填长链**。
但评估这些能力的比例之前，必须先消除或单独控制公开引用契约这一强干扰项。
