## 3. 通用 worker 与脚本控制

在线函数只接收公共 identity、冻结 messages、请求的依据条件及响应流，不接收
bundle_path、私有 Oracle 或来源正确角色表。脚本构造和离线评估是不同能力层。
read_source 真正读取公开 JSON 数值或指定原始表格单元格，calculate 执行有界精确算术；
原单位及换算比例都留在工具事件中，不能把私有答案尺度直接贴到输出。

第一处 Final 结束会话，包括错误／格式不合法的 Final；此前格式恢复保留全部原始
字节与后续历史。离线重放工具事件，依据实际首 Final 支持链判断：

- 同值错来源、年份字面量或答案相等但不接地，不能因此合格。
- 请求 movement 不等于实际 movement；算过组成路线也不代表它支撑 Final。
- 合法等价表达按符号关系核验，不要求与参考表达式字符串相同。
- 方法标签与细完整类分开；来源选择、共享基数、实质修订、重复重算及替代依据
  核对均保留。未知意图／格式恢复等不强制填类；“另一计算”不自动称独立核验。

控制固定选旧233中每个 family×quantity×实际surface类别的最小Task ID。
实际只有14/16格：存量差额canonical、公司定义差额canonical不存在，不能重写旧题
伪造两格。仍覆盖四任务组、两目标及两种题面类别。
开发控制不等于正式阶段执行；正式阶段会另行保存选择表、完整脚本会话、评价和物化。

原样包复用既有精确编码器及已有 Qwen2.5-7B-Instruct tokenizer／模板／掩码资产，
只在 CPU 运行。不得超出原冻结模型／配置上限，不下载模型、不载入权重。
脚本包训练资格恒为 false，不能用于凑每方法八包或冒充真实 A/B 材料。

生产前核验修正了一项开发偏差：先前两次本地开发物化各调用两次 tokenizer 构造，
合计4次，却各报告为1次；当时的49,152长度政策也高于既有24,576配置上限。
这些开发结果不作为最终物化资格证据。最终实现只调用一次已验证的构造原语，
继承24,576上限，并检查模型实际32,768上下文，不采用 tokenizer 声明的131,072。
最终 worker 的35项控制包含显式分组映射、单次构造和长度绑定反例。
