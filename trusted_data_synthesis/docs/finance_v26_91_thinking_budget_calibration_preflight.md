## Budget-Shape Coverage

envelopes. For every request index in a Mechanism x Path cell, the envelope stores
the maximum certified prefix bound over all corresponding role paths.

Natural fresh-source capacity was slightly below the role maximum in some Context
and Stopping cells. The calibration therefore freezes a stress-only Prompt policy:
each registered Compiler prefix receives enough trailing ASCII spaces to reach the
role prefix envelope plus a 64-token margin. Trailing spaces are part of the
Provider Prompt string and content hash. They are never applied to role
measurement.

## Statistical Admission Contract

The v26.89 no-call requirement is retained without outcome-dependent relaxation:

```text
minimum Jobs                          = 32
confidence rule                       = one-sided Clopper-Pearson 95% upper bound
frozen upper-bound threshold          = 0.10
CP95 upper bound for 0 failures / 32  = 0.08936819898626475
CP95 upper bound for 1 failure  / 32  = 0.13984946027422601
```

At the exact frozen denominator, zero typed no-call Jobs pass and one fails. The
same prospective confidence rule is separately applied to Completion-Unusable Jobs.
The two denominators are not pooled. Provider transport failures are also reported
separately and remain execution-integrity outcomes rather than resource no-calls.

The job-level rules are:

- a typed no-call failure occurs when a Job reaches any typed no-call terminal;
- a Completion-Unusable failure occurs when the terminal request cannot produce a
  usable structured decision after at most one Contract-repair attempt; and
- semantic trajectory validity is not Completion Usability and does not rescue a
  failed resource or completion gate.

Both thresholds were frozen before any v26.91 model outcome existed.

## Thinking Continuity Contract

The Provider thinking guide checked on 2026-08-21 states that native Provider tool
calls require `reasoning_content` to be passed back with the tool turn. The current
Runtime instead uses Host-instrumented JSON decisions and does not send Provider-
native tool calls. v26.91 therefore freezes the following protocol:

- Provider-native tool calls are forbidden and fail closed;
- each request reconstructs the compact public state;
- private reasoning content is omitted from later Host-instrumented requests;
- only reasoning presence, character length, and Usage tokens are retained;
- every HTTP-success turn requires positive reasoning presence, length, and token
  telemetry;
- ordered turn attestations bind the public request hash, public final-content
  SHA-256, telemetry, and previous attestation identity; and
- Verifier and State Mapper dependencies on private reasoning content are
  forbidden.

The public final-content hash explicitly excludes private reasoning content. No
private reasoning text or private-reasoning hash is persisted. Missing telemetry,
missing parents, out-of-order turns, native tool calls, and attempted reasoning-text
persistence all fail closed in the local fixtures.

The guide is `https://api-docs.deepseek.com/guides/thinking_mode`. The same guide
states that `temperature` and `top_p` do not affect thinking output; v26.91 records
those fields as Provider-ignored and does not interpret them as experimental
controls.

The Thinking Continuity Contract identity is
`thinking_continuity_contract:a4c8025741e13e38025ac6250e18d57ad5e317a2f2db23d66b54d9d8de2144e8`.

completion allowance as the structured decision. The prospective Completion

## Interpretation

v26.91 positively establishes that an exact, fresh, thinking-enabled 32-Job Budget
Calibration protocol is statically closed and covers every v26.90 role budget-shape
cell. It also prospectively closes the measurement gap between typed no-call and a
Provider call whose 4,096-token completion is unusable.

It does not establish either empirical claim. No Job has run, so typed no-call rate,
Completion Usability, reasoning-token share, failure-loop behavior, path adherence,
Program closure, and independent validity remain unmeasured.

The most important scientific limitation remains task depth. The calibration can
show whether the thinking-enabled compact Runtime is resource-adequate and able to
produce structured decisions on this frozen task family. It cannot show that the
two-Evidence, one-leaf role design has enough capability or state information for
VTDO. Any later floor, ceiling, or path-collapse observation is descriptive unless a
separate prospective role protocol gives it an authorizing gate.
