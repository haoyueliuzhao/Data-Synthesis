## 3. 后继规则 public_task_target_binding.v2

### 3.1 局部关系与原任务适用性分离

分别记录 local_relation_validity、public_task_applicability、
public_scope_match、registered_scope_match_diagnostic_only，以及实际 Final 依赖链
是否完成公开请求。模型自述目标不是原任务的替代物。

局部公式可以正确但不适用于所问期间或物理量。私有登记匹配只作单列诊断，
不能将 PUBLIC_UNDERSPECIFIED 或 NEED_SOURCE_CHECK 自动填成 PASS。
明确违反所有相关公开解释的对象或完成链仍可记录 FAIL，而不被另一未定轴掩盖。
公开任务清楚但私有登记直接错误时，可独立核对公开任务适用性；旧参考仍不能进入
后继主成绩，必须先另立正确的任务/参考版本。

不要求每个中间结果直接等于最终目标。例如先计算有符号净资产贡献，再完成所问
正金额的合法转换，可以是完整链；只完成中间物理量而直接终止则不能替代目标。
本轮不改数量容差、Final 提取、符号解析、单位词元或计算器实现。

### 3.2 来源字段承担何种声明

真实公共合同明确规定 arguments.variables 的每个变量名可映射到数值，
或嵌套的 {value, source, unit}，或既有 result_id；另有 arguments.sources，
用于变量名到来源 ID 的关联声明。它未将扁平 variables.value/source/unit
定义为一个源值断言对象。

| 来源语义 | 核对对象 |
| --- | --- |
| DIRECT_SOURCE_VALUE | 明确声称来源直接记录该输入值，核对事实值与对象/期间 |
| DERIVED_FROM_SOURCES | 声称该值由来源和关系导出，核对推导支持，不要求单元格等于结果 |
| GENERAL_REFERENCE | 普通相关引用，核对其相关性，不自动扩展成源值等式 |
| UNRESOLVED | 合同和周围文字不足以唯一确定声明角色，保留未定 |

未消费字段可能仍是当前错误声明，不因未参与算式而消失；但字段相邻也不能自动
认证一条直接源值断言。撤回旧错误须有实际公开纠正或明确替代证据，不能因为出现
后来正确答案就抹掉旧记录。历史错误及其是否仍有效分别记录。

没有新增 numeric-ID-only、统一 JSON 模板、强制来源列表完整或某条指定公式门槛。
本规则是测量规则，未改旧 Harness，也未向模型新增提示。

## 5. 旧 252 条的派生失败结构

七维为 quantity、formula、source、unit、publication、execution、Final。
前五维直接使用原数量状态及原对应语义子项；execution 只表示是否存在真实成功
calculate（缺失为该条件 FAIL，不推断原因）；Final 保留原一致性状态并禁止无 Final
时成为 PASS，原交付状态另列。

七维不假装包含全部原资格门。调用前/同调用证据、计算量解释、工具结果与发布量
一致、显式 Final.result_id 对应、选中成功计算及实际 Final 金额检查等布尔条件，
均作为原始剩余门单列。只核对保存门的布尔组合与原完整 PASS 投影是否一致，
不重新运行旧财务资格器，不重新判断 1,260 项语义。

| 互斥分类 | 定义 |
| --- | --- |
| ALL_SEVEN_PASS | 七维都 PASS；还需单看原技术剩余门 |
| ONLY_ONE_FAIL | 恰一项 FAIL，且没有未知 |
| MULTIPLE_FAIL | 至少两项 FAIL，且没有未知 |
| INFORMATION_INSUFFICIENT | 至少一项原未知/未建立；同时存在的已知 FAIL 仍另列 |

保存每条向量、精确联合模式、两两未通过交集及唯一未通过条件；按阶段、任务、
种子、分布臂、臂×组和具体模型分别汇总。跨种子和同题不是独立任务。
调用数仍与会话数区分，不将 434/599 的旧调用错误比例当成会话失败率。

这些统计说明保存的评分条件如何共同未成立，不表示模型失效的唯一原因，
不证明工具错误掩盖了来源类效应，也不等于修复某环节后的因果效用。
如列 C04 单条翻转的分数，只是“其他所有旧指示不变”的显式假设：
20/72 对 20/72，仍无正收益，不是本轮实测重评分。

## 8. 十八条限定案例的实际核对

共读完十八条案例的 46 条既有公开响应、全部对应工具事件和原评审引文，
并固化 60 处来源声明记录。它们不是 46 次新生成，也不是十八次新实验。
所有十八条都只有一个成功计算，成功输出的 resolved_variables 均为空：
这些响应使用字面算式。因此“变量未被消费”这一属性同时出现在清楚正确的
来源声明、明确错误的期间声明和语义未定的元数据中，不能单独决定声明效力。

### 8.1 C04：相同答案，不同声明合同

五条标准响应的两个公开响应正文逐字相同；它们在 arguments.sources 中将
value_2002/value_2004 明确对应到各自来源，随后以命名输入的来源映射说明差额。
这种 Final 来源语义是推导来源，不是声称两个单元格都直接含有 2.7。

minus_D_29 / confirm_126 的实际形状不同：arguments.variables 是扁平
{value:2.7, source:"source:t6c1", unit:"millions"}，Final 也保留一个 source 字段。
真实计算只消费字面 8.2−5.5，得到 2.7；同一公开消息明确说 2002 为 5.5、
2004 为 8.2。原表 t6c1 确实是 8.2。

如果将扁平字段解释成“该源直接记录 2.7”，数值会冲突；但公共合同只明确了
嵌套变量对象和独立 sources 映射，没有明确这种扁平字段配对。结合周围减法说明，
推导引用或普通引用不能被排除。该引用没有被后续撤回，所以也不能丢弃。
新记录将这两处当前声明的角色保持 UNRESOLVED，而不自动判为源值 FAIL 或 PASS。

运行器只在算式实际消费命名变量时解析其取值，故这类未消费字段没有触发数值
解析错误。执行成功不是对其字段合同或来源语义的认证；本轮也不新增一条
“未消费参数类型不合约就事后判 FAIL”的无关门槛来替代所审计的语义问题。

这收窄了对原唯一失分案例的解释：不能独立认证原摘要中的直接源值等式解读，
更不能把它称为数值金融能力退化。原评分保留不动。即使另作“仅将该条完整 PASS
指示翻为真，其他原指示全部不变”的假设，也只是 20/72 对 20/72；这一平局是
明示的局部评分敏感性，不是本轮新成绩或模型修复效果。

### 8.2 C08：公开歧义不抹去确定的期间错误

pi0_11、minus_D_29、minus_D_47 的实际成功计算为 1220−1217=3，明确为百万股。
它们选择了原表中的两个年末，而不是登记的完整三财政年度起止点。
部分消息只写年份，年末归属由其表格位置和所用数值确定；本报告不将这一推断
说成模型逐字写出了具体日期。公开题面未唯一指定起点，因此对原公开任务的
适用性保留未定，不因为局部年末比较成立而认证原目标。

pi0_29、pi0_47、minus_D_11 的实际成功调用则明确声称“2016 年末是 1214”。
公开表的 1214 属于 2016-01-03，2016-12-31 是 1217；这些声明没有在 Final 前纠正。
minus_D_11 虽然还给出了 1214 到原年初单元格的正确数值—ID 对应，
也不能用正确 ID 修复同一响应中的错误期间说明。

后继记录对这三条的实际完成链记 FAIL：按照其声明的年末比较，用错了期间值；
若按登记的年初比较，也不能将仍明确标为年末的输入静默重定向到年初。
这个 FAIL 来自独立可核实的当前期间冲突，而不是利用私有的 6 消除公开题面歧义。
账本仍为 PUBLIC_UNDERSPECIFIED，旧数量 PASS 也仍原样保留。

五条出现语法失败的案例后来明确换用字面式并清空 variables/sources，
故旧计算参数关联按“已被当前请求替代”单列；这不是全局抹去旧错误。
其中 pi0_11、minus_D_29 在 Final 又列出未解释的 SEGMENT 标识，新记录将其作为

### 8.3 C09：负贡献没有被转换为登记正金额

### 9.2 单条件与多条件不能混用

“单条件”只是旧测量向量中的描述，不是独立验证其余六项都没有语义缺陷；

无口径条件的算术能力错误；也不能因此说所有 122 条数量 F 都由目标问题造成。

### 9.3 执行缺口和调用负担

旧 252 条中有 90 条没有成功 calculate；这 90 条也全部在发布对齐上非 P。
其中数量 F 为 41、数量 P 为 18、数量未定为 31；来源 F 为 45、公式 F 为 29。
因此，正确答案可以伴随执行缺口；执行缺口也常与数量、公式或来源问题共同出现。
这不是证明“工具问题掩盖来源效应”，也不是修复接口后的收益预测。
