# V6 Experiment 0：双审阅输出容量审计与修订说明

## 1. 结论、状态与本次授权

本次问题是审阅请求的输出设计及容量登记不足，不是已经证实的 Probe 轨迹整体质量不足，更不是 VTDO 训练算法失败。原审阅的 `max_tokens=16384` 是实现者在未做实际包容量测量前自行设置的单请求输出上限，并非 DeepSeek 官方最大输出上限。把这种可预见的系统性截断直接批量归入 unknown，虽然没有伪造通过结果，却会使库存主要反映接口容量失败，而非轨迹语义判定；原执行方案需要修订。

用户已授权审计、按实际问题调整上限，并允许在必要时重新采集轨迹。本次全总体审计支持的方案是：**保留全部 8000 条已封存真实轨迹，停止旧审阅协议，保留旧审阅原始失败与全部费用，修订接口及容量规则后重新执行全部 2000 次双审阅。** 生成重采尚未实施，也没有根据原生答案成绩补槽、换槽或选择性重采。

本文区分以下状态：

- 已发生：8000 条生成完成、全总体只读审计、旧审阅 427 次返回的审计、停止旧审阅并完成在途结算。
- 修订计划：压缩审阅传输结构、按实际包估计输出容量、事前固定 6 题×双审的容量/格式小批、满足登记条件后全量重审。
- 尚未发生：容量小批的实际模型结果、修订后 2000 次全量双审、任何本轮五臂训练；不得把下面的设计或估计写成已验证效果。

本说明是对原协议“固定 16384、不提高上限、不补审”条款的显式修订建议，不回写原不可变 `experiment0_01/protocol.json`，也不把旧结果抹成未发生。最终修订协议须绑定实际代码、精确容量公式、选择名单、检查条件及既有账本继承关系。

## 2. 原上限来自哪里，为什么不成立

原生成每响应上限为 2048 token；原语义审阅则要求一个响应同时覆盖一题的 8 条轨迹、关键命题及证据跨度、公开监督标记、动作与观察更新关系、规范图，以及 28 对轨迹的关系。两者是不同任务，不能由生成回答很短推断整个审阅 JSON 也很短。

旧审阅的 16384 是项目请求中的 `max_tokens` 参数。项目保留的官方快照登记最大输出为 393216 token，参见 [DeepSeek 官方价格与模型规格说明](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 和 [Chat Completion 请求说明](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)。官方上限是模型/接口约束，不代表每个问题都应请求最大值，也不代表在预算内一定能完成。项目应根据输出职责、实际原文和目标覆盖规模选择足够容量，同时受同一个费用硬上限约束。

原实现没有先测量完整审阅结构的必需输出量，也没有以容量/格式小批验证固定 16384 能否承载该结构；这是本次具体执行错误。既有协议虽然事先说明过“长包可能截断”的风险，但风险披露不能替代容量设计。此次修订不是为了提高模型成绩，而是让相同有限语义判定可以被完整输送和校验。

## 4. 旧审阅的实际失败与结构性负担

停止旧协议并结清在途后，共有 427 次旧审阅返回：426 次 `finish_reason=length`，1 次 `finish_reason=stop`。**唯一未截断的返回也不是合格审阅：138/138 个引文为空，未满足原证据引用契约。** 因而不能把 stop 当作内容通过，更不能认为只需恢复这些旧结果即可获得有效双审。

本结论没有将未知记为通过，也没有修改旧审阅原始 body。旧 427 个结果及其账单应完整保留，作为已被容量/格式问题污染的旧协议执行记录；剩余旧审阅不再按旧协议继续发出。新修订必须对原固定 1000 题全部重新执行双审，不能只补 length 的 426 次，也不能把旧 stop 结果混入新协议。

公开轨迹段、审阅包与容量量测的尺度如下。不同口径不能相加，也不能把字符直接称为模型 token：

原始每包公开正文通常很短，但旧接口带入大量重复源材料、长标识和结构，并要求模型回显精确引文、输出多个相互关联的语义层次。仅使用固定 16384，没有为必要结构留足容量，是当前最直接且已由截断率证实的问题。压缩结构后仍可能存在语义不确定或源证据不足；容量修复不能保证共同材料核完整。

## 5. 修订接口：降低机械输出负担，不由主机补语义

修订计划保留原封存轨迹、原私有参考隔离边界、两次相互隔离的审阅上下文、同一 `deepseek-flash` 模型，以及 1000 题×2 审阅分母。模型名称必须在发送请求前验证，无模型回退。

接口使用 compact 短 alias 表示文档、原文片段、动作和槽位；共享源材料在传输视图中去重，但所有 alias 可逆绑定到原始不可变对象。模型输出语义判定以及对原文片段的选择；主机仅按已绑定的片段 ID / 原始跨度恢复长 ID 与 exact quote，避免模型为机械回显原文花费大量输出。

这种恢复有明确边界：

- 主机可恢复原文中已经存在、由模型明确引用的字节/Unicode 跨度及标识，不能新写证据、推导、判定、chi 或状态关系。
- 未知 alias、越界或不一致的原文定位、缺少要求的语义字段不得被主机“猜对”；应报格式/证据失败。
- 不以填充空 quote 的方式使旧 138 个空引文通过。新接口须事前约定紧凑引用语法，再由真实模型输出合法引用；旧返回保持旧判定。
- 短 alias 和机械反展开不改变正向 mask 的原文定位，也不删去错误、撤回或未解决历史。
- 空间不足、格式失败、证据不足、审阅分歧仍分别保留；不能把扩容当作 valid 资格。

## 6. 按实际问题登记输出上限及容量小批

不再对所有任务盲用同一个 16384，也不直接把所有请求一律提至官方最大输出。计划按每个真实审阅包的原文目标 token 量、需覆盖的 target spans / 文档数、动作数及固定关系结构估计完整输出负担，增加 **1.5 倍余量**，再上取整到预先允许的 **16384、32768、65536、131072** 四档。

修订实现采用 `ceil(1.5 * (4096 + 3*T + 64*F + 128*A))`：T 为该题8槽已结算的真实 DeepSeek 生成 completion tokens 总数，F 为事前机械划分的目标原文片段数，A 为实际动作数。选择不低于此估计的最小登记档；超过131072直接阻断登记，不截断包。4096是共同结构开销项，其余系数和1.5余量是显式工程估计，不是官方 tokenizer 测量，也不是已证明容量保证；通过事前小批校验。上限只按输入规模和输出职责计算，不得读取原生正确率、审阅 valid 数、chi、状态数或训练效果来调整。

全量新审阅前，事前固定 6 道按容量估计排序的代表原题：按上述估计升序、同值按原题顺序，取零基位置0、250、500、900、990、999。每题保留全部8槽并做双审，共12个请求。这12个请求事前登记为新2000中的首批，不是额外优选材料；具体任务 ID、上限、rubric/schema、源代码及检查条件在调用前冻结。不按答案成绩、旧审阅通过情况或期望训练价值选题。

小批要求12次全部以 `stop` 结束且通过 JSON/schema、alias/原文绑定和必须字段一致性校验；同时保留真实输出 token 与容量估计、账单。检查不要求任何 valid 产率或预期方向，合法报告invalid/unknown不会仅因判定为负而阻断。若未满足条件，保留全部结果并停止放大；不无登记地反复试提示。全量阶段出现同类容量/格式失败也停止新派发，重启不能跳过失败继续。小批与正式重审受同一800元上限约束。

HTTP等待上限也随请求容量调整：`max(180, ceil(90+max_tokens/128))`秒，避免扩大输出后仍沿用短响应等待时间导致未知计费。这个时间是输送容忍度，不是任务完成时间预测。实际输入JSON的UTF-8字节数加输出额度还需通过1M上下文保守预检；字节计数不伪称精确API token数。

截至本文所记状态，**这 12 次小批尚未实际执行，没有修订后的有效率、成本、耗时或容量通过率可报告**。任何正式启跑、后续结果及完整精确公式须追加新的绑定执行记录，不覆盖本次旧协议审计。

## 7. 预算继承及恢复安全

暂停并结算后的联合费用保守上界为 **113.828123 元**，包括生成的 **30.665504 元**和旧审阅的 **83.162619 元**；相对 800 元总上限剩余 **686.171877 元**。未知账单为 0，在途预留为 0。这些数值按登记的高峰费率对真实 usage 向上取整，是费用保守上界，不冒充供应商发票。

失败审阅的费用仍然计入原 800 元上限，700 元预警保持不变。重新审阅和容量小批不得新开一个 800 元额度，也不得删除、重建或清零旧账本。新旧请求需要不同执行坐标和明确修订 ID，避免与旧 427 条审阅发生覆盖或重复结算。

提高单请求输出上限时，要按每次真实 `max_tokens` 重新计算最大费用预留，并在收到返回后用该请求的实际上限核验 usage；不能仍用 16384 校验新请求，也不能仅改 API 参数而不改预算预留。已结算费用与所有在途/未知预留之和始终不能超过 800 元。遇到未知账单仍需保留预留并停发，不能以容量修订名义重试未确定的已付请求。

800 元是硬上限，不是保证获得 2000 份合格审阅的费用估计。原生成历史保守费用约 30.67 元，只能作为既往观测，不能保证重采价格或质量。此次没有实施重采；如未来发现独立的生成协议缺陷，须完整登记新的固定批次、保留旧批并继续计入授权预算，不按答案成绩选择性拼接。
