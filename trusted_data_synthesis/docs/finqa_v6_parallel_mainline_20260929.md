## 2. 独立Base评价的预登记选择

Base使用原始`Qwen2.5-7B-Instruct`冻结基座，不加载旧Static或其他LoRA。数据为原角色规划中的全部883条官方dev；不改split，不挑题、不补失败。使用已登记的新公开执行接口`bigfinance-derived-vtdo-v7` / `finqa-public-reasoning-v2`，工具及公开说明与未来同批Student比较一致。它不是API Probe，也不调用DeepSeek，不占用800元API预算。

原五臂计划指定greedy，但没有独立冻结dev解码细节。本次在看到Base结果之前明确：temperature0、top_p1、top_k0、每会话最多32响应、每响应2048输出token、完整context上限24576，seed20260928仅用于可复现标记；不在多个解码配置之间择优。这些选择必须同时约束未来15个最终模型的对应主dev评价，不能只为Base选择不利或有利配置。

按原任务顺序进行两个固定分片，计划GPU0和GPU7各加载一份基座；先检查实际显存余量，至少24GiB才加载，允许同卡已有其他作业，但不结束其他进程、不创建占位。遇余量不足先保存等待。该门是当前执行安全余量，不宣称模型必需24GiB权重显存，亦不保证并发情况下绝不会OOM。

所有883次生成完成并封存之前不打开dev私有参考评分。保存完整真实响应、工具事件、token凭据和失败；模型正常失败保留在883分母，基础设施中断不冒充金融错误，也不静默重发已开始的会话。生成完成后使用已有公开推理profile专用原生程序评分入口`v6_task.score_public_reasoning_program`：正常`submit_program`没有单独final_answer字段，不能错误走旧answer+program入口判无Final。

先执行Base不表示把dev改成反馈数据；dev不进入gJ、SFT材料、资格审阅或状态构建。Base结果也不得用于更改本轮生成prompt、资格规则、训练臂、步数或检查点。后续比较须沿用同一登记配置和原始Base工件；若执行契约真的另改，必须单独披露新旧不可直接配对，而不是择优复用。

## 3. Experiment1–3的执行准备不是结果

新增机器可读计划将五臂、三种子11/29/47、10遍、每遍200步、每步5题及共同前400步明确化；每个seed的任务置换和批次日程供全部臂共用。Manual±来自固定先验赔率倾斜，不从C选方向；机制reverse是另一条仅400→600的控制，不替换Manual−。

共享400→800以及step800反馈必须先证明真实参数、Adam、RNG、日程、分布和反馈点身份一致；不能因为两个奖励计数相同就共享。原方案的实际执行剂量、反馈700分母、3240/2160校准会话和最终dev14128会话不改变。计划中的共享节省只是条件分支，不预填为已经节省的GPU时长。

材料结构检查只是一层前置：库存、双审共同mask、全部joint-valid原包和Student编码必须精确保留，任一原1000题缺支持仍阻断。对调用者提交的hash/结构声明检查通过，也不等于已经核验磁盘原件或获得真实训练启动权限。没有填造真实训练结果、完整材料核或已完成的反馈seal。

新增`v6_mechanism_diagnostics.py`按原Experiment2定义实现纯计算：每repeat固定350分母，一半C提出方向、另一半C评价，完整700的C为等分两半均值；C已含mu，不再乘mu或pi。自评分与交叉评分分开报告，不选择较好repeat。记录TV、KL(new||old)、熵及同点C-only/Full的N分布差异；这不替代真实step800→1000训练对照。正方向相对反方向少受损但仍低于Static时明确不称为正收益。

本次数值测试只验证软件定义、边界和固定分母，不能冒充实际FinQA或Student实验结果。Experiment4原工件ID为`finqa_v6_experiment4:97e43c1da30d7d2f1276da671b7590b523a0233de7554e42551593e951a22ccc`，证明仍仅限固定正势、固定平滑C/RMS的数学映射，不外推动态训练闭环。

## 4. 最新监督标记的有限后续适配

对R5引入的`nonassertive_context`仅做显式版本的状态对齐及编码接通。空Q栏保持原文和零目标，不成为金融命题、正向token或χ证据；双审仍须一致，所有真正共同合格包均须整体映射，不删除难例。旧入口默认不接受该新标签。对排序落盘后的证据编号做确定性重建，避免重演主机字典顺序改变请求绑定的问题。

这一实现与合成控制不是新的API审阅，不重判R4/R5原失败，不把不同版本中的成功拼成材料核。R5技术门仍为false；新8000槽的登记仍不等于采集已经启动。

实际控制已完成：9项机制算术、19项训练日程/声明边界，以及8项新对齐编码控制＋23项原对齐回归通过。真实CPU Qwen tokenizer验证空Q栏所在token不进入目标，而获认可推理、Final及EOS仍有监督。新对齐wire为`v6_alignment_review.v4`，本次没有开放API传输白名单；未来真实审阅仍需独立登记，不因离线函数存在就自动请求模型。
