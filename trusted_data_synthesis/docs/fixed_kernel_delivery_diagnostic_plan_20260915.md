## 2. Agent 接线的实际含义

已训练 Student 在评测时实际接入项目自有 Agent runtime，不是仅做一次文本生成：

```text
公开任务与工具合同
  → 本地 Qwen + 已恢复 LoRA 生成一个 JSON 对象
  → runtime 解析工具请求并执行公开来源/计算工具
  → 工具结果或协议错误作为下一轮消息回填
  → Student 再次生成
  → 顶层小写 final 出现即停止，或达到运行预算
  → 完整会话结束后独立财务评分
```

主链为 `fixed_kernel_value/evaluation.py::generate → runtime.generate(provider=decoder)`，
decoder 实际调用本地 `model.generate`；runtime 不根据金融答案正确性决定是否
设置 first Final，也不替模型补出规范 JSON、定位正确证据或强制最后一轮回答。
该实现不是 LangChain/AutoGen 的使用声明，也不是把 Codex 协作 agent 当作模型运行时。

训练本身为离线、固定材料轨迹监督微调（SFT），不是 Student 在线 Agent/RL 训练。
训练资料的成功工具主要为 `read_source / calculate`，推理环境另增加完整快照中的
`query_source / list_concepts / read_json` 等发现接口。因此，已经接入 Agent 框架
不等于已经训练过并掌握全部评测接口；工具迁移差异应进入诊断，而非被归入预算不足。

## 3. 阶段 A：一次有界的既有输出扫描

- 规范 Final、疑似但不合法的 Final、JSON/长字符串循环；疑似文本不自动修补。
- 概念发现是否使用；查询是否非空、首次非空位置；相同查询参数且公开证据未变
  的重复，不仅统计工具总数。

- 是否执行计算、是否有明示的来源引用；不能仅凭 calculate 出现就声称算对本题。

## 6. 结果解释与后续约束

- 原训练历史下能计算/交付，但完整快照下不能发现来源：优先定位工具迁移和检索。
- 基座可以、微调后不行：支持微调相关或条件依赖的假设，不直接锁定超参数原因。
- 基座和微调均出现相同问题：检查接口可理解性和共同工具能力，不能以加预算代替证据。
- Final 恢复但财务资格仍为零：再检查数值、来源、单位、期间及支持链。
- 仍不能区分：报告剩余未知与证据缺口，不自动扩样或开始新训练。

这仍是开发诊断。旧成绩保留，原 720 题确认边界不打开；进入 B 必须依据新版本
完整开发结果和明确授权，不能因一次诊断正例自动恢复旧 B 分支。
