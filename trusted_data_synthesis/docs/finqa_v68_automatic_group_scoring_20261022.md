# FinQA V68：已完成组自动接续原生评分

## 1. 授权与范围

用户于2026-10-22先要求“已经完成的几组可以先开始评分”，随后明确“设置自动接续，已完成的组自动进入评分，不再等待统一评分，提高效率”。因此本次不是只评分当前两组的一次性任务，而是为原六组固定矩阵设置自动就绪队列。

新目录为原V63科学根下 `partial_scoring_01/`。原V63、V65、V66、V67的冻结协议、源码、失败、回答及控制状态不改写，不重启现有生成器。原“全部24项生成结束才打开私有评分参考”的时序，在本次独立授权中改为“单组四项全部完整封存并验收后，允许该组评分”；不能据此宣称原全24项屏障已经通过。

固定范围是三个seed（137、251、389）乘C1/C05，共六组；原24个生成作业、7458条评价会话不增加。自动接续只允许每组首次进入评分，不解释为重新训练、采样、生成、重评旧b0/Hold或异常自动重试的许可。

## 2. 每组就绪条件

每组必须同时具备四个原始作业的完整封存与实际验收：

| 面板 | draw | 每组分母 |
|---|---|---:|
| development greedy | 原固定greedy seed | 883 |
| calibration greedy | 原固定greedy seed | 120 |
| calibration random T1 | 11、29两个draw，各120 | 240 |

每组共1243条会话。只完成calibration的三个作业不能视作整组完成；不逐条抢先打开尚未完成组的私有参考。组内任务顺序、draw顺序、checkpoint、模型point、反馈批次b=1和解码配置保持原值。

截至13:32只读核验时，seed137/C1、seed137/C05各4/4已接受，可先评分8个作业、2486条回答。seed251/C1、seed251/C05、seed389/C1各3/4；seed389/C05尚无完整接受作业。后四组在原生成及V67封存完成后自动进入同一固定队列，无需再确认。

来源必须明确区分：

- V65回答：原GPU实际exit1、已知Episode JSON收尾错误及原资源PASS保留，加上V67 CPU补封存的实际exit0和接受记录；不伪称旧GPU成功退出。
- V67新回答：自己的完整原生回答、运行层seal、资源PASS、实际GPU exit0及accepted。
- 两类来源都须绑定原科学身份、来源计划、完整任务顺序与原生seal。UNKNOWN调用、缺失内容、未退出、未接受、状态漂移或资源失败均不能作为就绪组。

## 3. 评分数学与缓存

逐条复用冻结的 `score_public_reasoning_program`，指标复用原 `native_metrics`。保留原生执行准确率、程序准确率及I/W/R/UNKNOWN分解；UNKNOWN仍为显式未知，不归零，不删去分母。存在UNKNOWN时，完整数据集均值仍按原定义为null。

随机calibration报告按draw11、draw29的原顺序合并为240条；不做best-of、选择draw、池化不同反馈批次或挑选表现更好的seed。每条保留task key、draw、native结果、生成停止原因、模型调用、tool数量、生成token数与source group，便于后续统一统计直接只读引用。

每个完整作业写入独立native评分行，每组输出三个面板报告及组评分结果。原回答不复制或重写；已经接受的评分不会再次执行。未来完整矩阵分析须只读接纳这些结果，不能重新评分以得到另一套结果。

当前仅执行原生评分与组内描述指标，不调用原要求全6组/24项的统一 `score()` 入口，不计算不完整矩阵的paired summary、跨seed置信区间、bootstrap或advancement。组分数产出不等于完整研究结论。

## 4. 自动调度、停止与资源

独立协调器观察固定六组：等待完整accepted→发布不可变组就绪证据→首次派发CPU评分→观察实际exit0→接受结果。最多两个CPU child并行；已接受组只读跳过。未完成组继续等待，不改变GPU生成顺序、配置、采样或实验剂量。

每个CPU评分worker主存历史峰值硬限32GiB，全机有效可用RAM保留96GiB。启动采用固定保守门512GiB：96GiB余量＋6个GPU生成启动预算（6×48GiB）＋V67 CPU修复预算64GiB＋两个评分预算（2×32GiB）。不按其他进程较低的实测RSS抵扣；这是启动预算公式，不是保证所有GPU worker同时达到192GiB RSS硬上限仍可容纳。

评分禁用CUDA，不加载模型、不调用provider/API、不取GPU租约。不会中断、迁移或向原V65/V67 worker发信号。协调器只管理自己核验过PID/birth的CPU child；保留原合法停止语义。明确停止即停止自动接续，异常CPU尝试不自动重试，未观测的退出码不伪造为0。

新评分文件严格写入 `partial_scoring_01/`。现有冻结生成器只读取其预登记生成目录及模型点，不读取这个新评分目录；因此评分结果不进入剩余生成的策略、停止条件或参数选择。

全部六组接受后只标记六组评分齐全，仍不自动开展新训练、生成或研究分支；不把这一控制完成状态冒充全部科学分析完成。
