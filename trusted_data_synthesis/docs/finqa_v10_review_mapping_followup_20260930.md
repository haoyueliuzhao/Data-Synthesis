## 22项映射unknown的准确归因

22项全为`annotation_failed`，不是22项模型主动选择语义unknown。其中21份可完整解析的原JSON自行标为complete，另1份被截断。这些分类来自实际保存的原请求、tool arguments、finish_reason及本地错误，不改写任何响应。

1. **19项必填字段缺失。** 均遗漏`states[*].evidence[*].slot_id`，其中PNC/2018/page_45.pdf-5还遗漏`state_id`。真实已发strict schema明确把slot_id列为required，且启用strict；本地验证并未临时增加字段要求。虽这19项均为单包任务，也没有据此自动填字段放行。
2. **1项原文定位错位。** AMAT/2012/page_37.pdf-2中，原文切片`[0:468]`对应的quote只有364字符；另一处`[0:273]`的quote只有263字符，漏掉末尾Q段。请求明确为Unicode codepoint偏移，原文与验证单位一致，问题是返回的end与quote不一致，不是现有证据表明的索引单位实现错误。
3. **1项状态与歧义声明冲突。** HFC/2011/page_92.pdf-1声明complete，同时提供非空ambiguities，内容涉及ratio/percentage及是否乘100。states已经覆盖唯一包；错误文案中“retain every jointly valid original”是完整性联合校验的泛化提示，不能误报为漏包，也不能擅自清空歧义数组。
4. **1项输出容量截断。** KMI/2010/page_164.pdf-2的max_output_tokens=2048、completion_tokens=2048、finish_reason=length，原arguments尾部截在slot ID。本地JSONDecodeError是非正常工具完成后生成的包装诊断，根因是实际输出触顶；不是无返回网络错误，也不是已证实的本地JSON解析器bug。

这些结果说明当前映射接口仍有结构和容量问题，不能解释为五臂训练算法失败、22题金融推理都错误，或提示“多给GPU即可解决”。本次不自动修复原JSON、推断缺失ID、篡改quote/end、删除歧义、重审A/B或重新采集。
