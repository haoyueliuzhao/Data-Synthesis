## Actual Runtime And Independent Validation

`run_candidate` resolves inputs from current visible Evidence or already verified Claims,
checks registered contracts and typed roles, and writes a pre-action proposal and receipt.
Only after durable commitment does it call the actual registered executor. It then persists the
execution, actual Observation, accepted Claim/Update, and next State before the next Action.
The final record uses the route's own grounded absolute-spread Claim and exact source citations.
Source comparability is a Host check; it is not counted as an invented registered Operation.

`validate_candidate` reopens the saved artifacts through a separate reader and independently
reconstructs source roles, state readiness, proposal/receipt ordering, actual operands, operation
contracts, Observation support, Claim production/consumption, and terminal grounding.
Its implementation imports neither the candidate Runtime nor its source-construction helpers.
It uses registered Oracle implementations for arithmetic replay and rebuilds obligation witnesses
from actual saved dependencies. Caller-supplied validity and ownership labels confer no authority.

QA validation separately applies `CandidateAnswerNormalizer` to the frozen Schema and independently
recomputes the unchanged eight-node answer Oracle with `TaskProgramOracleVerifier.derive_expected`.
Citation checks require the exact four Evidence identities, source identities, and locators.
`Qualified = QA_valid AND trajectory_valid`; answer correctness cannot compensate for an invalid
public trajectory. Candidate-route replay and answer-Oracle recomputation are separately counted.

The five discharged obligations are comparability, revenue growth, operating-income growth,
exact signed-and-absolute spread, and final grounding/citations. Actual Claim IDs and supporting
Evidence are persisted in `evidence_to_obligation_discharge`; coverage is not an equality check
against historical D0–D4 names. The old `CandidateWorkflowVerifier` iterates every frozen Oracle
node and is therefore not reused as the unique-route validator for A. No missing Oracle lookup
is backfilled as an A Action. General alternative-route validation remains outside this local family.
