## 3. 固定推理与调度

- 每完整会话最多 32 响应 / 32 工具，每响应最多 2,048 新 token；
  完整历史加预留新 token 不超过 24,576，不裁剪历史、不续写失败响应。
- 原 greedy、BF16 基座、FP32 LoRA、Flash SDPA 和 `logits_to_keep=1` 保持；
  不为速度改用量化、降低精度或换 attention 后端。
- 十模型固定顺序：基座，随后种子 11、29、47 内各 alpha0、plus、minus。
  偶数索引先 Γ0 后 Γdoc，奇数相反，两种顺序各五模型，运行前冻结。
- 最多 8 个 GPU worker，每张卡本实验同时至多一个 worker；按剩余显存准入，
  不要求利用率为零，不终止、移动或改写他人的作业。
- 每个模型进程只实际加载一次基座/adapter/分词器；第二说明条件复用模型对象，
  但建立新 decoder、独立计数/收据/output。第二条件的物理加载计数真实为零，
  并绑定首条件实际加载收据；不是伪造第二次加载。
- 每个完整会话都重新建立历史与工具结果；`model.generate` 不传前一会话 KV，
  不让条件或题目间的消息、工具结果、缓存相互进入。
- GPU 生成进程全部退出后，再并行启动独立 CPU 评分进程；完整财务评分不会
  作为后续模型输入或决定追加样本。

显存准入冻结为 **24,576 MiB**。估算来自 7,615,616,512 个 BF16 参数约
14.19 GiB，以及最大上下文的 GQA KV 约 1.31 GiB，准入余量约 8.5 GiB 用于
激活、算子工作区、LoRA 和分配缓存。**这是工程估算，不是已测峰值或无 OOM
保证**；每实际 worker 另记录 PyTorch allocated/reserved 峰值。外部作业仍会
影响吞吐和可用显存，但本实验不以占满整卡或修改他人作业为前提。

只进行一次父进程基座文件 SHA 准入，再通过可信 spawn 把准入身份传给 worker；
各 worker 检查文件未变并做实际加载匹配，不十次重散列完整基座。

## 6. 六前缀的单步语义诊断

完全复用阶段 B 的 `annual_flow / stock_rollforward / company_defined_metric`
各计算前、Final 前两份前缀；不重新选任务或原包。每模型六次单步生成，总计 60。
只向模型发送冻结 `input_messages`，不加入 Γdoc，也不发送下一条参考响应。

生成与语义分析分离：原 Probe 已完成的来源读取、计算不是 Student 行为。
语义分析使用原训练 `read_source / calculate` 合同，不误送到 R1 评测接口。

- 计算前：分别报告 JSON、工具可执行、引用成立、所求数量成立。
- Final 前：分别报告本步立即交付、已有结果支持、数值及单位正确。
- 精确数值、单位转换与有界有理来源表达式比对可接受合法代数等价；不能证明的
  替代来源关系或超出分析范围的函数保留 `undetermined`，不直接判错。
- 逐字复现率只可作文本描述，不能代替语义通过。继续核验仅表示本步未立即
  Final，不推断永远不会 Final；本轮不会再续写一轮来追求正例。

这些是给定 Probe 历史的条件能力，不加入完整自主资格分母，也不加入训练材料。
