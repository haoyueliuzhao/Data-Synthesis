# FinQA V41：按阶段显存需求准入与被动交接

## 结论与授权边界

用户针对“完全空闲且 free ≥ 72GiB”提出“此条件是否过于严苛，根据实际需求放宽”，随后明确选择“保持满额，自然空队列时切换”。本次只调整原剩余九模型矩阵的设备准入策略及其安全接续实现，不新增实验、class pass、response 回放、反馈采样预算或优化轮次。

历史过程内显存记录支持取消统一的 72GiB 准入门，改为分阶段 24–48GiB；其他项目存在计算进程不再单独构成否决条件。设备仍限已授权的本机物理 GPU0–7，总并发最多四个 worker、每卡最多一个本实验 worker，CPU 初始化、CUDA 前等待及 draining 均计入名额。不能把“有空闲显存”理解为允许重复占用本项目已租用的设备。

切换方式固定为 `passive_all_or_none`。不向正在计算的 worker 发信号，也不逐步扣留自然释放的卡来迫使队列排空。原 V40 正常调度继续运行，只有自然出现全局零 worker 且全部已派阶段成功封存、真实退出的安全边界，才允许接续到新冻结版本。如果登记期限内没有出现该边界，交接停止而不强制排空、不自动改变模式。

原 V40 的冻结源码、协议和历史停止记录不修改；新科学目录为 `production_resume_01/admission_relaxation_01/`，被动交接目录为 `production_resume_01/recovery_02/controlled_admission_handoff_01/`。本报告中的策略与实现说明不等于已实际切换，实际状态必须以对应登记、启动及 worker 记录为准。

## 显存依据：观测不是理论上界

仅只读分析本轮已封存的资源 JSON，不启动新 GPU profiling，不读取终点答案或提前查看准确率。下表列出七份代表性成功记录的进程生命周期 `peak_reserved_bytes`，覆盖模型加载；原始记录的绝对路径及 SHA-256 见 [显存证据引用](finqa_v41_memory_evidence_20261013.json)，顺序与下表一致。

| 实际阶段 | 代表记录的 reserved 峰值（GiB） | 新准入 free 下限（GiB） |
| --- | ---: | ---: |
| 完整任务类梯度分片 | 19.387 | 28 |
| 真实 SFT / outer 提交阶段 | 24.855 | 32 |
| R3 response 梯度回放 | 40.654 | 48 |
| 虚拟点，复用同点已封存反馈 | 14.291 | 24 |
| 虚拟点，原剂量内首次反馈采样 | 20.029 | 32 |
| distribution：C 与 π 复算 | 14.330 | 24 |
| 终点回答生成 | 39.990 | 48 |

这些证据来自既有数学和相同模型配置。采用 reserved 而非单看 allocated，是因为 PyTorch 已保留的显存同样会占用设备；整卡 NVML 使用量则可能包含其他项目，不能直接当作本 worker 的内存需求。

准入阈值是在上述已观测 reserved 峰值之外，加入约 1GiB CUDA / 非 PyTorch 余量、原有 2GiB 边界空闲要求及至少 4GiB 未观测波动余量后向上取整。它是本次明确登记的工程估计，不是通过理论分析证明的最大需求。未来响应长度、分配器行为和其他进程的显存增长仍可能导致资源失败；本次不据此宣称消除 OOM 风险，也不声称共享 GPU 一定提升吞吐。

不把两种 virtual_point 混为同一档位：准入直接读取原 context 的 `feedback.mode`，仅识别 `sealed_existing` 与 `first_sampling`；缺少模式、未知阶段或不完整设备观测一律拒绝，不能通过传入便宜阶段的别名绕过检查。

## 保持不变的硬门与共享设备语义

- 整个冷进程 allocated 历史峰值最多 76GiB，规定边界 free 至少 2GiB；模型加载计入，加载后不重置峰值。R3 非 KV 激活驻留预算仍为 16GiB。
- 类梯度分片 RSS 最多 160GiB，其余阶段最多 192GiB，全机有效可用主存至少保留 96GiB；原磁盘、数值、同点、参数 / Adam / RNG / buffer 及真实退出验收继续执行。
- 派发前及同一 worker 初始化 CUDA 前均重新检查实际 free、物理 UUID 和进程信息。共享设备上的外部 PID 被真实保留在审计记录中，不伪造空进程列表。CUDA 前出现本 worker 自己的 GPU PID 仍属异常。
- 设备 UUID、原 CPU 亲和及原项目 GPU 租约沿用；不信号、不终止、不迁移其他项目进程。遇到 CUDA 前资源竞争，仅允许原同一进程按原预算有界等待；CUDA 后失败停止全池，不自动重试。
- 既有阶段绝对 deadline、outer 已用时间及累计资源等待继续继承，不因政策调整重新发放 24 小时预算。交接和初始化墙钟按登记口径保守计费。

## 被动交接与原值继承

观察器仅运行 CPU 控制逻辑，不占 GPU worker 名额。每次探测尝试取得原八卡租约；只要任一卡仍被本实验占用，就立即释放本次全部已取得的锁，不逐卡积累。对于已有未派齐的 class，释放屏障让原控制器继续派发，避免把部分 class 困在等待状态。取得全八锁后仍须读取取得锁之后的新鲜空队列，并检查每个已观察 launch 对应实际 `COMPLETE`、原资源门通过、exit 0 和真实进程退出。

只有上述条件及原状态只读预检通过后，才可对核验 PID、birth、UID 和完整命令行的旧控制器发送一次停止信号。此时没有科学 worker；随后核验旧控制器真实退出、干净暂停记录及实际训练进度。新控制器在全锁屏障内完成继承和计费，释放屏障后才开放新派发，禁止两个科学池并行运行。停止或交接失败不能被改写为科学成功。若旧控制器已经干净退出、但新初始化失败，则安全停止并保留状态，不自动回退重启 V40；“旧调度继续”仅指尚未实施暂停的被动观察期间。

继承使用每个阶段真实来源目录与其自身 `protocol_ref`，不能把 V37、V38、V40 的混合来源都当作单一父协议。已封存值保持原 context ID 和实际 Tensor / checkpoint 绑定，不重算成功阶段、不重放成功 response，也不重新采样已封存反馈。未完成的 class 必须先由旧调度器自然完成全部四片，不能借新策略重派部分片或以零值补齐。

Full389 step298 的 V40 恢复首点已在北京时间 2026-10-13 03:42:41 完成真实验收：继承 response261 后新增 186 条，共 447 条；outer 只提交一次，真实 SFT 到 299，worker exit 0。新策略只继承该成功事实，不再次执行先导验收。证据为 `recovery_02/pilot_acceptance/record.json`，内容 ID `7e8861ffe5dbc2096610658117e3d6c2bc16542eb9de337f096fdc6fa909a3bc`。

C-only251 step1192 的特殊 class 补齐由 V40 执行。继承时必须验证旧 186 题只读缓存与 V40 新 558 题实际缓存正好组成原序 744 题，保留各自来源，不能再发放那次已经起算的四小时窗口。所有其他原数学、剂量、训练边界和九模型统一评分屏障不变；当前已封存的终点结果不提前评分。

## 实际进度观察与验证范围

北京时间 2026-10-13 12:16:49，只读队列观察为 V40 `RUNNING`、首点验收已通过，三个活跃 worker 分别为 GPU6 的 replay_R3、GPU2 的 replay_R3 和 GPU0 的 virtual_point。原四个已封存训练与终点评价坐标仍为 seed137 的 Static / C-only / Full 以及 seed251 的 Static。此时接受计数为 1966 次 optimizer 更新、5 次 outer；这是控制器接受计数，不替代接续时的实际 checkpoint 审计，也不是九模型实验完成。

“保持满额”意味着不为本次变更人为减少原调度并发，并不保证资源竞争下每次观察都恰有四个 worker。此时尚未冻结或启动 V41 交接，新准入尚未用于实际派发。后续冻结、CPU 核验、启动和切换状态将在完成后单独追加，避免将计划写成结果。

## 实现核验结果

最终 V41 CPU/mock 集成测试 **208 项通过，用时 9.68 秒**；八个新脚本及七个测试文件 Ruff 检查全部通过。测试临时产物位于 Git 忽略的 `artifacts/test_tmp/`，不纳入正式实验提交。此前另运行了含 32 项 V40 worker / evaluation 回归的消费者测试组合，以及修订前的 200 项集成测试；这些运行与最终 208 项存在重叠，不能相加为独立测试数。

覆盖包括分阶段共享设备准入、CUDA 前竞争同进程等待、UUID / RAM / deadline / 合法停止拒绝路径、同点 186+558 真实 CPU Tensor 原序只读合并、缺失与损坏拒绝、实际 worker / endpoint 消费接口、逐阶段 owner 继承、R3 的 261+186 计数、原绝对 deadline、三处 endpoint 等待区间并集合账，以及自然空队列交接不逐卡积累锁。交叉审查发现并修复停止处理器交棒窗口：新控制器创建后先安装桥接处理器，同时记录观察器停止和控制器停止，再交给原运行框架，避免遗漏合法停止。

服务器实际 Python 3.12.13 未导出 `os.pidfd_open`，但本机 libc 提供该接口。新 V41 只在原生接口缺失时调用本地头文件确认的 libc `pidfd_open`，保持描述符绑定、身份复核和关闭；原生调用失败不换路重试，没有裸 PID 信号回退。登记前新增只打开并关闭当前自身句柄的能力检查，实际检查通过，发送信号数为零。旧 V39 / V40 源码未作兼容修改。

这些测试和能力检查没有启动新的真实 GPU 计算、反馈采样或 API 请求，也不构成共享 GPU 上的实际资源验收。历史七份资源证据的 SHA-256 与上表峰值已逐项核对；最终派发后的实际结果仍需遵守原资源与科学验收门。
