# V6主实验的新完整材料批：V7执行协议与类型化审阅定位

这里V7是公开执行接口版本，不是新增第七个研究实验；主线仍是原Experiment0–5和五臂设计。

## 1. 用户选择与旧批保留

用户在获知旧1000题中224题的8槽均无原生正确程序后，明确选择“设计并登记新一整批轨迹，保留旧批，不按成绩拼接”。新批覆盖相同原始SFT角色1000题，每题8个全新独立槽，共8000，所有8槽均为共同材料候选。不会只补224题，不把旧新正确结果拼成一个核，也不自动改成条件性删题训练。

旧生成8000条、427旧审阅、两轮各12次审阅和后续R3技术审阅均保留。模型固定deepseek-flash，thinking仍disabled；所有费用继续扣同一800元联合上限，700元预警，原258000请求硬上限不重置。新批的8000×32最大生成请求数是逻辑上界；加上旧调用后可能超过剩余全局请求预算，因此不保证能把每槽都跑满32轮。原费用/请求上限始终优先。

## 2. 已观测的通用生成缺陷

全8000旧轨迹中3891条原生错误，其中3387条可执行但结果错误。按五位执行舍入容差比较，1553条约为参考执行值100倍（涉及360题），其中1424条最后一步明确乘100。另有90条约为−100倍、70条约为0.01倍、110条符号相反。这些仅是数值关系，不能证明剩余推理正确。

535个简单百分号参考文本中，459个执行值兼容“文字百分数÷100”，19个兼容原百分数，57个其他。因此不能事后统一缩放旧程序或声称所有百分比问题都有一个相同的金标准尺度。

373条多工具终止中，368条只是并列读取多个来源（336次双读、28次三读、3次四读、1次九读），大部分发生在首轮。59条无效最终程序中，22条嵌套调用、20条裸常量、13条裸数值、4条执行失败。它们是新整批可以统一澄清的公开接口问题，不是给特定题提供私有答案的依据。

## 3. 新公开协议：只改统一契约

新身份为 `bigfinance-derived-vtdo-v7` / `finqa-public-reasoning-v2`。保留公开R/U/Q摘要、原题及公开表格/文本、list_sources/read_source/run_program/submit_program四工具和每响应一个实际动作。仍不要求固定工具顺序、额外核验或故意犯错，不制造χ行为。

统一新增说明：

- 原文已在初始输入中，不为形式而重复读取；若多个来源确实有用，一次只读一个，在后续轮次再读下一个。
- 原始执行数值与百分号显示不是同一个量：人工合成例divide(1,20)输出0.05、可显示为5%，不能仅因出现百分号就额外乘100。比例、百分数、百分点和单位按问题与证据判断，不宣称一种缩放适用全部参考。
- 程序必须是完整线性步骤；人工合成示例`subtract(9, 4), divide(#0, const_10)`得到0.5；常数答案也应是合法完整程序，如`add(const_1, const_0)`得到1。裸数值、裸常量和嵌套表达式不自动修复。

例子不含真实题ID或答案，不是当前问题证据。旧V6系统文本和profile原件保持不变；V7原生评分、公有轨迹视图、离线Student编码有显式版本支持，不用新系统文本冒充旧轨迹输入。

[DeepSeek Chat接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)没有给出可依赖的`parallel_tool_calls=false`保证，[Responses兼容说明](https://api-docs.deepseek.com/guides/responses_api/)明确该参数会被忽略。故本版不把未获确认的参数当作禁并发修复；真实多工具响应仍按协议保留为失败，不拆改为成功。

生成输出容量只看公开任务尺寸，同题8槽相同：公开问题＋来源原文超过8000字符或表格超过200单元格时为16384，否则2048；这是工程容量分档，不是API精确Token预测，不读取旧成绩/私参。即使较大额度未用满，也只按真实usage结算。该两档已在原联合账本允许范围，无新增额度。

## 4. R3分解接口的真实验证结果

R3协议`248ab0864b9c9cb9b503c2076505a4f11c5e73551fb94998ce29d54578564a46`原定同6题96次逐槽、12次对齐工程调用。提前停发规则触发后，在途结算完共15次逐槽，全部tool_calls、无length；机械接口1/15通过，语义一致0。没有进入对齐，也没有扩大旧库存。新增费用保守上界0.650226元，累计118.433295元，全部已结算、未知0。

12次`wrong source/action/observation kind`中，12/12都有node源字段错误，9/12兼有term源字段错误；76个node错误引用和40个term错误引用大多指向真实工具观察，包括read_source转录、run_program结果和submit观察。1次还把来源/问题当作模型已发表断言。另2次缺/多schema字段。不是所有失败都来自数据缺失，也不能把真实观察自动替换成公共源以放行。

## 5. R4最小类型化定位修订

R4仍使用同6题、全部8槽和双审，不只补坏例、不沿用旧唯一接口pass。单层原文片段ID显式分为`src_* / text_* / action_* / obs_*`；无法解析的原调用仅用只读`raw_*`，不伪造成功动作。

Term和Node的原公开来源锚点字段明确改名`public_source_anchor_ids`；命题引用改为`model_claim_ids / support_evidence_ids / retraction_model_ids`。派生量锚定原始输入来源，真实计算观察可作为evidence；不暗示计算结果原文存在于源中。schema、枚举与rubric同步采用这些角色名。

主机只做预登记的定位符/字段名双射映射，再走原有限语义检查；旧错误obs源锚仍会拒绝，不补src，不放宽V_trace、χ、mask或映射条件。保留真实v4原参数SHA、机械映射JSON SHA和语义展开SHA，映射产物不冒充模型返回。

R4仍最多96逐槽＋12对齐，沿用≥95%机械接口、无length/未知费用、失败窗口提前停发规则。语义不确定仍为unknown，不产生正向材料。类型化命名是待实际验证的修复，不预先声称一定有效。

## 6. 新整批的登记与启动必须分开

`v7_full_probe.py`是新完整批次的登记器，不因创建协议就自动发请求。它绑定原1000题、8000全新槽、公开协议、逐题容量、同账本历史全集、费用和剩余请求数，并明确`REGISTERED_NOT_STARTED`。

登记绑定实际分解审阅技术门。若门未通过，可如实登记新批设计，但`execution_admitted=false`，不打开key发请求。后续若技术门修订通过，必须登记新的准入版本，不能修改已有false为true。所有新Probe完成封存之前，不对该新批读取私参做原生评分/语义审阅；旧批已有私有评分不进入新Probe输入。

新批生成后仍须检查真实原生支持、有限语义资格、完整状态映射与Student编码；8000候选不保证1000题完整支持。不得自动进行第三轮补采、缩题或旧新拼接来制造完成。五臂训练、GPU占用和训练价值结论目前均未开始。

本说明在R4实际调用及新批登记前写入；后续观察写入独立不可变协议/运行记录。

## 7. R4实际结果及主机绑定更正（2026-09-29更新）

R4实际发出15次：14次取得完整计费返回，另1次发生`RemoteProtocolError`，没有收到可结算的服务响应或usage。原始14份assessment均因主机`typed slot catalog/schema/rubric/request binding differs`被拒；原登记、返回、assessment、提前停发记录及false技术门均不覆盖。

定位发现JSON落盘采用`sort_keys=True`，会将`e0,e1,e2...`字典迭代顺序改为`e0,e1,e10...`，重建typed定位符时因此重新编号；内部字段顺序变化还影响原始消息字符串。修复从已绑定的原始wire JSON恢复catalog字段顺序，按原e数字坐标重建，原模型输入和返回均不修改。新增排序落盘往返测试。

原14份返回的只读离线更正结果为：12/14接口通过，0/14完整语义一致；另2份为实际模型参数JSON解析错误，无length。更正结果发布到单独`offline_binding_correction_01`，包括原文件哈希、原请求与原返回、原assessment与更正assessment、源码绑定及重放入口。它不是新的API调用，不替换旧门，也不自动开放训练。

12份语义不一致不能概括为12条金融推理均错误。首失败中7份是原文`Q: None.`被标approved却没有proposition绑定；另1份在其他首错误之外也有同类空栏问题。剩余首错误包括term/node引用域混淆、decision node缺term、unknown命题被positive mask引用、关键未解决claim却报valid、派生term缺原始来源锚点。后者仍须实质审查，不能用空栏例外掩盖。

## 8. 未知费用的保守弃置，而不是补造结算

用户回复“预算充足，整体仍有七百左右的预算”，据此采用在原800元上限内继续的保守处理：精确弃置那一次中断调用，永久保留其最大预留、不重试、不新建替代调用，不扩费率/额度/请求上限。

弃置前已结算的峰值费率上界为119.030706元，UNKNOWN预留2.228224元，总风险占用121.258930元，剩余678.741070元。上述不是供应商账单。原行仍为UNKNOWN，usage/实际收费未知，held与unknown计数不变；独立授权记录及event绑定该调用、原请求SHA、原halt、原行摘要和全部守恒计数。仅这次明确处理过的UNKNOWN不再阻断不同的新请求；未处理UNKNOWN、任何无关halt及额度不足仍阻断。已弃置的原调用也不能重新发送或伪装成普通SETTLED。

新完整材料批的登记器现在允许如实封存“含UNKNOWN预留、仍未通过审阅门”的设计快照，明确`execution_admitted=false`。登记不调用旧恢复器重写assessment，不把“可以登记”混同于“可以付费执行”。剩余额度扣除全部held，非仅扣已结算数。

## 9. R5前瞻性有限修订与一次固定12调用技术小试

审计要求检查关键事实、推导、更新和终局，并不要求把每个空可选栏强行当成金融命题。为使正向监督规则表达这一边界，新增仅显式opt-in的`v6_slot_review.v5`，旧V3/V4的默认解析、rubric、schema与正向规则不变。

新mask标签`nonassertive_context`仅允许整片public_content为`Q: None`或`Q: N/A`（大小写/格式空白及末尾句点可变），且proposition_ids必须为空。它由模型明确选择，主机只核验范围，不替模型改标签。原文始终保留在输入与历史，目标损失为零，不计作证据、语义状态或χ。工具参数、金融陈述、一般旁白、“已核验/无错误”等都不在白名单；真实unknown、矛盾、未撤回关键错误仍按原规则阻断。任意approved片段仍必须绑定已审且支持的命题；不能离线把旧失败改为通过。未来共同mask仍须双审一致。

R5只取原预选6题各原slot0、每条双审，共12次；不是按成绩选择，不复用R4某一侧的成功判断。该次小试继续deepseek-flash、thinking disabled、原逐请求容量规则、4并发、零重试，全部最大费用预留须在共同800元上限内。12次须12次真实strict接口通过、无length且本次无新增未知费用；没有“必须给出positive”的门。错误与未调用槽均留在固定12分母。无论结果如何，不自动开展下一轮接口采集，不自动扩大旧库存或新8000生成，更不自动训练。

本次仅验证逐槽修订，不替代原96逐槽＋12对齐门。尤其新标签进入未来共同状态对齐和Student编码，仍需显式版本适配及必要验证；不得将新标签塞入旧Mapper假装全链路已准入。新整批设计、R5启动及结果各有独立不可变记录，实际执行数字以运行记录为准。
