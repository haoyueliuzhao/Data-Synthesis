## 固定前沿与计算预算

先冻结全部财务／发行人／公开视图前置可用候选，再沿既有 issuer hash 轮转与实际期末／task ID 排序推进。不以审核完成速度选题，不读取 Student 得分，不降低三个 60 配额。

每轮暂把未审候选保留为“可能可用”，按原顺序取前 60 个组成任务，并审核其需要的完整报告文本。具有具体语义疑点的任务记录为来源证据不满足，而不是声称现成汇总已经被确证存在。仅当仍可能改变选择的前 60 个任务都已真实通过时，前沿才闭合；此时未审尾部不会改变选择。面板编译器独立重算这个条件。

每个文本包使用一次 `deepseek-v4-pro` 语义审核，不再先运行两个定位模型。最多 16 个并发请求；每包最多两个保存的物理尝试，每次输出上限 4,096 tokens。HTTP／JSON／定位等技术错误用独立尝试记录保留，两次均不成功则停在技术待处理，不把该任务当作金融不合格来换题。中断前已保存的包可复用，未决物理尝试不退还额度。

已有只读核算：406 个组成候选通过身份和公开视图前检，涉及 43 个发行人；它们的报告并集为 233 份、5,663 包。若最前 60 个任务均通过，首轮需 94 份报告、22,098 页提取文本、43,755,615 个原始字符、2,336 包。上述是工作量，不是准入成功数或服务商计费 token 数。运行时协议将重新绑定确切清单，最大请求数为候选报告并集包数的两倍，不要求把尾部全部审完。
