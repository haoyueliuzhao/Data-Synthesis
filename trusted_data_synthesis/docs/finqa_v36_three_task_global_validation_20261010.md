## 生命周期修订

`Popen.poll()`的返回值用于判断父进程是否已经观察到子进程退出；短时间的 `wait()` 超时只表示给定时间内等待未完成。结果文件已经写出和进程已经退出不是同一事件。[Python 3.12子进程文档](https://docs.python.org/3.12/library/subprocess.html#subprocess.Popen.wait)

本次将可信完成结果与真实退出分开记录，不再对结果已完整封存的worker同步等待两秒后中止其他工作。

| 状态 | 准入与行为 |
| --- | --- |
| RUNNING | 保持身份、资源和失败记录检查；没有可信结果就不得豁免必要观测 |
| RESULT_COMMITTED_DRAINING | 完整结果、模型释放和末阶段资源门已核验；保留锁与名额，非阻塞轮询退出 |
| EXITED_PENDING_VALIDATION | 已取得实际退出码，再核验封存结果、资源及工作范围 |
| SUCCEEDED | 真实退出码0且全部结果门通过，才释放进程资源并允许后继阶段 |
| 全局失败或收尾超时分类 | 真错误、身份冲突或固定收尾期限耗尽，保存已有缓存并停止 |

进入draining后，可读的进程RSS和身份仍须检查；若已确认完成收尾而进程字段暂不可读，记录具体观测缺失，不伪造0或把它直接记成显存/RSS超限。全机可用内存及设备资源继续观察。没有可信完成记录、身份确实冲突或真实资源越界时，仍保守停止。

冻结worker在发布完整结果后不再进入科学计算；这一边界由原worker字节身份及结果、模型释放、末阶段资源证据共同约束。结果文件还在写入时不能进入draining；成功文件本身也不允许提前释放GPU锁。

同一个draining episode从首个已完成worker被观察到时起算，共享最多10分钟，不随轮询重置。该组所有进程真实退出后episode结束。后继阶段只可在原全局截止时间内启动；一旦进入全局停止宽限，就不再派新计算。仍由同一Popen对象统一观察和回收子进程，不引入竞争的独立wait路径。

持久化的细分状态是上表前四种正常生命周期状态；失败原因单独记录为事件及全局 `STOPPED_FAILURE_NO_RETRY`，不把解释性“收尾超时”标签冒充已经实现的另一种细分状态。
