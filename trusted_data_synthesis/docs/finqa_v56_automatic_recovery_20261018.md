# FinQA V56 分任务自动恢复

用户于 2026-10-18 针对“任一失败即停全池、不自动重试”要求“处理各种常见问题，设置自动恢复”。本次将该规则改为按故障类型处理，并接续原固定父点反馈温度实验。资源不足不再直接停止其他独立任务；只有实际断点、调用结算和故障证据允许接续时才自动重派。未知模型调用、状态/哈希/数值不一致不能靠重试消除，明确停止后不能自动拉起。

新目录为 `v18_researcher_continuation_01/v54_feedback_temperature_01/automatic_recovery_01/`。旧 V54、V55 的源码、协议、失败、UNKNOWN 和一次性请求额度均保留，不热改旧执行包。原科学设计见 [V54 实验报告](finqa_v54_feedback_temperature_20261018.md)，上次有界恢复见 [V55 恢复说明](finqa_v55_bounded_feedback_recovery_20261018.md)。本说明区分已保存的旧事实、注册运行规则和本次实际验收。

## 故障分类与恢复行为

| 情况 | 自动处理 | 不允许的行为 |
|---|---|---|
| GPU 或 RAM 暂时不足，尚未进入下一科学调用 | 清理本进程可回收缓存、重新观测，短时等待；仍不足则让出该 worker 的 GPU/名额，稍后重新准入 | 将失败观测写成通过、降低硬门、干预其他项目 |
| 有实际证据的 OOM、R3 容量错误或暂时性进程/文件系统资源错误 | 真实退出后审计持久状态；允许接续才独立重派，其他就绪任务继续 | 仅凭错误文本猜测可恢复，重复已提交工作 |
| 文件系统空间不足、暂时 I/O 失败 | 按实际 errno 和可读断点退避；无法可靠写入最小日志或审计断点时保守阻断 | 伪造完成回执、把读失败当成不存在、删除历史数据腾空间 |
| 模型调用已开始但无持久返回证据 | 阻断该任务及依赖它的后续任务，保留原意图 | 自动重采样、把 UNKNOWN 当零或当作未调用 |
| 参数点、哈希、数学数值或不可解释的实现错误 | 隔离受影响任务并报告，其他独立任务可继续 | 放宽校验、替换数学路径或换实验分支 |
| 进程自身历史 allocated/RSS 硬峰超标 | 当前进程不得继续；不能靠等待或清零峰值恢复为通过 | 重置历史峰值或循环重试同一不可行计算后声称验收成功 |
| 用户明确停止监督器或控制器，或设置停止标记 | 停止派发、协作保存、真实退出，自动拉起终止 | 将合法停止当普通故障重新启动 |

资源重试退避为 30、60、120 秒，常规上限 300 秒。连续四次没有新增持久进度的已确认资源问题转为 900 秒冷却，再自动按原门槛重新准入，不要求用户手动解锁，也不引入整轮截止。进度以完整科学单元衡量，不能用新 attempt ID、重新写审计记录或重复复制旧文件冒充进展。

“支持 OOM 自动恢复”不包括 OOM 之后出现未知生成调用的情况。如果 token 返回无法确认已经保存，必须执行 UNKNOWN 的阻断规则。自动恢复不保证所有故障都能继续，也不能保证共享 GPU 永不发生资源中断。

## 计算前资源检查与让渡

保留 GPU0 至 7、总科学 worker 最多 4、每卡最多 1；CPU 初始化、资源等待和 draining 均计入名额。使用原项目 GPU 租约 inode，子进程继承租约描述符，确认真实退出后才释放，不影响其他项目。

物理 free 不足时，新的计算前检查先记录不足事实，只释放当前进程没有活跃张量占用的 allocator 缓存，再观测一次。最多等待 60 秒，仍不够则以可审计资源让渡退出，控制器为其他任务腾出名额。只有重新观测通过之后才能执行下一次科学调用；等待记录不是一次通过的科学边界。

原硬门保持：全冷进程 allocated 历史峰值不超过 76GiB，规定计算边界物理 free 至少 2GiB，class RSS 不超过 160GiB、其他阶段不超过 192GiB，全机有效可用 RAM 至少 96GiB。模型加载计入峰值，阶段间不重置；native 按需分配、无人工暖大块或锚点，确定性 CuBLAS 配置和 CUDA 前检查保持。首次阶段准入仍是 class/feedback/distribution/generate 24GiB、train 26GiB、R3 56GiB，不因自动恢复下降。

原控制器累计资源等待 89.84583379887044 秒继续继承。各 worker 的等待单独记录，不把多个并发进程的秒数重复加成控制器墙钟。

## 持久返回与科学断点

生成使用稳定的科学目录，每次尝试有独立调用意图、实际返回、失败和退出记录。收到模型返回后先保存完整 turn/token receipt，再进入后续调用。冷接续按原 FinQA harness 重建已经返回的消息和纯工具状态，并对下一科学请求作一致性核对；重建工具状态不等于重复模型生成。任何无法解释的消息、工具输出或请求差异都不能自动通过。

70 条完整 episode 按原字节与完成事件复用；三个部分 episode 的返回序列也逐字绑定。完整 draw、cohort 和冻结奖励只封存一次，已经完整的反馈不重新生成或重新评分。旧两次请求授权只作为已消费的历史证据，不再挂接可执行 quota。

类梯度用 overlay 读取旧 9 个完整任务，保留旧 parent/task binding 和真实 CPU Tensor；本轮新目录只写剩余任务的新绑定。协调器仍按原 task/state/parameter 顺序汇总，不能因为缓存来自两个目录改变浮点累加顺序。seed389 的原同点完整类缓存继续只读复用。

R3 仅从实际已保存的累计梯度继续，不把实时日志游标当断点；真实训练仅从已经提交的参数、Adam、RNG、π 和步号继续，不重复提交 optimizer 或 outer。没有封存的计算可能需要重做，属于故障开销，必须与已提交科学剂量分开记录，不能宣称所有物理 forward 都零重复。

## 调度与监督器

每个 job 有独立 attempt 的 launch、日志、结果、实际退出、故障分类、断点审计和退避决定。稳定科学状态与尝试记录分离，冷恢复不能清空历史。成功依赖仍要求可信科学结果、资源记录及真实成功退出共同验收，不能只见到结果文件就开放后续阶段。

独立监督器覆盖控制器的部分可确认意外退出场景：只有调度日志没有活跃或未结算派发、所有已派尝试都有实际退出或启动失败结算、旧身份已退出、原 GPU 租约都能立即探测取得后释放，且持久状态审计通过，才自动重新启动控制器。控制器退出时还有存活 worker 或缺失真实退出证据的场景不能伪造 exit0，须报告阻断。明确停止不走这一恢复入口。

被阻断任务不消失，也不能令整轮被标为 COMPLETE；其依赖任务等待，其他独立任务可以继续。九个逻辑分支、十八个快照和训练侧实际退出全部齐全之后才开始评估，完整面板后再评分。评估生成也使用相同的持久返回与 UNKNOWN 保护，不改变原生评分或样本分母。

## 剂量与实施核验

还需完成 1788 次新 optimizer 更新、2030 条尚未完整的反馈 episode 和 12267 条评估会话；2030 包括三个已经部分返回的 episode。逻辑低温反馈总目标仍 2100，不能把已继承的 70 条都计成本目录新增。两个需新计算的 class pass 原共 1488 任务，扣除旧 9 个完整任务，剩 1479；未封存的旧行不抵扣。没有新的 test1147、QA、外部 API 或完整闭环扩轮。

实施包预计为原 81 个数学文件加 15 个执行模块，共 96 文件；旧冻结包逐字保留。必要核验聚焦故障注入、部分轨迹接续、缓存 overlay、资源让渡、退避、明确停止和进程生命周期，不重复旧全量数学测试。正式科学恢复前还需新鲜进程按实际 CLI 导入顺序核验依赖与真实继承绑定，避免历史控制器别名污染科学依赖选择。

本次 48 项不同 CPU/mock 用例已通过：登记与剂量绑定 8 项，持久生成/部分轨迹接续 7 项，worker/runtime 13 项，控制器与监督器 18 项，评估接入 2 项。关键故障注入包括继承文件只复制一部分、已返回之后资源门失败、退出码为零但读取结果遇到 EIO、等待期主存压力、R3 原始低 free 快照不得被后来的缓存清理改判，以及明确停止时只处理核验过身份的己方孤儿 worker。
