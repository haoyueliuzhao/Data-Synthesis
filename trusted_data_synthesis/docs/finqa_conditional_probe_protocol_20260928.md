## 4. 有限资格规则与 Mapper

冻结两种证据路径：公开表格中明确指标、期间与单位的有限关系；以及私有作者程序/证据锚定、
每个数据叶子唯一绑定到原公开表文的推导。后者显式信任作者标签作为任务语义证据，
并要求来源数值、指标、期间、单位、尺度及程序依赖相容，不能仅凭 native correctness 放行。

支持有限算术及已登记表聚合。不能唯一绑定数值、期间、尺度或替代解法时为 unknown；
发现真实矛盾为 invalid。允许同一明确指标的共同未知单位在合法比值中抵消，不能据此猜测 USD，
也不能放行未知单位的金额交付。混合尺度与冲突单位不作乐观解释。

资格检查保留全历史及失败前缀，检查真实 API 请求/响应 provenance，离线重放原工具调用并比较输出。
这是核验已有行为，不是额外生成，也不把离线参考程序执行伪称为 Student 在线 calculate。
有独立来源证明的声明式 Final 程序可以合格；“必须先读工具”不是新增门槛。

Mapper 依据来源依赖 DAG、必要实际计算/恢复与交付方式区分状态；措辞、重复读取、重复计算、
可交换顺序、slot、seed、长度和 NLL 不构造新状态。不预设每题两个状态。

## 5. 固定真实采集库存

范围冻结后，每题固定 8 个 slot：0–5 为训练材料候选，6–7 为封存支持/表示诊断。
全部 N×8 会话结算完成后，才统一进行轨迹资格判断及支持冻结。
静态名册检查与事后轨迹资格检查是不同操作；前者可读作者证据，后者不得提前观察部分生成结果。

- API 模型唯一为 `deepseek-flash`，无回退模型；thinking 显式 disabled。
- temperature=1，top_p=1；不发送不支持的 API seed，不把相同配置的 slot 伪称为本地 seed 复现。
- 每会话最多 32 个响应，每响应 max_tokens=2048。
- 最多 16 个会话并发；第一个登记 slot 串行完成传输/结算检查，它属于正式库存，不额外做付费 pilot。
- 发起顺序固定为 slot_index 优先、原 SFT 顺序其次，不依结果改采样顺序。
- HTTP 超时 120 秒，不自动网络重试、不续写、不补采、不重抽、不挑最佳输出。
- 所有原始请求、响应、工具轨迹、实际 usage 和错误均保存。

全部训练槽位中的合格完整轨迹都保留；不按 NLL、长度、文风、稀有性或未来 Student 表现筛选。
封存两槽不得转训练、补缺失状态或改变训练先验。若任一入选任务缺少合格训练支持，
条件性研究仍不获全任务训练准入；不得把有支持的任务再静默组成更小训练集。

实际支持冻结时 π0=r=n_xz/n_x，含义为合格训练包的经验频率，不宣称估计 Probe 的真实状态概率。
单状态任务单独记录为 static；只有实际非平凡支持带来 π 的自由度。

## 7. 保存、恢复与 CPU/GPU 使用

运行原件保存至 `/data1` 数据盘，不把大批原始库存写入空间紧张的 `/tmp`。
协议与槽位记录不可变；费用账本用 SQLite WAL/FULL 事务，在网络发送前登记预留与发出状态。
状态进度定期原子替换。单控制器文件锁防止并发重复运行。

安全恢复仅跳过已完整保存、且调用账本逐项相符的 slot。出现中断中的 slot、未知费用、丢失/回退账本
或规则源码漂移时停发新请求；不能删除失败目录重跑、创建空账本重置预算，也不能丢 WAL 后继续。
全槽位封存与资格入口再次核对费用调用守恒，防止恢复过程遗失支出。

资格阶段采用 8 个 CPU worker，实际数据按 task 绑定，环境密钥不传给资格子进程。
本阶段无需 GPU，没有为了 API 采集占卡。按用户资源授权，将在确定需要 GPU 的阶段前检查空闲卡，
只对本项目合法空闲资源设置有期限的预留；不挤占其他项目，不长期占用却没有可运行任务。
