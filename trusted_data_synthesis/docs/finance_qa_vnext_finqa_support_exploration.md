## 4. 私有数学／可表达性控制，不进入模型请求

以下只是控制构造和后续诊断的候选，不是在线参考计划或已发生的模型轨迹。

J2当前逐年度结构：`q1*p1 - q0*p0`，7次实际操作。
另一结构：`(q1-q0)*p0 + q1*(p1-p0)`，9次实际操作。
代入原绑定：`(11-13)*26.93 + 11*(33.32-26.93) = -53.86+70.29=16.43`。
对称的`(q1-q0)*p1 + q0*(p1-p0)`也登记为可诊断的分解形式；不因此改变Final目标。

J1的来源是带负号税收利益，不将其改成正数再沿用加法：

`c1=18.1, t1=-6.3, c0=14.6, t0=-5.2`。

逐年度税后成本结构：`((c1+t1)-(c0+t0))/(c0+t0)*100`，9次操作。
分项变化结构：`((c1-c0)+(t1-t0))/(c0+t0)*100`，10次操作。
成本变化为3.5，带符号税收利益变化为-1.1，净变化2.4、基期9.4，
两式均为 `1200/47 % ≈ 25.53191489 %`。

控制实际通过原read／显式accept／算术／显式accept／Final生命周期。
mock HTTP运行分别绑定N/D，故可检查提示曝光和完整原响应；明确标为adapter_mock，
不进入12模型会话总体，不作为模型监督素材发布。
所有控制公式、目标探针、人工解释和参考操作数均不进入HTTP消息。

### 5.3 非冗余候选的更具体见证

命名路线探针另行保存，不是完整行为类，也不是对所有合法方法的穷尽分类。
J2逐年度路线要求真实年度乘积在实际减法中消费；分解路线要求真实数量差、价格差及
对应乘积都被执行、接受，并通过实际输入连接到合并操作。J2合并Claim必须就是Final选择的Claim。
不能用“刚好算过某个相等值”或“位于被乘零的旁支”充当这个切分见证。

J1要求真实两年度净成本相减，或真实成本变化与带符号税收利益变化相加；该combine Claim
必须直接作为divide的分子，分母是实际add产生的基期净成本，随后直接multiply常量100形成
Final选择的答案Claim。这样命名探针不会仅因为多做过某些运算就记录机制收益。
这套直接发布结构是有限识别边界；其他有效结构仍有其完整原图，可记录为未分类支持，
不判成无效。模型没有进入此候选结构也不判失败。

探针计算项名称只表示代数项，不是经济因果贡献或VTDO的Contribution。
没有以操作次数、少见程度、长理由或提示分层赋奖励。

## 6. 新探索源分布与类内来源

每题6会话，每层3会话。若成功数为`m_N,m_D`，则：

`q_hat=(m_N+m_D)/6`；
`pi_hat(z|Y=1)=(n_Nz+n_Dz)/(m_N+m_D)`。

N/D的各自成功率、各自成功条件分布和总体成功条件分布分别保存。
不能把两个成功条件分布各乘1/2：两层成功数可能不等。
完整行为类可以跨这两个**预先声明的探索源组成部分**比较／合并，但不跨任务或混入旧样本。
每个类保留其实际N/D计数及类内来源比例，不把D请求删除后重新配给中性目标。

任一有效完整映射未定时，完整行为分布为null，记录原成功分母、已知质量与未定质量；
实际支持图分布可单独报告。零成功保持null；未知Outcome与有效但未定映射是不同状态。
不会只在已映射子集中重新归一化。
