## 四、两种新请求并行，不以投影结果阻塞映射

### 4.1 Projection：限定已有目标域，保留学习用途判断

投影输出为一个扁平对象：`status`、`positive_reason_ids`、`partial_positive_reason`、`positive_action_ids`。本包已知的机械类型约束提前进入 schema：

- reason 选择仅限原公开正文单元，不包括工具观察、表格来源或动作参数。
- action 选择仅限本包真实存在、关联事件成功的动作。成功只是进入可选域的必要条件，不意味着自动获准作为正向训练目标。
- 公共来源、工具观察、错误及修订历史完整保留为模型输入；可引用证据域与可监督目标域不混用。不能形成非空证据的单元不会被伪装为有效证据，但空原文仍保留在原始表示中。
- 主机根据已有 ID 还原坐标及完整原动作参数范围；部分 quote 必须是原段中唯一、连续、逐字的精确匹配。不猜位置、不改金额、不删除限定词。

未批准的内容仍在原始上下文中，不自动进入正向监督。既有过程资格不意味着全部正文正确，不设每包最低 reason 字数，也不删除 reason0 包。新 raw 返回、机械展开与投影状态分别保留。

### 4.2 Mapping：每题全部共同包一次语义分区

645 个多包任务各产生一个完整 mapping 请求，输入包含该题全部共同原包的完整公开轨迹，而非只包含最终批准的 SFT 片段。映射基于证据使用、推导依赖、观察理解及确有实际后果的核验或修订；不按字数、工具调用次数或措辞差异制造状态。

不要求 28 对穷举，不重建逐句命题图，不套用旧 endpoint/movement 模板。模型必须对完整同题集合给出一致分区；难分类包不能丢弃，也不能为了获得自由度强行拆成新状态。χ 的实质核验仍需实际动作、观察与后果证据，不能由工具执行成功或“做过检查”的措辞自动赋值。

两类请求都依赖已固定原轨迹，而非彼此的新结果。登记队列为 `alternate_projection_mapping_preserving_each_purpose_order`：两种用途稳定交替，各用途内保持事前顺序。控制器直接执行登记顺序，不等待 671 份投影先全部通过才启动 mapping，也不因某个投影失败取消该题映射。

### 4.3 真单例与歧义映射严格区分

99 个单包任务的经验支持只有一个元素，可确定记录一个状态：`r=π=1`、中心化分布梯度为 0、Novelty 为 0。其 χ 为 `None`，状态为 `not_required_for_weighting`；不虚构为 0 或 1，不发 99 次 API 确认“是否存在第二个状态”。

这些记录明确为确定性来源、`actual_model_calls=0`，不是模型审阅。此规则只适用于原共同核真实单包任务，不能用来替代多包任务中的未知或歧义映射。单例保留为静态训练部分，不为满足五臂名称而制造干预差异。

## 七、并发、网络与有限失败停止

控制器沿用 16→32→64 的真实结算升档策略；不按投影或映射语义通过率升档。两个用途共享该并发上限，并按登记顺序交错。

使用已批准的现有 `127.0.0.1:7897` 显式代理，并核对登记的环境来源和地址哈希；`trust_env=False`、TLS 验证开启、连接池 64、读取超时 1200 秒、底层重试 0。代理缺失或绑定不符时保存停止，不默默退回直连或换出口。全局代理配置不在本轮修改范围。

故障与终态原则：

1. **普通标注失败仍是已返回终态。** 错工具、缺参数、坏 JSON、非法 ID、未知 mapping 等原样保存；不补写、不删除非法选择、不另发补答。新 projection/mapping 的失败不追溯修改旧过程资格。
2. **纯连接 UNKNOWN 不伪装成结果。** 只有本 V13、无 HTTP 状态、无响应、无 usage、异常位于固定白名单，且整组在途排空后，才按精确 invocation/request-hash 集合追加网络终态确认。原 UNKNOWN 和完整预留永久保留，inspection 为 None。
3. **只清精确覆盖的网络 halt。** HTTP 429、服务已响应但 usage 缺失、模型/计费合同异常或来源错误不属于上述网络确认，保存后停止。旧批 UNKNOWN 不随本次清除或释放。
4. **同波达到 3 项纯连接 UNKNOWN，保存退出。** 账本可以记录真实终态；控制器仍不自动重启、不重发。不存在第三 attempt 或将剩余额度变为补发许可。
5. **预算暂时占用与实际不足分开。** 若仅因在途全额预留，未预留任务可以等待结算并降并发；排空后仍不能准入一条原未发送请求，则保存 `BUDGET_SAVED`，不提高上限。

只有全部 **1316 个登记任务均有真实终态**才生成 `v13_material_completion_seal.v1`。实际模型返回数、网络 UNKNOWN、分用途可用数和失败分开报告；“全部终态”不等于“全部标注有效”。任何失败都保留在完整分母，不能拿成功前缀或可用子集触发训练。

统一编码保留全部原始公开推理、动作、观察、错误及修订顺序，不裁历史、不按长度筛包。实际编码的 `L_P`、正向 Token、EOS 和模板边界由冻结 tokenizer 链路检验；公开 reason 不被描述为模型隐藏内部思维的完整恢复。

经验先验与类内核保持：

\[
r(z\mid x)=n_{xz}/n_x,\qquad K(P\mid x,z)=1/n_{xz}.
\]

真实任务批大小为 \(B_j\) 时，监督 Token 权重为：

\[
w=\frac{\pi(z\mid x)}{B_j n_{xz}L_P},\qquad
\pi=r\Rightarrow w_{Static}=\frac{1}{B_j n_xL_P}.
\]

不再额外乘一次 π，不除全局 N 或全局 Token 数，不因 reason/tool/final 再加新归一化。反馈的 \(g_J\) 继续基于真实本地采样 Token 与 EOS 的完整概率域，不使用此次投影 mask 代替。
