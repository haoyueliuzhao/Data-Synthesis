## 2. 为什么开展这一轮

用户审计指出，旧 step894 dev883 比较的三个父点 C05−C1 净正确数分别为 −27、+37、−9，合计仅 +1；C05−Hold 为 +28，C1−Hold 为 +27。原严格正值筛选规则确实通过，应保留；但 +1/2649 是该完整评价结构下最小的正刻度，不能据此建立低温具有实质、稳定额外收益的结论。

本轮只检验一个问题：同一真实父点和相同 298 次后继更新下，两种反馈温度都重新获得一个独立反馈批次后，T0.5 相对 T1 的增量能否重现；同温度跨批次变化与同批次跨温度变化分别有多大。

旧结果已参与研究选择，dev/cal 也不是重新获得的未见确认集。本轮两个反馈批次不能被表述为足以精确估计总体反馈方差，三个父点不能因两温度、两批次或多个评价 draw 被扩写为更多独立训练重复。

## 3. 科学设计与精确新增预算

### 3.1 固定父点及五条件矩阵

沿用 seed137、251、389 三个真实 `step0596_step` 父状态，即第二次 outer 之前的实际状态。不得替换成已执行第二次 outer 的状态或虚拟点。每个父点包含以下条件：

| 条件 | 反馈与分布 | 本轮处理 |
|---|---|---|
| Hold | 实际父分布 π⁻，不是历史 Static 先验 | 只读复用已完成模型、回答及分数 |
| C1，b=0 | 旧 T1 的 700 条及旧 q | 只读复用 |
| C05，b=0 | 旧 T0.5 的 700 条及旧 q | 只读复用 |
| C1，b=1 | 新 T1 的独立 700 条及其新 q | 新训练 597—894 |
| C05，b=1 | 新 T0.5 的独立 700 条及其新 q | 新训练 597—894 |

总计 15 个逻辑终点条件：旧 9 个、新 6 个；独立父点数仍为 3。旧 C1 路径不能冒充新 C1。新旧反馈不合并，每个新 q 只能使用自身 700 条反馈。

每个新条件使用相同的 350 道反馈任务、两个 draw，反馈 seed 固定为 101、103。两温度的条件身份分别绑定父点、温度、反馈批次、完整任务顺序、配置、模型参数及 tokenizer/chat-template；新 T1 同样必须具有新条件 receipt，不能走允许旧 T1 receipt 的兼容分支。

反馈使用该父点原合同确定的虚拟参数点；真实后继训练仍从共同的父 θ、Adam、训练 RNG 和原日程开始。各分支固定自身 q，实际训练 597—894 共 298 次，保留 745/894 快照，但 894 不执行下一次 outer。本轮不新评价 745。

各父点原完整类梯度缓存只读复用，不新增 class forward，不跨父点或跨参数状态借用梯度。分布阶段按原序重建全局 G 与虚拟点，须与同一父点原保存结果逐位相等。材料、任务边际、监督 mask、loss、学习率、clip、dropout、RMS、sigmoid、历史锚、先验锚、parser、奖励及输出额度不因本轮温度重复改变。

## 4. 正式概率与新增 draw 分量

采样与回放保持同温度概率合同，实际导数路径保留 `log_softmax(logits / T)`，不能仅把旧 gJ 乘二。正式回放仍使用原 response 顺序、原每项 `reward/700` 累加和完整轨迹；零奖励 episode 不产生 response 回放工作，但不能从 700 分母中删除。

每个新条件在原回放旁路保存两个 CPU 诊断累加器，各 draw 分母为 350。正式 total、两个 draw 分量、response cursor、RNG 与绑定必须保存在同一个原子断点中；不得仅凭 cursor 恢复缺失的分量。

分量均值与正式 gJ 的比较固定为：

`atol = 1e-7`，`rtol = 2e-4`，来源标签为 `V54_CPU_full_autograd_gradient_comparison`。

这是本轮诊断数值门，不能冒称原生产逐位门。正式 gJ 不被分量均值替换；不因不通过而放宽容差或重试数值计算。

分布阶段在同一个固定优化器 pullback 和同一类梯度上，额外执行每条件 2 个解析 VJP、2 次中心化 C 内积计算，并用相同容差核对原始 C 分量均值。六条件对应计划额外 12 个解析 VJP和 12 次中心化内积；恢复造成的实际重算另计。没有额外 class forward 或为诊断另行 response 回放。

正式 q 仍仅由正式原始 C 一次性执行原 RMS、势和锚定计算。两个分别归一化后的 q 不计算、不平均，也不影响正式 q。draw CPU 缓冲、序列化峰值、GPU VJP 和清理前后边界均计入原 worker 资源观测。

旧独立 draw 分量只读检查绑定的原 outer/distribution 现成字段；旧 C05 每条件再读正式 replay result 和最终完整 response checkpoint 的 JSON 元数据，不扫描中间断点、不打开旧 replay Tensor。已有分量字段保留 source/field 引用，标为 `PRESENT_REFERENCED_NOT_NUMERICALLY_RECOMPUTED`；检查范围内确无已登记字段才标为 `NA_NO_DRAW_FIELDS_IN_FORMAL_METADATA`。记录无法读取或绑定不一致会中止，不能被转换成 NA。字段存在不等于独立数值比较已完成，不强行补跑旧 R3。

### 5.2 最多 36 对定性样本

仅在旧 b=0 的 C1→C05 转移中抽取 I→R、R→I：

- 每父点、每方向最多 6 对，每父点最多 12 对，总计最多 36 对。
- 某层不足 6 对时，不把剩余额度转给其他父点或方向。
- 固定 digest 字段为 policy ID、seed、task key、transition、两侧原 episode SHA；按 digest 升序，再按 task key 排序。
- 先不可变封存选择名单，再读取选择的双方原轨迹与现有工具事件。
- 不修复输出后评分，不重执行工具，不生成延长回答或“继续即可答对”的反事实准确率。

自动 `reading_packet` 只整理原字节和可直接核对的事实，固定 `manual_reading_completed=False`。后续须实际阅读所选双方内容并另存人工记录，才可声称定性分析完成；不能把 packet 已生成表述为已人工阅读 36 对。

### 5.3 C/q、反馈支持与完整分母效用

对旧六个 C 条件和新六个 C 条件共 12 条记录，报告成功 episode、不同成功任务和来源簇覆盖、各 draw 的成功数、保存 RMS/floor、实际 q 相对父 π⁻ 的 μ 加权 TV 及双向 KL，以及：

`sum_{x,z} C[x,z] * (q[x,z] - parent_pi[x,z])`

C 已包含 μ，方向求和不得再次乘 μ。μ 加权只用于所登记的分布距离。结果同时保留 dev883 完整分母下 I/W/R/UNKNOWN，不能改用各分支自行形成的“可执行子集”替代主效用。

跨批次表包含 3 父点 × 2 温度共 6 组同温度 old/new 比较，交叉计算旧 C 对新方向、新 C 对旧方向；同批次跨温度表为 3 父点 × 2 批次共 6 组。旧新效用分列，不汇总成新主判据，不挑选较好的批次。

旧 C1 从原 outer 元数据读取；旧 C05 每父点只允许一次 SHA 绑定的 CPU mmap 元数据提取，共 3 次。此操作会打开含 Tensor 的容器并完整读取文件字节以核对 SHA，因此不能声称“完全没有打开 Tensor 容器”；但不访问梯度 Tensor 数值、不构造模型、不重算完整 Tensor state digest、不初始化 CUDA。提取的小型 C/q/evidence 输入封存后复用，postrun 不再次映射旧载荷。新六条件在完整结束后采用相同的元数据提取约束。

方向分数、小 TV/KL 或分量一致性只用于解释，不单独证明稳定性、因果机制或 298 步效用可预测性。两批次也不构成总体方差的精确估计。

### 5.4 各分支实际监督系数

## 7. 资源准入与自动恢复的实际边界

### 7.1 资源合同

当前新实现登记 GPU0—7，绑定固定物理 UUID、CPU 亲和和原项目 GPU 租约；总 GPU worker 最多 6 个，每卡最多一个本实验 worker。初始化、等待和 draining 均占名额，租约保留到真实退出。六并发是上限，不保证有六个作业始终满足显存、主存和依赖门。

阶段准入继承当前 V54/V56 原资源实现，不套用更早 V41 的数值：

| 本轮阶段 | 启动 GPU free 至少 | 主存启动预算 |
|---|---:|---:|
| feedback | 24 GiB | 64 GiB |
| replay | 56 GiB | 48 GiB |
| distribution | 24 GiB | 64 GiB |
| train | 26 GiB | 48 GiB |
| generate | 24 GiB | 48 GiB |

本轮没有新 class 队列。各科学 worker allocated 历史峰值仍不超过 76 GiB，规定边界物理 free 至少 2 GiB，RSS 历史峰值不超过 192 GiB，全机有效可用 RAM 保留至少 96 GiB。模型加载计入进程历史峰值；只允许科学分配前一次峰值初始化，随后不得重置峰值掩盖失败。

启动主存公式为 `96GiB + 新作业阶段启动预算 + Σmax(0, 活跃作业阶段启动预算 - 当前RSS)`；运行 RSS 上限与启动预算不同，不能混写成每活跃 worker 均预留完整 192 GiB。无法读取活跃进程必要内存信息时，不用猜值放行。

允许与归属明确的其他进程共享 GPU，但实时显存门仍成立；未知 UID、无法可靠归属的 MPS 或身份观测失败阻止准入。调度取锁后、worker CUDA 前、模型前及资源采样时继续检查。仅处理本项目核验 PID/birth 的进程，不干预、迁移或停止他人进程；共享准入不保证全局独占或没有瞬时重叠。启动阈值是经验准入，不能当作未来峰值保证。

### 7.2 自动恢复不是无限制重试

本实现不设总科学 deadline 或累计资源等待截止，但继续保存实际等待和 attempt 历史；这不放宽任何数值、状态、剂量或资源硬门。

已确认、具有实际证据的资源/I/O失败，仅在同一科学数据的持久断点审计通过后获得新 attempt。退避为 30、60、120、300 秒；连续 4 次没有增加持久科学进度后，进入 900 秒资源冷却，之后仍按原门自动准入。已确认资源失败没有固定总 attempt 上限；“有界”在此指单次等待、退避、进程生命周期和恢复范围，不应误写成四次即终止所有资源恢复。

worker 单次容量等待最长 60 秒，耗尽后让出自身设备和名额。科学完成项不重做；只允许接续完整已封存反馈/turn、formal+draw response 累计断点、训练提交或完整阶段。未封存计算可能重算，明确记为开销。

以下情况不能盲目自动重试：

- 新 provider 调用已发出、无返回断点而成为 UNKNOWN。
- 父点、哈希、状态、条件或绑定不一致。
- 原数值门或新增 draw 诊断数值门失败。
- 未知或含糊的 worker 信号来源、缺乏已登记资源/I/O证据的异常。
- 明确 SIGTERM/SIGINT 或 STOP 请求。

旧实验给予个别 UNKNOWN 请求的重新执行额度不继承到本轮新条件。某作业硬阻断后，健康且独立的作业可按登记依赖继续；被阻断的依赖不能伪装成成功，所有合同未齐全不能晋级或报整轮 COMPLETE。

监督器只在原 controller 已退出、journal 新鲜且为空、没有未结清派发、相关原身份确已退出、全部项目租约可取得、持久状态审计通过时重启 controller。活跃或无法确认退出的 worker 会阻止自动重启；不能用 PID 消失伪造非子进程的 exit0。未知 controller 无进度崩溃最多连续 4 次；明确可恢复资源失败按冷却规则处理。

明确停止监督器必须终止自动拉起，停止宽限由本次活跃进程共享 600 秒；只对身份核验过的本项目进程操作。当前是本地监督进程机制，不能据源码宣称已安装主机重启后的外部 watchdog、cron 或服务，也不能保证整个进程树被终止后仍能自动自举。

## 8. 冻结前待关闭项与后续证据

初稿整理没有重复运行既有测试或执行正式诊断。随后针对 parser 阻断与旧分量字段检查的有界修订，仅运行受影响的 CPU/mock 用例：7 项通过、29 项未运行。用例覆盖字段存在与缺失、无法读取不能转换为 NA、禁止读取旧梯度 Tensor 数值及 parser 不一致阻断；不等于实际模型资源门、正式恢复或新效用结果已通过。

冻结前需在最终 registration 中明确保存：

1. 用户本次审计与追加资源/恢复指令的原始绑定、原根协议/实施包/closeout、三个父点及旧九终点只读来源。
2. `diagnostics_policy` 完整对象，以及 draw seeds、350/700 分母、上述固定容差、额外 VJP/内积预算、原子断点合同。
3. `evaluation`、统计门 27/1、六新分支和 24 评价作业剂量、只用新批次主判据及零自动后继许可。
4. `resource_policy`、`resource_recovery_policy`、`gpu_isolation_policy`、`auto_recovery_policy`，八 UUID、CPU 亲和、项目租约和最大六 worker。
5. 最终 source commit、原 96 文件逐字保留证明、新完整实施清单 SHA、正式冻结入口与依赖绑定。

当前诊断实现有三项需要在最终记录中保持准确表述：

- parser 终末互斥类别与首次拒绝 turn 是两个不同量，冻结后不能根据结果重新换分类口径。
- `parser_disagreement_count` 与检测标志单独报告；非零现在硬阻断诊断验收，不能被扫描完成状态掩盖。
- 旧分量现在进行上述有界字段检查，存在则保留来源引用，缺失且检查完成才 NA，无法检查不等于缺失。自动 reading packet 仍非人工分析，人工 ≤36 对阅读及其独立记录尚待实际完成。

正式启动及完成后应在本节另行补入真实协议/实施包 ID、source commit、首次派发 PID/birth、资源准入、各 attempt、实际完成剂量、三面板结果、诊断与人工阅读记录、主判据及真实退出。没有实际证据前，以上项目均不得填写为已完成。
