## 信号处理合同

运行者真实和有效UID均固定为1004；若以root或其他UID启动，入口拒绝运行。来源判断只采用内核返回的信号字段，不依据可读的进程名、缓存候选或推测的人名。

| 输入 | 处理 |
|---|---|
| SIGTERM，发送PID>0，发送UID明确且不等于1004，si_code=0（SI_USER） | 记录原始回执及过滤决定，不调用停止handler |
| UID1004发出的SIGTERM | 原主线程停止handler继续生效 |
| 任意来源SIGINT | 原主线程停止handler继续生效 |
| 未知发送者、PID0、非SI_USER的SIGTERM，包括SI_QUEUE | 不适用过滤，保留原停止行为 |
| 本次明确STOP标记、科学绑定/数值失败、资源硬门 | 原停止/故障规则不变 |
| SIGKILL、SIGSTOP | 不能捕获、阻塞或忽略；不声称已提供此类保护 |

这是对本实验进程的一条窄规则，不是对宿主机管理员的隔离，也不能区分同一UID下的不同操作者。通过sudo发送的SIGTERM可能表现为UID0，因而会落入过滤；本账号不提权的SIGTERM、SIGINT和STOP仍是明确有效的停止入口。若系统资源管理器采用“SIGTERM后再SIGKILL”，过滤SIGTERM会失去它提供的优雅停止宽限；完整持久断点仍保留，但未封存计算可能丢失。不能把此实现描述为不会再中断。

SIGKILL不可屏蔽以及信号权限规则见 [Linux signal(7)](https://man7.org/linux/man-pages/man7/signal.7.html) 与 [kill(2)](https://man7.org/linux/man-pages/man2/kill.2.html)。提升被保护进程的UID不能消除宿主机有权限者发出SIGKILL的能力。
