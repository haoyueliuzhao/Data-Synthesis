## 2. CPU诊断发现与解释限制

只读数值审计比较完整830断点中的正式梯度及两份原子保存的 draw 梯度。绑定范围包括112个参数、2,523,136个元素；仅一个元素未通过原来的逐元素容差：

```text
parameter: model.layers.17.self_attn.v_proj.lora_B
shape: [512, 8]
flat_index: 73
registered atol: 1e-7
registered rtol: 2e-4
```

该失败元素的实际CPU观测如下；均值用float64复核仍为同一值：

| 量 | 实际值 |
|---|---:|
| 正式梯度 | 1.1346863175276667e-05 |
| draw101 | −0.13516968488693237 |
| draw103 | 0.1351926028728485 |
| 两draw均值 | 1.1458992958068848e-05 |
| 绝对误差 | 1.1212978279218078e-07 |
| 原逐元素阈值 | 1.0226937263505533e-07 |

全部元素的最大绝对差为5.364418029785156e-07，相对L2差约5.04e-07。全局最大差不一定就是失败元素，因为每项阈值随正式梯度幅值变化。L2归约可能随CPU线程归约出现细微差别，以上只作实际观测，不另设例外门；例外以完整Tensor摘要和精确失败坐标绑定。

因此，不能称“原诊断门已通过”。将最终均值计算改为更高精度也不能把既有诊断失败当作已经修复。正式梯度、两份 draw 梯度、response顺序及反馈奖励均有实际封存值；不允许用均值替换正式梯度，或事后修改其中某个数以满足门槛。

两个 draw 分量异号，其现象与浮点抵消相容，但尚未证明具体因果来源。本文不将“浮点抵消”“CPU/GPU累加次序差异”写成已确认的根因，也不从一个元素超门推出训练或最终评价必然不受影响。

V66准备阶段应独立登记 `diagnostic_evidence/record.json`，保留原 `FAIL`、具体原始数值、阈值、L2误差、失败坐标、正式及两draw摘要、完整断点哈希和原失败引用。本文初稿时该新冻结证据尚待正式准备，不能伪造协议ID或已冻结证据路径的存在。

## 6. 两控制器的并发与资源隔离

原总科学worker上限仍为6，并非重新执行先前被中断的“四并发”请求。此次将并行范围固定拆分为：

| 控制层 | 固定worker上限 | 启动主存公式之外的对等控制层预留 |
|---|---:|---:|
| V65生成 | 5 | 64GiB，为V66最重的distribution准入预留 |
| V66问题组 | 1 | 240GiB，即5×48GiB，为V65预留 |

初始化、资源等待和draining均计入各自名额。对等控制层空闲时，不自动把其名额借给另一侧；额外主存预留也不按对方瞬时RSS抵扣。各侧继续执行原自己的活跃worker主存准入公式，然后添加上述保守预留；原全机至少96GiB有效可用RAM余量、各阶段RSS上限不变。这会保守限制派发，不能为了“尽快”绕过主存门。

两个已登记且任务集合不重叠的新控制器在运行期间对原 `S/owner.lock` 取共享锁 `LOCK_SH`；旧V63/V64控制器要求独占锁 `LOCK_EX`，因此无法并行进入。每个新根的控制owner和supervisor owner仍独占，禁止同根双启动。

每个实际worker仍取得原全局物理GPU租约的独占锁，UUID、CPU亲和及每卡1worker保持。GPU0—7只是许可范围，实际准入仍须满足容量、归属和原资源检查；不干预其他项目或账户进程。V65+V66的worker数量合计最多6，不会因拥有两个监督器而变为两套六并发。

控制器暂时故障后的恢复只要求本控制根没有活动/未结算dispatch、自己的所有attempt具有匹配的实际退出，再按原断点审计接续。不能要求合法对等控制器释放其全部GPU租约，否则会把正常并行误判为恢复失败。未来派发时仍逐worker取得原独占GPU租约，没有取消真实设备互斥。

GPU历史allocated峰值76GiB、边界free2GiB、原阶段准入及R3容量检查保持；模型加载计入历史峰值，不重置。合法TERM/INT/STOP仍按登记语义终止相应控制层的自动恢复；旧非本UID SI_USER TERM过滤边界不扩展，不宣称能屏蔽SIGKILL。停止一侧只处理该侧核验过的本项目进程，不给另一侧或外部项目发送信号。
