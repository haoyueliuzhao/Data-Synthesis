# 金融Agent训练数据合成与优化：综合实习面试介绍

准备日期：2026-10-28，适用算法、机器学习与工程综合面试。材料以项目当前FinQA主线及已封存实验为依据；“个人负责部分”需要按真实经历选择，项目实现不自动等于个人独立完成。

## 1. 项目名称与一句话介绍

**推荐名称：面向金融工具Agent的可验证训练数据合成与训练优化。**

一句话：研究怎样把大模型真实的“查资料、算数字、用工具、交答案”过程，整理成可靠的训练数据，再研究哪些解题路线值得多训练，让模型更可靠地完成金融问答。

可以用“给模型编练习册”的比喻：既要检查例题和解题过程是否合格，也要研究练习如何分配，最终还要通过考试检验是否真的学会了。

## 2. 一分钟到一分半口述版

> 我做的项目是金融Agent的训练数据合成与优化。它关注两个问题：大模型生成的解题过程能不能作为可靠的训练数据，以及有限的训练预算应该分给哪些解题路线。
>
> 我们基于FinQA金融问答，让模型读取财报、调用工具执行计算并提交预测程序，并保存完整的交互记录。数据进入训练前，会检查答案、程序以及过程来源，而不是只看回答写得是否流畅。
>
> 在训练侧，我们使用Qwen2.5-7B做LoRA微调。每道题的总训练份额保持固定，主要研究同一道题内部，不同解题路线的权重怎样调整，并用相同预算的对照实验验证效果。
>
> 后续实验发现，一部分训练退化表现为模型不再完成有效提交，因此又补充了训练题初始状态和学生真实工具后状态上的教师示范。最近一次实验在883题开发集上达到63.08%的执行准确率，对照为48.81%。这属于单次训练下的示范组合收益，还不能当作完整方法稳定有效的证明。
>
> 我主要负责的是【填入实际承担的两项：数据与工具流程、训练实现、实验设计、评估诊断或资源调度】，可以进一步展开其中的具体实现。

时间紧时，保留前四段；如果面试官更关注工程，先把最后一段替换为真实的系统实现经历，不必在开场解释公式和全部版本号。

## 3. 用一个例子讲清任务

以下数字是讲解用的假设例子，不是某道真实实验题：

“某公司上一年收入100亿元，本年120亿元，增长率是多少？”

合格过程包含：从财报中找到对应年份及口径的数据，编写受限计算程序计算`(120−100)/100`，执行得到0.2，最后按要求提交该计算程序，执行结果对应20%的增长率。模型在中途读错年份、混淆单位、调用工具失败，或者算完却没有提交，都可能导致任务失败。

因此，项目训练的不只是说出“20%”，还包括读取证据、正确调用工具、使用工具返回和完成提交。答案、程序与过程依据分别审查；执行正确不代表全部推理语义已获独立认证。

## 4. 完整流程：从原始问题到模型评价

主流程是：

**原始财报与问题 → 真实工具交互 → 轨迹记录与验证 → 训练材料 → 数据权重与模型训练 → 完整任务评价 → 失败诊断。**

### 第一步：整理任务并划分用途

当前研究使用FinQA原始问题、财报文字和表格。公开输入与私有参考答案分开；训练、反馈、校准和评价分别登记用途。模型求解时看不到评分用参考答案。

需要说明边界：官方任务划分不等于公司或年度报告完全隔离，当前开发集也已多轮用于研究。可以说做了输入隔离和来源审计，不能说彻底消除了所有数据泄漏或预训练曝光。

### 第二步：让模型实际解题，采集交互过程

模型通过受限工具完成资料读取、程序执行和最终提交。典型工具包括`list_sources`、`read_source`、`run_program`、`submit_program`。

系统记录实际模型输入、生成token、工具名与参数、执行返回、历史状态和最终结果。失败过程也保留，不能把失败输出修好后假装成原始成功样本。

这一步得到的“轨迹”，就是一份带执行记录的解题过程，不是让模型事后编写一段看似合理的过程。

### 第三步：验证、筛选并组织轨迹

先判断会话是否完整、工具交互是否符合协议，再用原生规则检查执行结果和程序。来源与状态资格另行核验；EA正确不等于整段公开推理已被独立认证。

同一道题可能有不同证据使用或决策路线。项目将可接受路线组织成题内状态和完整训练包；只改写措辞或增加无意义调用，不算新的实质路线。共同训练材料包含744道题、1360个状态、2468个完整包。

“状态”可以通俗解释为某道题下的一类可验证解题路线；在具体示范采集中，“工具后状态”则是模型已经实际调用工具后所处的完整上下文。面试时注意两者的粒度，不说成每个token都是一个独立训练状态。

### 第四步：把完整过程转换为监督训练数据

保留原始上下文，把指定assistant回应作为监督目标；用户输入和工具观察通常只作为条件，不强行让模型学习生成它们。保留实际结束标记，并按登记的完整包或完整后继规则归一化损失。

通俗解释是：让模型学习“处在这个真实上下文里，下一步应该怎么做”，而不是只背最终答案。也避免仅因某段过程更长，就无意获得不成比例的训练权重。

### 第五步：研究训练预算怎样分配

每道题的总训练份额固定，只调整题内不同路线的比例。这样可以减少“方法只是多训练了容易题”带来的混淆。

算法主线研究两个量：

- **贡献度C：** 局部估计增加某类路线的训练权重，是否可能提升后续任务效用。实现上先构造一次不提交的虚拟AdamW更新，在相应参数点取得真实模型反馈，再将反馈梯度通过该更新反传到训练权重。它是局部代理，必须用后继真实训练验证。
- **欠覆盖量N：** 衡量某类路线相对初始比例是否被训练得过少，用于研究覆盖与收益的取舍。当前形式为`max(0, log r − log π)`，不是模型置信度，也不是正确性分数。

在初始比例和历史比例的约束下更新题内权重，再进行真实加权监督训练。贡献估计阶段的虚拟参数不直接当作正式训练结果提交。

最新V75是另一项局部材料对照：固定题内权重，补充教师示范，不执行上述C/N外层优化。面试时应把“项目总体方法”和“本轮实际干预”说清楚。

### 第六步：训练学生模型并设置对照

基座为Qwen2.5-7B-Instruct，使用LoRA降低可训练参数和优化器状态成本。实际配置是冻结底座，q/v投影增加rank8、alpha16、dropout0.05的适配器；可训练参数约252万。没有依据说本项目完成了LoRA rank搜索。

主线对照包括固定分布Static、仅贡献度C-only、贡献度与欠覆盖项结合的Full。比较时控制共同起点、任务日程和预算，保留多seed结果。

参数学习主要是加权监督微调；使用反馈估计数据权重不等于采用PPO或DPO。V75更直接，是固定教师材料组合下的一条SFT分支。

### 第七步：让模型独立完成全部评价任务

评价从原始公开请求开始，不提供教师历史或参考答案。全部轨迹封存后再按原生规则评分，同时保留正确、错误、无效提交和UNKNOWN的完整分母。

主要指标：EA衡量执行结果是否正确，PA衡量程序是否符合原生匹配规则。除总准确率外，还比较同一道题哪些变对、哪些变错，并按真实报告来源做簇统计，避免把相近来源的问题当成完全独立证据。

### 第八步：分析失败，再提出有针对性的改动

项目后续没有只追最高分，而是依次研究反馈采样、固定分布续训、学习率、相同上下文行为和示范覆盖，区分不同可能原因。

一个适合展开的诊断故事是：继续训练后准确率下降；进一步发现，一部分退化体现为模型算到中途却没有完成有效提交。降低学习率只能缓解一部分退化，同上下文探针又提示历史条件影响行为，于是设计训练侧真实状态的教师示范对照。这个过程说明实验如何推动下一步设计，不等于已证明唯一根因。

## 5. 最近一轮结果：面试时怎样讲准确

V75固定选128道训练题，分别采集初始示范和学生真实工具后状态上的教师后继。实际得到101份初始、78份工具后合格示范。教师是已有共同父模型检查点，不应称为每步在线调用更大模型。

候选从共同父点1192恢复，以1e−5学习率续训298步到1490，完成1488次任务暴露。两类示范的实际平均目标权重合计约6.03%，不提高128题出现频率；两个槽各¼是题内配方，不是全数据一半都换成示范。

| 条件 | 开发集执行准确率 | 比较意义 |
|---|---:|---|
| 共同父模型P1192 | 536/883，60.70% | 续训前的起点 |
| 原低LR续训B1490 | 431/883，48.81% | 复用的同起点低LR对照 |
| 新示范候选S1490 | 557/883，63.08% | 本轮新训练结果 |

推荐表述：

> 在固定起点、学习率、任务日程和更新次数的条件下，加入训练侧真实状态的教师示范后，开发集执行准确率从低LR对照的48.81%提高到63.08%，净多答对126题，提高14.27个百分点。相对续训前父模型60.70%，点估计提高2.38个百分点，但区间跨零；目前是单父点、单次训练、已多轮使用的开发集结果，还需要独立验证。

追问时补充：相对B新增152题正确、丢失26题；无调用从218题减少到49题，但有效错误也从222增加到259。因此不能把“更愿意调用工具”直接等同于推理能力全面增强。工具后78份示范中71份来自原成功状态，只有7份来自原无调用失败，无法将增益单独归因于修复失败历史。

工程状态如实说明：训练、883题生成与原生评分已完成；最终CPU汇总因缺失字段停止。报告统计从已封存分数独立派生，历史失败保留，不能称原科学流程全部验收通过。结果出处见[本轮完整报告](finqa_v75_experiment_report_20261028.md)。

## 6. 兼顾算法和工程的三个亮点

| 亮点 | 通俗说法 | 可展开的技术细节 |
|---|---|---|
| 可验证数据流程 | 每份训练材料都能追溯到真实交互，知道是怎样产生的 | 工具执行记录、完整轨迹、来源绑定、token及mask、原生评分与过程资格分离 |
| 受控训练与诊断 | 不只比较总分，还控制训练份额，逐步弄清变化来自哪里 | 固定任务权重、题内分布、虚拟AdamW更新、贡献代理、消融、同题配对 |
| 可恢复实验系统 | 长实验中断后尽量从真实完成位置接续，同时避免重复计算改变实验 | 多GPU任务分片、checkpoint、Adam/RNG/游标恢复、实际退出屏障、GPU租约和资源门 |

工程恢复不是“异常就无限重试”：只有已确认的安全边界才接续；未知未返回调用、状态不匹配和数值异常会停止。失败日志和原断点保留，不用最终成功覆盖历史失败。

个人贡献建议只选能讲透的两三项，用“我实现了什么、为何这样设计、怎样验证、遇到什么失败”组织，不必把全部项目内容归到自己名下。

## 7. 常见追问与简短回答

| 追问 | 回答要点 |
|---|---|
| 为什么选金融问答？ | 同时要求证据读取、单位和口径理解、数值计算及工具执行，且有程序和结果便于客观评价，适合研究过程数据。 |
| 和普通问答数据合成有什么区别？ | 监督对象包含真实工具交互与状态下的后续动作；不仅保存问答对，还保留可追溯的执行过程。 |
| 为什么不直接用模型打分挑好样本？ | 自评会有偏差；本项目优先依据实际执行与原生评分。正确性和对训练的增量价值还要分开，后者用受控训练验证。 |
| 为什么固定每道题的份额？ | 把研究重点限定为同题不同路线的配置，避免多练简单题或改变题目覆盖影响结论。 |
| Contribution是不是训练loss越大就越重要？ | 不是。它估计路线权重对反馈效用的局部影响，经虚拟更新与反馈梯度获得；训练loss高也可能只是噪声或不合适材料。 |
| 贡献估计计算量如何处理？ | 使用LoRA减少可训练变量，按完整任务分片计算梯度、保存实际中间结果，再按绑定顺序汇总；恢复时核对参数点和反馈一致性。 |
| Novelty是不是越稀有越好？ | 不是。这里只是相对初始比例的欠覆盖量；它的额外收益尚未稳定建立，不能只因为“多样”就断言有用。 |
| 这是不是强化学习？ | 主要参数训练是加权SFT；反馈用于研究训练数据分布。需要区分反馈梯度估计与直接用PPO更新策略。 |
| LoRA为什么能省资源？ | 冻结大部分底座，只训练小的低秩适配器，减少梯度和优化器状态；仍需承担底座前向等成本，不说成本降到零。 |
| 怎样保证对照公平？ | 尽量固定共同检查点、任务日程、更新数、评价面板和评分规则；同时披露额外示范前向改变随机消费和算力，不能声称所有因素完全等同。 |
| 断点需要保存什么？ | 模型适配器、优化器状态、随机状态、训练游标、数据分布及阶段绑定；仅保存权重不足以精确接续。 |
| 为什么训练完还要等进程退出？ | 写出结果不代表工作进程已成功结束或释放资源；实际退出和结果校验通过后再接续，避免重叠、重复提交或错误接受。 |
| 最大收获是什么？ | 数据正确不等于训练有效；总体提升也不代表每道题都变好。应同时检查材料覆盖、实际消费、有效提交与最终正确性。 |
| 下一步是什么？ | 在不改写本轮结果的前提下，先处理正式汇总的工程缺口，再考虑独立父点重复、分开两类示范的贡献及来源隔离评价；这些是建议，不是已完成成果。 |

## 8. 按面试官关注点调整

算法面：重点展开题内权重为什么需要优化、贡献度如何近似、消融怎样设计、为何区间与平均值不能替代训练seed重复。

工程面：重点展开模块划分、不可变产物、工具调用生命周期、GPU并行与资源限制、完整断点和恢复幂等性。可以讲一次具体故障定位，但不要只讲调度而漏掉业务目标。

综合面：先讲“可靠练习册＋合理训练分配”，用增长率例子说明端到端流程，再用一组结果和一个失败诊断说明判断能力。

临场记住五个数字即可：7B基座、744道共同训练题、2468个训练包、883道开发评价题、最近对照48.81%到候选63.08%。说明是**提高14.27个百分点**，不是“相对提高14.27%”；不要把该结果归到全部VTDO方法或独立测试集。
