## 2. 零调用表示解释：统一规则，不盲目删除字段

新模块 `v14_material_protocol.py` 对全部 633 个已返回 mapping 统一执行新解释，而不只挑 256 个顶层字段失败。原始 JSON 必须严格可读，重复键、缺关键字段、坏 JSON 均不猜补。核心依然遵守原成员恰好一次、证据归属、真实动作—观察与后果、无未解决分区歧义等要求。

附加字段在新 sidecar 原样保留，不移动到某个状态，也不补核心证据：

- `slot_ids`：仅当是全题原包唯一完整清单时，确认是机械重复。
- `semantic_summary`：仅接受空白，或与核心中已经存在的一份状态 summary 逐字相同；其他自然语言不由关键词猜测为“无关说明”。
- `partial_evidence`：仅接受空列表，或每个对象已逐字存在于核心状态的部分证据中。
- 其他字段或无法确认冗余的内容继续 pending；没有额外人工语义判定，也没有新的模型调用。

原 325 份成功输出必须保持 `states`（含证据）、`state_by_slot`、`chi_by_state` 及完整机械展开映射一致。新消费者只为明确的多包来源补 `deterministic_singleton=False` 的元数据，不改上述语义字段；这避免误将“缺少消费者标志”当成状态判断失败。

### 实际恢复为何只有 12 题

256 份顶层额外字段中，244 份含自然语言 summary；多数不能证明与核心逐字冗余。按统一规则，只有 **14 份**进入核心完整核验，继而又拒绝 **2 份**：一份 χ 动作／观察不匹配，一份同包跨状态重复归属。因此最终 `m=12`。

其余 **242 份**不能确认附加内容机械冗余，保留待补；例如，附加说明可能说“仅措辞不同应同类”，核心却拆成多个状态。不能为提高恢复率而忽略此类信息。14 份可消除外层冗余也不意味着 14 份最终可用，已保存首个错误不是穷尽诊断。

两份重叠投影经原引用、类型、实际动作及同一正向权威检查后可以派生，`b=2`。所有原 span 保留；每个 span 先按原 Token 边界规则取得允许位置，最后取布尔并集。既不先合并字符范围以扩大可监督 Token，也不重复计算 loss。第三份动作 ID 缺字符的结果不模糊匹配、不猜原意。
