## Content-Addressed Typed-Rejection History

The v26.176 Runtime retains the v26.175 State-local Schedule and accepted reference behavior. It
adds a separate rejection-history state with exact Observation, Acceptance, and feedback parents.
On a typed State-precondition rejection, it:

1. executes the production classifier and appends the actual typed rejection event;
2. returns a content-addressed public Observation;
3. creates a content-addressed feedback object binding rejected Action ID, displayed Choice,
   selected Operation hash, rejection code, Observation Receipt, Acceptance report, predecessor
   feedback, corrected-response attempt index, and bound;
4. persists Observation, Acceptance, and feedback in dedicated Runtime state;
5. keeps the same target Component current and clears only the pending Prompt projection;
6. renders the next Prompt with the exact feedback object in public current-State facts.

The recovery Prompt state token and Prompt hash therefore change with the feedback. Dependency
`prior_observations` retain their original topological meaning, while the same-Component rejection
parent remains a distinct typed public fact. This preserves the existing Result receipt validator
and makes the correction history model-visible and content-addressed.

The prospective correction bound is exactly one. If the corrected response is accepted, ordinary
Runtime execution resumes and the final Result binds the changed Prompt and the rejection event.
If the corrected response repeats a typed-rejected Action, the Runtime creates a second terminal
feedback object and rejects any attempt to render a third Prompt.
