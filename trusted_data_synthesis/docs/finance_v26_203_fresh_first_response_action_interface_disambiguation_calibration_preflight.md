## Pre-Registered Calibration Question

The future online calibration asks one narrow question. Holding the frozen public Task, current
State, Candidate set and order, Candidate Action IDs, Schedule, model, Thinking, sampling
parameters, Completion bound, bounded Policy, resource Contract, privacy policy, telemetry
policy, Action parser, and Runtime semantics fixed, does replacing the old dispersed interface
with one continuous, authoritative four-field Action contract improve first-response ABI
instantiation?

For paired source cell `i`, the future outcomes are:

```text
Y_i^C = 1[control first response crosses the exact Action ABI]
Y_i^R = 1[repair first response crosses the exact Action ABI]

Delta_ABI = (1 / 12) * sum_i(Y_i^R - Y_i^C)
```

The secondary first-Action admission value requires ABI validity, a current Candidate Action
reference, and the exact current State binding. Neither quantity is `q_first`; neither measures
Program completion, correction Capability, Final validity, or trajectory-depth Capability.

The repair is intentionally a composite interface package. A passing paired calibration could
attribute an effect to the package as a whole, but not separately to system role, contiguous
four-field presentation, or competing-Schema labeling.
