# FinQA V39 临时 GPU6 受控切换说明

日期：2026年10月12日，时间采用北京时间。

## 授权与当前状态

用户先明确“可以临时占用GPU6”，随后对“让当前阶段完整封存后，换用支持GPU6的调度器，保留原状态、反馈和剩余预算”的受控切换回复“同意”。V39只扩展本轮剩余矩阵的可用设备，不增加实验、重试、采样、回放或优化预算。

新代码已通过115项CPU/mock测试及Ruff。此处的测试结论不代表交接已经完成，也不代表GPU6已派发。实际状态分别由下列独立目录的记录确认：

- 原V38：`production_resume_01/recovery_01/`。
- 自然排空与旧控制器收口：`recovery_01/controlled_handoff_gpu6_01/`。
- 新V39：`production_resume_01/gpu6_resume_01/`。

所有路径均位于`trusted_data_synthesis/artifacts/finance_research_20260928/finqa_v6_01/v18_researcher_continuation_01/v25_training_replication_01/`。交接完成、新控制器启动及GPU6实际占用是三个不同状态，不能互相替代。

## 资源变更范围

新调度范围为物理GPU3、4、5、6、7，但**总共仍最多4个worker，每张卡最多1个本实验worker**。CPU初始化、CUDA前等待和结果封存后尚未真实退出的进程均占名额。GPU0、1、2不纳入调度。GPU6的UUID固定为`GPU-6cf85ebf-ae89-905b-5d97-46f83b295526`；已核对其NUMA节点为1，采用原GPU4、5、7相同的CPU亲和范围。

GPU6只是临时许可，不作空闲时的显存占位。新派发仍要求设备完全空闲且free至少72GiB；运行allocated历史峰值不超过76GiB，规定边界free至少2GiB。分片RSS上限160GiB，其余阶段192GiB，全机有效可用RAM至少保留96GiB。模型加载计入峰值，加载开始后不重置峰值。

新调度器可通过封存的`queue/gpu6_withdrawal/record.json`停止未来GPU6派发；已经派发的任务保留租约直到其自然完成和真实退出。该入口不是中断反馈的紧急停止开关，须按用户的归还要求另行写入明确指令。

## 为什么不能直接修改运行中的白名单

V38的租约池、worker、CUDA前准入和结果验收均有固定四卡校验；其协议按完整内容比对，实施文件逐一绑定SHA。修改开发目录不会热更新当前进程，直接改冻结目录又会破坏后续校验。

现有SIGTERM/SIGINT逻辑会停止整池，并不提供“只停止新派发、让当前任务自然结束”的开关。准备切换时Full389正在首次反馈，直接停止可能留下原实现明确禁止自行重采样的部分反馈。因此V39不使用热补丁、进程注入、伪造设备身份、旁路GPU6 worker或第二个并行科学控制器。

## 自然排空与控制器交接

独立CPU交接进程使用原V38的GPU租约锁命名和路径，对GPU3、4、5、7逐张尝试取得文件锁。已有worker持有的租约不被抢占；只有原持有者真实退出、旧控制器释放租约后，交接进程才能取得对应锁。取得的锁一直保留，阻止旧控制器在该设备重新派发。该操作不锁定其他项目，也不向它们发信号。

旧控制器与交接进程可能竞争刚释放的锁，因此登记时的active列表不是绝对的最终收口集合：登记后、锁完全取得前出现的新launch也纳入观察，仍必须自然完成，不被隐瞒或强制终止。

正常路径为：

```text
逐张取得旧租约释放后的锁
  → 全部四锁持有，旧全局队列新鲜且active为空
  → 全部已派阶段COMPLETE且真实exit 0，迁移预检通过
  → 核验旧控制器PID、birth、UID和完整argv，用pidfd发送SIGTERM
  → 旧控制器在零worker情况下自主暂停、审计真实保存点并退出
  → 锁仍持有时初始化新协议与CPU控制器
  → 补记交接和初始化耗时，释放屏障
  → 同一协调进程运行新四worker租约池
```

只向旧控制器发一次信号，而且必须晚于worker自然退出；交接代码不会向worker发信号。旧控制器按其既有逻辑写入`PAUSED_DURABLE_BOUNDARY_NO_AUTO_RESUME`及`DurablePause / explicit safe stop requested`记录。这一记录保留原义，不改写为旧实验成功，也不伪装为科学失败重试。

交接进程不是旧控制器的父进程，因此只记录已观察其真实退出，不伪造可获取的退出码。各科学worker仍必须有原控制器记录的真实exit 0。交接失败、超时、身份不符、资源预算耗尽或出现未封存阶段时，不启动新科学进程，也不自动重试。

## 可继承与不可继承的状态

已完成训练以原实际checkpoint为准；已完成终点生成只读复用封存回答，不读取准确率，也不重新生成。原首点验收以引用方式继承，不再执行一次试运行。

尚未完成outer但已有成功阶段的context保留原context ID、protocol归属、参数点、task绑定、缓存和反馈。新目录只建立明确alias；已经完成的阶段从父目录只读消费，后续阶段才写新目录，不复制或重新标记旧Tensor。

为了避免在旧task cache中新增梯度，**任何继承的class阶段必须四个shard全部COMPLETE并真实exit 0**。仅完成一至三个shard的context不属于本次迁移能力；这一条件在停止旧控制器前检查，不通过则不切换。完全没有派发过阶段的旧context可以依据同一真实保存点在新目录重新登记，这不执行额外forward或采样。

只读登记检查记录、路径、文件stat、完成及退出证据；大Tensor和大型反馈内容仍由实际消费者按原内容哈希、Tensor摘要和同点合同核验。登记不是重算，也不以完成布尔值替代实际保存值。

首次反馈已生成但对应outer尚未提交时，原CPU快照的“未来首次采样”数字仍可能包含该点。V39另外记录已生成及已生成未提交的cohort，实际剩余新采样量按原8400条减去已完成首次采样计算，不能对已封存cohort重新发放700条预算。

## 时间与科学预算

原24小时outer计算窗口、24小时全局外部资源等待以及所有阶段时限保持不变。交接上限取登记时已派阶段最晚绝对deadline加原600秒停止宽限，与原全局资源等待剩余额所允许时刻的较小值；新增观察到的阶段不得延长该上限。

每个未完成outer的已用计算时间取旧context计时快照与已派worker真实起止区间并集的较大值，向上取整。已起算的phase保留原绝对deadline；未派过的新阶段没有继承其他无关阶段的时长，但仍受该outer剩余总额限制。

全局资源等待保守继承为：

```text
max(旧控制器最终累计等待,
    交接登记时旧累计等待 + 整段交接墙钟时间)
```

这一口径保守地计入部分worker仍计算的时段，不宣称它等于实际空闲等待。新控制器CPU初始化期间也继续计费，释放屏障前再次核验并封存账单；不通过则不会启动新调度。原预算没有重新发放。

V37登记的原剩余5810次optimizer更新、15次outer、8029条终点回答是累计计数基准。新队列从旧实际审计继承已经完成的份额，而非把新episode的计数归零。原C-only与Full分支、700分母、反馈奖励、轨迹logP、虚拟点、pullback、C与π及optimizer数学不变。API预算不新增。

## 实施与验证

新入口为`finqa_v39_controller.py`，配套独立handoff、inheritance、worker、admission和evaluation模块。新implementation保留全部父实施文件的原字节与哈希；历史四卡验证器与新五卡runtime分别加载，不能因更新runtime常量而污染历史协议验收。

终点生成继续调用原生成及评分函数，仅对原评价模块的两处设备准入应用有作用域的资源适配：核验新协议中的固定五卡UUID，门槛取原minimum与72GiB的较大值，使用后恢复原函数。原科学评价注册不改，全部九模型回答封存且worker退出后才统一评分。

115项CPU/mock联合测试通过，用时1.60秒，Ruff通过。覆盖自然排空、只有新鲜空队列才允许控制器信号、真实退出、禁止部分阶段切换、GPU6准入与其余禁卡、总worker上限4、预算继承、初始化耗尽时不启动、原反馈和父阶段只读、原评价准入适配与评分屏障。测试没有运行GPU或API，也不代表新增吞吐或准确率结果。

后续实际登记、租约取得、父暂停及新派发状态需以对应不可变记录为准；本说明不把交接启动直接表述为GPU6已经投入计算。
