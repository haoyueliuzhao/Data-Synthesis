# FinQA V54 反馈温度固定父点实验

本轮检验一个限定问题：把估计 Contribution 的反馈策略温度从 T1 改为 T0.5，在相同真实训练父点、材料和后继更新预算下，是否改善后继模型的原生执行准确率。它不是重新开展完整闭环，不修改训练损失、解析器、奖励或 Contribution 的归一化方法，也不恢复已经完成的 B 块。

用户于 2026-10-18 授权“参照方案修订并开展后续实验，本轮实验开放GPU使用限制，并发数暂设为4”。新实验独立根为 `artifacts/finance_research_20260928/finqa_v6_01/v18_researcher_continuation_01/v54_feedback_temperature_01/`，下文相对运行路径均以此为根。原 B 的训练、输出和失败历史只读保留。本文件的实验设计部分是执行合同，实际启动与阶段完成情况以末节及相应不可覆盖记录为准。

## 三个真实父点与三种固定分布

父点固定为原 B seed137、251、389 的 C-only `step0596_step`。这是真实完成第 596 次 optimizer 更新、但尚未提交第二次 outer 的状态；其 `outer_done` 应为 `[298]`。共同父点包括模型参数和 buffer、非空 Adam 状态、原 π、随机数状态、学习率与批次计划、任务池和完整材料绑定。`step0596_outer` 只提供旧 C1 更新及其来源证据，不能用其中已更新的 π 替换共同父 π。虚拟点 θ̄ 仅用于反馈与导数，不作为真实训练起点。

| 分支 | 固定用于 597 至 894 更新的分布 | 反馈来源 | 新 GPU 训练的条件 |
|---|---|---|---|
| Hold | 共同真实父点的 π | 不生成新反馈 | 每父点真实执行 298 次更新 |
| C1 | 原 T1 outer 得到的 q | 只读复用原 700 条反馈、奖励和实际导数证据 | 完整旧路径及两快照验收通过时复用，不重训 |
| C05 | 在同一 θ̄ 上用 T0.5 反馈重新得到的 q | 每父点独立新生成 700 条 | 每父点真实执行 298 次更新 |

Hold 不是原 Static 的先验分布。三个分支都使用原批次计划和相同父 RNG，整个 597 至 894 窗口固定各自 q；保存 step745 和 step894，不执行 step894 outer。训练 dropout 保持 0.05，类梯度仍使用原 eval 方式。

旧 C1 复用须核对全部 298 个实际更新回执、loss 与批次计划，以及父点、旧 outer、745 和 894 的实际完整状态、RNG、固定 q 和优化器绑定。找到了旧快照不等于复用已验收。三分支逻辑剂量为每父点 894 次更新、总 2682；三个旧 C1 都通过后，新增物理 optimizer 更新为 1788，复用 894，不把复用称为新增训练。

## 温度对应的真实概率与梯度

新条件使用 `p_T = softmax(raw_logits / T)`，T 为 0.5。实际采样回执和 R3 回放均绑定这一分布；反向传播同时包含归一化项和 `1/T` 导数。不能把旧 T1 的 gJ 乘二作为低温梯度。

每父点仍是原 350 题乘两个 draw seed 11、29，共 700 条反馈。题目顺序、任务名册、采样种子、调用及 token 上限、工具协议、奖励和其他解码配置保持原样，仅温度变化。回放计入完整生成轨迹，包括真实 EOS、多轮、错误与恢复调用；不套用 SFT mask、不按轨迹长度归一化。零奖励样本仍在 700 分母内；可产生梯度的实际 response 数不等于反馈样本总数。

在采样前先封存新条件身份，绑定父参数点、T、概率合同、完整配置和有序名册。新条件目录、collector/cache 和回执与旧 T1 分离；完成后再绑定真实 700 条回执、cohort seal 和冻结奖励。已有完整反馈只能读取，不能重新评分后改写；未知未返回反馈或不完整 cohort 不自动生成一份替代品。

G 与 θ̄ 可复用原同点实际张量，但必须匹配完整真实父状态和原 point。gJ、pullback、C、RMS 温度和 C05 的 q 则由低温反馈独立求得。原 C 指数 0.8、N 指数 0、RMS floor、sigmoid、历史锚、先验锚和 KL 约束不变。

seed389 有与本父点绑定的原完整类梯度缓存，可只读复用。seed137 和 seed251 各执行一次原 744 题、1360 状态、2468 包、4974 有效行的完整类梯度，仍按四个完整任务分片保存实际 CPU 梯度；不为凑并发增加 pass。反馈可基于已封存 G/θ̄ 先行；新的分布复算须等待对应完整类梯度和低温回放全部成功。

## 配对统计和开发筛选

主比较是 step894 dev883 greedy 原生 execution accuracy 的 C05−C1；关键辅助比较 C05−Hold，同时报告 C1−Hold。按同一父点、同一题目配对，先得三个父点的完整分母差值，再等权平均。独立训练父点数是 3，不是 9 个分支或 18 个快照。

报告每 seed 差值、均值、样本标准差、最小最大值和正零负个数；seed 层区间使用 df=2、临界值 4.3026527299 的近似 t 区间。n=3 时其正态近似假设不能由本实验可靠检验，区间不截断，也不新增 p 值或稳定阳性标签。

按题目的原始 `lineage.source_group` 做配对来源簇敏感性分析，预登记 10000 次 bootstrap、PCG64 seed20261018。每次抽取 G 个来源簇，同一组簇权重同时用于全部三 seed 和三臂；统计量为抽样簇的配对正确数差之和除以对应题数之和，使用 2.5% 和 97.5% 线性分位数。它描述固定三个父点下的来源构成敏感性，不替代训练随机性的 n=3 区间。

I、W、R 分别表示 invalid、可执行但错误、正确。按 baseline→candidate 给出转移表，并核对精确恒等式：`Δ = (I→R − R→I + W→R − R→W) / 完整题数`。两者都可执行子集的准确率只作解释，不取代完整分母主结果。

仅当所有科学合同完整、C05−C1 的精确均值严格大于零且 C05−Hold 的精确均值严格大于零，才通过本次开发方向筛选。符号由整数正确数差决定，避免浮点抵消残差把数学上的零变成阳性；精确零保留基线。通过也不代表显著性或稳定收益，不自动启动完整闭环跟进。

## 资源与进程约束

本轮允许物理 GPU0 至 7，独立绑定八卡 UUID 和 CPU 亲和，取代已收口旧轮的 GPU2 禁止安排。总 worker 暂限 4，每卡最多一个本实验 worker；CPU 初始化、CUDA 前等待和结果封存后的 draining 都占名额。使用原项目 GPU 租约 inode，并把已持有文件描述符传给子进程，避免控制器异常退出后错误重派同卡。不停止、不迁移其他项目进程。

新阶段全部使用 native 按需分配，不做人工暖大块、锚点或高显存占位。阶段首次准入是经验调度下限，不是未来峰值保证：

| 阶段 | GPU free 首次准入 GiB | 主存启动预算 GiB | worker RSS 硬限 GiB |
|---|---:|---:|---:|
| class | 24 | 160 | 160 |
| feedback | 24 | 64 | 192 |
| replay R3 | 56 | 48 | 192 |
| distribution | 24 | 64 | 192 |
| train | 26 | 48 | 192 |
| generate | 24 | 48 | 192 |

feedback 的 24GiB 准入依据是原同模型同上下文/token 上限过程观测到约 15.96GiB allocated 峰值，加登记余量；T0.5 不增加原 KV 尺寸，但不保证所有实际轨迹都具有相同峰值。主存启动公式保留新作业预算、活跃 worker 预算与 VmHWM 上浮需求尚未实际占用的部分，以及 96GiB 全机有效可用 RAM 余量。进程退出观测竞态只延后准入，不能伪造 RSS=0。

所有阶段仍要求整个冷进程 allocated 历史峰值最多 76GiB，规定边界物理 free 至少 2GiB，主存按 RSS 硬限及全机有效可用 RAM 至少 96GiB 检查。模型加载计入峰值；CUDA 初始化后、模型前仅一次清零初始峰值，后续不重置。R3 自身原始容量检查同样保留。资源检查保存实际观测和最终边界，只有资源 closeout、结果绑定及真实 exit0 全部一致才验收。

没有任意阶段、outer 或资源等待截止。本轮新入口只允许一次新鲜启动；资源尚未准入时同进程或队列等待，不把明确科学失败自动重试。任何状态、数值、资源或未知反馈错误停止全池，保留已经完整保存的任务梯度、response 累计梯度和逐步训练断点。合法停止不被忽略：R3 在完整 response 可保存边界协作暂停，其他阶段在安全边界退出；全池共享 600 秒退出宽限。冷恢复机制不构成自动增加实验次数的许可，失败后的新接续需根据实际断点和原因另行登记。

## 失败后的离线修复与恢复边界

源码检查发现确定的启动环境遗漏：原模型开启 `torch.use_deterministic_algorithms(True)`，旧 worker 在模型加载前设置 `CUBLAS_WORKSPACE_CONFIG=:4096:8`，新 worker 环境没有设置该值。工作区修复已显式传入并在 CUDA 初始化前核对精确值，缺失或错误立即拒绝，防止把配置问题拖到已登记模型调用中。3 项环境 CPU 回归通过。

另修复了新 provider 的异常记录：未来保留 Python cause 的类型、完整文本与 traceback，以及 condition/概率合同身份；不改变 UNKNOWN 结算、实际调用计数，不伪造 token 回执或发起重试。3 项针对性 CPU 检查通过，覆盖异常落盘、缺少 cause 时不虚构以及调用前停止仍零调用。

在科学进程全部退出后，独立持有原 GPU2 项目租约，串行执行两次 16×16 矩阵乘法作最小 CUDA 诊断：未设置该环境时实际报 CuBLAS 确定性 `RuntimeError`，设置 `:4096:8` 时运算通过，结果全部为 16。该诊断无 Student、生成、反馈、反传或 optimizer 更新，同时最多一个 GPU 子进程；allocated 峰值分别为 2048 和 33557504 字节，边界 free 均超过 48GiB。证据为 `implementation_diagnosis_01/cuda_minimal/record.json`，ID `5d2734583bca2f12c7bffe71519f0ab0e2e6574c57fe7ff8b6a4cc50811cf91c`。
