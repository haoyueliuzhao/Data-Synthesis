## 3. 三种关系各自回答什么

### 3.1 答案等价

沿用父阶段已成立的三个完整有效 Final，不重新跑金融判定器。
三条轨迹的真实 Final 依赖均建立同一来源绑定目标：

`11 × 33.32 − 13 × 26.93 = 366.52 − 350.09 = 16.43 USD_million`。

这里只是复述已成立的有效性。最终数字、展开表达式或正确答案都不单独决定完整行为类。

### 3.2 主要求解机制／Final 支持子图

沿实际 Claim ID 反向追踪 Final 的生产—消费依赖。只为这个**单独诊断对象**抽取
Final 支持操作 DAG，去掉非支持操作、调整历史和人工判断标签，保留真实来源、
操作、明确接受、实际输入及 Final。比较采用精确有标号图同构，输出实际节点对应表。

该子图允许乘法输入换序。若三个支持子图同构，表示当前见证的主要年度配对机制相同，
不表示完整行为相同，更不表示发现三种独立求解算法。
跨 V0/V1 的支持子图对照只作描述，不建立跨条件行为类池或采样分布。

### 3.3 完整有限公开行为

完整行为以来源绑定的有标号 DAG 定义，规则版本 `finqa_numeric_public_behavior.v1`。
节点与边如下：

| 对象 | 保留内容 |
| --- | --- |
| 来源节点 | 原 numeric ID、数值、位置、原 fragment；并绑定 task、source digest、当前 protocol |
| 实际 Action—Update 节点 | 操作、输入边、精确输出和来源表达式、accept/reject、公开关键判断 |
| 未准入 Action 节点 | 实际提议操作、输入与 raw-source/accepted-Claim 区别、错误代码、公开判断 |
| Final 节点 | 原发布值／单位／引用，连接实际选择的已接受 Claim 的生产节点 |
| 算术边 | 实际 Claim 出现身份，不用符号等价副本替换；乘法 factor 无序，减法端口有序 |
| 公开知识边 | 模型明确声称已有结果的前置 Action；不把仅计划读取的对象冒充已有结果 |
| 调整顺序边 | 每个未准入提议或合法 reject 前后的已观察相对顺序 |
| 重复前驱边 | 相同操作实际使用相同输入出现时保留前一个实际操作及额外执行 |

Action 与其紧随的首次合法 Update 在商图中视作原子节点，但模型的两个原始提交、目标、
各自交互 ID 和序号仍分别保留。若存在交错的生命周期而当前有限规则未覆盖，返回未定，
不删掉中间提交。所有处理过的提交都要有原样索引。

允许纯局部 ID 双射和不改变依赖的独立调度；不把数值相同当作来源相同，不允许减法交换，
不进行多项式总等价归约、死代码删除、自动单位修补或“看起来重复就删掉”。
完整图中的所有实际运算都保留，包括未用于 Final 的已接受乘积和被 reject 的数量差。

三条未准入提议都保留为行为节点：它们在尚未 read／accept 对应价格时提议算术，
V1 的两条还选择不同年度的输入，不能当作相同提议的文案重复。
本轮没有证明它们是与下一次准入动作完全相同、无新增语义作用的格式修复，因而不归约。
保留顺序表示实际观察顺序，**不证明反馈造成了某次调整**。

图同构比较首先允许用标签多重集给出直接差异证据；若标签相同，完整搜索保持所有边与
重复边数量的节点双射。相同图哈希不是同构证明。每个有限状态由当前条件内代表轨迹、
规则和投影绑定；不是可以跨协议、跨任务或跨生成条件继承的普遍类 ID。

## 4. 公开判断：有限人工解释而非自动意图识别

[judgments.py](../src/trusted_synthesis/experiments/finance_qa_vnext_finqa_quotient/judgments.py)
逐条列出 26 条 Action 的关键对象、期间、数值、方法或已接受知识承诺，并附完整原 reason、
subgoal 和原响应哈希。合法 Update 与 Final 没有自由理由字段，其显式判断由 disposition、
实际 Observation／Claim 引用和发布对象保留。

这些标签是未盲化的人工语义审阅。程序验证引文、原响应字节、索引完整性和前置对象存在，
**不自动认证人工解释正确，更不把公开理由当作金融正确性证明**。
全量原文与结构标签一起输出，便于逐项反驳或复核。

“当前年度没有明确说出”被显式记录为 `current_period:unspecified`，不会根据选中的输入
补为 2016 或 2017。因而本轮可以表示这个“未指定”的公开行为；这不把上一轮意图审阅的
UNDETERMINABLE 升格为 MATCH。两者问题不同：一个记录说了什么，另一个比较当前明确意图
是否与实际输入一致。

例如原文只说“使用 shares 和 prices”时保留依据陈述，不擅自补出完整乘减算法。
原文用 “2016 stock options value” 而未明确量纲时，保留 measure-unspecified，
不把它自动校正成正确财务角色。明确提出以 11−13 作为 total-value increase 的判断也保留。

若人工映射未定，完整商映射返回 UNDETERMINED，原有效性与候选仍保留。
不同措辞只有经过有限语义解释后才可能保留不同承诺；不以全部理由原文、字符长度、
哈希或每一个文案差异直接赋类。本轮若出现类差异，先报告可独立确认的实际工作差异，
不将细微表达差异包装成新算法。

## 5. 分布与任务边际

分别计算 `pi_hat_v(z | J2,Y=1) = n_vz / m_v`，其中 `m_V0=1`、`m_V1=2`。
同条件等价则合并类质量，不等价则分别记数；任一有效映射未定，则该条件完整分布为 null，
同时记录已知质量与未定有效质量，绝不只在已映射子集上重新归一化。

E1 在每个视图中的成功条件分布无法由本批零成功样本估计，故为 null。
它不等于“E1 不存在有效解”，也不允许删除 E1 后声称还保持原 E1/J2 各一半任务权重。
本阶段只建立 J2 条件内对象与原样素材，不能直接生成保持原两任务边际的有效训练集。

所有概率都只是当前有限成功样本经验质量，不是稳定的总体类概率。
不估计 Novelty、Contribution、训练效用，也不执行类权重更新。

## 6. 原样物化与 Token 策略

每一行同时绑定原 request/state/transition、Provider attempt/outcome、HTTP request/response
和各自字节哈希。输入是当次实际两条 HTTP 消息；另保留完整 HTTP body，包含真实生成配置。
目标是当次 Provider `message.content` 的完整原始 UTF-8 字节，与 runtime 原响应和
transport public content 三方相等，不做重排、压缩、去理由、补字段或改写。

V1 的 `accepted_result_bindings` 和原反馈属于输入，保留原请求当时的内容。
人工解释表、商图、正确支持子图与 Host 视图都不写入模型 target。
合法 reject 属于真实准入监督行为；未准入提议不进入49个目标，但全部留在按时序打包的
52 次原交互中。原始包保存每次交互的十项原始字节对象及绑定文件。

每条成功轨迹是一包：预期准入单元为 17、17、15，不是49条独立轨迹。
原样候选与商状态映射是不同关系：映射未定不会清除有效候选；Token 超长不会改写轨迹失败。
整包 Token 适配必须所有准入单元都 fit，不能悄悄丢掉长行。

Token 化复用既有本地 `Qwen2.5-7B-Instruct` 五文件、模板、软件绑定：
revision `a09a35458c702b33eeacc393d103063234e8bc28`，不联网、不下载、不加载模型权重。
引用 H1/H2 迁移实验已明确绑定的 32,768 长度政策；历史 tokenizer binding 的
24,576 字段原样保存，本轮单独绑定 32,768，不篡改旧资产身份。
模板、五文件和软件由原只读加载器核对。

编码器原样复用既有边界政策：system/user、assistant header、EOS、suffix 和 padding
的标签均为 -100，仅原 assistant content 有监督。完整模板必须等于 prefix + 原 target +
固定 suffix；验证 Token 边界不跨目标、目标可逐字节解码、无截断、因果位移为 1。
超长时保存原候选和长度诊断，不保存虚假可消费数组，也不换模板或提高上限。

即使所有行适配，也只证明 CPU Token 表示和长度可消费性，不证明 Student forward、
GPU 显存、优化可行性或训练收益。Provider usage 与该 tokenizer 监督 Token 不是同一计量。

后续如开展训练，须先选择生成条件／任务／类／完整轨迹，再明确单元级损失聚合。
本轮不提供49行均匀采样器，不默许按行数改变轨迹权重，也不分配训练权重。
