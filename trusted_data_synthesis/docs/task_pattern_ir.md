# Task Pattern IR and Binding Compiler

## Purpose

Version 0.6 moves task construction from domain-specific imperative factories to a declarative,
proof-carrying compilation path:

```text
Task Pattern Spec
        +
Evidence Binding
        +
Domain Pattern Runtime
        +
Operation Registry
        +
Evidence Bundle / Proof Graph
        -> Task Pattern Compiler
        -> Task Program DAG
        -> Public Task / Oracle Contract
        -> Difficulty Profile
        -> Quality Contract
        -> Proof Certificate
        -> Release Manifest
```

The Pattern describes a reusable task family. The Binding identifies one concrete evidence
instance. The Runtime validates domain semantics and realizes public language. Core compiles and
audits these objects without understanding finance, law, or science.

## Core Objects

### Task Pattern Spec

`TaskPatternSpec` freezes:

```text
pattern ID, version, domain, and task type
typed Evidence roles and cardinalities
role-local and cross-role semantic constraints
declarative Program node templates
answer schema and output node role
instruction renderer and quality profile identities
retrieval, planning, and source-grounding contracts
base difficulty and structural cost
```

Pattern validation is fail-closed. It rejects duplicate roles or nodes, forward references,
invalid foreach/group references, an ambiguous output node, and unknown evidence roles.

### Evidence Binding

`EvidenceBinding` is a content-addressed assignment from Pattern roles to Evidence IDs. It also
freezes the source Proof Graph, optional domain snapshot, node parameters, public slots, and
binding features. Its hash changes when any role, Evidence version, graph, or parameter changes.

Binding identity is Oracle-only. A Public Task exposes the Pattern identity and difficulty profile,
but never the Binding ID, Binding hash, exact role assignment, or gold Evidence IDs.

### Domain Pattern Runtime

`TaskPatternRuntimeProtocol` supplies only domain-owned behavior:

```text
validate_binding
  Check metric comparability, legal authority/conditions, protocol alignment, and similar rules.

materialize
  Render the instruction, public retrieval scope, dynamic answer context, and hidden selection
  contract after the Binding is known.
```

Every renderer ID must be registered by the Runtime. An unknown renderer, mismatched domain, or
failed semantic check rejects compilation.

## Program Compilation

Program templates use four typed input forms:

```text
evidence_role       all Evidence items assigned to one role
current_evidence    the current item in a foreach expansion
operation_node      one previously compiled operation
operation_group     all operations generated by a prior foreach template
```

The compiler expands foreach nodes deterministically, resolves dependencies, and validates every
concrete node against the frozen Operation Registry. The registry, not the Pattern, owns the
operator output schema and verifier identity. A stale Pattern schema therefore fails instead of
silently changing task semantics.

## Difficulty Compilation

Every Pattern task receives a `TaskDifficultyProfile` derived from:

```text
Evidence count
Proof Graph depth
Program depth
Program branch factor
Operation count
semantic constraint count
domain semantic-alignment cost
Pattern base cost
```

The final level is the stricter of the Pattern prior and the structural score. This profile is a
compiled, versioned property, not a label inferred from surface wording.

## Quality and Proof Binding

Quality Contract Compiler v2 emits two additional fail-closed clauses:

```text
task_pattern_binding_integrity
  Pattern identity, Binding identity, role coverage, role uniqueness, graph pin, and contract hash.

difficulty_profile_integrity
  Complete difficulty features, policy version, score, and level.
```

Proof Certificate v2 and Proof-Carrying Sample v2 bind the Pattern hash, Binding hash, and Pattern
Compiler version. Release Manifest additionally freezes:

```text
Pattern schema and compiler versions
Pattern Runtime IDs and versions
Pattern quality profiles and Pattern hashes
Binding schema versions and Binding hashes
Difficulty policy versions
```

This prevents a task factory, semantic Runtime, evidence assignment, difficulty rule, or verifier
from changing while retaining an old sample or release identity.

## Domain Implementations

The same compiler currently instantiates:

```text
Finance
  fact retrieval, comparison, temporal growth, temporal average

Legal
  rule application with condition/exception checks and authority resolution

Science
  protocol alignment followed by uncertainty-preserving effect comparison
```

Domain task plugins retain their previous public methods as compatibility facades. Those methods
now create a Binding and invoke the common compiler; they no longer hand-build Task Programs.

## Validation

The v0.6 controlled validation produced:

```text
Finance compiled tasks                         50 / 50
Finance accepted references                    50 / 50
Finance accepted clean candidates              50 / 50
Finance rejected generated error mutations    803 / 803
Finance fixed/contract decision parity        853 / 853
Finance unique Evidence Bindings                50 / 50
Finance Pattern/Binding clauses                 50 / 50
Finance difficulty clauses                      50 / 50

Legal compiled and clean-passed tasks           10 / 10
Science compiled and clean-passed tasks         10 / 10
Cross-domain contract decision parity           20 / 20
Cross-domain unique Evidence Bindings            20 / 20
```

Run the repeatable checks with:

```bash
trusted-synthesis validate-task-patterns \
  --tasks-per-domain 10 \
  --output artifacts/task_pattern_validation_v06.json

trusted-synthesis finance-pilot \
  --config config/finance_archive.json \
  --pilot-config config/finance_pilot_v06_pattern_50.json \
  --output-dir artifacts/finance_pilot/v06_pattern_50
```

These results establish controlled compiler and verifier portability. They do not establish
production Legal/Science corpus quality, open retrieval, live-agent quality, or Greater China data
coverage.

## Next Method Milestone

Version 0.7 should derive typed counterfactual opportunities from Pattern roles, Program nodes,
Proof Graph relations, and Quality Contract clauses. Counterfactual generation should preserve one
minimal intended violation, prove failure closure, and measure mutation minimality. It should not
return to a larger hand-written list of finance mutations.
