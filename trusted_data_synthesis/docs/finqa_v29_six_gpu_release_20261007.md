## 后续六卡策略

新的资源策略已绑定用户的后续明确确认：允许物理GPU0–7，但本实验同时最多有6个GPU worker，且每卡最多一个本实验worker。名额从进程派发时计入，包括还在CPU准备、尚未显式占用CUDA显存的worker。恢复接管、候选派发和真正启动三个入口都执行六卡限制。

GPU0、1、2、6只有在没有其他计算进程且空闲显存至少80000 MiB时，才可重新被本实验使用，并采用原高缓存模式。GPU3、4、5、7继续原双模式规则。占卡上限不赋予抢占权限，也不保证始终有两张空卡：其他项目可使用本实验未占用的设备。

四项暂停任务各登记一次行政断点续跑授权。在其他合格设备上有空位时使用原worker `--resume`，恢复同一模型、Adam、RNG和分布，不重新初始化，不丢弃反馈；启动前复核最后检查点、文件集合和元数据。它们不消耗原每任务最多两次的OOM恢复预算，也不把接续当成新增seed或额外统计样本。

为让接管后的OOM保护仍有效，新证明模块沿绑定的 `origin_launch` 找回实际执行来源，核对原wrapper及其显存回执，而不是假定回执都位于当前队列目录。检查点、历史反馈完整性和禁止重采样的科学约束继续使用已冻结实现；未知异常或不完整反馈仍不能自动重试。
