# 7897非SEC连通性与7890监听归属核查

## 结论

2026-09-26北京时间10:48:43—10:48:46，强制通过服务器 `http://127.0.0.1:7897` 访问三个非SEC网站，系统curl与实验虚拟环境Python共6次HTTPS HEAD均得到HTTP200。curl的代理CONNECT均为200，TLS实际握手完成且证书验证通过。

因此，本次检测不支持“整个7897代理已经失效”或“实验Python普遍无法建立TLS”。这只是短时、小请求的实测，不证明SEC已恢复，不排除SEC专属分流／访问策略、间歇性故障或长连接／大文件下载问题。没有再次请求SEC，也没有重置任何采集账本。

用户已说明7897是本人本机代理的转发，本机可访问相关网址。服务器上的端口监听与用户本机的同号端口不是同一个概念，仍须通过实际转发映射确定两端关系。

## 1. 测试范围与方法

- 目标仅为 `https://example.com/`、`https://github.com/`、`https://www.wikipedia.org/`。
- 每目标各1次curl HEAD、1次实验Python urllib HEAD；没有自动重试，没有跟随重定向，不下载正文、不带API key或认证信息。
- 明确指定7897代理，子进程移除大小写HTTP_PROXY／HTTPS_PROXY／ALL_PROXY／NO_PROXY，再配置唯一显式代理，避免意外直连。
- curl首参数 `-q` 禁用用户curlrc，connect超时10秒、整体20秒，TLS校验开启；Python使用默认CA与主机名校验，socket超时10秒，外层进程总限时20秒。
- 每批最多3个并发。预设最多9个请求：仅代理检测失败时才增加3个相同站点的服务器直连对照。实际6次均成功，因此未触发直连对照。
- 新SEC请求0、TLS-only探测0、其他代理请求0；不访问IP检测网站，不修改代理、SSH或实验配置。

## 2. 实测结果

| 目标 | curl代理CONNECT | curl HTTP | curl TLS完成时间 | curl总时间 | 实验Python HTTP | Python耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| example.com | 200 | 200 | 0.515秒 | 0.994秒 | 200 | 1.308秒 |
| github.com | 200 | 200 | 0.547秒 | 0.916秒 | 200 | 0.653秒 |
| www.wikipedia.org | 200 | 200 | 1.800秒 | 2.035秒 | 200 | 0.975秒 |

curl三次退出码均0，ssl_verify_result均0，time_appconnect大于0且取得HTTPS HTTP响应，不能仅靠单独的ssl_verify_result=0认定握手成功。每次remote_ip为127.0.0.1，表示连接到本机代理入口，不是出口IP。

实验Python使用同一venv及OpenSSL 3.5.7；不是换成系统Python以掩盖原环境问题。表格为每站点每客户端单次观测，不代表平均延迟或持续可用性保证。

## 3. 7890与7897的归属

只读 `ss -ltnpe` 与进程信息显示：

| 服务器监听 | UID | 所属服务／会话 | 已见进程 |
| --- | ---: | --- | --- |
| 127.0.0.1:7897 | 1004（当前用户） | SSH session-42439.scope，09:15:19建立 | sshd PID2656216 |
| 127.0.0.1:7890 | 1000 | 用户服务mihomo.service | mihomo PID545228，9月7日启动 |

这些证据只能确定当前服务器端监听归属不同，不能确定7890的具体配置、可用性，也不能仅凭本机端口推断7897最终出口。没有读取UID1000的私有配置、日志或凭证，没有使用或修改其代理。

若用户所见的是自己电脑上的7890，它可能是某条SSH转发的目标，但目前没有转发参数证据，不能将此可能性写成已确认映射。

## 4. 下一步应核对什么

现有证据将范围缩小到SEC目标相关或间歇性的链路差异，而不是证实了其中某个原因。适合比对用户本机代理中同一SEC目标的连接记录：

1. 服务器北京时间10:01:10—11：目录请求得到403。
2. 服务器北京时间10:30:03—24：目录请求在TLS阶段EOF，未收到新HTTP响应。
3. 本次10:48:43—46：三个非SEC目标全部正常。

重点是对应目标的规则命中、上游节点／连接错误和SSH转发映射；不需要DeepSeek API key。用户可提供这些片段并隐去订阅链接、密码和token。不要将浏览器能访问主页直接等同于实验客户端能获取指定JSON，也不要通过切换端口绕过原SEC403停止条件。

本报告仅作网络诊断，不改变已启动的负向训练子协议或SEC采集停止状态。原恢复与保存点证据见[实验恢复说明](calibration_recovery_20260926.md)。
