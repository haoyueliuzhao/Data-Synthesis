# FinQA：公式选择与自主执行首批诊断

## 1. 冻结时的状态与范围

本轮依据最新审计新建生成架构，不继续增加旧 N/D 分解提示，不补齐旧商映射后再开始。
历史基线为 `a84ba9b46ac35e1d4322b253ac757fa366515b27`。旧批十二会话、十条有效轨迹、两条
在线反馈后的恢复、四条未定完整图和十个原样包全部保留；新实验不追溯改变其结论。

本文件前八节为首个正式 Provider 请求前冻结的设计。冻结副本另存于正式工件的
`preparation/design_at_freeze.md`；文末结果部分只能在采集全部结束后追加。

主问题：在无任务专属计划、强制 accept 和在线答案反馈的环境中，模型能否自行选择适用公式、
绑定真实数据并完成任务；公开轨迹能否反映这些决定和实际执行？本批不是盲测，不证明新架构
优于旧架构，不估计连续历史、整式工具或撤去 oracle 中任一单独因素的因果效应。

## 3. 责任重构与在线接口

新入口是 `finance_qa_vnext_autonomous_formula.stage`，不继承旧在线 Runtime。旧的强制
Update、accepted-Claim 输入准入、目标判定和 R 反馈不在在线控制路径中。

```text
模型公开消息／明确工具请求 → 通用工具执行 → 原结果回传 → 模型继续
                                         模型首个 Final → 结束进程
十二个进程全部结束、原记录封存 → 独立数值复算 → 原文引证的语义评价
```

模型自己决定查资料、暂定或修改公式、配对变量、处理单位、安排中间量、检查和结束。通用提示
鼓励在公开消息或计算请求中说明关系和所选量，但不存在必须先通过的计划或 Formula 对象。
直接回答、缺少来源或错误财务公式不会被在线拦成“尚未达到正确解题阶段”。

模型每次输出一个 JSON 对象，可含 `message`，或 `tool` 与 `arguments`，或 `final`。
同一对象出现 `final` 与 `tool` 时 Final 优先，不执行该工具；`final: null` 也立即终止。
无法解析、重复键、非对象等只得到接口错误，不得到答案反馈。

三个工具：

- `calculate`：执行明确的完整或局部算式。变量可为数值、带模型自填来源／单位的 value 对象，
  或此前成功标量结果的 `result_id`。支持有界加减乘除、整数幂与 sum/avg/min/max/abs。
  原表达式及数值词法保留，内部按 Fraction 精确计算。返回精确分数、50 位十进制展示、实际
  变量、直接消费的结果 ID、表达式操作计数和深度；不认证财务含义或来源正确性。
- `read_source`：按模型提供的精确定位返回公开记录和原段落。完整材料最初已经可见，不要求
  再次逐个 read。单个数字读取结果可直接作为后续数值结果输入。
- `notebook`：只存取模型明确写出的文本，不由 Host 自动摘要、建议或补全正确计划。

财务含义错误但数值可算的表达式照常执行。例如跨年度乱配的合法乘法不会触发正确年份提示。
缺少来源声明的数字也可算。Host 不按相同数字匹配来源，不修复符号、年份或单位；来源声明
完整保存在原始参数和派生记录中，不构成执行许可或财务认证。工具输出直接可用，没有 accept。

计算器只遍历白名单 AST；不执行 `eval`、字符串代码、导入、属性访问或文件操作。
语法错误、变量未定义、除零和越权语法返回真实执行错误。数字大小与 AST 资源边界属于工具
执行边界，不是题目目标检查。

## 4. 连续历史、终止与资源

每次请求都包含相同通用 system、完整初始材料、此前全部原始 assistant 内容以及实际工具
返回或接口回执。工具调用采用 JSON 消息路由而非 Provider 原生 tool_calls：工具输出包装为
`user` 角色的 `tool_result`，它明确是 Host 的工具回传，不冒充模型原文。纯消息后的回执仅为
`model_message_recorded`，不安排下一阶段。消息不摘要、不截断、不替换为 Host State。

统一教师为 `deepseek-v4-pro`，temperature 0.7、top_p 1.0、thinking disabled、JSON object、
max_tokens 8,192、非流式。实际响应须符合固定条件；允许服务返回登记的 pro／pro-0813 名称。
不更换教师、不开另一种 Thinking、不使用备用模型或自动网络重试。

| 资源 | 冻结边界 |
| --- | --- |
| 单会话模型请求／响应循环 | 最多 32 |
| 单会话工具调用 | 最多 32（错误调用也计数） |
| 全部正式请求 | 最多 384 |
| 每次实际完整 HTTP body | 最多 98,304 字节，包含全部历史与参数 |
| HTTP 响应保存 | 最多 2,097,152 字节 |
| 单次输出 | 8,192 Provider token 上限 |
| 连接／单请求总时限 | 30／180 秒 |
| 每请求预算登记 | 98,304 + 1,024 + 8,192 = 107,520 allowance |
| 全批最大预算登记 | 41,287,680 allowance |
| 算式长度／AST 节点／深度 | 4,096 字符／256／32 |
| 整数分子分母位数／幂指数绝对值 | 16,384 bits／12 |

字节加开销的 allowance 是保守资源登记，不是实际分词、收费 Token 或已花费用。真正成本
以 Provider 原 usage 分字段报告；缺失不填零。保存每次请求、原响应、耗时、响应状态与预算
登记；不再把旧“最多 12 次原子数值操作”搬过来。表达式中的一元、二元、聚合运算节点各计
一次，依赖深度也保存；这不是跨工具链最长深度，不可与旧 Action 计数直接比较。

首个可解析 JSON `final` 无论内容、答案、来源、单位或公式是否正确，都立即结束。独立评价
从不把目标差异发回模型。达到响应／工具／历史边界则按真实状态结束；HTTP 或响应条件异常
作为未知保留，不重试补成功。仅有执行错误的修订，不代表收到隐藏答案提示。

## 5. 公私分离的实际实现与边界

预处理父进程把公共材料和私有目标分开写入不同目录。在线 worker 由 `/usr/bin/python3`
以 `-I -S -B` 独立 exec 启动，不继承父进程的 Python 地址空间；部署包仅含 common、calculator、
isolate、worker 四个标准库文件，没有项目 Panel、旧 Runtime、目标或独立评价模块。

在载入公共材料及首个 Provider 调用前，worker 启用 Linux Landlock（要求 ABI≥3）与
no_new_privileges，仅开放系统解释器／动态库、TLS/DNS 所需系统文件、自己的四文件代码包、
一个任务的公共 JSON 和自己的新输出目录。其它任务输出、私有目标和项目文件内容不在
allowlist。API Key 由父进程经匿名管道一次性传入并关闭 FD；不保存认证请求头或 Key。

每个进程实际尝试只读打开私有评价文件和隔离 canary，必须得到 PermissionError 才继续；
不读取其字节。隔离报告同时保存允许路径、实际 ABI、隔离解释器状态和已加载项目模块列表。
局部控制实际验证 OS 拒绝，而不只是检查提示中不含答案。

限制：这是有限原型的文件内容隔离，不宣称生产级沙箱证明；标准库和系统库仍可读。网络
由固定 HTTPS 客户端约束，不是 Landlock 网络沙箱；模型没有任意 URL 或文件工具。
隐藏参考文件不是给模型后再要求其“不要看”。父进程在准备阶段知道参考材料，但不给 worker；
只有全部 worker 退出、在线目录封存之后，另一个 `assess` 调用才运行私有评分。

## 6. 冻结的离线评价规则

评价不调用模型，不修改原始响应，不制造新结果。完整 HTTP 历史按原 assistant 字节和真实
工具返回逐次重建并核对；首次 Final 必须是最后一次请求，原 Final 与结果记录一致。

三个结果分开：

1. **任务答案**：先评分 Final 实际发布的数字及显式或原问题明确隐含的单位，再检查 Final
   文字、方向与字段是否自相矛盾。参考目标按原来源独立代入。分数严格相等；十进制允许其
   发布精度的半个舍入单位，但容差不超过原答案单位 0.005。百分数单位是百分点数值，不是
   无声明地把 0.1 当作 10%。没有可辨认数字／无法判定口径保留未定。无公式不改写数字评分。
2. **公式驱动可验证过程**：适用公式、变量来源／期间对应、尺度／符号、真实执行、发布分别
   检查。独立 SymPy 数值 AST walker 复算实际算式，不调用在线 Fraction 计算器。原计算请求
   本身是计算前可观察关系，离线还原式只能标成实际执行式，不能冒充更早的计划。
3. **自主规划的公开表现**：引证模型何时取证、组织算式、复用中间结果、检查、修改或结束。
   不把计划长度、调用次数、公式数量当作能力分数；不推断内部“接受”或私有认知过程。

机器来源检查只接受模型显式的来源／结果关联，不按数值相等自动绑定。公开文字、表格位置
或先行明确单位换算可由有限语义复核判断；纯参考符号不匹配不直接等于答案错误。
模型给出的值与所引原数不同，会标记需换算说明复核；不能仅凭符号图相等认证代入。
缺少依据、替代依据超出已解释范围时可标 UNDETERMINED，不强迫所有表达式回到参考图。

逐会话语义复核字段：formula_applicability、variable_correspondence、unit_handling、
publication_alignment，以及 Final 自身的 final_answer_consistency。PASS／FAIL 必须有原始
模型响应内的逐字引文；引文检查只证明出处，不自动认证语义。复核者了解任务与目标，明确为
非盲的有限人工式分析，不宣称另一个未知答案评委或通用证明器。

要计入“公式驱动轨迹已验证”，必须选择一个确实成功执行的答案计算；公式、数据、单位三项
证据至少分别有引文出现在该请求之前或同一模型请求中；Final 发布值与该结果数值一致，
显式 Final result_id（若存在）也要一致，并且语义各项和任务答案通过。仅在 Final 才补公式，
或只直接报出正确数字，没有实际计算轨迹，不可升级为这项成功。

缺省数值字段不强制模型回补。若 Final 是自由文字，复核只能从实际 Final 引文提取明确
数字／单位；不得从参考目标填值。Final 字段数值正确但实际文字／方向矛盾，也不能记为完整
任务有效。未结束、资源耗尽、未知会话均保留在十二会话分母；未知不是已证失败或成功。

## 7. 局部控制与冻结流程

局部控制只覆盖新增职责：错误财务关系照常算；无 accept 直接复用；错误或空 Final 立即结束；
真实文件隔离、精确原历史；常见执行错误；独立复算与不按同值绑定；Final-only 公式不获前置
证据信用；精度／单位／Final 文意分开；成本缺失保留未知。脚本响应仅用于控制，带
`scripted_control` 来源，正式采集不传脚本，离线正式入口拒绝脚本来源。

冻结前局部测试和 Ruff 通过后，提交并推送新实现及本设计；正式准备器将全部项目 Python
文件逐字与该 Git 提交核对，再冻结十二条登记、公共材料、私有目标、完整设计、代码包和
仅本轮测试的结果。采集后再次核对全部源码和历史 guard。原始目录的 manifest 覆盖全部文件
并核对长度和 SHA-256；不把日志整理文件当作原始模型消息。
