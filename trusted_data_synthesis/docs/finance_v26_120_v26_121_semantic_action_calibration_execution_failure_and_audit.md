## Final Interface Failure

The Final Primary Prompt says to return exactly `rationale_summary` and `answer`. All 31 models did
exactly that. The frozen parser instead accepts exactly `stage`, `answer`, and `protocol` and
rejects extra fields. Thus 31/31 Prompt-conforming Final Primary payloads fail with
`final_answer_not_exact_object_contract`. This is an exact, credential-free Prompt/Parser contract
mismatch, not a demonstrated failure to derive the answer.

The Final Rescue Prompt narrows its visible contract further to `answer` only, while the same
three-field parser remains active. In addition, all 31 exact Rescue Prompts lack a case-insensitive
`json` lexical cue even though the request body freezes `response_format.type=json_object`; every
such Provider call returned HTTP 400. The Primary Prompt contains the JSON cue in 31/31 cases.
The missing cue is a strong prospective localization of the deterministic Rescue failure, but the
HTTP error bodies were not persisted, so v26.121 does not claim it as the unique Provider cause.

## Privacy Persistence Failure

The incomplete Job localizes a second Instrument defect. `RawActionProviderCall` validates the
parsed public payload, including the recursive reasoning-key privacy scan, before writing the
artifact. Only after successful artifact validation and file persistence does the ledger append
telemetry. A response containing a reasoning-classified public JSON key therefore fails before
the privacy-redacted telemetry can be retained. There is no telemetry-only fallback artifact.

The future repair must preserve the private-reasoning prohibition. It must first persist the
already-redacted Provider telemetry and public content hash/length, then either persist a validated
public payload or omit that payload and attach a typed projection/privacy failure. It may not
serialize the rejected content, key, private reasoning, or a reasoning hash.
