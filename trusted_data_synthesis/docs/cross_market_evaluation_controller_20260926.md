# 跨市场评价控制器：未登记、未启动

`run_fixed_kernel_cross_market_evaluation_20260926.py`新增有限的`register/start/coordinate/worker/status`执行入口。本文是实现合同，不是模型运行记录。当前财务准入仍不足三个组各60题，因此没有登记评价协议、转换真实保存点、启动GPU或进行私有评分；不能因为控制器已实现就报告实验完成。

## 固定对象与预算

控制器只能使用已有准入中的六个Static／正向step240点和已完成负向尾段的三个step240点，固定seed11、29、47。准备阶段只在CPU上从已绑定hash的原checkpoint提取LoRA参数并保存adapter；不执行训练、更新参数或重建训练数据。同一模型在随机／greedy模式下共享同一个参数点。随机种子只依赖实验盐、训练seed、模式、题目与repeat，不包含arm。

登记先核对原训练信用及负向完成记录的内容身份；统计适配器和原精确数值核也纳入登记源码hash，使推断规则在读取任何新Q之前冻结。无需再重跑原九份checkpoint的完整训练准入。

拟定180题×9模型×（2次随机＋1次greedy）共4,860会话。每模型随机分3片、greedy分2片，共45个生成工作单元；分片只改变执行调度，不改变完整任务顺序／采样种子／参数身份。最多8个GPU worker，启动所需空闲显存49,152MiB；GPU状态查询只读，不终止或迁移其他进程。

| 项目 | 固定上限 |
| --- | ---: |
| 每生成分片物理启动 | 4次 |
| 每评分cohort物理启动 | 2次 |
| 所有worker启动 | 216次 |
| 真实generate调用 | 157,824次（4,860×32＋2,304） |

| 物理评分案例 | 5,100次（4,860＋240） |
| 同时评分cohort | 2个，各最多12个spawn CPU worker |

未达到显存启动条件只等待，不消耗物理worker尝试。资源/OOM或已确认PID退出的中断允许在上述上限内恢复；恢复复用已提交会话／评分，既有未结算调用不退款。普通实现或准备错误停止，不自动改成Q=0，也不根据结果扩充预算。无法确定PID身份的未结算启动留给审查，不盲目再启动副本。
