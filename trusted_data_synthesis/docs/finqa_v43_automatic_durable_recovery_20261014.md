# FinQA V43 无截止时间的断点恢复

日期：2026年10月14日，时间均为北京时间。实验路径以 `trusted_data_synthesis/artifacts/finance_research_20260928/finqa_v6_01/v18_researcher_continuation_01/v25_training_replication_01/production_resume_01/` 为基准。

用户明确授权“修复版运行，当前资源紧张，取消截止时间限制，设置自动恢复”。本次独立版本使用 `recovery_04/`，取消资源等待、阶段和 outer 的时间上限，并为可核验的持久断点提供自动接续。原九模型剂量、同点数学与资源安全门不变，V42失败记录和冻结源码不回写。实现准备、测试和真实启动的状态分别记录，不能把自动恢复设计当作已经成功恢复的生产结果。

## 继承状态与原失败修复

V42在模型调用前因恢复校验错误而停止：它把新尝试合法生成的审计UUID误当成必须与旧请求完全相同的科学输入。本次使用离线修复后的校验；messages、tools、config、请求摘要、参数点、参数摘要和调用坐标仍须严格一致，仅允许合法重新生成的审计身份变化，新旧身份关联在模型调用前持久化。

V42新增模型调用、完整反馈、完整任务梯度、outer和optimizer提交均为0。V43继承五个已封存终点，原剩余剂量为2355次optimizer更新、7次outer和四模型4588题终点回答。九模型及回答全部封存后才统一评分，不提前读取已完成模型准确率。

| 未完成坐标 | 已保存状态 | 允许接续的原工作 |
| --- | --- | --- |
| Full251 step894 | 完整744题类梯度、700题反馈、474条实际response回放 | distribution及原outer与SFT提交 |
| C-only389 step894 | 完整类梯度、实际G与虚拟参数、450题完整反馈 | 原获批的唯一未返回请求重新执行一次，余249题首次执行，再接原后续阶段 |

父450题反馈与277题完整任务梯度只读复用。中断题中未封存的行不能作为可恢复梯度，因此补齐完整任务可能重复计算该任务内未封存的行；这不称为零额外forward。已经成功的先导验收、终点和训练提交不重复执行，不改变原context及参数点身份。

## 时间策略

新协议的资源等待、阶段和outer截止均为无上限，而不是把deadline换成一个很远的日期。历史时间继续作为资源使用统计保留，不归零，也不再作为V43停止条件。V42停止时累计资源等待93720秒；Full251894、C-only389894、Full389596三个outer分别已用45931、29728、10688秒。旧协议的截止与失败结论仍按历史记录解释。

取消实验截止不等于忽略用户停止。明确停止监督器时，停止新派发、向核验过身份的本项目worker请求安全收口，并禁止监督器自行再次拉起。正常收口仍保留停止宽限，以免失去响应的进程无限占用资源；该宽限不是新的训练阶段期限。

## 自动恢复的安全边界

自动恢复必须使用实际落盘的训练、完整任务或response累计梯度断点，核验来源、参数点、配置和完整性，并在独立尝试目录保留中断原因及后继关系。旧尝试不能被覆盖或从失败改为成功。瞬时资源不足先等待，符合恢复条件的中断按退避策略接续；UUID、数值、数据绑定或状态完整性异常不能盲目重试。

完整反馈和模型调用回执保持只读。对有调用意图却没有可恢复返回结果的新请求，自动恢复授权不自动扩大采样预算，也不意味着可以重复执行未知结果的请求。C-only389旧悬空请求仍只有之前明确批准的一次重新执行额度，不能随尝试次数重置。已完成的450题和首次完成的新题按实际记录继承；反馈完整700题后才允许原评分与奖励封存。

| 中断位置 | 本版自动接续范围 |
| --- | --- |
| CUDA前等待 | 实际退出且确认尚无科学调用后，在新尝试重新准入 |
| 类梯度分片 | 合并各尝试已原子封存的完整任务，只计算未封存任务；完整缓存但缺成功退出验收时走零新增forward收口 |
| R3回放 | 读取同点最大完整response断点，严格核验梯度、反馈顺序及RNG；已完整时不重复backward |
| distribution | 从已封存的原G、虚拟点、反馈及gJ重新执行未提交阶段 |
| 训练 | 从真实完整checkpoint及已提交outer状态建立下一段，不重复optimizer或outer提交 |
| CUDA后的virtual_point或终点generate | 若没有完整成功结果，本版停止自动恢复，等待人工处置；不凭部分episode数量重启生成 |

监督器在实际确认上一次控制器退出后才判断恢复，按30、60、120、300秒退避，之后每次保持300秒；不设置累计等待上限。每个后继尝试使用原冻结实施包和新目录，不能原地重启已经使用的阶段入口。此机制覆盖监督器存活期间的受支持中断，不等同于服务器重启后由系统服务自动启动。

## 显存与并发约束

物理GPU0至7可选。用户随后补充“gpu4也可以占用”，本次优先顺序登记为GPU0、4、3、5、7、1、2、6。每卡最多一个本实验worker，总并发最多4个，CPU初始化和draining均计入。其他项目进程不构成单独否决条件，但不得被终止、修改或抢走其已分配显存。

| 阶段 | 准入空闲显存 |
| --- | ---: |
| 类梯度分片 | 至少28GiB |
| train与首次反馈采样virtual_point | 至少32GiB |
| R3回放与终点generate | 至少48GiB |
| 复用完整反馈的virtual_point与distribution | 至少24GiB |

运行时allocated历史峰值仍限76GiB，规定边界free至少2GiB；模型加载计入峰值，冷进程内不重置。分片RSS上限160GiB，其他阶段192GiB，全机有效可用RAM保留至少96GiB。R3的非KV激活驻留预算仍16GiB。这些显存准入值来自历史用量与登记余量，不保证未来必然不会触及运行门。

原C-only的b_N=0、Full的b_N=0.2、C指数、温度、历史和先验锚、完整轨迹logP与700分母保持不变。外部API模型仍限定 `deepseek-flash`，不引入模型回退。
