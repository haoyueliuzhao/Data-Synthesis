## 资源与持久化

- 每个完成的optimizer更新保存完整参数、Adam与RNG；每段完成的反馈响应保存累计梯度和游标。先写临时文件并fsync，再原子发布，旧状态不覆盖。检查点放在数据盘的独立恢复缓存目录，不提交git。
- 一次最多两组训练worker，外层梯度保持单路。两组失败处理独立：一组错误不会再主动杀掉健康的另一组。
- 启动训练需要至少60 GiB空闲显存；运行中在已保存边界检查可供本进程使用的显存容量，不足则等待。共享GPU仍可能在一次计算过程中被其他进程占用，因此这不是硬件独占保证。
- 最终生成使用更保守的72 GiB容量门槛，辅助采样仅借用满足72 GiB空闲门槛且未被本恢复流程租用的卡。可用资源不足时会等待，不能把训练结束时间当作GPU最终释放时间。
- 不停止、驱逐或修改其他用户的GPU进程，不修改服务器全局GPU计算模式。
