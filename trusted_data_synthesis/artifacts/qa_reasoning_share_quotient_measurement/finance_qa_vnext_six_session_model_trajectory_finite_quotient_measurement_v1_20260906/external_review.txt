# 一、本轮实验审计

## 1. 当前声明：接入机制完成与模型成功率必须分别判断

本轮检验的是：

> 在固定任务、公开信息、工具和协议下，真实模型能否自行提交 Action、显式 Observation Update 和 Final，且 Host 不代替它选择语义内容或修复输出？

报告明确：六会话不必全部成功，也不要求两种支持方式同时出现；完整记录的模型失败可以被接受为实验结果，自动补齐 Claim、隐式重写响应或丢失失败证据才是接入机制缺陷。

本轮实际测试条件是新登记的 `deepseek-v4-pro`、`thinking=disabled`、temperature 为 0.7，以及每会话 3 Action、3 Update、12 Submission 的有限协议。**结果只归属于这一明确条件，不能直接并入其他模型、Thinking 配置或旧主链的能力结果。** 

这里有三个不同判断：

$$
\text{证据完整}
\neq
\text{Host 正确处理协议}
\neq
\text{模型完成 Qualified 会话}.
$$

本轮分别得到六会话证据完整、六会话 `protocol-valid`、五会话 Qualified，三者并不矛盾。

## 2. 实现状态：模型提交、Host 执行和反馈后的新提交分开了

### 2.1 适配器没有替模型生成语义内容

请求由当前 `request_for(State)` 确定性呈现；模型必须自行提交操作、输入角色、parameters、public basis、完整 proposed Claim 及 Final 引用。

适配器不移除围栏、不抽取 JSON 子串、不填默认 operand、不补 Claim 或 citations。每次调用先保存请求及 attempt reservation，再进行一次实际 HTTP 请求；没有自动重试、模型回退或 fixture 替代。 

本轮所有 51 条公开响应均通过严格 Schema，原始公开 JSON 得以保存；其中 18 条仍未通过语义准入。因而，这些具体语义错误能够根据保存的公开提交复查，不只是接收端的一条错误标签。

### 2.2 accepted Claim 确实来自新的模型 Update

14 个在线 accepted Claim，均在新的模型回调提交完整命题后产生。Action 执行本身没有自动接受 Observation。

模型随后补足依据、修改 proposed value 或修正 citations，属于**后续新的模型提交**；旧错误响应和拒绝记录仍然保留。这与“Host 在原响应上直接修复”有本质区别。 

不过，当前 Update 仍是对完整 Observation 命题的接受／拒绝，不是任意新命题推导、部分接受或旧 Claim 修订。本轮也没有真实模型 `reject` 提交。**公开反馈后的纠正提交已经被观察到，一般推理修订能力仍未被测量。** 

### 2.3 本地控制和正式模型分母没有混用

两个完整 mock 分别验证了直接路线，以及实际 reject commit 后转向披露总额的路线。非法 JSON 控制只运行一轮，未终止，因此完整会话判断保持 UNKNOWN；这不妨碍其单轮失败接缝检查通过。

这些 mock 结果没有进入模型成功分子或六会话分母。真实模型没有提交 reject，因此本轮拒绝 Observation 的完整运行见证仍只来自 mock。

**G1 接受的是对应控制的限定声明，不是把四个控制都说成完整成功会话。**当前没有发现这一层的解释矛盾。

## 3. 直接反例与计数核对

### 3.1 逐会话结果与汇总一致

根据报告中的逐轮说明，本次重建得到：

| 会话     |   实际调用 | 准入 Action / Update / Final |  被拒绝提交 | 终局                   |
| ------ | -----: | -------------------------: | -----: | -------------------- |
| M01    |     12 |                  3 / 3 / 0 |      6 | 提交预算耗尽               |
| M02    |      7 |                  2 / 2 / 1 |      2 | Qualified，披露总额       |
| M03    |     12 |                  3 / 3 / 1 |      5 | Qualified，重建总额 Claim |
| M04    |      6 |                  2 / 2 / 1 |      1 | Qualified，披露总额       |
| M05    |      9 |                  2 / 2 / 1 |      4 | Qualified，披露总额       |
| M06    |      5 |                  2 / 2 / 1 |      0 | Qualified，披露总额       |
| **合计** | **51** |            **14 / 14 / 5** | **18** | **5 成功、1 失败**        |

计数来源与逐轮说明一致；只有 M06 是无准入拒绝的完整过程，不能把其余成功会话解释成首次提交始终正确。

阶段分母也闭合：

$$
20\text{ 次 Action 提交}
+22\text{ 次 Update 提交}
+9\text{ 次 Final 提交}
=51,
$$

$$
14+14+5=33\text{ 次准入},
\qquad
51-33=18\text{ 次拒绝}.
$$

这与报告的 `29/29` action-or-final Schema 通过、`22/22` Update Schema 通过相容。**29 个 action-or-final 请求不是 29 次 Action。**

### 3.2 M01 是真实端到端失败，不是缺失证据，也不是 QA 错答案

M01 在第十二次回调才成功接受 percent Claim，此时提交预算已经耗尽，没有剩余合法 Final。即使最终 State 已有三个 accepted Claim，也不能替代模型尚未提交并通过验证的 Final。

因此：

```text
evidence_complete = true
protocol_valid    = true
QA                = null
Y                 = 0
```

是合理的分层结果。`QA=null` 表示有效 Final 检查未到达，不表示这个完整会话不能进入端到端成功率分母。

所以本轮主结果应继续保持：

$$
\widehat q_{\mathrm{public\ protocol}}
=\frac{5}{6}\approx83.33\%.
$$

不能改成 5/5，也不能因为共有 51 次调用，就把会话成功率的分母改为 51。报告没有犯这两类错误。

同时，**“再给 M01 一次调用就一定成功”仍然没有证据**。只能说它在结束时还需要一次合法 Final；不能用假想续跑回填历史结果。

### 3.3 主要错误不是 JSON 格式，而是公开命题和实际支持的对齐

18 次拒绝可以准确拆为：

| 拒绝类型                               | 次数 | 本轮实际含义                                |
| ---------------------------------- | -: | ------------------------------------- |
| `admission.public_basis`           |  6 | basis 没有准确覆盖实际 inputs、Claim 和 lineage |
| `admission.observed_claim_content` |  8 | proposed Claim 与完整 Observation 内容不一致  |
| `admission.final_grounding`        |  3 | Final 引用了不属于实际完成依据的 Evidence          |
| `admission.final_percent_claim`    |  1 | Final 引用的不是已接受 percent Claim          |

其中八次 Claim 内容拒绝，都涉及把中间 percent Observation 提前写成六位 Final 表示；七次仅 value 不同，另一次还改变了 definition。 

因此，本轮支持的定位是：

> 模型能够产生要求的 JSON 结构，但在“完整已观测命题”与“最终答案表示”、以及“可见证据”与“实际使用依据”之间仍有提交错误。

不能将它扩大成模型不会计算占比，也不能将重复的八次 Update 错误当作八个独立任务失败。

对 M01 而言，首个实际被拒绝的环节是第三次回调的 `public_basis`。但这只是该会话的首个失败位置，**不是整个研究链必须停下、先把所有会话都调成成功的全局 Gate**。

### 3.4 算术与资源汇总无内部矛盾

本次按冻结的 Decimal 规则复算得到：

$$
100\frac{20397}{21813}
=
93.508458258836473662494842525099711181405583826159,
$$

最终量化为：

$$

$$

它同时解释了：完整 Observation 命题应保留上述值，而最终 answer 可以采用六位表示。不能因为两者面向同一数值任务，就在 Update 阶段事后放宽合同。

用量核对为：

$$

$$

$$
51\times74752=3812352.
$$

前者是报告实际 usage，后者是发送前预留 allowance，二者没有混同。`reasoning_tokens` 缺失保持 null，也没有被包装为实测零。模型字符串和 fingerprint 只作为实际接收元数据，不被当作远端权重不可变证明。

## 5. 当前允许的科学结论

现在可以明确保留：

**第一，公开协议的真实模型可达性已经有正向见证。**不再只是“适配器预计能接入”或“fixture 可以生成”。

**第二，两种实际依据使用都有完整模型会话支持。**M03 的有效 Final 沿 accepted percent Claim、ratio execution 回溯到重建总额 Claim；其他四个成功会话最终依赖披露总额。M01虽然也重建并消费了总额，但没有有效 Final，不能补计为第二个重建成功。

**第三，正式商状态及其经验分布仍未测量。**`disclosed_total` 和 `reconstructed_total_claim` 是实际支持描述，不是自动继承的旧 D/S 商 ID。本轮将新类数和类概率保持 null 是正确的。

由此，当前研究位置应更新为：

$$
\boxed{
\text{真实模型公开行为已观察}
\;\longrightarrow\;
\text{真实模型轨迹的商身份尚待落实}
}
$$

而不是仍停留在“模型能否提交协议”的问题上。

# 二、后续实验：冻结六会话的有限商映射与经验测量

以下是本次提出的方案，**不是本轮已完成结果**。

建议阶段名称：

```text
finance_qa_vnext_six_session_model_trajectory_
finite_quotient_measurement_only
```

**范围：零 Provider，使用现有六会话；对五条 Qualified 轨迹建立有限语义投影和 Assignment，同时保留 M01 的完整失败分母。**

这不是再审计一次在线执行，而是把现有真实行为变成 VTDO 所需要的测量对象。

## 1. 为什么优先做这一项，而不是继续优化提示词？

当前已经有五条有效轨迹和两种实际支持使用方式。先追求 6/6，会把下一步变成局部接口成功率优化；即使成功率更高，仍没有回答：

> 哪些完整行为属于同一个 \(z\)，哪些差异只是接口纠正，最终统计的条件分布又是什么？

反过来，**并不需要所有生成都成功，才能在完整、可判定的执行总体中测量有效轨迹的条件分布。**Validity 负责准入有效轨迹，失败保留在成功率分母；二者可以同时成立。

下一轮应固定当前任务、生成条件和历史记录，不同时改 Prompt、Update 语义、预算或模型。否则新增行为变化和测量规则变化会混在一起。

## 2. 固定输入：六个 Outcome，五个待映射对象，十个同任务配对

建议使用以下精确输入域：

| 输入对象               | 数量 | 用途          |
| ------------------ | -: | ----------- |
| 本轮完整会话             |  6 | 保持端到端分母     |
| 原始公开提交             | 51 | 保留真实交互及拒绝历史 |
| Qualified 会话       |  5 | 有效商映射的候选域   |
| 非 Qualified 会话 M01 |  1 | 失败记录，不进入有效类 |
| 五条有效轨迹的无序配对        | 10 | 有限等价／差异检查   |

$$
\binom{5}{2}=10.
$$

M01不能因为拥有最终 percent Claim 就获得有效 Assignment；也不能在测量阶段由 Host 补一个 Final。

旧确定性 D/S 证据可以作为规则解释或回归依据读取，但**不进入这六会话的经验分母，也不通过名称直接给新轨迹贴旧 State ID**。

这里复用已有资格与独立验证证据，不要求重新进行来源扫描、模型执行或整套适配器安全审计。

## 3. 本轮最关键的设计问题：纠正历史怎样进入商表示？

五条成功模型轨迹与旧的干净 D/S fixture 不同：四条经历过被 Host 拒绝后的新提交。不能直接：

```text
删除所有拒绝记录
→ 只看最后分母
→ 输出两个类
```

也不能反过来：

```text
每多一次接口拒绝
→ 多一个新解决策略
```

已有设计要求保留实际支持、类型化依据、推导依赖和**有意义的拒绝／修订因果关系**；同时也要求归并偶然身份、措辞和合法操作性变化。

建议在新测量合同中明确分开三种记录：

| 层次      | 保留什么                                                      |
| ------- | --------------------------------------------------------- |
| 原始交互轨迹  | 每次模型提交、Receipt、拒绝、反馈、计数、预算与真实顺序，全部保留                      |
| 任务解决行为图 | 实际执行、accepted Claim、支持使用边、依据、Observation／Update及需要保留的语义变化 |
| 协议纠正记录  | 未获准提交的错误类型、纠正次数及其预算影响，不自动当作新的任务解决策略                       |

这项分层是**后续测量设计**，不能被描述成本轮已经实施的投影。

### 建议的有限判定原则

**未获准提交不是成功完成的 Action 或 accepted Claim。**例如 M03 提交过六位 proposed value，并不意味着系统曾接受该值后又修订；实际发生的是接受请求被拒绝，pending Observation 保持等待。

**仅与现有公开约束对齐的接口纠正，可以在新合同中明确作为非分类信息，但必须保留原始证据。**适用前提应逐项检查：没有新增工具事实，没有改变已接受命题，没有发生需要保留的任务依据切换，最终实际行为图也未被改写。

**真实依据、执行或知识状态的变化必须保留。**若拒绝促成了不同实际支持选择、已接受 Claim 的撤销、重新验证或下游依赖改变，就不能当成纯格式修正删掉。

**预算影响不因商归并而消失。**即使某些接口纠正不决定 \(z\)，它们仍然影响固定生成条件下的成功率和成本。M01的预算失败不能因为“与某成功路线具有类似算术结构”而被消去。

对无法按当前规则解释的情况，返回 `undetermined`。**不能为了得到预期的两个类，事后决定哪些错误重要、哪些不重要。**

由于这些轨迹已经被观察过，下一轮应准确称为“已知模型轨迹上的测量规则实例化”，不是数据盲确认。

## 4. 投影对象：不能只比较最终答案或分母标签

每条有效轨迹至少需要从实际工件恢复：

```text
精确 Task 与验证合同
实际使用的 Evidence、来源、角色与关系
行动前 public basis
实际 Operation 及有序 operands
Observation 与 accepted Claim 的内容、grounding
Claim 的生产—消费依赖
显式 Update 与 Final 的关系
协议拒绝／纠正及其被保留或归约的依据
最终答案、引用与终止语义
```

其中，M03 的核心区别必须仍然可见：

$$
E_F,E_O,E_{\mathrm{relation}}
\rightarrow
\mathrm{relation\_sum}
\rightarrow
C_T
\rightarrow
\mathrm{share\_ratio}.
$$

直接路线则是：

$$
E_T\rightarrow\mathrm{share\_ratio}.
$$

这不是一个可以仅靠 ID 重命名消除的来源差异；但它也不能代替对其余完整公开行为的检查。

新投影可以复用旧的注册 Operation、透明转发和精确数值规则，但不能假定旧投影器天然理解新的模型提交、Update 和拒绝事件。需要的只是**当前有限事件类型的解释**，不是一次性完成通用 Mapper。

## 5. 十个配对的结果与 Assignment

建议每个配对只返回三种结果：

```text
equivalent
different_retained_semantics
undetermined
```

等价结果需要提供语义标签保持的对应；差异结果需要指出实际保留语义上的差异；未知需要给出具体缺失解释，而不是拿不同图哈希代替结论。

通过有限关系一致性检查后，再产生：

$$
z_j=\phi_{x,\Omega,\Gamma,R}(\tau_j).
$$

这里显式绑定：

* 固定任务及验证语义；
* 当前协议和生成条件；
* 新测量规则版本；
* 实际轨迹与其资格证据。

**不以“正好两个类”为通过条件。**四条直接路线是否归并，需要依据它们的实际图和纠正规则决定；不能因最终支持描述相同就直接归并。反过来，也不能仅因错误次数不同就把它们分成四类。

若比较器把披露总额与真实分项重建的保留依据全部抹平，应先检查它是否违反当前语义保留要求，而不是把这一结果立即解释成模型没有多样性。

## 6. 完成映射后，才物化有限经验分布

设五条 Qualified 轨迹均已完成映射，状态 \(z\) 的计数为：

$$
n_z
=
\sum_{j=1}^{6}
\mathbf 1\{Y_j=1,\phi(\tau_j)=z\}.
$$

则应该同时报告三个不同对象：

### 端到端成功比例

$$
\widehat q=\frac56.
$$

保留全部六个会话，包括 M01。

### 各有效状态的联合出现频率

$$
\widehat u(z\mid x,\Gamma)=\frac{n_z}{6},
\qquad
\sum_z\widehat u(z\mid x,\Gamma)=\frac56.
$$

剩余的 \(1/6\) 对应未形成 Qualified 终局的会话，不是一个可进入 VTDO 有效支持的状态。

### 成功条件下的经验商分布

$$
\widehat\pi_{\mathrm{gen}}(z\mid x,\Gamma,Y=1)
=
\frac{n_z}{5}.
$$

**这是这批冻结经验数据的推前频率，不是精确总体概率，也不是训练目标分布 \(\pi_t\)。**六会话不支持忽略生成条件、时间或小样本限制的外推。

例如，只有在正式映射确实确认“四条直接路线同类、重建路线另一类”时，才可以得到：

$$
\widehat\pi_{\mathrm{gen}}=(4/5,1/5).
$$

这只是条件示例，**本次审计没有提前完成该映射或授权把当前支持标签直接升级成这一结果。**

如果五条有效轨迹中还有未映射对象，应记录：

$$
\sum_z n_z+n_{\mathrm{unmapped}}=5.
$$

不能删掉未映射对象后，按较小分母重新归一化，并仍称之为全部有效轨迹的条件分布。

## 7. 最少的控制与完成条件

新增控制只针对新测量对象：

| 控制                       | 要检验的边界            |
| ------------------------ | ----------------- |
| 一致重命名、纯标签或获准的表面变化        | 不产生伪新类            |
| 改变实际分母生产链或支持使用边          | 不因 Final 相同而被错误合并 |
| 改变有意义的 Claim／Update 因果关系 | 不能当作普通接口纠正删除      |
| M01 或未定映射被强行加入有效类／改分母    | 必须拒绝或保持未定         |

这些是隔离的测量控制，不是新的模型样本，也不重新执行金融候选。

本轮只需四类完成条件：

| 完成对象           | 判断要求                    |
| -------------- | ----------------------- |
| 精确输入总体         | 六会话完整保留，五条有效轨迹与一条失败身份不变 |
| 有限投影           | 每个保留或归约决定有实际事件和冻结规则依据   |
| 比较与 Assignment | 十个配对、等价关系和状态赋值一致；未知不被填补 |
| 经验测量           | 会话分母、有效分母、映射缺失和生成条件准确分离 |

建议新增执行预算为：

只读数值和结构复算属于验证，不应记成新增候选执行。

# 三、后续推进边界

如果下一轮在五条真实有效模型轨迹上得到完整、非退化的经验商分区，那么科学证据将推进到：

> 固定任务与生成条件下，真实模型已经产生多个有效商状态，并且这批执行的成功率与成功条件分布可以被明确测量。

这仍不等于 Contribution 已获得授权，更不等于应把经验频率直接设为最优训练权重。覆盖先验 \(r\)、Contribution、类内物化规则及 Student 比较仍是后面的不同对象。

如果投影在某类纠正事件上未定，就只修复该具体测量解释；**不重新扫描来源，不重跑六会话，不返回整套 callback 身份审计。**

本轮观察到的 basis、精度表示和 citations 问题值得后续做受控协议实验，但它们不应现在与商映射同时改变。否则，无法分清是生成分布变了，还是状态定义变了。
