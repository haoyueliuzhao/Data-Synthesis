# v26.176 修订报告联合审计结论

## 一、最终判定

$$
\boxed{\text{保留并冻结 v26.176，但暂不消费当前 192-Job Runner-preflight transition}}
$$

v26.176 对上一轮发现的缺陷做出了**直接、对症且证据化的修复**。特别是，它没有只修改 Validator 后宣布通过，而是先让冻结的 v26.175 Validator 实际接受此前遗漏的 10 个完整重哈希替代图，再建立新的权威父对象重建、192 次 fresh replay、44 个破坏性攻击、全六 Replica 组合审计和模型可见 rejection history。 

因此，上一轮的核心 P0：

```text
Development / Runner authoritative parent reconstruction 不完整
```

在**报告所记录的证据层面**已经被实质关闭。

但新的第一个根本阻塞点是：

```text
typed-rejection history 只在 Failure Recovery 分母上闭合，
尚未覆盖 production classifier 的全部 typed state-precondition rejection kinds；
同时，新加入模型可见 Prompt 的 feedback 是否为严格 public-only projection，
在缺少 v26.176 源码的情况下仍为 unknown。
```

整体判定如下：

| 理论对象                                 | 判定                      |
| ------------------------------------ | ----------------------- |
| v26.175 历史工件冻结与重建                    | 报告通过                    |
| 10 个旧 Validator 绕过的实际复现              | 报告通过                    |
| Development / Runner 权威父对象重建         | **报告层通过，源码层未独立验证**      |
| 192 个六 Replica baseline fresh replay | **报告层通过，源码层未独立验证**      |
| 44 个完整重哈希攻击                          | 报告通过                    |
| 772 组合 × 6 Replica                   | 报告通过                    |
| Failure Recovery rejection history   | 报告通过                    |
| 所有 production typed-rejection kinds  | **证据分母不完整**             |
| 模型可见 feedback 的 public-only 性质       | **unknown，fail-closed** |
| one-correction 完整分支矩阵                | **不完整**                 |

# 四、新 P0：typed-rejection 控制没有覆盖完整 production rejection surface

## 1. 报告中的一般命题比实际分母更宽

v26.176 对 Runtime 的描述使用：

```text
On a typed State-precondition rejection ...
```

并声称 rejection 会：

1.执行 production classifier；
2.产生 public Observation；
3.持久化 Acceptance 和 feedback；
4.保持同一 target Component；
5.让下一 Prompt 绑定 rejection history；
6.在第二次错误后阻止第三 Prompt。

但实际 corrected 与 repeated-wrong 控制的分母明确是：

```text
20 Failure Recovery Components × 6 Replicas
```

其错误 Action 固定为：

```text
wrong current-Rule Action
```



冻结的 production acceptance classifier 不只对 `revise_selector` 定义状态前置条件，还包含：

```text
reconcile_record
consume_normalized_output
assess_dynamic_readiness
```

即 Semantic Reconciliation 和 State-dependent Stopping 也存在独立的 state-precondition 判定分支。

因此，当前证据链实际达到的是：

$$
\boxed{
\text{Failure-Recovery wrong-current-rule rejection-history closure}
}
$$

而不是：

$$
\boxed{
\text{complete production typed-rejection-history closure}
}
$$

这不是在断言其他分支的实现一定失败，而是说明：**其他生产分支尚未进入正式验证分母。** 按 fail-closed 原则，通用代码路径不能由单一 Decision-family 的测试替代。

---

## 2. 下一 Gate 必须按 rejection kind 分层

至少应冻结：

```text
(
  capability_family,
  decision_kind,
  rejection_code,
  choice_count,
  Replica,
  correction_disposition
)
```

并对每个 production classifier 可达的 typed rejection kind 验证：

```text
initial rejection is public and content-addressed
same target Component remains current
next Prompt binds the exact public feedback
accepted correction commits exactly once
second invalid response terminalizes before a third Prompt
Retry / Tool / Component advancement remain zero where required
final or terminal artifact binds the complete rejection lineage
```

若某个生产分支在当前 32-Package Catalog 中不可达，也必须形成显式的：

```text
registered_but_unreachable
```

证据，而不能从分母中静默消失。

# 五、P0-unknown：模型可见 Feedback 是否严格 public-only 尚未证明

报告称 feedback 绑定：

```text
rejected Action ID
displayed Choice
selected Operation hash
rejection code
Observation Receipt
Acceptance report
predecessor feedback
correction attempt index
correction bound
```



但冻结的 v26.175 `ActionAcceptanceReport` 包含：

```text
package_id
component_key
source_choice_handle
selected_operation_hash
failure_receipt_id
publicly_grounded
publicly_executable
state_precondition_valid
mechanism_relevant
...
```

因此，必须区分以下三种实现：

```text
A. Prompt 中包含完整 ActionAcceptanceReport
B. Prompt 中只包含 acceptance_report_id
C. Host report 经独立强类型 PublicTypedRejectionFeedback 投影后进入 Prompt
```

其中：

* A 可能直接暴露 Host-side source parent；
* B 仍可能形成隐藏父对象的内容寻址伪名；
* C 才是可以直接审计的 public/Host separation。

当前报告没有给出足够具体的模型可见 schema 来判定采用了哪一种。

报告的 hidden-parent scan 检查的是 Schedule ID、seed、nonce、source Package artifact、reference handle/path 和 Replica metadata 的 exact key/value 暴露。

这不能自动排除：

```text
hash(hidden_parent)
content-addressed report ID whose preimage contains Host-only fields
stable pseudonym derived from source_choice_handle
```

这是一个**未决风险而非已证实泄漏**。但在新对象直接进入模型 Prompt 的情况下，`unknown` 必须 fail-closed。

建议将模型可见对象收缩为：

```text
PublicTypedRejectionFeedback
  public_rejected_action_id
  public_displayed_choice_handle
  public_rejection_code
  public_observation_receipt_id
  correction_attempt_index
  correction_attempt_bound
  predecessor_public_feedback_id | null
```

并明确禁止：

```text
package_id
component_key
source_choice_handle
source Operation hash
reference handle/path
Schedule identity/seed/nonce
ActionAcceptanceReport object
ActionAcceptanceReport identity
任何 preimage 含 Host-only 字段的内容地址
```

完整 Acceptance report 可以保留为 Host 审计父对象，但必须通过独立、可重建的 public projection 才能进入下一 Prompt。

# 六、one-correction bound 的分支矩阵仍不完整

当前报告证明了：

```text
wrong A -> reference-valid correction -> Qualified
wrong A -> same wrong A -> typed terminal -> no third Prompt
```



尚未得到证据支持的是：

```text
wrong A -> valid nonreference B
wrong A -> different invalid B
wrong A -> stale action ID
wrong A -> foreign current-State action ID
wrong A -> malformed but ABI-valid action reference
```

这里最关键的是：

```text
wrong A -> different invalid B
```

报告的 terminal 条件被描述为“repeats a typed-rejected Action”。如果实现仅检测“重复同一个 Action”，而不是检测“第二次 correction attempt 仍然 typed-invalid”，那么不同的错误 B 可能生成第二个 feedback，并出现第三 Prompt。

下一控制矩阵应固定为：

| 第二响应               | 必须得到的结果                                             |
| ------------------ | --------------------------------------------------- |
| reference-valid    | commit exactly once，继续 ordinary suffix              |
| nonreference-valid | 按同一 public semantics 接受，不得因非 reference 被拒绝          |
| same-invalid       | typed terminal，no third Prompt                      |
| different-invalid  | typed terminal，no third Prompt                      |
| stale/foreign      | 明确 typed 或 ABI terminal，不得进入 Runtime exception loop |

# 七、正向 correction 只使用 reference Action

120 条成功恢复路径全部采用：

```text
public-only corrected reference Action
```



这证明 reference correction 可恢复，但不能证明 feedback-parented Prompt 保持了合法 nonreference 行为。

只要 reached State 中存在 Base-valid 或 Qualified-valid 的 nonreference Choice，就应执行：

```text
wrong
-> visible feedback
-> valid nonreference correction
```

并将其与“没有先发生 rejection、直接选择同一 source Choice”的结果比较：

```text
Action acceptance
public effects
Base validity
Mechanism qualification
Qualified validity
```

否则 correction channel 可能在工程上退化为 reference-imitation channel，而当前测试无法发现。

# 八、下一 Runner preflight 必须分离首次能力与纠错后能力

引入一次模型可见 correction 后，实验条件已经发生实质变化。后继 192-Job outcome Contract 至少应分别保存：

```text
first_response_abi_valid
first_action_state_precondition_valid
first_action_accepted
first_attempt_base_valid
first_attempt_mechanism_qualified
first_attempt_qualified_valid

correction_invoked
correction_feedback_id
corrected_action_accepted
correction_terminal_reason

final_base_valid
final_mechanism_qualified
final_qualified_valid
```

并分别报告：

$$
\hat q_{\text{first}}
$$

与

$$
\hat q_{\text{bounded-correction}}.
$$

“最终经一次纠错 Qualified”不能覆盖“第一次无法选择合法 Action”。否则将把：

```text
current-State 首次可读性
错误识别后的恢复能力
```

折叠成一个最终成功率，进而破坏 Capability Depth 的解释。
