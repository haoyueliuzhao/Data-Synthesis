## 三、实现状态

### 1. 补集现在确实由实际 Registry 派生

构造逻辑已经变为：

```python
reachable = {
    policy.terminal_kind
    for policy in registry.policies
    if policy.registration_status == "reachable"
}

admitted = {"instrument_failure"}
forbidden = tuple(sorted(reachable - admitted))
```

并要求：

```text
admitted ∪ forbidden = exact reachable set
admitted ∩ forbidden = ∅
reachable / admitted / forbidden = 16 / 1 / 15
```



提交源码中的 `_complement_binding` 确实从解析后的 `FreshTerminalRegistry` 读取全部 reachable `(terminal_kind, policy_id)`，再从 v26.217 的实际 admitted mapping 推导 singleton 和补集，而没有继续调用旧的 `FORBIDDEN_UPSTREAM_TERMINALS` 手写常量。

### 2. 不只是构造正确，运行时 admission 也独立重算

`ExactRegistryComplementAuthority.admit(candidate)` 会：

* 重新验证 candidate；
* 从持有的实际 Registry 对象重新提取 reachable terminal-policy pairs；
* 重新计算 `actual_kinds - admitted`；
* 比较 Registry identity；
* 比较全部 terminal-policy pairs；
* 比较精确 forbidden complement；
* 检查 union 与 intersection；
* 要求 candidate 与预期 Binding 字节完全一致。

因此，长度为 15 或重新计算 content ID 本身不再足以获得授权。

### 3. 正式产物中的集合已经正确

实际持久化的 `exact_registry_complement_binding.json` 包含：

```text
reachable = 16
admitted  = {instrument_failure}
forbidden = 15
```

其中正确包含：

```text
provider_failure_no_payload
resource_budget_exhausted
```

并且不再包含两个旧拼写。正式产物还保存了全部十六个 terminal-policy pairs，而不仅是一组名称。

这直接关闭了上一轮的阻塞点。

## 五、关于 lifetime adapter

v26.218 新增了一个很窄的 `LifetimeStableSourceExitProofAuthority`，用于保留已经记录的 Python exception objects，避免 v26.217 使用 `id(error)` 作为进程内键时因对象释放和地址复用产生非确定性重复。

该 adapter：

* 只包围 retained v26.217 consumer 调用；
* 在 `finally` 中恢复原类；
* 不改变 exception、Event、Observation、proof、decision 或持久化字节；
* 最终生成的 35 个 retained runtime files 与 v26.217 保持字节一致。



这是一个已披露的本地重放稳定化措施，不构成本轮语义范围扩张，也不推翻 Registry-complement 修复。
