# 二、现在真正需要检验的理论命题

当前首个根本阻塞点已经不在证据持久化、Outcome 父绑定或 estimator exact-set，而在：

```text
model-visible first-response Action interface
```

现有证据表明：

* parser 要求 `action_id / decision_kind / protocol / state_id` 四个字段；
* 当前 `response_abi` 没有直接包含 `action_id`，却包含了额外的 `grammar_id`；
* `action_id` 位于 Candidate 行；
* `answer_fields` 和 `operator_output_fields` 作为竞争输出 Schema 出现在同一个 user message 中；
* 167/188 个公开响应恰好匹配这些 Answer/Operation Schema，而不是 Action ABI。

因此当前可支持的是：

```text
结构性 Prompt-interface ambiguity 已被确认
```

还不能支持：

```text
该结构性歧义因果导致了 188 个非 ABI 响应
```

下一实验应当直接检验这个因果缺口，而不是继续审计历史证据链，也不是立即重跑 192 Jobs。

## 1. 要检验的命题

在冻结任务、状态、Candidate、模型、Thinking、采样策略、资源界限、Action parser 和 Runtime 语义的情况下，只改变模型可见的响应接口：

> 将分散且相互竞争的输出说明，改为一个唯一、连续、权威、与 parser 完全同构的四字段 Action 合同，是否会提高首响应 Action-ABI crossing？

对于第 \(i\) 个配对 source cell，定义：

$$
Y_i^{C}
=
\mathbf 1[
\text{control response crosses exact Action ABI}
]
$$

$$
Y_i^{R}
=
\mathbf 1[
\text{repaired response crosses exact Action ABI}
]
$$

主要有限总体 estimand 为：

$$
\Delta_{\mathrm{ABI}}
=
\frac{1}{12}
\sum_{i=1}^{12}
\left(
Y_i^{R}-Y_i^{C}
\right)
$$

进一步定义：

$$
A_i^a
=
Y_i^a
\cdot
\mathbf 1[\text{action reference valid}]
\cdot
\mathbf 1[\text{state binding valid}]
$$

用于衡量是否真正得到一个 model-owned、当前状态可接受的首个 Action。

这不是 `q_first`，也不是 Capability estimate；它只是一个独立的 **Action-interface calibration estimand**。

## 2. 两个实验臂

为了避免过度实验，建议只做一个配对两臂实验，不再拆成多因素四臂设计。

| 实验臂                                | 模型可见接口                         | 用途                      |
| ---------------------------------- | ------------------------------ | ----------------------- |
| `C`：contemporaneous control        | 精确复现所选 v26.200 first Prompt 接口 | 控制 Provider 时间变化和模型服务漂移 |
| `R`：disambiguated Action interface | 唯一、连续、四字段 Action 合同            | 检验完整接口修复包的因果效果          |

### Control 臂

Control 使用所选 source Jobs 的历史 first Prompt 字节：

```text
one user message
old response_abi
action_id outside response_abi
visible answer_fields
visible operator_output_fields
```

但必须创建 fresh calibration Job 和 fresh persistence namespaces。它是**同期复现对照**，不是 v26.200 Job rerun、Recovery 或旧分母替换。

### Repair 臂

Repair 臂只允许改变模型可见输出接口：

```text
system message:
  exact Action response contract

user message:
  exact frozen task
  exact current public State
  exact Candidate set and order
  exact Schedule and task semantics
```

系统消息中的响应对象必须由实际 Action parser/Grammar 自动编译，而不是手写：

```json
{
  "action_id": "<one exact current Candidate action_id>",
  "decision_kind": "<exact grammar-defined value>",
  "protocol": "<exact grammar-defined value>",
  "state_id": "<exact current state_id>"
}
```

必须同时满足：

```text
required fields                 exactly 4
allowed fields                  exactly 4
additional properties           forbidden
grammar_id                      Host-side parent only
parser                          unchanged
Candidate action IDs            unchanged
current state_id                unchanged
```

`answer_fields` 和 `operator_output_fields` 不删除其语义内容，但应移动或标记为：

```text
verifier/internal task metadata
not a model response schema
```

旧的、缺少 `action_id` 的 `response_abi` 不得继续作为第二个响应合同留在 user message 中。

需要明确记录：这是一个**复合接口修复包**。实验通过后，可以声称整个修复包对 ABI crossing 有因果效果，但不能进一步声称究竟是 system role、四字段连续呈现还是竞争 Schema 标记中的哪一项单独起作用。当前没有必要为拆解这些子机制再增加实验臂。

## 4. 在线执行协议

在线阶段建议命名为：

```text
fresh_first_response_action_interface_disambiguation_
paired_24_call_online_calibration_only
```

执行规则：

1. 每个 Job 只调用一次 Stage 1。
2. 收到第一响应后立即停止，不发 Correction，不继续 Program，不请求 Final。
3. 对合法响应仅执行本地：

   * JSON/ABI parse；
   * Action reference validation；
   * state binding validation；
   * 可选的一次本地 `Runtime.step` 可提交性检查。
4. 不因为 ABI 失败、Thinking exhaustion 或其他 typed terminal 重试。
5. C/R 调用顺序根据 source cell ID 的哈希交错：

   * 一半 `C -> R`；
   * 一半 `R -> C`。
6. 所有 typed Provider、Transport、Privacy、Resource、Thinking、Usage 失败保留在原 arm 的完整分母内。

这样既能控制短时服务漂移，又不会把实验扩大成一次缩小版 Capability run。
