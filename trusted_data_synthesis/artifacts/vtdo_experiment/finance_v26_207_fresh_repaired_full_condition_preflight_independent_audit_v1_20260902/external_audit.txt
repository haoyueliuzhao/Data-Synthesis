## 一、本轮修订解决了正确的问题

v26.206 没有尝试直接把 v26.204 的 `11/12` 校准结果推广为完整 Capability，而是完成了从局部接口校准到完整实验条件之间的工程桥接：

```text
v26.194 frozen semantic condition
+ v26.193 registered callsite coordinates
+ v26.203 repaired Action Contract
-> fresh repaired full-condition identities
-> full callsite projection
-> scripted Runtime integration
-> prospective estimand contract
```

它保留了原来的 32 Packages、6 Replicas 和 192 个语义 Jobs，只修改 prospective Action-interface projection，并为 Package、Job、Manifest、Runner、Execution Contract、Prompt、Request 与证据链重新建立 fresh identities。没有复用 v26.200 或 v26.204 的 Job、Raw、Result、Prompt 或 request identity。 

这符合实验身份原则：**语义 source population 保持相等，但实验条件因为接口变化而获得全新身份**。

Repair 不再只覆盖 first Action，而是覆盖：

```text

```

每个当前 State 都重新编译准确的：

```text

```

Final interface 保持冻结；Parser 没有放宽；历史 response 没有被适配；旧的 `response_abi` 不再与完整四字段 Contract 竞争；Answer 和 Operation-output schemas 仍保留其任务语义，但被明确标记为非模型响应 Schema。

这说明 v26.206 不是通过“接受更多错误格式”来提高通过率，而是把已由 v26.204 支持的复合接口修复正确投影到后续 Action 和 Correction 阶段。

## 四、失败路径与 estimand 定义基本正确

五个最小失败控制覆盖了当前真正需要验证的终止面：

```text
invalid first Action ABI     -> first_response_abi_invalid
unknown current Action       -> first_action_reference_invalid
invalid Correction ABI       -> correction_response_abi_invalid
invalid Final ABI            -> final_response_abi_invalid
typed outer failure          -> instrument_failure
```

每个控制都产生一个 typed Outcome、没有异常逃逸、不调用任务 Verifier，并且不混入 192-Job scripted denominator 或未来 empirical denominator。该控制集合已经足够，不需要在本轮继续扩展为大型攻击矩阵。

未来 estimand 也已被正确区分：

$$
q_{\mathrm{first}}^R
=
\frac{
\#\{\text{zero-Component-Correction 且最终 Qualified 的 Jobs}\}
}{
192
}
$$

$$
q_{\mathrm{bounded\ correction}}^R
=
\frac{
\#\{\text{每个 reached Component 至多一次 Correction 且最终 Qualified 的 Jobs}\}
}{
192
}
$$

Pre-ABI terminal 与 outer terminal 都保留在 192-Job denominator 中；只有 post-ABI conditional quantity 在其条件分母为零时保持 null。目前 empirical rows、numerators、estimates、intervals 全部仍为零或 null，没有把 scripted success 错报成 Capability。

# 五、唯一需要在独立审计中重点确认的问题

本轮没有发现需要立即修改 v26.206 的硬错误，但 **F2 的独立证据必须进一步收紧**。

v26.206 的 792-row census 来自冻结的 reference-plus-rejection coordinates。此前 v26.193 已明确说明：

> 这 792 行不是全部 model-reachable accepted prefixes 的穷举；未来状态的路由总量性应由 source-level no-bypass proof 提供，而不是由 792-row denominator 本身提供。

v26.206 报告声称“Every Action-producing model call”都经过修复后的 Contract，但正式报告展示的直接证据主要是：

1. 792 个注册参考坐标的重新渲染；
2. 192 条 reference trajectories；
3. 120 条已注册 typed-rejection branches。

这些足以证明**注册参考表面的集成闭合**，但不能单独证明模型选择另一合法 Action、进入另一 accepted-prefix State 后，也一定无法绕过 repaired renderer 或动态 Contract compiler。

因此，F2 当前应解释为：

```text
repaired registered-callsite surface       PASS
fresh Runner source-level no-bypass        PENDING INDEPENDENT AUDIT
all model-reachable states enumerated       NOT CLAIMED
```

这不是要求回退或重做 v26.206。它正好应由已经授权的下一阶段独立审计解决。只要下一阶段从源码证明所有 Action/Correction Provider routes 都必须经过同一个动态 repair compiler，就可以关闭该关注点。
