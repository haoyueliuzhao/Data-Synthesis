这五项正好对应 v26.182 冻结的五个失败 Gate，没有额外改变任务、模型、Manifest 或估计语义。

### 1. Terminal validity factorization：PASS

新 `TerminalValidityEvidence` 独立保存：

```text
final_base_valid
final_mechanism_qualified
final_qualified_valid
```

并强制：

$$
V_{\text{qualified}}
=
V_{\text{base}}
\land
Q_{\text{mechanism}}
$$

两种此前丢失的合法无效状态均被保留：

```text
Base=true,  Mechanism=false, Qualified=false
Base=false, Mechanism=true,  Qualified=false
```

对应测试也明确要求重建后得到这两个不同组合，而不是统一变成 `false/false`。

### 2. Diagnostic empirical admission：PASS

生产验证入口现在明确执行：

```python
if (
    expected_evidence_kind == "empirical_execution"
    and policy.registration_status
        != contract.empirical_admissible_registration_status
):
    raise ValueError(
        "non-reachable terminal policy cannot enter empirical evidence"
    )
```

因此：

```text
policy_horizon_exhausted
measurement_support_exit
```

即使被重新标记为 empirical、重建 Result 文件并重新计算全部下游身份，也会在正式经验估计返回前被拒绝。

这里尤其值得保留 v1→v2 的处理：初版 `policy_horizon_exhausted` 在更早的 validity 检查处失败，没有真正到达目标 Admission Gate；最终提交 `0cd043...` 调整了非完成态边界验证，并新增测试，要求两个控制都必须在精确的 non-reachable admission reason 上失败。这个修订避免了“虽然拒绝了，但拒绝在错误位置”的假通过。

### 3. FailureLocus reconstruction：PASS

FailureLocus 不再作为调用者可自由附加的权威对象，而是从：

```text
canonical Raw component attempts
+
canonical Result Final-Verifier evidence
```

重新派生完整 tuple。随后生产入口比较重建的 Trace 和 Outcome row，而不是只检查传入对象内部是否自洽。

两个完整重哈希控制——向 Qualified Result 添加虚假 Base failure，以及引用 attempt trace 中不存在的 Mechanism Component——均被拒绝。

### 4. Raw/Result persisted-byte authority：PASS

新的 Descriptor 同时绑定：

```text
artifact_relative_path
artifact_sha256
artifact_byte_count
payload_id
```

Loader 要求目标是普通文件而非 symlink，读取实际字节后比较长度与 SHA-256，再解析 JSON、验证 canonical form 和 payload identity。代码中的实际字节检查已经存在：

```python
payload = path.read_bytes()
if len(payload) != expected_byte_count \
        or sha256_bytes(payload) != expected_sha256:
    raise ValueError(
        "artifact descriptor does not bind the actual file bytes"
    )
```

脚本预检实际写入并重新加载：

```text
192 Raw files
192 Result files
384 total artifact files
384 byte matches
```

Raw 和 Result 各一次文件字节替换控制均被拒绝。

### 5. Authoritative parent revalidation：PASS

入口通过 `_strict_revalidate()` 从普通 Python 数据重新验证：

```text
AuthoritativeTerminalRegistry
ArtifactBackedOutcomeContract
CapabilityDevelopmentJobManifest
Manifest 内每个 Job
JobBoundRunnerContract
每个 Evidence Bundle
```

并进一步要求 Bundle 中的 Job 必须等于 Manifest 内对应的完整 Job 对象，而不只是 Job ID 相同。

针对 Registry、Contract、Manifest、Job 和 Runner 的五个 `model_construct()` 注入控制均被拒绝；测试也明确检查五类父对象全部出现且拒绝数为 5。
