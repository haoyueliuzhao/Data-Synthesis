# 五、当前允许的科学结论

可以正式保留的结论是：

> 在冻结的 12 个分层 source cells 和精确的 24-call 配对执行上，完整的复合 Repair interface package 对首响应 exact Action-ABI instantiation 产生了超过预注册门槛的配对改善。

这已经不是单纯的 Prompt 静态分析，而是一个具有 contemporaneous Control、冻结语义父对象和独立 postrun reconstruction 的在线接口干预结果。

但结论只到这里。以下仍然没有被证明：

```text
一般性的 deepseek-v4-flash ABI 成功率为 11/12
完整 repaired condition 的 q_first = 11/12
用 v26.204 替换或合并历史 v26.200 的 0/192
任一单独 Repair 子机制的因果效果
Runtime transition 或 Program closure
Correction、Final、Base、Mechanism、Qualified
trajectory-depth Capability
Mapper、State frequency、Contribution 或 VTDO
```

报告已经正确写出了这些边界。

## 一个非强制的措辞优化

报告使用了：

> the complete Repair interface package **caused** ...

这不构成 Gate 问题，但从最严格的统计措辞看，12 个 cell 每臂只有一次随机模型调用，因此建议在后续总结中改为：

> the complete Repair interface package **produced a preregistered-threshold-exceeding paired improvement**

或：

> the result supports a package-level causal effect on the exact calibration surface

这样既保留干预性质，也避免把有限随机调用上的 realized contrast 表述成更广泛的概率因果定律。**无需修改冻结证据或重新生成 v26.205 工件。**


消费范围：

```text

integration_and_identity_preflight_only
```

v26.205 已明确规定，该阶段只能建立 fresh full-condition identity chain，并运行零凭证、零 Provider 的 scripted integration controls；完整 repaired 192-Job 在线执行仍未授权。

## 1. 冻结实验对象

以原 192 个语义 cell 作为不可变 source parents，但不得复用 v26.200 的实验身份。新建：

```text
fresh repaired Runner Packages
fresh repaired Jobs
fresh Raw / Result namespaces
fresh Manifest
fresh Runner
fresh Execution Contract
fresh request/prompt identities
fresh execution-bound Outcome chain
```

这里应区分：

* **执行条件身份必须 fresh**；
* 已经稳定的 terminal、validity 和 evidence semantics 可以作为冻结父 Contract；
* 不应仅为了版本递增而无语义地复制全部 authority semantics。

新实验是一个单独的 repaired condition，不是把 v26.204 的 12 个 Repair rows 扩写成 192 行，也不是重标历史 v26.200 Jobs。

## 2. 将 Repair 语义覆盖所有 Action-parser callsite

需要覆盖：

```text
first Action
subsequent Action
typed-rejection Correction
```

但“应用完整 Repair profile”不能理解为复用第一轮消息的固定字节。每个当前 Runtime State 都必须动态重新编译：

```text
exact current state_id
exact current Candidate action_id set
exact decision_kind
exact protocol
```

同时保持以下原则：

```text
一个连续、权威的四字段 Action response contract
grammar_id 继续保持 Host-side
Answer/Operation schemas 只能标记为 verifier metadata
不得再次成为竞争性的 model response schema
不得插入缺失字段或适配模型响应
```

Correction 可以增加拒绝原因和当前状态证据，但不能改变四字段 Action ABI。

## 3. 做全 callsite census，而不是新的模型校准

建议重新构造原注册路径对应的全部 Prompt coordinates，例如此前的：

```text
first Action
subsequent Action
typed-rejection Correction
Final
```

逐行绑定：

```text
Job
Runtime State
phase / prompt kind
Component coordinates
Candidate set and order
canonical messages
canonical request body
Repair profile identity
Parser / Grammar identity
```

目标是证明所有 Action-parser callsite 都进入同一套修复后的接口编译路径，而不是只修第一请求。

## 4. 运行 scripted full-condition integration

使用确定性的 reference Action，在 192 个新 Jobs 上走通：

```text
Action
-> State transition
-> subsequent Action
-> typed rejection where registered
-> Correction
-> terminal State
-> Final
-> independent Validity
-> Raw / Result / Trace / Outcome
```

这只是 Runtime 与证据链构造性测试，不是模型 Capability 结果。

只需额外保留少量有代表性的失败控制：

```text
invalid first Action ABI
unknown Action reference
invalid Correction ABI
invalid Final ABI
one typed outer terminal
```

没有必要再次枚举所有历史攻击类别。

## 5. 预注册未来 estimand，但不计算结果

v26.206 应冻结未来 repaired condition 的新 estimand：

$$
q_{\mathrm{first}}^{R}
=
\frac{\#\{\text{新 repaired Jobs 首策略最终 Qualified}\}}
{192}
$$

$$
q_{\mathrm{bounded\ correction}}^{R}
=
\frac{\#\{\text{新 repaired Jobs 在 correction bound 内最终 Qualified}\}}

$$

必须预先规定：

```text

pre-ABI terminal 计为 compound success = false
post-ABI conditional quantities只在条件 denominator > 0 时定义
outer terminal 不得从 denominator 排除
```

但 v26.206 的 numerator、estimate 和 confidence interval 都应保持未物化。

## 6. 最小非补偿 Gate

建议只保留六类主 Gate：

```text

```

还应确认所有 Jobs 满足冻结的 Prompt、request、Provider-call 和 token resource bounds；否则应在在线授权前暴露，而不是在执行中途发现。
