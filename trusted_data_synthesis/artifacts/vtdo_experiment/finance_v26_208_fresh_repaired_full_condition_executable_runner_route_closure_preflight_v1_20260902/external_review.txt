保存的 Census、Integration Audit、Failure Controls 与 Estimand 只在独立对象构造完成后作为比较目标，没有充当 outcome oracle。

## 二、A3 失败是真实阻塞点，不属于过度审计

v26.207 确认 v26.206 在**注册表面**上的 Repair 是完整的：

```text
repair compiler definitions                         1
callsite builder definitions                         1
request builder calls inside callsite builder        1
scripted integration callsite-builder uses           3
registered Action/Correction repaired          600 / 600
old ABI registered routes                             0
unrepaired registered routes                          0
```

但精确源码中同时存在：

```text
executable future online Runner definitions           0
injected transport seams                              0
Action transport dispatch calls                       0
Correction transport dispatch calls                   0
```

所以当前存在的是：

```text
current State
  -> repaired callsite data object
  -> scripted reference parsing
```

而不是在线执行所需的：

```text
current Runtime State
  -> repaired message compilation
  -> canonical request construction
  -> request validation/certificate
  -> injected transport seam
  -> observed model response
  -> parse / State-Candidate validation
  -> Runtime step
```

数据型 `RepairedRunnerContract` 和脚本型 `_callsite_row` 不能证明未来任意模型响应一定经过 repaired route。

这不是过度审计，原因在于它没有要求：

* 穷举所有 model-reachable States；
* 再做一轮接口因子分解；
* 再做一次 24-call calibration；
* 提前获得 Capability 结果；
* 实际调用 Provider。

它只检查了**准备进行在线实验前必须真实存在的生产调用路径**。没有该路径时，所谓 no-bypass 只能因“没有可执行路径”而真空成立；v26.207 正确拒绝了这种解释。

需要注意，问题也不是“源码中没有直接 Provider 调用”。零 Provider preflight 本就不应访问网络。真正缺少的是一个**可注入假 transport、将来可替换为真实 transport 的统一执行 seam**。

## 四、当前允许与禁止的科学结论

# 六、唯一合理的后续实验：Finance v26.208

```text

```

任何实施必须先由新的外部审计决定明确授权。

## 1. 实验问题

v26.208 只回答一个问题：

> 在不改变冻结语义条件和 repaired interface 的情况下，能否构造一个真实可执行、零 Provider 的 future Runner，使每个 Action、Correction 和 Final 请求都必须依次经过动态 State 重建、接口编译、请求构造、请求验证和唯一 injected transport seam？

这仍然是工程机制 preflight，不是模型实验。

## 2. 必须冻结的对象

保持不变：

```text
v26.194 source Tasks / Components / Candidates / Schedules
v26.194 Runtime semantics and step/finalize behavior
v26.203 exact four-field Action Contract
v26.206 Repair Profile semantics
model / Thinking / sampling / Completion bound
Action Grammar / Final Grammar
Policy / resource / correction bound
Validity semantics
192-Job denominator and thresholds
```

v26.206、v26.207 的所有正式工件保持不可变。

由于 Runner implementation 与 Execution Contract 会发生真实变化，v26.208 应创建新的：

```text
implementation binding
Runner Package identities
Development Job identities
Manifest
Runner
Execution Contract
Prompt / Request identities
Raw / Result / Trace / Outcome control namespaces
```

不能直接给 v26.206 的 Runner 对象补一个方法后继续沿用旧身份。

## 3. 最小生产路径

建议只增加一个统一的执行入口，例如概念上的：

```text
ExecutableRepairedFullConditionRunner._invoke_current_state(...)
```

所有调用必须满足：

```text
Action / Correction / Final
  -> read actual current Runtime State
  -> compile phase-specific authoritative messages
  -> build canonical request body
  -> validate request body and certificates
  -> emit pre-transport receipt
  -> exactly one injected transport seam
  -> receive public payload or typed exception
  -> privacy/persistence projection
  -> exact Parser
  -> current State and Candidate validation
  -> production Runtime step/finalize
  -> terminal dispatcher
  -> Raw -> Result -> Trace -> Outcome control chain
```

Action 与 Correction 使用 repaired four-field Contract；Final 继续使用冻结 Final Grammar，不得被误改成 Action ABI。

重要的是：**Census 和 callsite evidence 应由该可执行路径产生，而不是再由一个平行的 evidence-only builder 代替生产 Runner。**

## 4. 建议仅设置五个 Gate

不需要扩大成新一轮大型审计矩阵。

```text
R0  exact v26.207 authority/freeze and unchanged semantic condition

R1  fresh executable Runner/Manifest/Execution identity closure

R2  source-level and dynamic no-bypass closure:
      one shared invocation entry
      one injected transport seam
      Action/Correction/Final all route through it
      repair -> request -> validation -> transport order exact
      old ABI and unrepaired routes zero
      direct Provider/network access zero

R3  zero-Provider full-condition execution control:
      192 Jobs
      600 repaired Action/Correction invocations
      192 frozen Final invocations
      792 total injected-transport calls
      192 terminal reference paths
      zero exception escape

R4  existing five typed failure controls plus boundary:
      invalid first ABI
      unknown current Action
      invalid Correction ABI
      invalid Final ABI
      typed outer failure
      empirical rows and estimates zero
```

可再加入一个非常窄的正向分支控制：选择一个当前 State 中存在两个合法 Candidate 的冻结 Job，让 injected transport 返回非 reference、但当前合法的 Action，确认 Runner 会从新 accepted prefix 动态渲染下一 State。该控制只用于排除“Runner 实际硬编码 reference trajectory”，不需要枚举所有可能状态。
