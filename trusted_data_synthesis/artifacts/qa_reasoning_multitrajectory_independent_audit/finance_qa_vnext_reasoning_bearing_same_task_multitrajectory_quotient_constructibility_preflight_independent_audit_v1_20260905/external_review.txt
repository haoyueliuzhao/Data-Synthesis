# 本轮审计结论

**`PASS_AS_SCOPED`：本轮可以接受为“同任务合法换序的执行与商归并预检”，其科学结果是有效的局部负结果——每个固定任务仍只见证了一个商类。没有发现需要阻断本轮结论的直接问题，也不要求为获得两个商类而重跑或修改归约规则。**

这与刚刚确定的理论基础一致：**不同轨迹身份、不同执行顺序，不自动构成不同解决行为。**报告明确区分了九项工作流 Gate 通过与“同任务多商类见证缺失”，没有将前者解释成后者。

本次审计依据是完整上传报告及我们刚刚确认的理论基线。我另外对报告中的决策 DAG 做了独立组合核对；**没有访问实验仓库、重建源码、重跑验证器或检查所列 156 个工件的实际字节**。以下判断因此属于报告一致性与科学解释审计，不代替源码／工件独立确认。

---

## 一、本轮究竟检验了什么？

本轮固定两个任务，并在**各任务内部**执行两种调度：

```text
S1：D0 → D1 → D2 → D3 → D4
S2：D0 → D2 → D1 → D3 → D4
```

同任务两条候选保持 Task、问题、EvidenceBundle、角色绑定、RealizedTaskPackage、答案 Program、答案语义与五决策图相同；变化仅在两个独立分支的先后顺序。报告还明确：四条候选只执行已有的 execute Action，没有引入新的成功行动语义或拒绝／恢复轨迹。

因此，本轮实际包含三个可分开的检验对象：

| 检验对象      | 本轮应回答的问题                            |
| --------- | ----------------------------------- |
| 合法轨迹可构造性  | 同一任务能否按两种合法调度完成真实执行，而不是仅复制轨迹、修改 ID？ |
| 验证器的路径容许性 | 第二种合法调度能否凭自身证据通过，而不被要求等于旧参考轨迹？      |
| 商归并正确性    | 两条仅有独立分支换序差异的轨迹，是否归入同一语义商类？         |

**这三个对象都不要求最终得到两个商类。**“同任务至少两个不同解决行为”是尚未得到的科学见证，而不是能够用工作流通过数量补偿出来的结果。

---

## 二、实现描述是否对应这些对象？

### 1. 同任务身份与结果前注册：描述吻合

报告不是把 F1 和 F2 当成同一道题的两条轨迹，而是在每个任务内部保持精确父对象一致。它还记录，`quotient_contract.json` 和 `preregistration.json` 在首个 Runtime Action 前完成独占创建与持久化，执行后重新读取注册字节，不接受结果后的注册变更。 

这支持本轮所需要的窄解释：

> 分区依据是事先声明的商规则，不是看到轨迹数量之后，再选择一种能够制造多个状态的规则。

### 2. 第二条轨迹不是“换 ID 的参考副本”：描述吻合

报告记载四条候选均重新执行，每条产生六个 State，以及各五个 Envelope、Receipt、ActionExecution、Observation、Update，共 31 个 Runtime 文件，四条合计 124 个。每次 Action 在自身 Envelope 与 Receipt 持久化、重新读取并通过准入之后执行。

数量关系也一致：

$$
6+5\times5=31,\qquad
4\times31=124,\qquad
4\times5=20.
$$

这些算术核对不能证明文件真实存在，但报告内部没有数量矛盾。

### 3. Own-trajectory replay 是本轮有价值的新增点

报告中的独立只读验证器从实际文件重建当前 State、就绪 Action、Evidence／Claim 输入及对应执行结果，并在 D4 执行公开 Program、核验答案、Schema、引用与质量决定。

尤其重要的是：

> **准入不要求新轨迹等于前驱参考轨迹，而要求它与自己的真实持久化链和独立重算结果一致。**

这正好避免“只有参考执行顺序才能通过”的问题，也使第二种合法调度能够被接受。

按照报告结果，四条轨迹分别通过 QA-valid、trajectory-valid 和联合 Qualified；32 个 Program 节点是四次八节点正向重放的覆盖数，不是额外轨迹样本。

### 4. 本轮商规则与当前理论基线相容

新投影保留任务与证据语义、决策角色与因果依赖、实际选中 Action、Evidence／Claim 输入、Claim 生产角色、公开数值结果与 grounding；删除调度顺序、措辞、偶然 Runtime ID、序号、路径及 fsync 序号。

D1 与 D2 不消耗对方的输出，而是共同向 D3 提供相同源结果，所以换序只改变执行过程，不改变所声明的因果解决图。**将它们归并，是符合本轮规则的结果，不是多样性测量失败。**

这里也没有必要因为“本轮只对 Qualified 轨迹进行分区”，就认定它违背了 Validity 与商身份分离的原则：**这是本轮分区的准入域限制，不等于声称所有未来商映射都只能定义在 Qualified 轨迹上。**

## 三、直接反例检查：有没有内容能够推翻本轮声明？

### 1. 最关键的独立核对：该 DAG 恰好只有这两种合法全序

按照报告给出的依赖：

$$
D0\prec D1,\quad D0\prec D2,\quad
D1\prec D3,\quad D2\prec D3,\quad D3\prec D4,
$$

我枚举了五个决策的全排列。**在每个决策恰好执行一次、依赖保持不变的条件下，合法顺序恰好只有 S1 和 S2。**报告的候选调度及依赖图相互一致。

这带来一个重要解释：

> **本轮充分覆盖了这个固定五决策执行图的两种合法线性调度，但没有覆盖不同的语义解决方案。**

两种调度又被事先声明为商等价。因此，一旦两条执行都通过并保留相同语义，得到一个商类就是预期结果。

这不是推翻本轮的反例；它说明本轮最准确的科学定位是：

**“执行器允许合法换序，验证器不强制参考顺序，商投影不会将换序误判为新策略。”**

它不是一次对不同语义策略的充分搜索。

### 2. 报告有没有利用身份、任务或合同变化制造多状态？

没有发现这样的报告内反例：

| 可能直接推翻本轮结论的问题              | 报告中的处理                         | 本次判断      |
| -------------------------- | ------------------------------ | --------- |
| 用不同 trajectory ID 直接判定不同商类 | 同任务两条轨迹 ID 不同，但归入同一类           | 未见此问题     |
| 把 F1 与 F2 的差异算成同任务多类       | 明确按任务分区，跨任务差异不计入同任务多样性         | 未见此问题     |
| 结果后改商规则，保留 schedule 以制造两类  | 改规则并重哈希的控制在预声明合同检查处拒绝          | 报告记录了对应控制 |
| 第二种调度借用第一种调度的通过证明          | 准入绑定自身轨迹及六域内容；另一调度 replay 不可复用 | 报告记录了对应控制 |

上述分区和控制分别见报告的商准入、逐任务分区及测试章节。  

报告还明确将四项 Runtime 内容变异控制限定为 **single-object rehash**，没有夸称已经验证全链联合重哈希攻击。这是正确的证据边界，**不需要为了本轮有限结论，临时升级为全系统对抗完备性审计**。

### 3. 深度是否被调度或文件数量虚增？

没有看到这种情况。四条轨迹报告的指标均为：

$$
(\text{semantic depth},\text{reasoning depth},
\text{integration depth},\text{correction depth},\text{coverage})
=(3,4,4,0,1.0).
$$

报告明确这些指标对独立分支换序不变，没有将 Token 数和措辞长度作为深度。

其中，依据当前 DAG 可以独立核对：最长决策路径是四个节点，而不是五个串行决策。

**本轮增加了有效执行实例与换序控制，没有增加已见证的推理深度、纠错行为或任务类型覆盖。**其他深度值的实际重算仍属于报告所述验证器的结果，本次没有独立重跑。

## 四、Gate 判定与发现分级

### Gate 判定

| 判断对象                      | 本次结论                      |
| ------------------------- | ------------------------- |
| 本轮报告的实验对象、结果与解释是否一致       | **PASS_AS_SCOPED**        |
| 九项工作流 Gate 通过与局部负结果能否同时成立 | **可以，二者不矛盾**              |
| 同任务多商类见证是否已经获得            | **未见证**，不是本轮工作流 Gate 自动失败 |
| 源码实现与全部工件是否经本次独立重建确认      | **UNKNOWN／本次未执行**         |
| 是否支持模型能力、状态概率或 VTDO 效用结论  | **不支持，本轮未测量**             |

报告的 G6 是“逐任务 Qualified 商分区已计算”，不是“每个任务至少两个商类”。因此，不能因为分区结果为一类，就事后把 G6 改成失败；同样不能因为 G6 通过，就宣称多状态支持已经成立。

### 发现分级

**Blocking defect：在本次审阅范围内未发现。**
没有发现报告内部能够直接推翻“两个合法调度分别执行、通过自身验证并按预声明规则归并”的矛盾。**Mandatory revision：无。**

**Scope limitation：主要是候选族缺少语义变化。**
四条候选只改变独立分支顺序，没有引入不同证据选择、不同有效验证分支或不同推理修订结构。因此，本轮不能检验投影是否能够区分“两条都有效、但确实语义不同”的解决轨迹。这个能力仍未评估，**但不是对本轮换序归并结论的否定**。

**Future hardening：留给对应声明出现时处理。**
更广候选域中的语义分离能力、完整 Mapper 集成、纠错轨迹处理，以及更强的联合篡改控制，都应在未来确实提出相关声明时检验。本轮不需要补齐这些内容才能收口。报告也只声明有限源成员权威，而非完整传递依赖或环境闭合；未将它包装成后者。

## 五、当前可以保留的科学结论

本轮结果可以准确写成：

对每个 \(x\in\{\mathrm{F1},\mathrm{F2}\}\)，存在两条实际身份不同、均通过验证的执行：

$$
\operatorname{ID}(\tau_{x,S1})
\neq
\operatorname{ID}(\tau_{x,S2}),
$$

但在本轮预声明的商规则下：

$$
\phi_x(\tau_{x,S1})
=
\phi_x(\tau_{x,S2}).
$$

因此，在本轮注册候选集 \(\mathcal C_x\) 上：

$$
\left|\mathcal C_x/{\sim_x}\right|=1.
$$

这与报告逐任务分区一致。

对 VTDO 的直接含义是：

**本轮已构造的支持尚未提供非平凡的类间概率重分配空间。**继续增加同一类的合法换序实例，不会自动补出这一空间。

但不能据此推出：

$$
\left|\mathcal T_{\mathrm{valid}}(x)/{\sim_x}\right|=1,
$$

因为本轮没有穷尽所有合法解决行为。更不能把确定性构造计数解释成模型生成分布、成功概率或训练价值。报告已明确保留这些边界。

**这里需要定位的不是“商归约太严格”，而是“当前候选族只包含同一因果解决图的不同线性调度”。**为凑出两个状态而保留 schedule、序号或措辞，反而会违背我们刚刚确定的理论对象。

## 六、哪些范围仍未评估，但不阻断本轮？

当前仍然没有证据证明模型能够生成这些公开决策与更新，也没有证据证明同任务存在多个模型可达商类。四条轨迹都是确定性 Host 构造；广泛 QA 覆盖、纠错行为、训练效用与 Release 资格均未测量。

还应区分：

> **本轮的局部商投影可以作为新理论基础中的一个构造性实例，但不能被宣布为整个 reasoning-aware Mapper、State Assignment、生成协议和训练表示都已完成。**

这与报告中 Mapper、VTDO State、Contribution、VTDO 和训练计数为零并不矛盾。这里的“计算局部商分区”，不等于已经完成正式 VTDO Mapper 链路的集成。

这些未评估范围应继续保持未授权；无需将它们重新列为本轮失败项。

---

## 七、报告提出的下一步是否可以继续？

**从本次审计意见看，没有发现阻断报告所列“一次、零 Provider 的本轮独立确认”的理由。**

需要准确区分：报告中的下一步目前是 **prospective successor**，其 Transition 仍为 `next_stage_authorized=false`，要求新的外部决定；它不是已经生效的执行授权。

这次独立确认应只覆盖本轮新增内容：四条 own-trajectory 链、实际准入与重算、预声明商规则及逐任务分区。**不需要重做已经结束的前驱审计，不要求找到第二个商类，也不应顺势扩展到在线模型执行或全系统完备性检查。**

独立确认收口后，研究推进仍按刚刚确认的基线：先统一公开推理语义、可允许的行为变化及商等价规则，再设计具有真实语义差异的候选族。不能将本轮通过直接转换成候选扩增、主链恢复或 VTDO 测量权限。
