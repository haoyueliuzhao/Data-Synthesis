# 本轮审计与后续实验方案

**审计结论：`PASS_AS_SCOPED`。Flash/high与Pro/high的同条件比较已经完成，Thinking适配、公开内容保存和统一评价规则均已实际接通。本轮可以收口，未发现需要推翻限定结论的阻断性缺陷，无强制重跑要求。**

本轮最重要的结论不是“Flash不能用”，而是：

> **Flash已经能够生成有效的自主公式轨迹，但“正确回答问题”和“生成符合当前研究要求的可验证轨迹”之间仍有明显差距。这个差距部分来自计算或发布问题，部分来自模型直接作答、没有留下实际工具执行证据。**

**下一轮建议继续以Flash/high为主研究条件，保持当前自主Harness不变，在新的任务实例上比较“原自主求解指令”与“明确要求交付可核验计算过程的指令”。**不重新加回accept、Formula Gate或在线答案反馈，也不继续在旧六题上补采样到满分。

本次完整阅读了附件，核对冻结提交`cd317baa…`中的请求配置、响应投影、在线执行、评价和采集入口，抽查发布提交`1282a57…`中的原始响应及空响应投影，并独立复算主要数量、数值与按报告费率计算的成本。**没有重跑32项控制、模型采集或全部工件重建。**

## 一、当前声明与实现：本轮该完成的比较已经完成

### 1. 两个模型确实在同一自主执行框架下运行

源码中的两组请求都显式使用：

```text
thinking = enabled
reasoning_effort = high
max_tokens = 16384
```

`temperature`和`top_p`未继续携带；任务材料、通用SYSTEM、计算工具、连续公开历史及首次Final终止规则保持一致。采集按两个固定重复波次进行，没有根据前一批答案决定是否运行后一批，也没有用Pro结果补Flash。

因此，当前比较可以解释为：

**在本次固定任务、资源与Thinking/high条件下，两种模型产生公开求解行为的有限差异。**

不能解释为Thinking开关的独立效应；相同`high`和输出上限，也不意味着服务内部进行了完全相同数量或方式的计算。

### 2. Thinking适配没有把私有内容混成公开轨迹

投影器在内存中提取公开`content`、受限身份字段、usage及推理存在／长度遥测；worker先调用投影器，再保存投影和原公开内容，没有先将整个HTTP响应写盘后再删除私有字段。

这符合本轮声明，但应继续保留证据强度边界：

**保存的是受信接收程序产生的公开字段投影，不是完整HTTP原响应；推理Token和字符数只是遥测，不能补充缺失的公开公式、来源解释或工具执行。**

这一适配问题可以关闭，不需要下一轮再做同内容的Thinking接入校准。

### 3. 新精度政策已经实际生效，历史评分未被覆盖

评价器确实采用：

$$
\tau=\min\!\left(0.005,\max\!\left(\frac{\Delta_{\text{词法}}}{2},10^{-12}\right)\right),
$$

精确分数仍严格比较，Final文字及其他答案字段另行检查。旧Pro/off的十二条只生成评价侧表：旧严格10/12保留，新政策侧表为12/12，没有计入本轮24条。 

**此前E3的末位表示问题已按新规则处理，不应继续列为待修复接口问题。**

## 三、直接反例检查：本轮缺口究竟是什么？

### 1. 四条直接Final：缺执行证据，不等于不会公式

抽查Flash/J2_01的原始响应，模型已经明确写出：

$$
V_t=q_tp_t,
$$

$$
11\times33.32-13\times26.93=16.43.
$$

年度、数量、价格、单位和来源都在公开内容中，答案也正确；但同一响应直接提交Final，没有调用计算器。

按本轮冻结的“完整公式驱动轨迹”定义，不计入完整轨迹是正确的。但是：

> **不能把它描述为“没有公式”“没有公开推导”或“没有自主求解能力”。它缺少的是本轮要求的实际工具执行及其对应证据。**

当前SYSTEM本身允许直接Final，公开说明也是“可以说明”“在可能时说明关系和所选量”，没有明确要求每个数值任务都交付工具核验过程。

这揭示的是一个**生成目标与数据验收目标之间的差距**：

* 在线任务主要要求模型自主解决问题；
* 数据验收要求它同时留下计算前依据和实际执行记录。

两者并不矛盾，但也不完全相同。**这个差距值得实验检验，不能直接当作模型能力不足，更不能靠Host事后补算消除。**

### 2. Pro的一条裸算式：做了计算，也不等于公开依据已经充分

Pro/C2_02原始计算请求只有：

```json
{
  "tool": "calculate",
  "arguments": {
    "expression": "3581 / 21813 * 100",
    "variables": {}
  }
}
```

执行前没有说明两个数承担什么角色，source IDs到Final才出现。按当前“相关依据必须在计算前或同一请求中可见”的要求，完整轨迹未建立，处理正确。

所以不能把下一步简单化为“让Flash多调用一次计算器”。真正需要的是：

$$
\boxed{\text{公开的任务关系与变量含义}
\rightarrow\text{实际计算}
\rightarrow\text{一致的最终答案}}
$$

只有一次工具调用、没有可核验的变量对应，仍可能达不到当前数据目标。

### 3. Flash/M3：真实的发布尺度错误，不需要重开公式问题

原Final同时写有：

```text
answer = 14.91284%
value  = 0.14912841106142192
unit   = percent
```

实际工具已计算约14.912841个百分点，Final却把比例小数放进`percent`字段。原始响应与报告一致。

这里的错误是**发布数值与单位不一致**，不是三年汇总错误，也不是工具计算错误。不能挑选正确的`answer`字段覆盖错误`value`，更不需要为解决它重新建立逐步accept或在线目标反馈。

### 4. Flash/E1：真实舍入来源与精细参考不等价

模型选择的是原文真实存在的139.5 million，实际计算：

$$
\frac{15.3}{139.5}\times100
=\frac{340}{31}
\approx10.96774194\%.
$$

冻结参考使用139.549 million，目标约为10.96389082%。独立复算，两者相差约0.00385112个百分点；发布的10.97%与参考相差约0.00610918个百分点。按当前主要数值精度和两位小数要求，失败成立。

但它**不是来源捏造、单位混用或公式错误**，而是公开来源精度选择与精确目标的差异。

源码中的`inconsistent_final_numeric_fields`实际上是在检查次要答案是否符合参考值，不完全等于检查模型两个字段彼此矛盾。报告已经披露这个命名限制。建议后续诊断显示区分“字段内部不一致”和“与参考精度不符”，**不改变本轮评分，也不为此新增一轮在线实验**。

### 5. Flash/C2空响应：未知处理正确，不是截断或金融失败

抽查投影，实际为：

```text
finish_reason = stop
content = ""
completion_tokens = 58
reasoning_tokens = 58
```

模型身份匹配，原公开内容确实为空。不能补入此前计算器的正确结果，也不能将它改称`length`截断。当前未知处理符合记录；尚无证据判断服务端为何没有返回公开内容。

**一个这样的事件不足以要求现在增加重试、回退或提高预算。**继续完整记录即可，避免修订生成条件后又把新旧结果混在一起。

# 五、后续优先实验：明确轨迹交付目标，但不恢复脚手架

## 1. 唯一主问题

建议下一轮检验：

> **固定Flash/high与当前自主Harness，仅明确“需要交付可核验的公开计算过程”，能否在新的真实任务上提高完整轨迹产量，同时保持答案质量和合理成本？**

这是由本轮结果支持的**待检验假设**，不是认定一句提示就能解决所有问题。

本轮已经有同协议Flash/Pro对照，下一轮不必继续重复这组模型比较；先弄清Flash的产量差距有多少来自交付目标不明确。Pro保留为已完成参照，不自动成为默认，也不拿它补齐Flash失败。

### 为什么这不等于重新加脚手架？

需要区分：

**规定交付物：**希望得到有依据、可复核的解题过程。

**规定解题路线：**必须先完成某个计划、使用指定公式、read每个数字、accept每个结果，才能继续。

下一轮只检验前者。**模型仍决定公式、证据、操作组合、计算粒度、检查方式和结束时机；Harness仍只执行与返回。**

## 2. 两种指令条件

| 条件             | 说明                                |
| -------------- | --------------------------------- |
| **A：原自主求解指令**  | 保留本轮SYSTEM与全部接口，直接Final仍合法        |
| **T：公开轨迹交付指令** | 在同一SYSTEM上追加固定、跨任务相同的交付要求，不提供本题解法 |

T的建议内容可以概括为：

> 本次交付不仅包括答案，还包括可复核的计算过程。请在相关计算前或同一计算请求中，说明所采用的关系及各输入的含义、来源和必要单位处理，并使用计算工具产生最终答案所依据的结果。你仍自行决定计划、公式、取证、计算粒度和是否检查，不要求固定步骤、冗长解释或重复计算。

**这段内容是拟议的新实验条件，尚未冻结或验证。**

它不应提供任务专属公式、正确数字组合、年度对应或尺度因子；不要求使用某套固定变量名，也不要求额外的计划提交回合。

在线执行器完全不变：

**没有计算就Final，仍立即结束；来源说明缺失，仍允许算术执行；答案错误，不反馈重新生成。**

不满足交付要求只在离线评价中体现，不能由Host补公式、补来源或代调用工具。这也避免将“工具使用次数增加”误当成“自主推理增强”。

## 六、实验面板与执行范围

### 1. 使用六个新的任务实例，每条件两次，共24会话

建议从现有冻结来源中选择**未用于当前提示和运行调试**的六题，保持工具已经能够表达和执行，按以下三类各选两题：

| 类型        | 观察重点                      |
| --------- | ------------------------- |
| 比例与尺度转换   | 模型能否说明量的含义、统一单位，并一致发布百分数  |
| 多期汇总与比较   | 能否识别成员集合，区分汇总比率、单期比率和比例平均 |
| 复合金额差或增长率 | 能否正确处理数量—单价、期间配对、净额及符号    |

规模为：

$$
6\text{ 题}\times2\text{ 指令条件}\times2\text{ 次新会话}
=24\text{ 会话}.
$$

每个条件内任务权重仍各为 \(1/6\)。这六题的具体ID应在运行前一次性选定；**本次审计没有替你挑定新的题号，也不保证某种来源组合已经接通。**

选题应排除当前反复使用的六题及同页近重复题，优先使用不同公司年度报告组。它们可以称为迁移诊断集，**不能据此声称模型训练时从未见过，或自动获得正式盲测身份**。

参考答案和来源解释可以用于离线核验，不进入模型请求。对舍入正文与精细表格并存的情况，提前记录评价所采用的精度解释；不能看见新模型选择之后才决定哪种来源合法。

### 2. 保持当前其余条件不变

固定Flash、Thinking enabled/high、16K completion、完整条目材料、全部数字索引、三个工具、连续公开历史和首次Final终止。

每会话仍最多32次模型响应、32次工具调用，全批最多768次请求。两种指令交错登记，独立历史，不共享答案、笔记或工具结果。

**不降低Thinking、不临时提高预算、不增加网络重试，不加入Pro回退，也不因某题直接Final而追加一个“请再用工具计算”的回合。**

新的任务接线和指令接线在同一阶段完成即可，不需要重新统计FinQA、重跑全部历史控制或单独开展一轮accept／JSON校准。

## 七、测量重点：提高的是可用数据产量，而不只是工具调用率

### 1. 同时保留答案与轨迹两个主要结果

对每个任务、每个条件分别报告：

$$
\widehat q_{\mathrm{answer}}(x,c)
=\frac{\text{答案PASS数}}{2},
$$

$$
\widehat q_{\mathrm{trace}}(x,c)
=\frac{\text{完整可验证轨迹数}}{2}.
$$

未知、直接Final、过程不足和答案失败均保留在登记总体中，但分别标注，不能全部合并成“模型算错”。

继续使用本轮已冻结的评价v2，不为了提高轨迹通过率临时放宽来源、公式或发布标准。

### 2. 用同一条证据链定位缺口

建议围绕以下关系记录，不再增加大量在线字段：

**是否公开提出关系 → 是否明确输入含义与来源 → 是否实际执行 → 是否与目标语义一致 → 是否正确发布。**

其中应特别区分：

| 情况                   | 正确解释                  |
| -------------------- | --------------------- |
| 正确公式与答案，但无工具执行       | 正确自主回答，未满足本轮执行可验证素材要求 |
| 有工具执行，但来源关系未在执行前建立   | 算术有证据，公开依据不足          |
| 公式、数据和计算正确，Final尺度错误 | 发布错误，不回头判公式错误         |
| 来源真实但精度不同            | 来源精度／评价语义问题，不自动判捏造    |
| 空公开响应或传输异常           | 观察或服务条件问题，不归因金融推理     |
| 工具次数增加，却没有完整有效答案     | 尚未获得数据产量收益            |

允许一次整式求值，也允许模型合理拆分。**不能要求所有题都有多步规划、反思或方法修订；任务简单时，简洁而完整的两轮交互就是合理结果。**

### 3. 以全部成本摊销到有效产出

继续报告：

$$
\text{单位有效轨迹成本}
=\frac{\text{该条件全部会话的实际估算成本}}
{\text{完整轨迹数}}.
$$

分母为零时不输出有限单位成本。保留全部失败与未知支出，并分别报告Token、时延和现金费率估算。

这次新增指令可能增加公开输出和工具调用，不能预先保证更省钱。**只有可用轨迹增加且代价可接受，才能支持它的工程价值；更长解释或更多调用本身不算改善。**

## 八、下一轮如何收口并衔接研究主线？

如果T提高了完整轨迹产量，同时答案质量没有出现明确退化，可将它选为后续合成条件。准确结论应是：

> 明确公开过程交付要求，在这个迁移面板上改善了数据产出。

不能称为模型内在推理能力提高，也不能拿新T结果直接与历史Pro结果作同期模型优劣比较。

如果T只让模型多调用计算器，却仍缺少变量说明或正确发布，就接受这个有限结果，**不立即新增强制变量Schema、接受步骤或答案重试**。

如果两种条件都大量直接Final，应先接受模型在这种任务和指令下的行为分布，而不是无限追加提示直到获得预期轨迹；若差距主要是实际公式或来源语义问题，后续再针对该对象设计实验。

如果Flash已稳定产出符合目标的轨迹，下一阶段再在**固定模型、固定指令和固定任务边际**下开展新协议的行为关系测量和原样物化。A/T的数据不能事后混为一个生成分布；私有Thinking不进入商状态或训练目标。

**本轮已有5条Flash和11条Pro完整轨迹可以保存为各自条件下的有效材料，不必等所有错误消失才有研究价值；但本轮尚未完成新商、Token训练表示或Student效用，不能提前宣布VTDO有效。**

## 最终决定

**本轮通过并收口：Flash/high为9/12答案、5/12完整轨迹；Pro/high为12/12答案、11/12完整轨迹。Thinking与隐私投影适配已完成，主要计数和按登记费率复算的成本一致。**

**后续重点应从反复比较模型，转向明确“自主求解”与“公开可验证轨迹交付”的差别。**建议固定Flash/high，在六个新实例上用24会话比较原指令与公开过程交付指令，保持Harness只执行和返回，不恢复旧脚手架。
