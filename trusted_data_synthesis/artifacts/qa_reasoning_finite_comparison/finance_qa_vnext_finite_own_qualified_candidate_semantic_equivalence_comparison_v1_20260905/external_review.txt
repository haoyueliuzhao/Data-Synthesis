# 一、本轮审计

## 1. 当前声明：候选族已经能够实例化，但语义分离尚未测量

上一轮要闭合的是：

```text
typed_candidate_family_source_and_validator_constructibility
```

本轮对应的实际对象为每个任务上的三条路线：

| 路线    | 实际构造                                           | 在本轮中的角色            |
| ----- | ---------------------------------------------- | ------------------ |
| **B** | 四个 `lookup`、两个 `growth`、带符号差、绝对差               | 基准候选               |
| **A** | 直接引用 Evidence 的 `value`，执行两个 `growth`、带符号差、绝对差 | direct-Evidence 候选 |
| **C** | 保留 B 的 lookup 顺序，只交换两个独立 growth Action         | 调度回归控制             |

A 使用的是现有 `task_program.v2` 已支持的 `InputRefKind.EVIDENCE` 和 `selector="value"`；本轮没有新增 Operation、代数规则、Evidence 别名或 Task Pattern。C 也没有被计作新的语义策略。 

因此，本轮真正检验的是：

> 在不改变任务、证据和答案合同的情况下，系统能否执行不与答案 Oracle 逐节点相同的合法候选，并根据该候选自己的实际行为判定有效性？

**这一对象不要求最终获得两个商类。**不能因为 A 可能与 B 商等价，就否定它对候选语言与验证器可构造性的检验价值。

## 2. 实现状态：报告中的实现与当前命题相符

### 2.1 候选来自已有语法和注册语义，而不是只有方法名称

本轮没有仅创建一个叫作“直接求解”的路线标签。报告明确给出了 A 的具体输入解析机制，以及 `lookup` 的 `transparent_projection` 注册角色和已有透明引用收缩语义。A 的四个 Operation 也实际执行了。

与此同时，来源清单没有把其余注册 Operation 的存在当作任意改写许可：

`growth_to_compare` 不适合当前同主体、跨指标的任务；增长率拆解和有序操作数反转，在本轮声明的来源形式中缺少相应组合规则。报告将这些限制限定在当前来源域，没有声称所有合法 DAG 都不存在替代方案。

这支持的是**一个有限来源族的闭合**，不是通用候选生成器的完备性。

### 2.2 来源检查、候选选择与结果评估没有混在一起

`source_inventory` 检查类型、角色、期间、同序列兼容性、对齐窗口、有限数值和正增长基数，不计算候选 Operation 输出，也不读取候选 Oracle 结果。

六项声明及顺序在 dispatch 前持久化，失败的 A 不允许在看到结果后被替换。报告还以阻断 executor／Oracle 的控制检查了来源阶段仍可生成全部六项声明。 

读取 Archive 中已有结果以核验整个目录的完整性，也不自动等于利用这些结果选择路线。报告明确区分了这两种用途，没有出现已披露的结果后筛选。

### 2.3 真正关键的修订是 own-route 验证，而不是删掉四个节点

实际 Runtime 从当前可见 Evidence 或已验证 Claim 解析输入，提交行动前提案和 Receipt 后执行注册 Operation，再保存实际 Observation、Claim／Update 与下一 State。

独立验证器通过另一条读取路径重建实际输入、角色、状态就绪性、执行合同、Observation 支持及 Claim 依赖；它不导入候选 Runtime 或来源构造 helper。

答案验证则单独重算冻结的八节点 Oracle。尤其重要的是：

> 旧 `CandidateWorkflowVerifier` 要求遍历全部 Oracle 节点，因此没有被继续作为 A 的唯一路线验证器；缺失的 lookup 也没有被补写成 A 执行过的 Action。

五项必要义务由实际 Claim 与 Evidence 的履行映射检查，而不是要求出现旧 D0–D4 名称。

这使下面两件事得到了真正区分：

$$
\text{候选自己实际做了什么}
\qquad\text{与}\qquad
\text{验证器为了检查答案计算了什么}.
$$

**这是本轮可以保留的实质性进展。**

## 3. 直接反例检查：没有发现推翻当前声明的问题

### 3.1 A 少了 lookup，是否意味着它绕过了必要证据或义务？

仅凭节点减少，不能得出绕过结论。

报告说明 A 直接解析的是同一冻结 Evidence universe 中的具体值，仍检查引用、类型、角色和状态可用性，最终要求精确四项 Evidence、来源身份及定位信息。必要义务也被单独重建。

所以，在当前报告范围内，**A 缺少 Oracle 中的 lookup 节点不是直接反例**。只有实际证据获取、来源约束或任务义务被跳过，才会推翻本轮有效性声明；报告没有披露这种情况。

但这不等于我已经独立检查了全部引用字节。当前接受仍然限定在报告及其所描述的验证证据层。

### 3.2 验证器是否可能只凭最终答案正确就接受轨迹？

本轮控制直接检验了这一点。

九个无效控制被拒绝，其中八个保留正确的 QA 答案，却因期间、操作数角色、可见 Evidence、Claim 状态、Observation、调用方权威或字段来源问题不能 Qualified。带符号操作数反转甚至保留了最终绝对答案字节，但仍在冻结的有序角色规则下被拒绝。

这些结果支持当前所声明的：

$$
V_{\mathrm{qualified}}
=
V_{\mathrm{QA}}\land V_{\mathrm{trajectory}},
$$

而不是“答案正确即可通过”。

同时，`route_label_only` 被接受也不是缺陷：它没有改变 Runtime 字节，说明装饰性路线名称不应决定有效性。**接受该控制不代表建立了新类别。**

### 3.3 计数是否将验证工作或重复构建当成更多候选？

没有发现这种混用。

根据报告路线规模，独立算术核对为：

$$
\begin{aligned}
\text{主候选 Action}&=2(8+4)=24,\\
\text{调度控制 Action}&=2\times8=16,\\
\text{实际候选 Action 总数}&=40,\\
\text{答案 Oracle 重放节点}&=6\times8=48.
\end{aligned}
$$

最大公开步骤数是 \(8+1=9\)，没有超过包括 Final 在内的十步界限。40 次 own-route Oracle 重放与48次答案 Oracle 重放都被计作验证工作，而不是额外候选 Action。 

第二次完整构建也被正确解释为可复现性检查，不是另一组独立采样候选。

本次没有获得四个原始标量值，因此**没有重新计算报告中的两个最终增长率差值**，不能将上述计数核对写成答案数值的独立复验。

## 5. 当前允许与不允许的科学结论

### 可以保留的结论

**固定 F1/F2 上，B、A、C 均能在当前有限 Runtime 中实际执行，并通过 own-route 验证及独立答案验证。**因此，当前系统不再只能接受与答案 Oracle 节点结构完全相同的执行。

### 当前仍不能保留的结论

**不能把本轮正式写成“两类”，也不能提前写成“一类”。**

本轮并未运行语义等价比较，正式类数为 `null`。历史换序族的一类结论继续成立，但不能直接代替新 A/B 候选族的测量。 

同样，注册 Action 从八个变为四个，不意味着关键推理深度减半，更不意味着推理能力、训练价值或成本效用提高。本轮没有提供新的深度测量表或模型实验；既有深度合同也明确，Program 节点数不能替代关键决策推理深度。

**当前不是“本轮仍有一个 Blocking defect”，而是“可构造性对象已闭合，下一测量对象尚未完成”。**

# 二、后续实验：有限已验证候选的语义等价比较

以下是建议的后续实施方案，不是本轮已执行结果。

采用报告所列阶段：

```text
finance_qa_vnext_finite_own_qualified_candidate_semantic_equivalence_comparison_only
```

**只处理现有六条轨迹，完成一次有限范围的语义比较并收口。**不新增候选、不调用 Provider、不重跑旧实验 builder，也不在该阶段开展模型协议或训练实验。

## 1. 本轮需要回答的唯一核心问题

> 对同一任务，B 经由透明 lookup 引用 Evidence，A 直接引用同一 Evidence 的值；在保留任务相关的公开决策、依据、来源、Claim 依赖及状态效应之后，这两种实际执行是否属于同一种解决行为？

用整理性记号表示：

$$
\tau_i\sim_x\tau_j
\quad\Longleftrightarrow\quad
N_R\!\left(G_{\mathrm{public}}(\tau_i)\right)
\cong_{\mathrm{typed}}
N_R\!\left(G_{\mathrm{public}}(\tau_j)\right).
$$

这里：

* \(G_{\mathrm{public}}\) 从实际保存的公开轨迹恢复，不从路线名称或候选模板直接生成；
* \(R\) 是本轮固定的、具有来源依据的有限归约规则；
* \(N_R\) 只能消除规则授权的操作性差异；
* 图对应必须保持语义标签、引用和有序依赖。

这是对已接受设计的有限实例化。原设计要求保留真实支持、类型化依据、操作语义、操作数角色和有意义的更新，同时明确最终答案相同、图哈希不同都不足以决定行为等价或差异。

## 2. 先明确最关键的边界：透明 Operation 不等于整段推理自动透明

本轮给出了很强的**等价性预期**：A 只省略了注册为透明投影的 lookup，保留同样的两个 growth 和两个 gap Operation。

但还不能直接执行：

```text
删除所有名字叫 lookup 的节点
→ 比较剩余四个 Operation
→ 宣布轨迹等价
```

因为下一轮比较的是**公开行为**，而不只是算术 Program。

必须确认 lookup 所对应的提案、Claim 或状态变化中，是否还包含应该保留的支持选择、验证依据或知识状态变化。操作被注册为透明投影，是规则来源；**它不是无条件删除整段公开决策及来源关系的许可**。

### 建议的透明收缩条件

对当前 B/C 中每个 lookup 实例，仅检查以下有限条件：

| 条件      | 必须由实际记录支持的事实                                              |
| ------- | --------------------------------------------------------- |
| 注册语义    | 对应精确版本确为 `transparent_projection`，而不是依据节点名称判断             |
| 值与来源保持  | 输出经相同 selector 指向同一 Evidence 的同一值，单位、来源、定位和角色不变           |
| 引用可替代   | 消费 lookup Claim 的引用可替换为对应 Evidence 引用，不改变操作数位置、类型或生产—消费关系 |
| 当前信息合法  | 直接引用的 Evidence 在相应 State 已经可用，不通过收缩绕过可见性或准入               |
| 无额外保留效应 | lookup 没有产生需要保留的验证结论、拒绝／修订、下游失效或其他任务相关状态效应                |

如果这些条件成立，可将：

```text
Evidence
→ transparent lookup
→ forwarding Claim
→ growth operand
```

归约为：

```text
同一 Evidence
→ 同一 growth operand
```

但原始轨迹中的 Action、Observation、Receipt 和计数**全部保留不动**。归约只生成新的测量投影，不改写历史执行。

这里的检查范围很小：由当前路线结构计算，B/C 一共涉及 **16 个 lookup 实例**，而不是要求证明所有未来 lookup 都透明。

## 3. 不必实现通用 Mapper，有限图对应已经足够

本阶段可以采用两步实现。

### 第一步：恢复完整的类型化公开行为结构

至少恢复以下内容：

```text
精确任务与验证合同
实际使用的 Evidence 及角色、来源和定位
公开决策的类型化依据
Operation 语义版本与有序输入角色
Claim 生产、消费、值、单位与 grounding
Observation / Update 的实际因果关系
必要义务的履行关系
最终 disposition、答案与引用语义
```

运行 ID、保存路径、纯路线标签和不冲突的执行顺序单独留在审计层，不作为行为类别依据。

**Host 的可比性核验仍应记录为 Host 行为，不能在投影时改写成模型作出的判断。**当前报告已明确所有提案与调度为确定性 Fixture，字段来源分别记录。

### 第二步：对这六个有限图构造对应关系

不必先实现适用于任意大图的规范化器。对当前有限域，可以直接寻找并核验语义标签保持的节点对应，检查全部节点属性及双向边关系。

等价结果应给出可检查的对应关系，例如：

> B 中某个经过透明转发的收入 Evidence 输入，对应 A 中同一 Evidence 的直接输入；其消费者都是同一语义版本的 growth，且 earlier/later 角色保持不变。

不等价结果则应指出**无法由已授权规则消除的保留语义差异**。不能仅报告“哈希不同”或“匹配算法没有找到”。

若规则不足、字段无法解释，或有限搜索没有完成，应返回 `undetermined`，而不是默认归并或默认分离。

## 4. 比较矩阵：六个同任务配对即可

每个任务内使用 B、A、C，共有三个无序配对：

| 配对      | 检验目标                                  |
| ------- | ------------------------------------- |
| **B–C** | 新比较实现是否保留独立 growth 换序的等价性             |
| **B–A** | 透明 lookup 转发与直接 Evidence 引用是否保留相同公开行为 |
| **A–C** | 交叉核对上述两类归约是否一致                        |

F1、F2 分别处理，共六个无序配对。**不做跨任务等价比较，不把 F1/F2 的差异当成同任务多类。**

主要科学候选仍是每个任务的 B/A；C 是回归控制。即使输出包含三条轨迹的完整分区，也应同时标明 primary/control 角色，不能将 C 当成第三个独立策略见证。

### 数据使用与执行预算

建议读取本轮冻结目录中的候选声明、实际执行、独立验证和候选结果；必要时对六条轨迹各调用一次现有只读验证器，以恢复被接受的实际输入和依赖。

这属于验证重放，不是重新运行候选：

```text
新增候选声明           0
新增轨迹 Runtime 执行  0
Provider 调用          0
待比较的冻结轨迹       6
同任务无序配对         6
```

不要为了“获得另一组验证样本”再次调用 `run_candidate`。现有实际轨迹已经足够回答这个有限问题。

## 5. 规则冻结与结果解释：不能事后选择想要的类数

下一轮需要在运行比较器前，固定具体保留字段、透明收缩条件、数值规范化及图对应规则。

由于本轮轨迹及结果已经看过，准确说法是：

> 在已知候选上的测量规则实例化与有限比较。

不应称为数据盲确认。但规则仍必须来自已接受设计和注册语义，不能在看到类别数后调整。

尤其要保持：

**Decimal 表面规范化只使用精确数值相等。**不能用两两容差接近合并类别。

**操作数角色继续有序。**最终使用绝对值，不允许比较器擅自把带符号 gap 的 reference／observed 角色交换当成无差异。

**Evidence 数值相同不代表来源相同。**别名归并必须有已注册来源语义；不能仅比较 scalar 值。

**路线标签变化不构成差异，也不应覆盖真正的类型化决策依据变化。**不能把所有名为 strategy、basis 或 reasoning 的字段一概删除。

这些边界已有设计依据，不需要为它们再单独开启一次设计审计。

## 6. 最小控制：只测试新增比较器的风险

现有 Runtime 拒绝控制不需要全部复制。建议对新增投影和比较器保留四组局部控制：

| 控制                               | 预期行为                |
| -------------------------------- | ------------------- |
| 一致的 ID 重命名、纯标签变化、独立调度变化          | 不改变比较结果             |
| 最终答案保持相同，但改变保留的 Evidence 来源或有序角色 | 不能因答案相同而合并          |
| 节点声称透明，但带有不能删除的状态／验证效应           | 拒绝透明收缩或返回未定         |
| 规则不支持的结构或缺失必要语义字段                | 明确未定／拒绝，不能产生虚假的确定类别 |

这些可以是隔离的**投影单元控制**，不必伪造新的完整 Qualified 轨迹。它们检验比较器的规则执行能力，**不计入实际商类见证**。

同样，不需要为了测试“分离能力”，在本轮强制再制造两条语义不同且有效的金融轨迹；那会重新扩大候选族，偏离当前比较对象。

# 三、下一轮结果与 Gate 应怎样定义

## 1. 配对结果采用三值判断

建议每个配对输出：

```text
equivalent
different_retained_semantics
undetermined
```

另行保存输入准入状态。输入轨迹未通过验证时，不进入上述比较，更不能成为一个新类。

每个确定结论应绑定对应证据：

* 等价：有限归约记录和完整语义对应；
* 不等价：明确的保留语义差异，或完成的有限不相容判断；
* 未定：缺失字段、未授权规则或未完成计算的具体位置。

类数只能在相应有限域的比较闭合后计算。出现未定关系时，不能将其随意计作“不同”，也不能用零替代未知。

## 2. 工作流通过与科学结果分开

建议本阶段只设四类完成条件：

| Gate 对象 | 完成要求                                  |
| ------- | ------------------------------------- |
| 输入域     | 六条冻结轨迹及其自身验证来源一致，primary/control 角色不变 |
| 语义投影    | 保留字段与透明收缩均有来源、实际引用和状态效应依据             |
| 有限比较    | 六个配对得到可检查结果，等价关系一致，直接控制正确             |
| 解释边界    | 类数只针对当前任务与候选族；无新生成、模型或训练主张            |

**不要求类别数大于一。**

但也不能把“准确记录了未知”写成“全部语义比较已闭合”。若关键规则无法实例化，可以接受这个定位结果，同时将完整比较 Gate 保持 `UNKNOWN`；它不会追溯否定本轮已经完成的构造性证据。

## 3. 三种主要科学结果

### 结果 A：每个任务的 B、A、C 都等价

这会支持：

$$
\left|\{\tau_{x,B},\tau_{x,A}\}/\sim_x\right|=1,
$$

C 同属该类，作为调度控制不增加类别。

结论是：**当前有限族中，透明投影删除与独立换序均没有带来新的保留行为语义。**

这是可以收口的局部负结果。随后应停止在 lookup 删除、直接引用、措辞和调度这些轴上继续扩样；它们已经不能为当前 VTDO 问题提供新的类间概率空间。

### 结果 B：A 与 B/C 存在实际保留语义差异

只有差异来自经过 own-qualified 执行支持的类型化公开依据、依赖或有效更新，而不是删减节点、换 ID 或方法名称时，才能接受为当前合同下的有限多类见证。

即便如此，也只得到：

> 固定任务、固定验证语义、固定候选域下，存在多个有效商类。

模型可达性、各类概率、Contribution 和训练收益仍未测量。

### 结果 C：能比较算术结构，却无法比较完整公开行为

例如四个核心 Operation 可以对应，但 lookup 关联的某项公开依据或状态效应尚无合法归约规则。

此时应报告：

```text
computational correspondence: established
full public-behavior equivalence: undetermined
formal semantic class count: null
```

下一步只补齐该具体解释或字段问题，**不因此回到全部 Runtime 审计，也不跳到模型执行寻找答案**。
