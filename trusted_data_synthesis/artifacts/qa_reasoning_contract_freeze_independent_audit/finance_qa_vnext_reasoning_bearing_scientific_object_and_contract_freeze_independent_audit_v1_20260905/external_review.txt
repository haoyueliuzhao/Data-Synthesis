# 二、按照限定审计框架逐项检查

## 1. 本轮明确检验的命题

本轮命题可准确写为：

> 能否在不执行真实 QA、不过问模型能力的前提下，冻结一组相互分离的科学对象和类型 Contract，使“答案 Oracle—关键决策—公开状态—先于行动的结构化判断—行动—Observation—Claim 更新—下一状态—最终有效性”成为可实例化、可验证和可直接反驳的形式对象？

它没有检验：

* 模型是否会生成这些对象；
* 这些对象是否足以描述真实金融任务中的关键推理；
* 同一个任务是否存在多条有效 quotient trajectories；
* QA 数据是否可以进入 Release 或 VTDO。

因此，本轮审计不能把这些后续问题反向提升为本轮 Blocking defect。

## 3. 科学对象是否真实分离

这一项在**合同定义层**通过。

当前 10 个 Contract 分别承担：


特别重要的是：

```text

  = 模型必须完成哪些公开关键判断、允许哪些替代行动、
```

这避免把唯一参考 Program 错当成唯一模型思考路径。每个 required obligation 还要求至少一个直接 counterfactual intervention，而且对象中不请求或持久化私有 CoT。

这正面解决了此前“轨迹只有工具调用和答案 Program，却不反映关键推理”的对象定义问题。

## 4. 推理是否被约束在 Action 之前

这一项在**Schema/parent-contract 层**通过。

冻结的父链是：

```text
PublicReasoningState_t
  -> ReasoningActionEnvelope_t
  -> ActionExecution_t
  -> PublicObservation_t
  -> ObservationUpdate_t
  -> PublicReasoningState_(t+1)
```

`ReasoningActionEnvelopeV1` 同时包含：

* 当前 Evidence/Claim references；
* 当前 subgoal；
* 未解决不确定性；
* 当前候选 Actions；
* selected Action；
* decision-basis relations；
* expected effect。

也就是说，公开关键判断和内部 Action 被放在一个 pre-action envelope 中。`ObservationUpdateV1` 又要求所有 accepted/rejected/revised Claims 精确引用对应 Observation，并说明该 Observation 如何改变下一状态。

但这里需要保持一个重要边界：

```text
合同规定了 pre-action parent order
    ≠
已经观察到真实 Runtime 中的 durable pre-action commitment
```

当前只有合成 conformance chain，没有执行真实任务。报告已经明确承认这一点，因此这是 **Scope limitation**，不是对本轮命题的直接反例。



的多步校准。

