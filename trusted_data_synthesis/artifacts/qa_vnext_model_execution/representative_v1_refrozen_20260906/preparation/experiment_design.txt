# 后续实验方案：统一 QA 协议下的真实模型执行与新轨迹表示接入

**建议下一轮直接开展：三个代表任务、一个教师模型配置、每任务四个会话，共十二个真实模型会话；在同一轮完成独立资格核验、实际广度／深度记录，以及新协议原始监督数据的导出与 Token 化检查。**

这轮不再重复 Registry 修复、九条 fixture 集成或旧五轨迹权重预检，也暂不开展 Student 参数更新。**核心推进是：把已经接通的统一离线链路，推进到真实模型可执行、结果可测量、数据可追溯的链路。**

下面是建议冻结的方案，尚不是已实现协议或实验结果；当前请求不触发 Provider 调用或训练。

---

## 一、本轮只回答一个主问题

> **在给定公开计划、合法动作候选及验证合同的条件下，真实模型能否通过统一入口完成不同结构的 QA 任务，并产生可归属、可独立验证、可原样导出的公开解决轨迹？**

这里明确选择**“给定计划下的公开选择与执行”**作为研究条件，暂不同时加入自主计划构造。

当前统一协议由 Host 提供合法动作的结构、依据引用和预期产物，callback 负责选择、完整提交及 Observation 后的明确接受／拒绝。这不是不受限规划，也不是自由生成全部推理结构。下一轮保留这一条件，避免一边测试统一接入，一边悄悄改变模型责任。

本轮主问题可以分成三个可分别判断的对象：

| 对象          | 本轮要获得的证据                                      | 不要求同时证明                    |
| ----------- | --------------------------------------------- | -------------------------- |
| **模型接入**    | 原始模型响应经过同一 Runtime，而不是 fixture 或 Host 代写      | 模型自主发现完整求解计划               |
| **代表任务执行**  | 不同结构任务上的完整 Action—Observation—Update—Final 过程 | 广泛金融任务能力、深度的因果效应           |
| **新协议数据接入** | 原请求条件下的真实响应可导出并正确 Token 化                     | 新商类分布完整、Student 有效、VTDO 有效 |

当前已经有十一类注册、八类来源实例和九条统一入口 fixture，但没有新协议上的真实模型样本；因此，这三个对象比继续增加确定性 fixture 更值得优先检验。

旧训练预检则保持其既有结论：P/Q 的类概率已准确作用于监督目标，但它没有进行 Student forward，也不支持训练效用。**不需要推翻或重做它，只需避免把旧协议数据当成新协议数据。**

## 二、固定实验总体：三类任务、十二个会话

### 2.1 选择已有真实来源任务，不扩大来源搜索

建议使用统一入口中已经完成离线验证的三个对象：

| 任务组           | 固定任务                                                        | 检验重点                              | 已有 fixture 的完整提交数 |  新模型会话 |
| ------------- | ----------------------------------------------------------- | --------------------------------- | ----------------: | -----: |
| **C：注册跨指标比较** | `registered_cross_metric_comparison` 的既有来源实例                | 注册语义与完整公开判断能否由模型使用                |                 3 |      4 |
| **B：分支合并**    | `branch_cdw_fy2015_fy2016 / derived_growth_absolute_spread` | 多个 accepted Claim、并行依赖及深度三语义链能否完成 |                17 |      4 |
| **S：不同充分依据**  | `source_explicit_part_whole_share` 的既有任务                    | 模型实际选择披露总额或分项重建依据                 |               5／7 |      4 |
| **合计**        | **三个固定任务**                                                  |                                   |                   | **12** |

表中的提交数来自已有离线执行，不是对新模型调用量或成功率的预测。branch 的实际语义操作深度为三；Share 两条路线分别为二和三。

这三个任务恰好对应三项已经有明确实现基础、但尚缺新协议模型证据的机制，不需要为本轮再寻找新公司、补齐毛利率目标或扩展 Operation。

### 2.2 四个重复会话不是四个独立任务

定义本轮观察总体：

$$
\mathcal X_{\mathrm{pilot}}=\{x_C,x_B,x_S\},
\qquad n_x=4.
$$

十二个会话在调用前全部登记，每个从独立初始 Runtime State 开始。它们不共享其他会话的模型输出，不把已成功的响应放入后续会话作为示例。

每任务四次是**有限工程观察设计**，不是经过功效分析后足以估计稳定能力的样本量。结果按任务分别报告，不把十二次运行写成十二种 QA。

建议按四个轮次组织，每轮包含 C、B、S 各一个会话，具体顺序在调用前固定，不能根据先前成功与否重排或替换任务。

### 2.3 Share 不预分配 D/S

四个 Share 会话使用相同的中性生成条件：

```text
不指定 disclosed_total
不指定 reconstructed_total
不要求两条路线都出现
不根据缺少哪条路线继续补样
```

两种合法支持可以作为当前公共动作空间的一部分被模型看到；但不能额外提供“本次应走哪条路线”的提示。

**模型只选择直接总额，不是本轮接入失败。**它只能说明本轮有限采样没有见证另一种选择，不能说明重建路线不可达。

## 三、冻结生成条件，不同时改研究对象

### 3.1 保留新统一协议的科学语义

以下内容从已审计的新入口继承：

```text
FinanceQACatalog 和共享 OperationRegistry
三个固定 Task、Evidence 及来源绑定
公开 Program skeleton／Share 合法支持空间
Action、Update、Final 的内容要求
Action 后仅产生 pending Observation
accept Update 后才产生 accepted Claim
现有独立数值验证、Final QA 和轨迹核验
```

协议基线为 `finance_qa_public_decision_protocol.v2`，Program 与 Share 分别使用已登记的 adapter。新增在线运行身份可以版本化，但不能为了方便模型输出而静默放宽这些语义。

Program 的 precision=28 和 Share 的 precision=50、最终六位量化仍分别保留；不能为了统一导出而把两者改成同一种精度。

### 3.2 教师配置：优先复用已登记条件，而不是同时换模型

建议将上一 Share 试验的教师配置作为本轮候选基准：

| 配置项                 | 建议候选值                       |
| ------------------- | --------------------------- |
| 请求模型                | `deepseek-v4-pro`           |
| Thinking            | `disabled`                  |
| temperature / top_p | `0.7 / 1.0`                 |
| `max_tokens`        | `8192`                      |
| 输出形式                | JSON object，仍需经过项目严格 Schema |
| 原生 tool calls       | 不启用                         |
| 自动网络重试／模型回退         | 0／0                         |

这些是已有报告中的历史登记值，不是对当前服务可用性、模型内部版本或价格的重新核验。正式执行前应确认本轮允许使用的精确配置；若必须改变，应在首个模型响应产生之前固定新的条件身份，不能在运行中回退到另一模型。

即使教师名称保持相同，本轮公开协议、任务和预算已经改变，**也不能把新旧成功率差异直接解释成源码修订的因果效果**。

### 3.3 会话预算：统一上限，明确包含 Final

建议本轮采用：

| 资源项                 | 每会话 |    全试验 |
| ------------------- | --: | -----: |
| 最大实际 Action 尝试      |  12 | 最多 144 |
| 最大公开 Submission     |  32 | 最多 384 |
| 最大 Provider attempt |  32 | 最多 384 |
| 失败会话替换              |   0 |      0 |
| 自动网络重试              |   0 |      0 |
| Student 参数加载／更新     |   0 |      0 |
| GPU 作业              |   0 |      0 |

Update 仍必须对应 pending Observation，不能脱离 Action 独立增加可消费 Claim。

选择 32 次提交，而不是复用旧 Share 的 12 次，是因为当前 branch 的完整合法流程已经需要：

$$
8\text{ Action}+8\text{ Update}+1\text{ Final}=17.
$$

统一上限同时给三类任务保留一定纠正空间，但**32 是硬上限，不是必须用满的调用目标**。有效 Final 后立即停止。

Token 预算不能从旧 Share 请求长度照搬。准备阶段应使用新协议的真实序列化请求，确定并冻结每请求输入准入预算 \(I_{\max}\)、输出预算 \(O_{\max}\) 和累计 allowance：

$$
B_{\max}=384\,(I_{\max}+O_{\max}).
$$

这里的 allowance 与响应实际 usage 分列。离线样本长度检查不声称穷尽未来所有 State；每次发送前仍检查实际请求，超限则记录资源终止，**不截断 Evidence、候选集或 pending Proposition 后继续冒称同一条件**。

## 四、只补齐在线接入新增的接口，不另造一套执行器

### 4.1 在线模型适配必须使用同一个 Runtime

建议实现路径为：

```text
统一 Catalog 和 source-bound Task
→ 同一个 ProgramTaskAdapter / ShareTaskAdapter
→ 同一个 PublicQARuntime
→ 新的实际模型 callback／transport
→ 原始公开响应
→ 原有严格准入、执行和 Update
→ 独立会话核验
```

可以增加在线编排、会话 Manifest 和模型证据模块，但不能复制一份“模型专用 Runtime”，再让离线和在线两条路径逐渐分叉。

当前 `ExternalJSONCallback` 只说明普通调用端可以接入，并没有真实模型归属证明；因此，**把 callback 的 `origin` 改成 `model` 不是接入完成**。

新的模型来源记录应实际连接：

$$
\text{Session}
\rightarrow
\text{PublicRequest/State}
\rightarrow
\text{ProviderAttempt}
\rightarrow
\text{公开响应}
\rightarrow
\text{Submission}.
$$

原始公开文本必须直接进入当前 Parser。不能补齐 operation、candidate IDs、basis、expected effect、proposed Claim 或 Final 引用；也不能在失败后调用 fixture 作为备用生成器。

### 4.2 单独记录“响应归属”，不要把 Host 预先提供的内容称为模型自主推导

建议每份结果附一张固定的责任表：

| 内容                                    | 当前协议中的责任               |
| ------------------------------------- | ---------------------- |
| 公共任务、计划结构、合法候选及其约束                    | Host／任务合同提供            |
| 选择哪个合法 Action、提交哪种 Update disposition | 模型公开提交                 |
| subgoal、basis、expected effect 的响应内容   | 模型提交，但受 Host 已公开候选合同约束 |
| 数值 Operation 和 Observation            | Host 工具执行              |
| 对 Observation 的明确接受／拒绝                | 新一次模型提交                |
| 内容是否合法、Final 是否有效                     | 独立验证器判断                |

因此，成功结果可以说明模型完成了受约束的公开判断与执行，**不能仅凭字段填写完整就宣布模型自主发现了 subgoal 或 expected effect**。

本轮不请求私有推理，不以解释篇幅或“思考 Token 数”衡量关键推理深度。

### 4.3 为在线失败增加有限、可重放的 Outcome 记录

这是下一轮必须补齐的新增接口，而不是重新否定离线阶段。

当前报告承认：callback／executor 异常会保留终止记录，但未闭合会话不在当前合格证明域中。在线试验需要进一步区分“完整观察到失败”和“证据真的缺失”。

建议至少分别保存：

```text
执行是否开始、是否已终止
Provider attempt 是否有对应观测
公开响应是否存在、是否通过 Schema
最后一次实际 State 与事件
终止原因
证据完整性
有效 Final 是否存在
QA / trajectory / Qualified 的可判定状态
商投影是否受支持
```

关键规则是：

**有完整证据的超时、资源终止或预算耗尽，可以是端到端失败；没有合法 Final 时，Final 条件 QA 可以为 null，但端到端成功事件仍为 false。**

**工件缺失、父关系无法确认或终止未知，则是 evidence incomplete，不能直接填成模型失败。**

这里只需要覆盖当前新路径实际可能产生的有限终止类型，不必重新搭建旧 192-Job 体系的全部 Terminal Registry 或生产级异常证明。

## 五、把准备、在线执行和导出放在同一轮

建议阶段名称：

```text
finance_qa_vnext_representative_model_execution_and_export_pilot
```

这是建议的新阶段名称，不表示当前已经存在对应在线 CLI。

### 5.1 零调用准备部分

这一部分完成三个任务和十二会话的精确登记、请求呈现、资源检查、模型来源绑定，以及必要的局部控制。**不再单独安排“设计审计—接入审计—控制审计”三轮。**

新增控制集中在四组即可：

| 局部控制                 | 检验的新增风险                                               |
| -------------------- | ----------------------------------------------------- |
| 一个 branch 完整 mock 会话 | 17 次合法提交能经过新 transport 接口；不会因错误继承旧上限而提前停止             |
| 一次未准入提交后，由新回调提交正确内容  | 旧响应未被改写，反馈与新 State 被保留，导出只选择实际准入目标                    |
| 无公开响应／身份不符的失败控制      | attempt 被消费，不重试、不伪造 Submission、不回退 fixture            |
| 新旧协议与导出边界控制          | 不能拿旧响应补新字段、不能混入 fixture 或未来 State、不能给未映射轨迹伪造 State ID |

这些是 adapter/mock 控制，不能进入十二个真实模型会话的分母。

准备过程中发现具体接口缺陷，只修复该缺陷并在首次在线调用前冻结实现。已有 Registry 修复、九条离线集成和旧 Token 权重恒等式不需要再次变成整轮通过条件。

### 5.2 正式在线部分

十二个会话各启动一次，不因失败而替换。

收到公开内容后，即使 JSON 或语义不合格，也按照冻结协议记录对应提交与反馈；模型可在同一会话剩余预算内作新的提交。这不是网络重试，也不允许修改历史响应。

没有公开内容时，不伪造空 Action 或 Receipt。保存实际 attempt 及类型化终止，并结束相应会话。

出现模型失败，不中途修改提示词、增加 Completion 预算或指定另一条路线。出现会污染后续证据的实现缺陷，则停止受影响运行，保留已发生部分和未启动会话；不能将这个部分执行报告成完整十二会话。

### 5.3 在线后直接完成只读核验与导出

同一轮执行：

```text
十二会话执行记录
→ 模型响应归属核验
→ 独立 QA／轨迹核验
→ 广度、深度与失败定位
→ 当前支持域内的有限比较
→ 原请求—原响应监督候选导出
→ 本地 Token 化和 mask 检查
→ 一份分层结果报告
```

不以“至少有多少成功样本”为条件追加采样。没有成功会话时，正向导出为零，是需要解释的模型结果，不是触发补样的理由。

## 六、测量方案：成功率、广度、深度和商状态分别报告

### 6.1 主指标：每个固定任务的完整成功比例

对任务 \(x\) 的第 \(r\) 个会话定义：

$$
Y_{x,r}
=
\mathbf 1[
\text{存在有效 Final}
\land V_{\mathrm{QA}}
\land V_{\mathrm{trajectory}}
].
$$

当四个会话都具有完整、可判定证据时：

$$
\widehat q_x=\frac{1}{4}\sum_{r=1}^{4}Y_{x,r}.
$$

总体可报告等任务权重平均：

$$
\widehat q_{\mathrm{pilot}}
=
\frac13\sum_{x\in\mathcal X_{\mathrm{pilot}}}\widehat q_x.
$$

必须同时展示三个任务各自的分子／分母，不能用总体均值掩盖 branch 全部未完成。

如果有未知或未启动会话，保留：

```text
success / known_failure / unknown / not_started
```

不删除未知行后重新归一化，也不把它填成零来伪造完整总体。

### 6.2 广度：区分来源覆盖、执行覆盖和成功见证

本轮完整 coverage 表仍列出十一类，但状态应是：

* 三类被选入本轮模型总体；
* 另外五类已有当前来源实例，但本轮未做模型测量；
* 三类仍缺少当前允许范围内的合法来源。

这三种状态不同。已有来源表支持上述区分，不能把“本轮未选中”写成“没有来源”，也不能把“注册了”写成“模型执行过”。

可报告“选定三个任务中，几个获得至少一个完整成功见证”，但不要把它称为整个 Finance QA 的总体覆盖率。

### 6.3 深度：从实际轨迹重建，不从题型填表

继续保留三个已有指标：

$$
d_{\mathrm{structural}},\qquad
d_{\mathrm{semantic}},\qquad
d_{\mathrm{observable\ choice}}.
$$

它们分别对应真实 Action 依赖、语义操作依赖、可观察选择依赖；不是 callback 数、解释长度或隐藏推理质量。

每个有效模型会话独立重建这些值。未完成会话可以另报“已到达前缀深度”，但必须明确它不等于任务完整深度。

**不能因为 branch 成功率低于比较题，就宣称深度导致失败。**三个任务同时存在来源、结构、操作和输出要求差异，本轮不是深度的因果对照。

### 6.4 公开推理落实：看实际选择与依赖，不看字段数量

本轮重点检查：

> 模型提交的 selected Action 是否真正执行；所声明的依据是否实际使用；accepted Claim 是否来自后续独立 Update；后继 Action 与 Final 是否消费了相应 Claim。

对 Share，只有最终有效链条实际使用了重建总额 Claim，才能记为重建支持见证；仅调用过 `relation_sum`，最后仍读取披露总额，不够。

对 Program，计划给定条件继续明示。即使模型完整执行八个节点，也不能写成自主发现了八步计划。

### 6.5 商比较是受限附加结果，不阻断主试验

当前比较器只覆盖完整合格、纯 accept 的事件域；有意义的 reject 或未准入纠正账本会使投影保持 `undetermined`。

因此，下一轮必须允许：

```text
Qualified = true
projection_status = undetermined
```

这不是矛盾，也不允许为了获得类数而删除纠正历史。

每任务最多四条有效轨迹，最多：

$$
3\binom42=18
$$

个同任务配对。只在当前规则支持时比较，不跨任务比较，不继承旧 Share State ID。

**本轮不要求得到两类，也不要求完整物化新的 \(\pi(z\mid x)\)。**若映射不完整，保留实际支持描述、已确定关系和未定原因，不将可映射子集的频率冒充全部有效轨迹分布。

## 七、新轨迹的数据表示：导出可以推进，类权重不能提前继承

### 7.1 先导出新协议的原始监督候选

本轮建议建立新的数据版本，准入条件为：

$$
\text{真实模型来源已绑定}
\land
\text{所在会话 Qualified}
\land
\text{该提交实际 admitted}.
$$

输入仍取该次真实 HTTP 请求中的公开 messages；目标仍取同一模型响应的原始公开字符串。保留当时的反馈、候选集、State 和数值表示。

这沿用旧实验已经验证的**来源保留原则**，但不是直接复用旧数据或旧固定行数。旧实现明确保留原请求和响应，并排除失败会话及未准入提交。

新行至少分别记录：

```text
task_id / context_id / protocol_id
session_id / turn_index
public_runtime_state_id
model_origin_evidence_id
request_id / response_id / submission_id / receipt_id
qualification_id
messages / target_text
projection_status
quotient_assignment_id（允许 null）
```

这里特意将 Runtime State 和商状态分开命名，避免两个 `state_id` 混用。

### 7.2 没有商 Assignment，不伪造类条件训练对象

旧 27 行导出要求既有 Assignment，因为它服务于已经闭合的两个状态和固定类内核。新会话尚不一定能够映射，所以本轮导出的第一层应叫：

> **新协议原始监督候选集。**

它不自动成为类条件物化结果 \(M_\psi\)。

有资格但投影未定的会话，可以保留原始监督候选；其 `quotient_assignment_id=null`，不分配 VTDO 类权重。这样既不丢失真实有效行为，也不越级制造分布优化对象。

**旧 P/Q、旧 \((4/5,1/5)\) 和旧类内核都不继承。**它们只对原五条轨迹和原表示合同成立。

### 7.3 同轮完成本地 Token 化，但不更新参数

继续使用已经绑定的本地 tokenizer 作为首选表示基线，重新检查新消息长度、目标边界、mask 和因果位移。旧实验的最大长度 24,576 是已登记条件；不能因为旧 27 行都能容纳，就推断新 branch 请求也能容纳。

处理规则：

**可容纳：**形成新协议 Token 记录与可消费表示。

**不可容纳：**原始会话和资格结果继续保留，Token 表示层标记不适配；不静默截断，不因为训练表示失败否定真实模型已经完成任务。

**没有 Qualified 会话：**候选集为空，Token 化没有正向对象；不制造占位行，也不报告“训练数据接入已验证”。

这一轮不计算新的类权重、不复跑旧 P/Q probes，不进行 Student forward、反向传播或优化器更新。

## 八、完成条件与结果后的唯一修复方向

### 8.1 工作流通过，不要求模型全部成功

建议只设置四个完成对象：

| Gate         | 本轮应当闭合的内容                                |
| ------------ | ---------------------------------------- |
| **G0：条件与接入** | 三个任务、十二会话、生成配置、预算、真实模型来源和当前 State 绑定准确   |
| **G1：执行证据**  | 不替换、不静默重试，成功、失败、未知与未启动完整分列               |
| **G2：资格与测量** | 独立核验真实轨迹，分母正确；广度／深度不越级解释，投影未定不伪装为有效类     |
| **G3：表示衔接**  | 对实际符合条件的响应原样导出，正确检查 Token 边界；新旧协议和类权重不混用 |

模型零成功仍可能对应完整、有效的实验负结果；但此时“模型可达见证”和“正向数据表示验证”没有成立，不能把执行完整写成这些科学对象通过。

### 8.2 按结果定位下一步，不事先要求追加审计

| 观察结果                                    | 合理的下一步                                    |
| --------------------------------------- | ----------------------------------------- |
| 三个任务都有完整模型成功                            | 关闭代表性模型接入问题，推进更多既有来源实例和新协议测量              |
| 比较／Share 成功，branch 主要在某一 Update 或依赖引用失败 | 只围绕该具体接口或长依赖问题设计新条件对照，不重新做来源与 Registry 审计 |
| 全部任务主要失败于 Schema 或请求呈现                  | 修复公共接口呈现；不通过扩大题型来绕过                       |
| Qualified 轨迹较多，但纠正事件导致投影未定              | 后续只扩展这些实际事件的有限测量解释，不删除它们、不补样凑纯 accept     |
| 模型执行合格，但新请求无法进入所选 tokenizer 长度范围        | 修复训练表示／模型配置适配，不回写轨迹失败                     |
| 少量或零成功，证据齐全                             | 保留有界负结果；不能为追求成功率追加会话或修改原条件                |
| 原始响应或终止证据缺失                             | 先修观测接口，不能用已有正确答案补偿                        |

本轮不存在“必须取得 12/12”或“Share 必须两类”的通过条件，也不需要先修完全部历史测试、补齐三个来源缺失类型或实现一般知识修订。

## 九、这轮之后如何回到 VTDO，而不是继续停留在接口实验？

**本轮完成后，应停止同内容的接入证明。**后续推进围绕新产生的数据，而不是不断追加新的 preflight 名称。

首先，在新统一协议上扩展到其余已有来源类型和更多真实绑定，建立用于后续训练／评价的固定任务面板。来源不足的类型继续明确记录，不能用重复会话或表面改写代替新实例。

随后，对该面板上的实际有效模型轨迹闭合商映射和类内表示。某些任务只有一个商状态时，可以保留点质量；不能为了得到非退化分布而删除这些任务，暗中改变已经冻结的任务边际。

最后，在独立评价目标和受益模型／优化协议明确之后，才开展类权重干预的 Student 对比及 Contribution 检验。旧单题训练表示可以保留为接口回归，但同题答案复现不能作为泛化收益。

### 建议冻结的下一轮范围

```text
研究条件：
  给定公开计划与合法候选下的模型选择、执行和显式 Update

实验总体：
  3 个已有来源任务 × 每任务 4 会话 = 12 个新模型会话

执行边界：
  每会话最多 12 Action、32 Submission、32 Provider attempts
  全部最多 384 Provider attempts
  无自动重试、无失败替换、无路线定向补样

本轮输出：
  模型归属证据
  完整会话 Outcome
  分任务资格、失败定位与实际深度
  有限比较及未定记录
  新协议原请求—原响应监督候选与 Token 表示检查

不执行：
  新来源扩张、自主规划改造、一般知识修订
  旧数据改写、旧 P/Q 权重迁移
  Student 参数更新、Contribution、VTDO 更新、训练 Release

旧主链：
  保持暂停
```

**这轮的成功标准不是把成功率调到满分，而是让“统一 QA—真实模型公开行为—独立验证—新协议数据表示”成为同一条可追溯路径。完成这一步后，才有依据在新的统一条件上扩大任务面板，并把研究重点真正推进到有效行为分布对训练的影响。**
