# 一、本轮实验审计

## 1. 当前声明：检验的是实际公开行为等价，而非答案相等

本轮的正式对象是：

$$
N_R\!\left(G_{\mathrm{public}}(\tau_i)\right)
\cong_{\mathrm{typed}}
N_R\!\left(G_{\mathrm{public}}(\tau_j)\right).
$$

也就是从实际保存的轨迹恢复公开结构，在授权归约后检查类型化图对应，而不是根据 B/A 名称、Program 节点数量或最终答案判断。

报告明确：六条轨迹及前轮执行结果已经被观察，因此本轮是**已知候选上的测量规则实例化与有限比较**，不是数据盲确认；测量合同与候选域在投影和比较前持久化，没有根据类别数事后调整规则。这个定位准确。

本轮也没有修改前轮历史结论。前轮的类数 `null` 仍表示前轮未开展测量；现在的“一类”是新测量得到的结论，不被回写成前轮当时已知的事实。

## 2. 实现状态：报告中的证据对应了上一轮提出的关键要求

### 2.1 实际输入域保持不变，没有重新生成候选

本轮读取六条已保存的声明、执行描述、结果和独立验证记录，按精确身份连接原始 Archive 行、EvidenceBundle 与 RealizedTaskPackage，没有调用 `source_inventory`、`build_family`、`run_candidate` 或旧 builder。

每条轨迹只经过一次现有只读验证，重新生成的完整验证结果与前轮保存结果一致；验证重放与历史实际执行分开计数。 

因此，本轮不是“多跑一组一样的轨迹”，而是使用已经成立的执行证据，完成新的语义测量。

### 2.2 公开行为没有被简化成四个算术节点

规范化图保留了任务、Evidence、Host 可比性检查、决策、Receipt、Operation、Observation、Claim、Update、State effect、义务和 Final 共十二种节点类型。

其中包括实际决策依据、字段来源、Claim 的生产与消费、Observation grounding、状态增量，以及义务履行关系。运行 ID、路径和装饰性标签与这些保留语义分开。

报告还保存归约前图和实际 State witness；出现无法解释的字段、未知语义或未授权效果时，进入 `undetermined`，而不是静默删除。**这直接回应了上一轮最重要的风险：算术结果相同，不能成为删除公开决策与更新的理由。**

### 2.3 lookup 收缩具有实例级依据，不只是依赖“透明”标签

本轮对实际十六个 lookup 逐项检查：

| 收缩条件    | 实际核对对象                                       |
| ------- | -------------------------------------------- |
| 精确注册语义  | 对应版本、公式、角色与合同哈希                              |
| 值与来源保持  | selected reference、payload、单位、Evidence 角色及输出 |
| 引用可替代   | 实际消费者、selector、操作数位置与替代后的精确值                 |
| 当前信息合法  | lookup 与消费者所在 State 已可见同一 Evidence           |
| 无额外保留效应 | 完整状态增量中没有其他验证、拒绝、修订或失效效果                     |

报告记录五项条件均在十六个实例上通过。

尤其是 selector 路径被明确解释为：

```text
B/C：
Evidence payload
→ lookup 输出 {selected_ref, payload}
→ growth 使用 payload.value

A：
同一 Evidence payload
→ growth 直接使用 value
```

两条路径对应同一 Evidence、同一值与同一 growth 操作数位置。lookup 的 verified Claim 被收缩，不是因为“验证过的 Claim 不重要”，而是因为这里验证的命题仅为已可用 Evidence 的透明转发，并且没有其他保留效应。

**这是当前归并结论成立的核心依据。**它不授权未来无条件删除所有 lookup，也不授权删除真实证据获取或核验行为。

### 2.4 等价结论有完整对应，而非只比较图哈希

六个配对均保存完整的四十节点双射与一百二十七条边的对应，检查全部属性、有序角色、位置、selector 和双向边多重集合。

报告还记录了一条不导入比较器、候选验证器或 Runtime 的独立只读证书检查路径，逐项核验节点覆盖、属性和边映射。六份证书均通过。

因此，本轮给出的证据形式已经足够支持**当前有限图域中的等价判断**；没有必要再要求通用图规范化器、全域形式证明或另一轮重复证书审计。

## 3. 直接反例检查：本次没有发现推翻限定声明的问题

### 3.1 独立数值复算与报告一致

依据报告公开的八个财务标量，我用如下运算顺序、二十八位 Decimal 精度复算：

$$
g(v_0,v_1)=\frac{v_1-v_0}{|v_0|}\times100,
\qquad
a=\left|g_R-g_I\right|.
$$

结果为：

| 任务 | 本次复算结果                          | 与报告答案 |
| -- | ------------------------------- | ----- |
| F1 | `32.54204712363284576989705565` | 一致    |
| F2 | `0.169266826069458582893397411` | 一致    |

输入和报告值见本轮数值表。该复算检查的是**公开标量与答案表的算术一致性**，不替代源码中的 Decimal 合同核验。报告也正确地将这些值解释为冻结有限精度计算的结果，而非无限精度实数值。

但必须再次强调：**这个复算不能独自证明行为等价。**行为等价的依据仍然是实际结构、条件收缩与完整图对应。

### 3.2 数量关系自洽，没有把节点、配对和样本混为一谈

本轮主要数量可以直接核对：

$$
2\binom{3}{2}=6
\quad\text{个同任务无序配对},
$$

$$
2\times2\times4=16
\quad\text{个 lookup 实例},
$$

$$
1+4+1+7\times4+5+1=40
\quad\text{个规范化节点}.
$$

B/C 比 A 多四组各七个节点的透明转发结构，因此：

$$
68-4\times7=40.
$$

这些关系与报告一致。**一百二十七条边的实际内容则需要证书或原始图检查；本次算术核对没有独立验证这些边。** 

### 3.3 新增控制针对了当前比较器的真实风险

二十二项控制中，最有科学意义的并不是总数量，而是以下三类边界：

**保留语义不能被 Final 相同掩盖。**改变 Evidence 来源、有序角色或高精度有效数字时，比较器返回保留语义差异。

**透明性不能通过删除摘要标志伪造。**额外验证结论被加入实际 State witness 后，检查器重新计算条件，拒绝将该效果随 lookup 消去。

**未知不能被填成确定分区。**A 相关关系未知时，不擅自将其并入或单列；矛盾关系也不能形成确定类别。

报告明确这些是投影、witness 或关系表上的隔离控制，不是新的完整 Qualified 金融轨迹。因此，不能将其中三个 `different_retained_semantics` 控制计为三个真实行为类。**当前报告没有作出这种越级解释。**

报告的四项 Gate 不要求类数大于一，也没有用其他指标补偿 UNKNOWN。当前十六个收缩实例及六个配对均记录为闭合，因而 `4 PASS / 0 FAIL / 0 UNKNOWN` 与“一任务一类”的结果不矛盾。

**Blocking defect：在本次审阅范围内未发现。**无强制修订。

**Scope limitation：当前比较器在六条已知、无额外修订效果的确定性轨迹上得到结果。**它没有证明任意新语义结构均可解释，也没有提供两个真实不同的有效行为类。这些限制不否定本轮。

**Future hardening：通用规范化、完整动态 Evidence 到达、复杂修订及更强联合篡改检查。**它们不是当前新增门槛，不应继续延长本轮审计。

## 5. 当前授权结论：商归并成立，非平凡分布支持仍未出现

对每个固定任务 \(x\)，现在可以接受：

$$
[\tau_{x,B}]_{\sim_R}
=
[\tau_{x,A}]_{\sim_R}
=
[\tau_{x,C}]_{\sim_R},
$$

所以：

$$
\left|\{\tau_{x,B},\tau_{x,A}\}/\sim_R\right|=1.
$$

C 属于同一类，但仍然只是调度控制，不是第三个策略。F1、F2 的类别数也不能相加后解释成某个任务有两个状态。

对 VTDO 的直接含义是一个**条件性逻辑结论**：

> 假如训练支持只取自当前已构造的候选族，那么每个任务的商支持是单点集，没有可供优化的类间概率自由度。

$$
\Delta(\{z_x\})=\{\delta_{z_x}\}.
$$

这**不是**模型生成概率已经被测得为一；本轮根本没有测量模型生成分布。它也不排除同一商类内部不同表达的训练效果可能不同，但那首先属于类内物化规则 \(M_\psi(\tau\mid x,z)\) 的问题，不能冒充 VTDO 的类间概率优化。

因此，当前阶段没有剩余 Blocking defect。**下一未完成对象是具有真实任务相关差异的行为来源，而不是继续强化本轮归并证书。**

# 二、后续实验：真实充分依据选择的最小构造与分离预检

## 1. 为什么建议换这个变化轴？

本轮已经关闭了：

```text
透明 lookup 删除
同一 Evidence 直接引用
纯标签变化
独立 growth 换序
```

报告最后也明确要求停止沿这些轴机械扩样。

我不建议下一轮马上把 `growth` 拆成更多算术节点，再以节点数量和 Operation 名称差异寻找第二类。那可能仍然只是同一个求解过程的计算展开；而前轮也指出，当前声明来源形式尚缺少相应增长率分解组合规则。

**更值得检验的是：两条路线是否真正选择和使用了不同的充分依据，并承担不同的依据验证义务。**这正属于已接受设计允许变化的实际支持选择、类型化依据与推导依赖，而不是外观差异。

建议新增一个范围明确的阶段，暂命名为：

```text
finance_qa_vnext_source_distinct_support_route_constructibility_
and_finite_separation_preflight_only
```

这是**本次建议的新阶段名称**，不是当前报告已经包含的授权。

## 2. 核心实验对象：一个新任务，两条真实证据路线

建议保留增长率绝对差值这一任务家族，但寻找一个具有以下来源结构的**新任务实例 \(x^\ast\)**。

以下符号是实验设计示意，不是已经找到的 Archive 数据：

$$
R_1=R_{1a}+R_{1b},
$$

其中来源必须明确支持：\(R_{1a}\)、\(R_{1b}\) 是该期间收入总额 \(R_1\) 的完整、互不重叠分项，期间、口径、单位和主体范围兼容。

任务仍要求：

$$
a(x^\ast)
=
\left|
g(R_0,R_1)-g(I_0,I_1)
\right|.
$$

设计两条路线：

| 路线           | 实际使用的充分依据                     | 求解方式                          |
| ------------ | ----------------------------- | ----------------------------- |
| **D：直接数值路线** | \(R_0,R_1,I_0,I_1\)           | 使用已披露收入总额，计算两项增长率和绝对差值        |
| **S：分项重建路线** | \(R_0,R_{1a},R_{1b},I_0,I_1\) | 根据分项与合法加总关系重建 \(R_1\)，再完成同一目标 |

这里希望检验的不是“多一个 aggregate 节点”，而是：

> S 的收入 Claim 是否真正由分项 Evidence 和加总依据产生，D 则由已披露总额产生；这两种支持及其使用关系在商归约后是否仍然不同。

**当前报告没有证明这种来源结构已经存在。**下一轮必须先核验来源；不能凭两个数字相加恰好等于第三个数，就自行认定它们构成合法总分关系。

## 3. 为什么必须使用新任务／新验证上下文？

F1/F2 当前冻结了精确 Evidence universe、角色与引用约束。不能给它们临时加入分项，再宣称仍是在原合同下发现新行为。前轮对此有明确约束。

因此：

**旧 F1/F2 与历史结果全部保留。新建 \(x^\ast,\Omega_{x^\ast}\)，在新任务内部同时允许 D/S 两套充分支持。**

两条路线必须共享相同的公开问题、Evidence universe、答案 Oracle、单位、舍入、容差和最终目标，不能每条路线使用不同任务合同。

新 Evidence universe 可以同时包含总额和分项，但必须区分：

$$
\text{当前可见的全部 Evidence}
\neq
\text{某条轨迹实际使用的 Evidence}.
$$

否则，两张图都含有同一全集，就可能掩盖真实支持选择差异。

这是 **QA 实验对象构建**，不是一次 VTDO 概率更新；不得把新任务加入后的变化归因于 \(\pi(z\mid x)\) 优化，也不得与旧任务混合后计算“同任务多类”。

## 4. 来源核验、实现和执行放在同一个有限实验内

不建议把它再次拆成多轮“设计—审计—来源设计—审计—执行”。可以在一个零 Provider 预检中按顺序完成，遇到具体阻塞即停止相应分支。

### 来源范围：只进行一次有限检查

首轮只读当前冻结 Archive 的原始材料，检查是否存在一个满足上述关系的任务绑定。选择规则应依据来源中明示的总分结构、期间和角色等条件，在候选执行前固定；不先执行大量路线，再只留下答案相同的案例。

来源条件至少包括：

**总分关系有来源依据。**不能仅凭数值巧合，不能遗漏抵销项或其他组成项。

**范围和口径相容。**分项必须对目标总额完整且不重叠，单位、期间及定义可验证。

**两套支持都能独立履行冻结目标。**不是一条路线读取总额，另一条表面引用分项、实际仍使用总额。

若当前 Archive 没有这样的结构，应输出明确的 `source_not_instantiated` 及缺失条件，**不伪造分项、不把计算出来的数字标为原始 Evidence，也不转而无限搜索其他变化轴**。外部来源补充属于后续另行确定范围的工作，不包含在本轮有限方案内。

### 实现边界：允许必要的局部扩展，不改旧合同

可以新增一个 preflight-only Task／Binding 合同，以及一条明确的总分重建组合规则。现有 Catalog 记录了 `aggregate`，但现有报告没有提供足以确认其输入限制是否覆盖该来源结构的全部信息，不能直接假定可以复用。

因此，应检查实际注册语义：

* 能直接支持时，复用精确版本；
* 缺少的是组合或角色解释时，新增局部版本化合同；
* 需要改变 primitive Operation 的含义时，记录具体阻塞，不静默改旧注册。

这些工作只服务这一条总分重建路线，不要求同时完成通用 QA 生成器或整个 Catalog 升级。

### 执行规模：一个新任务、两条主路线足够

建议首轮边界为：

| 项目                   | 建议范围           |
| -------------------- | -------------- |
| 新任务实例                | 至多 1 个         |
| 主路线                  | D、S 各 1 条      |
| 新候选 Runtime 执行       | 来源与合同准入后至多 2 次 |
| Provider／凭证／GPU      | 0／0／0          |
| 新任务家族                | 不要求            |
| 训练、状态频率、Contribution | 不执行            |

两条路线在相同的新 Runtime 和验证语义下各执行一次，失败结果保留，不替换成另一条直到成功。历史 B/A/C 可以作为不改写的回归证据，但没有必要重新生成整批历史轨迹。

## 5. 推理和 Validity 应如何体现？

### 共同义务不变，路线特有前提单独验证

两条路线共享任务必要义务：来源与可比性、收入增长、营业利润增长、有序差值及绝对值、最终 grounding。

S 额外承担总分重建的前提：组成项完整、不重叠、口径一致，以及实际加总结果的来源。

**不能要求 D 也执行一遍分项重建才有效。**那会再次把所有合法路线收束为同一个脚本。

相应地，共同关键义务覆盖与路线特有前提可以分别报告；不能通过改变 coverage 分母，让某一路线“看起来更完整”。

### S 必须真正完成公开的依据判断与更新

S 的公开链应能够检查：

```text
当前可见总分关系及分项 Evidence
→ 提出使用分项重建收入总额的依据与 Action
→ 实际加总
→ 实际 Observation
→ 接受带分项来源的收入 Claim
→ 后续 growth 消费这个 Claim
→ 同一 Final 目标
```

最终验证器可以使用冻结答案 Oracle 核对结果，但**验证器读取总额的动作不能补写成 S 的行为**。如果 S 实际直接消费了已披露总额，那么它没有形成所声称的分项支持见证。

本轮仍全部标记为 `deterministic_fixture` 或相应 Host 来源，不计为模型拥有的公开推理。

### 不可补偿关系继续保持

$$
V_{\mathrm{qualified}}
=
V_{\mathrm{QA}}\land V_{\mathrm{trajectory}}.
$$

即使两条路线最终答案相同，只要 S 的总分关系不成立、引用不真实或实际依赖与提案冲突，就不能 Qualified。反过来，轨迹链完整也不能补偿错误答案。

## 6. 语义比较与执行验证在本轮一起完成

当前比较器遇到未解释结构会返回 `undetermined`，这是正确边界。新 aggregate／总分依据进入轨迹后，需要在新测量版本中明确其类型化解释，不能因为 executor 能运行，就假定旧投影器已经理解该行为。

本轮只需实现这一有限扩展，并保留已经确认的旧规则：

**透明转发仍可条件收缩；独立调度仍归并；真实来源、使用边、分项依据和非透明推导依赖继续保留。**

正式比较 D/S 时，应给出三种可能结果：

```text
equivalent
different_retained_semantics
undetermined
```

`different_retained_semantics` 必须定位到实际支持及因果关系，例如：

> 收入增长的 later 输入，在 D 中来源于披露总额 Evidence，在 S 中来源于两个非别名分项及合法加总 Claim；这些支持边不能由透明转发或 ID 重命名规则消除。

不能只写“两个 Program 哈希不同”或“一个四步、一个五步”。

### 最少的直接控制

本阶段只需要针对新对象增加少量控制，不复制之前所有二十二项测试：

| 控制                           | 应当守住的边界                      |
| ---------------------------- | ---------------------------- |
| 分项集合遗漏或重复，但最终数值偶然正确          | 不接受不完整／重叠支持                  |
| 分项期间、单位或主体范围不匹配              | 不允许仅凭加总数值通过                  |
| 声称使用分项，实际后续读取总额              | 不授予分项路线见证；按真实行为判断，提案冲突时判轨迹无效 |
| 只复制 Evidence 并更换 ID，或者只改路线标签 | 不构成第二套实质支持                   |

这些控制的通过证明规则被正确执行，不被计作新的正向语义类。

# 三、下一轮如何判定成功、失败与未评估

这次需要把**实验机制完成**与**多类存在命题**明确分开。

定义当前有限候选上的科学见证：

$$
W(x^\ast)=
\mathbf 1\!\left[
V_Q(\tau_D)=V_Q(\tau_S)=1
\ \land\
\tau_D\not\sim_{\Omega_{x^\ast}}\tau_S
\right].
$$

但只有输入、执行与比较都足以判定时才给出 \(0\) 或 \(1\)；缺失时保留未知。

| 实际结果                      | 正确解释                                     |
| ------------------------- | ---------------------------------------- |
| 没找到合法总分来源                 | 实验对象未实例化，\(W=\text{null}\)；不是证明不存在多种解决行为 |
| 基准路线无法正确执行／验证             | 当前实现存在阻塞，先修复该具体问题                        |
| S 实际执行但无效                 | 当前预注册候选未给出多类见证；不能改合同救回结果                 |
| D/S 都 Qualified，但归并       | 有效局部负结果，\(W=0\)                          |
| D/S 都 Qualified，且实际保留语义不同 | 获得该任务的有限多商类见证，\(W=1\)                    |
| D/S 都 Qualified，但比较缺少解释   | \(W=\text{null}\)，只修复对应测量缺口              |

**不要求工作流必须得到两个类才能被接受，但也不能把没有得到两个类写成“多状态构造成功”。**

本阶段不需要概率估计或置信区间：它是确定性的构造见证实验，不是模型采样。两条轨迹的深度、步骤数和覆盖可以按新冻结合同报告，但均不能替代 \(W\)，也不能直接解释成训练贡献。

若得到 \(W=1\)，下一步才适合在这个真实可选择对象上，落实模型可见 State、公开决策提案与 Observation 后更新协议，并开展另外授权的小规模模型检验。**不必先证明广泛任务覆盖，也不能跳过模型可达性直接进入 VTDO。**

若来源没有落实，应精确输出缺失事实和绑定条件，后续围绕该缺口补充来源或调整新任务设计；不再返回 lookup、措辞或调度轴循环扩样。
