# 一、本轮实验审计

这一范围处理是合理的。**新的商测量不要求重新执行全部前置验证器，只需要准确绑定已经接受的资格证据，并完成本轮新增的投影与关系检查。**

## 2. 实现状态：关键不是得到两个类，而是如何得到两个类

### 2.1 实际行为图与原始交互没有被混为一份“清洗后轨迹”

本轮明确保留三个层次：

| 层次      | 本轮作用                      |
| ------- | ------------------------- |
| 原始交互    | 保存全部提交、拒绝、反馈、顺序、预算及终止     |
| 任务解决行为图 | 表达实际执行、显式接受、Claim 依赖和真实支持 |
| 协议纠正账本  | 解释哪些未获准提交可以不参与分类，以及依据是什么  |

图中保留所有实际执行和接受的对象，而不只是 Final 的祖先。四项 Evidence 都作为共同可见上下文存在，实际使用由 operand、basis、lineage 和 citation 等边决定，避免“可见同一批证据，所以使用依据也相同”的错误。

这与当前理论基础相容：**状态是任务相关的公开解决行为类别，不是原始消息数量，也不是最终答案标签。**

### 2.2 十二条纠正的归约具有具体前提

本轮没有仅凭错误代码删除提交，而是检查 C0–C4：

* 拒绝块没有产生实际执行、Observation、Claim 或 Final；
* accepted Claims、pending Observation、阶段和实际 Action／Update 额度不变；
* 后继是最近的实际准入提交，没有跨越其他准入事实；
* 变化只处于登记的对齐范围，语义目标保持一致；
* 原始提案、字段差异、父关系及预算影响继续保存。

这里两个细节处理正确。

**其一，提前舍入不是 Decimal 表面等价。**完整 Observation 值与六位 Final 值并不相等。可以归约的理由，是错误 proposed value 从未成为 accepted Claim，后续新提交才与同一个既有 Observation 对齐，而不是后来放宽了数值等价关系。

**其二，M03 的 Final 引用纠正不等于实际求解途中换了依据。**两次 Final 指向同一个已接受答案 Claim，之前的 ratio 一直消费重建总额；错误引用被拒绝后，模型才提交符合实际 grounding 的引用。

因此，本轮能够接受的是：

> 这些特定未获准提交，在满足本轮归约条件时，不区分任务解决行为类别。

不能进一步解释为：

> 反馈对模型后续行为没有因果作用，或者这些错误对训练、成本和成功率都没有影响。

后一类主张本轮没有检验，报告也没有通过归并消除预算消耗。

### 2.3 商差异建立在实际生产—消费关系上

M03 保留的是：

$$
E_F,E_O,E_{\mathrm{relation}}
\rightarrow
\mathrm{relation\_sum}
\rightarrow
\mathrm{Observation}
\rightarrow
\mathrm{accept\ Update}

其他四条有效轨迹的分母直接来自披露总额 Evidence。这个区别不仅是“曾经调用 sum”，而是已接受总额 Claim 被后续 ratio 实际消费，并最终连接到有效 Final。

同时，四条直接路线的等价性也不是按支持名称直接判定，而是通过完整节点双射及带角色边保持得到。图大小、答案相同或 correction 次数都不是单独的判据。 

**这完成了上一轮真正要求的新对象：从支持描述进入有限语义关系，而不是把原来的描述字段换名为 State ID。**

$$

# 二、后续实验：固定有效支持的训练表示与类级权重干预预检

以下是新方案，不是本轮已经完成的实现或结果。

建议阶段暂命名为：

```text
finance_qa_vnext_finite_support_training_representation_
and_class_weight_intervention_preflight_only
```

这不是直接开展 VTDO 优化，也不是把经验分布改为均匀后宣布算法有效。它要完成一个更基础、可执行的问题：

> **固定同一批有效轨迹和类内表示，只改变类权重时，训练加载器及损失函数是否确实只改变了 \(\pi(z\mid x)\)，而没有同时改变任务、语义内容、类内选择或隐含权重？**

## 1. 为什么这一步不能被“直接把五条轨迹拿去训练”替代？

当前五条轨迹不是等长的训练单位：

* A 类四条轨迹各有五条准入提交；
* B 类 M03 有七条准入提交；
* 合计二十七条准入提交。

**假如把它们拆成二十七行，然后按行等权，B 的行权重就会变成 \(7/27\)，而不是原来的 \(1/5\)。**

$$
\frac7{27}\approx25.93\%\neq20\%.
$$

如果再按所有目标 Token 直接求平均，隐含权重还会受实际长度影响；具体数值必须等真实 Token 化后才能知道。

这不是本轮已经发生的错误，而是下一训练接入必须避免的直接混淆：

$$
\boxed{\text{轨迹类比例}\neq\text{提交行比例}\neq\text{监督 Token 比例}}
$$

因此，下一轮不应只产出一个 JSONL，而应同时产出**原始轨迹归属、监督范围、类内选择规则和可验证的损失权重**。

## 2. 固定输入，不重新生成或“修复”历史轨迹

使用：

```text
六会话原始父目录
本轮两个 State 与五个 Assignment
五条 Qualified 轨迹的实际 Request / 原始公开响应 / Receipt
对应纠正账本
```

M01 保留为历史失败与审计输入，不进入这轮正向训练池。也不从它的成功中间步骤补出一条新的完整有效轨迹。

本轮两类简称 A/B 与正式 State ID 保持一致；不因训练表示变化，重做旧图归并或换一套状态划分。

**测量用的归约不等于训练数据清理许可。**尤其不能删除某次失败提交后，把后续 State 中的 `last_feedback`、计数或 parent 重新编造为“从未失败”，再将这段新过程标成原始模型轨迹。

## 3. 首版训练表示：采用原请求条件下的准入提交监督

建议第一版采用以下明确选择：

> 从五条 Qualified 会话中，为每条实际准入的模型提交构造一个监督单元；输入使用该次调用的真实公开消息，目标使用该次模型原始公开响应。

由此得到：

$$
11\text{ 个 Action}
+11\text{ 个 Update}
+5\text{ 个 Final}
=27\text{ 个正向监督单元}.
$$

这是依据本轮准入计数得到的拟议导出数量，不代表已经生成训练文件。

### 输入与目标的处理规则

**输入保留当时真实可见内容。**使用实际 HTTP 请求中的公开 `messages`，而不是把整条轨迹重新拼成从未发生过的多轮聊天。原请求含有反馈时保留反馈；不添加当时不可见的后续 Claim 或 Final。

**目标保留模型原始响应内容。**不将长数值缩短、不补 citations、不规范化成另一份“更好看”的提案。分词模板的角色标记可以由训练表示定义，但不能改变消息语义。

**不监督 Host 作为模型产生的内容。**请求、工具 Observation、Receipt 和 Host 元数据不作为模型输出目标；实际模型提交中的 operation、basis、完整 Update 和 Final 才是目标。

**十二条未获准提交在这一版中不承担正向 imitation loss。**它们及其原始关联继续留在审计与纠正账本中。采用零正向权重，是本次训练方案的选择，不是认定这些错误没有研究价值；以后训练显式纠错或偏好模型，需要另外定义目标。

这样得到的是：

> 真实请求条件下，已准入公开提交的条件监督数据。

它**不是**五条全新、无错误、从头到尾未经反馈的轨迹，也不证明删去错误后模型仍会作出相同选择。

## 4. 明确类内物化规则 \(M_\psi\)

先在这批有限池中定义一个最简单、可复现的规则：

$$
M_\psi(\tau_j\mid x,A)=\frac14,
\quad
j\in\{\mathrm{M02,M04,M05,M06}\},
$$

$$
M_\psi(\tau_{\mathrm{M03}}\mid x,B)=1.
$$

其中 \(\psi\) 同时固定：

* 原始请求与响应的选取方式；
* 哪些提交参与监督；
* Token 化与角色边界；
* 一条轨迹内部如何归一化损失。

这是**有限已有轨迹池上的类内采样核**，不是已经完成新鲜轨迹生成。

特别要保留：B 目前只有一个原始有效实现。增加其抽样次数或权重不会增加独立样本量，也不能证明 B 类内部的多样性或训练价值已经得到充分估计。

## 5. 两套权重视图：只检验干预是否实现，不宣称哪套更好

建议使用同一份二十七行基础数据，建立两个只改变权重的视图。

### 视图 P：显式采用经验分布作为基准

$$
\pi_P(A)=\frac45,\qquad \pi_P(B)=\frac15.
$$

这里是**主动选择**将经验条件分布用作训练基准，不是说经验频率天然具有最优性。

### 视图 Q：均衡权重控制

$$
\pi_Q(A)=\pi_Q(B)=\frac12.
$$

这只是便于检查概率质量转移的对照点，**不是已经授权的覆盖先验 \(r\)，不是 Novelty 更新结果，更不是“平衡一定更好”的假设结论。**

结合固定 \(M_\psi\)，轨迹权重为：

| 原始轨迹 | 类别 | 视图 P 的轨迹权重 | 视图 Q 的轨迹权重 |
| ---- | -- | ---------: | ---------: |
| M02  | A  |    \(1/5\) |    \(1/8\) |
| M03  | B  |    \(1/5\) |    \(1/2\) |
| M04  | A  |    \(1/5\) |    \(1/8\) |
| M05  | A  |    \(1/5\) |    \(1/8\) |
| M06  | A  |    \(1/5\) |    \(1/8\) |

两个视图的总权重均为 1；类内四条 A 轨迹的相对权重不变。原始记录无需复制多份，也不能把重采样副本报告为新轨迹。

## 6. 让权重真正作用于损失，而不是停留在 Manifest

建议主损失采用**轨迹内目标 Token 平均，再按轨迹权重混合**。

设第 \(j\) 条轨迹选中的所有准入响应，共有 \(T_j\) 个目标 Token：

$$
\ell_j(\theta)
=
\frac1{T_j}
\sum_{k\in K_j}
\sum_{\ell\in\mathrm{target}_{jk}}
-\log p_\theta
\!\left(y_{jk\ell}\mid q_{jk},y_{jk,<\ell}\right).
$$

则：

$$
\mathcal L_{\pi,\psi}(\theta)
=
\sum_z\pi(z\mid x)
\sum_{j:\phi(\tau_j)=z}
M_\psi(\tau_j\mid x,z)\,\ell_j(\theta).
$$

每个目标 Token 的系数相应为：

$$
\omega_{jk\ell}
=
\frac{\pi(z_j\mid x)M_\psi(\tau_j\mid x,z_j)}{T_j}.
$$

这样，累加后才能准确满足：

$$
\sum_{j:z_j=A}\sum_{k,\ell}\omega_{jk\ell}=\pi(A\mid x),
$$

$$
\sum_{j:z_j=B}\sum_{k,\ell}\omega_{jk\ell}=\pi(B\mid x).
$$

这是一种建议的有限训练目标定义，不是对所有训练实现的唯一规定。其优点是可以直接阻止“B 多两条提交，所以获得额外隐含权重”。

### 本轮只需验证损失组装，不更新模型参数

采用已经明确、可在本地读取的受益模型 tokenizer／chat template，检查真实输入长度、目标边界、截断、padding 和 mask。**报告没有提供这套 Student 配置，下一轮不能凭教师模型的字节数推算其 Token 数。**

若本地 tokenizer 尚未落实，可以先输出二十七行文本及精确有理数权重，但应将 Token 级 mask 和长度检查标记为未实例化，不能声称训练加载已全部通过。

用可控的逐 Token 测试损失，验证加载器聚合值等于上式即可；这属于损失实现控制，不能被叫作 Student 效用或 Contribution。

两个视图可以使用完全相同的记录顺序和 Token 张量，只改变系数。这样可直接检查数据内容未变。以后实际采用小批量重采样、加权训练或其他优化方案时，还须固定其优化协议；**期望损失相同不自动保证任意随机训练过程完全相同。**

## 7. 最少的直接控制

无需再复制本轮十二项商测量控制。新阶段只检查四类风险：

| 控制                                       | 预期边界                  |
| ---------------------------------------- | --------------------- |
| 导出时补字段、改数值、替换请求 State 或使用未来信息            | 拒绝；目标必须来自对应实际提交       |
| 未获准提交或 M01 被加入本轮正向目标                     | 拒绝，或明确零权重且不计入正向池      |
| 二十七行等权导致类质量改变                            | 权重汇总检查必须识别，而非只检查总和为 1 |
| 改变 \(\pi\) 时同时改变类内选择、文本、mask 或 tokenizer | 拒绝“仅类权重干预”声明          |

本轮不需要再次证明 D/S 可执行，也不需要重新跑十个历史配对。Assignment 作为已闭合输入使用，必要时核验其绑定即可。

# 三、下一轮的完成条件与科学解释

## 1. 建议的一轮边界

```text
原始有效轨迹           5
正向监督单元           预计 27
类内选择规则           1 套
类权重视图             2 套

```

“预计二十七行”需要由真实 Receipt 与输入关联重建验证，不应硬填表格。输出应是 preflight-only 数据与权重包，不是训练发布资格。

**这轮直接完成可消费数据与损失权重实现，不再单独增加一次纯文档设计审计。**

## 2. 不同结果应如何收口？

| 实际结果                       | 正确结论                                     |
| -------------------------- | ---------------------------------------- |
| 二十七行来源、mask、类内规则和两套类质量全部闭合 | 已实例化有限支持上的类级训练权重干预                       |
| 原始请求不能正确恢复或目标有 Host 补写     | 定位训练表示缺陷，不重新否定原轨迹的历史有效性                  |
| Token 化需要截断关键状态或完整 Claim   | 当前训练表示不适配所选配置；不能静默截断后宣称语义保持              |
| 文本与权重闭合，但 tokenizer 未落实    | 文本层通过，Token 层未实例化                        |
| 权重总和为 1，但 A/B 的有效质量不符      | 干预实现失败，修复归一化或采样机制                        |
| 所有准备通过                     | 仍不能宣布均衡分布更好、B 的 Contribution 为正或 VTDO 有效 |

这里通过的核心是：

$$
\boxed{
\text{任务和类内表示固定}
\quad+\quad
\text{只改变类权重}
\quad\Longrightarrow\quad
\text{实际训练目标按预定方式改变}
}
$$

而不是任何训练性能改善。

## 3. 为什么暂不直接估计 Contribution？

Contribution 的理论定义已经明确；缺少的是**本实例中可执行的受益模型、训练协议与独立目标性能对象**。不能把训练损失、梯度大小、罕见程度或多一步求和直接当作边际泛化贡献。

本轮训练表示预检完成后，后续有限 Student 试验才可以明确回答“相同 \(\psi\) 下改变 \(\pi\) 的结果”。届时必须另外区分训练数据与评价目标；不能在训练过这道已知题后，再用同题答案复现作为泛化收益证据。

这不要求现在先补齐广泛金融任务覆盖，也不是新增本轮审计门槛。**它只是防止把单任务的可操作性结果直接升级为训练价值。**
