# 固定 H1/H2 的四实例迁移与原样监督表示

## 1. 本轮问题与边界

依据审计《本轮审计与后续实验方案》继续实验。原文 SHA-256：
`2e5e4d720aefa236e6751470e8af5c2dc05985626a1da55ffa7bf351f73da008`。
前继提交 `bf602a421b27183f1281ca47fa1e29622786d112`，其 Harness 对照结论保持
`PASS_AS_SCOPED`，不重跑 H0、原 S/B 两题、Final 校准或原二十二项控制。

唯一主问题是：**固定已经验证的简化接口和有限开放规则后，H2 能否在不同既有真实实例
上继续正确选择证据、组合操作并形成有效答案？**H1 保留为计划辅助参照，不将 H2 预先
宣布为最优条件。不训练 Student，不更新 VTDO，不重定义完整行为商，不恢复旧主线。

这次是四个任务实例、两个任务族，不是四种新题型；两个 HII 实例来自同一文档。
来源以前已经用于开发或确定性验证，不是未接触的盲测集，也不是四个独立来源群。
原审计中“十二条有效轨迹”是三个生成条件的数量合计，不作为一个 Harness 的成功率继承。

## 3. 设计保持与必要的接线桥

直接复用前轮 `StudyRuntime`、`OpenAdapter`、简短引用、显式整观察接受、共同 Final
规则、中性系统提示、独立只读审计及描述性方法签名。前轮 Harness 源文件不修改。
模型／采样设置也不改；仅把运行人口上限从 384 调整为本轮十六注册所需的 512。

H1 仍有完整公开计划与绑定候选；H2 仍只有问题、证据、定义、通用有限工具和当前结果。
HII 两题复用原 Catalog 的同一任务模式编译，不给 H2 注入原节点、证据角色配对或后继义务。
准备中保存的原参考行包含历史数值、图和确定性结果，因此必须留在模型请求之外。

已有参数化 Share 适配器与原 S 适配器存在一个具体差异：其 `prepare` 内部还要求动作
属于原候选，Final 也要求原参考义务名。直接接到 H2 会恢复计划成员限制。
本轮在**新模块的来源桥**中去掉这两处成员／义务名依赖，复用原 `_admit`、
`_check_claim`、执行器、独立数值 verifier 和 Final 数值／引用公式。
Final Eligibility 改为接受过且来源元数据有效的 `scale_percent` Claim；不要求模型把
自拟子目标命名为 `percent`。新增桥显式版本化，不重新解释历史轨迹。

这不扩大 H1 的动作空间：H1 的原运行器准入仍只接受当前展示的精确候选。H2 的实际准入
则根据模型的操作和输入构造提案，检查真实来源、参数、关系和依赖，不搜索参考图节点。
Source bridge 不生成新的 H2 工具说明、绑定候选或问题专属“下一步”。

S 仍要求明确、完整、互不重叠的部件关系，不能凭数值相等伪造重建。
B 仍支持原 Evidence 直接输入、已接受 lookup 后消费及混合输入；差值方向可以交换后取绝对值。
新增控制必须覆盖这些组合，不能只证明标准参考图可以运行。

## 4. 接受与 Final 标准

E/C/O/A 为当前会话的精确别名，`Tn` 绑定当前状态。不能模糊匹配、使用未来／未接受 Claim，
或将 Observation 当成可消费结果。模型必须明确接受所指观察的整个命题；随后仍要另行
选择下一动作。Host 展开的完整 JSON 是 SYSTEM 绑定，不是模型原始生成目标。

两个条件共同使用前轮完整 Final：外层是 `kind/state_id/answer_claim_id/result/citations`；
result 仅 `value/unit`。S 为 precision 50、ROUND_HALF_EVEN、六位小数字符串与 `percent`；
B 为 precision 28、ROUND_HALF_EVEN、原精度字符串与 `percentage_points`，不套用六位舍入。
引用唯一集合必须等于最终 Claim 的实际 Evidence lineage，且答案通过原独立 Oracle。
不代填正确答案，不纠正原始目标，不追加 Final 专门采样轮。

## 5. 固定执行与停止规则

两波各八会话：每波按 U16、J15、H24、H13 排序，每任务依次 H1、H2；第二波后缀 02，
第一波后缀 01。最多八会话并行，波间屏障；HTTP 实际到达次序不是固定总序。
共 16 个独立新会话，无 H0，无 N/E 重建偏好，无失败替换或路线配额。

沿用 `deepseek-v4-pro`、thinking disabled、temperature 0.7、top_p 1、max_tokens 8192、
JSON object、单 HTTP 180 秒硬截止／连接 30 秒，以及 98,304 字节实际请求体上限。
每会话最多 12 次实际 Action、32 次模型提交／Provider attempt；全轮 attempt ≤512。
每次 Token 保留上界 107,520，全轮保留上界 55,050,240；不是实际 Token 用量。
实际 Provider usage 与调用逐次记录，缺失值为未知，不能从配置反推实测 reasoning tokens。

成功立即结束。无自动网络重试、模型回退、在线续跑、失败替换或补样。
模型的有界失败保留并继续原调度；若发生内部／工件完整性问题，已启动波记录到结束，
未启动波登记未知，保留十六分母，不为改到成功重启同一轮。
Student 权重加载、forward、参数更新、VTDO 权重更新均为 0；并行资源用于网络等待和 CPU 验证。

## 6. 本轮测量与结论边界

每任务／条件报告 `q = 完整有效数 / 2`，失败、未知分列；H1 与 H2 各有八条注册，
不把十六条合计包装成单一 Harness 成功率。所有已知失败支出进入成本统计，
不能只报告成功均值，未知使用记录保留且不删除分母。

核心观察是证据／期间配对和方法组织、实际生产—接受—消费与 Final 支持、错误及真实调整、
完整支出和未使用工作。沿用前轮字面错误码与分类；结合原始提案说明错误属于机械表达、
工具语义、证据／期间或数值要求，不能把所有 H2 错误重新称为旧格式问题。

方法签名仅作描述：Final 实际支持树、透明 lookup 折叠、求和部件对称化、有符号差保留顺序。
它不是完整公开行为商，不形成新 π 或类权重，也不要求每个任务出现两个签名或 D/R 两路线。
更短轨迹只有在目标、依据和完整验证仍成立时才可讨论效率，不能自动判为更优监督数据。

若 H2 在多个实例形成有效组合，只支持当前有限开放 Harness 的跨实例复用。
不据此主张通用自主规划、盲测泛化、最优设计或训练收益。结果不理想也按原范围收口。

## 7. 原样监督导出与 Token 长度政策

每条件单独导出完整 Qualified 会话中的**准入响应**，包括 Action、明确接受和 Final。
保留 Provider 的实际内容字节、空格和换行；不将 `language_binding.expanded` 当作目标，
也不为了 tokenization 再正规化 JSON。H2 的短子目标／理由保留为实际响应的一部分。

输入严格为当次真实 HTTP 的 system/user messages，保留 H1 计划、H2 开放条件、当前状态、
实际反馈。完整原轨迹保留全部拒绝，但拒绝不作为正向目标；失败／未知会话不导出正向目标。
后续有效响应的输入中出现拒绝反馈时，反馈照原样保留，不拼造一段没有发生的干净对话。

复用既有本地 Qwen2.5-7B-Instruct tokenizer 的五文件、软件、chat template 绑定，
以及已验证 32,768 最大序列长度、不截断、右侧 padding 政策。
原 tokenizer binding 中历史长度字段只作旧资产引用，不篡改为新值；本轮独立表示政策绑定 32,768。
调用既有精确编码器，而不把新简短响应伪装成旧完整协议候选去通过旧导出器。

只对原始 assistant 内容置 target mask；system/user、角色头和 `<|im_end|>\n` 后缀均不监督。
保留原 suffix token IDs `[151645,198]`、causal shift 1、精确目标 UTF-8 解码、前缀一致性与边界检查。
超长目标保留原候选并标 `not_fit`，不截断，不把表示失败改写成模型任务失败。
会话包是所有准入逐请求样本的集合，不是拼接会话。只有这些样本全部 fit 才称完整 Token 包。

`representation/H1` 与 `representation/H2` 的候选、Token 记录、排除项和会话包分别保存。
不合并成一个训练分布，不分配类权重，不加载模型权重或计算训练损失。
Provider usage 只是生成支出，不能代替上述表示验证。

## 8. 工程与复核入口

新实现：`src/trusted_synthesis/experiments/finance_qa_vnext_harness_transfer/`。
`panel.py` 固定四实例和 Share 接线桥；`stage.py` 冻结、运行及统计；`representation.py`
导出原始简短响应并复用编码器。旧 Harness、旧执行工件、旧商测量和用户已有改动保持不变。
只运行 `tests/test_qa_vnext_harness_transfer.py` 的本轮新增风险控制，不运行旧二十二项测试。

```bash
trusted_data_synthesis/.venv/bin/python -m trusted_synthesis.experiments.finance_qa_vnext_harness_transfer.stage prepare
trusted_data_synthesis/.venv/bin/python -m trusted_synthesis.experiments.finance_qa_vnext_harness_transfer.stage run
trusted_data_synthesis/.venv/bin/python -m trusted_synthesis.experiments.finance_qa_vnext_harness_transfer.stage verify
```

prepare 保存源码冻结、设计副本、来源、参数、十六注册、八个实际初始 HTTP 请求、
本地控制和 tokenizer/表示政策。run 拒绝已存在的执行目录；verify 只核验封存，不发请求。
