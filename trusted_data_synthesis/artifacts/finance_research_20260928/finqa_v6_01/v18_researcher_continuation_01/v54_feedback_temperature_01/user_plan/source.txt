### 为什么选择 \(T=0.5\)

这是一个预先选定的、严格正的候选温度。它让反馈采样更集中于模型当前的高概率输出，同时保留随机 score-function 估计的定义。

**这里没有“低温必然更好”的理论保证。**低温可能减少行为覆盖，也可能让成功反馈更加集中；它不保证梯度方差降低，更不等于 greedy 效用的无偏梯度。

本轮要检验的具体命题是：

> 在同一个 Student、optimizer 和经验分布状态上，低温随机反馈估计出的 C，是否能通过真实的后继训练，带来更好的 greedy 执行效用？

温度固定为 **0.5 一个候选**。本轮不同时搜索温度网格、改变 RMS、缩小外层更新、关闭 dropout 或调整监督目标。

## 二、核心实验：三个父点，三个分支，固定训练到 step894

### 1. 共同起点

使用最新 B 的全部三个训练 seed：

\[
s\in\{137,251,389\}.
\]

每个 seed 选取：

> **C-only 路径在 step596 完成内层训练、第二次 outer 尚未执行之前的完整状态。**

这里必须恢复当时的参数、buffer、非空 Adam、当前 \(\pi\)、训练 RNG、任务游标和材料版本。

特别需要防止两种起点错误：

- 使用 step596 outer **之后**的 \(\pi\)，再声称三个分支来自同一更新前状态；
- 把计算反馈用的虚拟参数 \(\bar\theta\)，当作真实续训的起点。

三个分支的真实训练，都应从原来的真实父参数与 optimizer 开始。

### 2. 三臂矩阵

| 分支 | step596 确定的训练分布 | 作用 |
|---|---|---|
| **Hold** | 保持父点已有的 \(\pi\) | 判断此时继续更新分布是否有必要 |
| **C1** | 使用该父点原 \(T=1\) 的 700 条反馈，计算原 C-only 更新 | 现行算法对照 |
| **C05** | 在同一虚拟参数点新采 \(T=0.5\) 的 700 条反馈，计算 C-only 更新 | 唯一新候选 |

**Hold 必须保持当时的 \(\pi\)，不能命名为历史 Static。**这个父点已经经历过第一次 C 更新，其 \(\pi\) 可能不同于先验 \(r\)。历史 Static 从头保持 \(r\)，检验的是另一个问题。

### 3. 后继学习窗口

三臂在 step596 确定分布后：

- 各自固定 \(\pi\)；
- 执行更新 **597–894，共 298 次真实 optimizer 更新**；
- 保存 **step745** 和 **step894**；
- step745 只做预定诊断；
- 正式终点固定为 **step894**；
- **不执行 step894 的下一次 outer。**

这覆盖当前算法一个完整的两 epoch 外层间隔。它与旧 V18 的 step298→447、149 步 C positive/Static/reverse 试验有明确区别。

三个 seed 全部保留，不按历史表现选择“容易有效”的父点。这项实验的结论范围是：

> 三个既有父点上，一次分布干预经过 298 步真实学习后的效果。

它还不是三个新 seed 的完整算法重训复制。

## 四、低温反馈必须怎样实现，实验才有效

这一部分直接决定新实验是否真正检验了温度假设。

### 1. 采样与回放必须使用同一个概率分布

对于温度 \(T\)，实际策略是：

\[
p_{\theta,T}(y\mid h)
=
\operatorname{softmax}\!\left(\ell_\theta(h)/T\right)_y.
\]

对应梯度为：

\[
\nabla_\theta\log p_{\theta,T}(y\mid h)
=
\frac1T
\left[
\nabla_\theta\ell_y
-
\sum_vp_{\theta,T}(v\mid h)\nabla_\theta\ell_v
\right].
\]

所以，\(T=0.5\) 同时改变：

1. 实际抽样分布；
2. softmax 的归一化；
3. 梯度中的 \(1/T\) 因子。

**只在生成配置中把温度改成 0.5，回放仍算 T1 的 log probability，会使估计对象不一致。**

把旧 \(g_J\) 乘二也不能替代新采样：轨迹没有改变，概率归一化也不同；而且在 RMS floor 未激活时，整体同比缩放还会被现有自归一化消去。

### 2. 分母和 token 范围保持原定义

每个父点仍然是：

\[
350\text{ 题}\times2\text{ draw}=700\text{ 条反馈会话}.
\]

估计量保持为：

\[
\widehat g_{J,T}
=
\frac1{700}
\sum_{i=1}^{700}
R_i
\sum_{t\in\text{实际生成 token}}
\nabla_{\bar\theta}\log p_{\bar\theta,T}(y_{it}\mid h_{it}).
\]

这里有三项不能变：

- 零奖励会话留在 **700 分母**中；
- 使用实际生成轨迹的完整 token 概率，包括错误尝试、恢复和实际 EOS；
- 不套用 SFT 的监督 mask，也不改为按轨迹长度平均。

如果拆成两个 draw 分量，每个分量按 **350** 归一化，合并后取均值。

### 3. 可以共享虚拟点，不能共享温度不同的反馈队列

两个温度可以共用同一父点的类梯度、\(G\)、虚拟 \(\bar\theta\) 和 Adam 回拉算子。

但各自的 \(g_{J,T}\)、回拉结果 \(a_T\)、C、RMS 数值和最终 q 必须分别计算。

交叉检查还发现一项具体的缓存兼容性风险：原 collector 的反馈目录按参数点身份派生，原流程只支持 T1。引入第二个温度后，不能仅因参数点相同就恢复旧反馈。相关逻辑位于 [v8_training_driver.py](https://github.com/haoyueliuzhao/Data-Synthesis/blob/98cf91cd7887e8547a698c1bc69115ef1900a705/trusted_data_synthesis/src/trusted_synthesis/finance_research/v8_training_driver.py)，原 T1 限制与采样配置位于 [providers.py](https://github.com/haoyueliuzhao/Data-Synthesis/blob/98cf91cd7887e8547a698c1bc69115ef1900a705/trusted_data_synthesis/src/trusted_synthesis/finance_research/providers.py)。

方案因此要求：

- 生成前，以参数点、温度、概率合同、题目与 draw 名册等确定独立反馈条件身份；
- T0.5 使用独立反馈缓存；
- 生成后，将实际 cohort seal 和 receipt 绑定到该条件；
- 下游 \(g_J\)、C、q 都追溯到正确反馈队列。

这是引入新温度时需要处理的兼容性问题，不能据此倒推旧 T1 实验已经出错。

## 七、主比较、统计口径与推进判据

### 1. 主比较和关键辅助比较

主比较固定为：

\[
\Delta_{\mathrm{temp}}
=
\frac13\sum_s
\left[
J_{\mathrm{dev,greedy}}(C05,s)
-
J_{\mathrm{dev,greedy}}(C1,s)
\right].
\]

关键辅助比较为：

\[
\Delta_{\mathrm{hold}}
=
\frac13\sum_s
\left[
J_{\mathrm{dev,greedy}}(C05,s)
-
J_{\mathrm{dev,greedy}}(Hold,s)
\right].
\]

同时完整报告 C1−Hold，以判断原更新本身是否有用。

主指标始终是**完整 dev883 分母上的原生执行准确率**。程序准确率、invalid 比例、工具调用和输出长度用于解释，不替代主指标。

### 2. 状态转移帮助解释收益来源

每个父 seed、每项比较都报告同题 I/W/R 转移：

\[
\Delta\mathrm{Acc}
=
\frac{n_{I\to R}-n_{R\to I}}{n}
+
\frac{n_{W\to R}-n_{R\to W}}{n}.
\]

这使两类结果能够区分：

- 无效预测与正确预测之间的净变化；
- 可执行错误与正确之间的净变化。

I→W 虽然降低 invalid，却不会提高准确率。双方可执行子集上的准确率可以另列，但不能取代完整分母。

若某项比较仍有无法解决的 UNKNOWN，该项完整 883 分母估计和晋级判定记为**评价未完成**；不删题、不缩小分母、不把 UNKNOWN 当零。其余已完成结果照实报告。

### 3. 不确定性怎样报告

本轮独立父点数仍为 **3**，不能用九分支、18 个快照或几千条评价回答扩大训练重复数。

方案固定报告：

- 三个逐 seed 差；
- 等权均值；
- 样本标准差、最小值、最大值和正/零/负个数；
- 附加 seed 层 t 近似区间，并明确小样本外推限制；
- 固定父点条件下的来源簇敏感性分析。

来源簇重采样时，同一道题的所有臂共同保留，同一组来源权重同时用于三个 seed。这只能描述来源构成敏感性，不能解决训练父点只有三个的问题。

### 4. 晋级规则

C05 获得后继完整闭环验证资格的默认规则为：

\[
\boxed{
\Delta_{\mathrm{temp}}>0
\quad\text{且}\quad
\Delta_{\mathrm{hold}}>0
}
\]

并且本轮的概率、父点、真实训练与评价合同成立。

**这是方向性的开发筛选规则，不是稳定性确认，也不是显著性证明。**不要求每个 seed 全部为正，但必须展示全部异质性；精确零差保留基线。

| 结果 | 应作的解释 |
|---|---|
| C05 同时胜过 C1 和 Hold | 在这些父点与训练窗口上获得支持，可另行设计完整闭环验证 |
| C05 胜过 C1，但不胜 Hold | 减少了原更新的损害，尚未建立动态更新的净收益 |
| C1 胜 Hold，C05 不胜 C1 | 原 C 在这些父点有价值，低温候选未带来改进 |
| 两种 C 都只提高随机、未提高 greedy | 本候选未解决目标差异 |
| C05 提高 greedy、降低随机效用 | 存在目标取舍，不能称为全面改善 |
| 主要收益来自 I↔R | 端到端交付效用改善，不能直接宣称纯推理能力提高 |
| 内部方向一致性提高，但主效用不提高 | 信号改善尚未转化为真实学习收益 |

### 原 C1 路径可以节省多少训练

若三个原 C1 的 step596→894 完整路径及 745/894 快照都能证明与本方案一致，则可以复用这三条对照路径：

\[
2682-3\times298=\boxed{1788}.
\]

也就是只新增三个 Hold 和三个 C05 的训练。

复用依据必须是父点、q、训练 RNG、任务日程、损失与 optimizer 版本、更新区间的对应关系，不能仅看文件名或总步数。如果另有分布和后续输入完全相同的分支可以共享结果，也可以进一步扣减，但要逐段登记，避免重复计数。

这些训练更新数不包括反馈回放、Adam VJP、缺失缓存恢复和失败重算。实际 GPU 小时与费用应按既有同配置吞吐补充，当前不填虚构估价。

## 九、本轮到哪里结束，怎样连接后续主线

**本轮在 step894 闭合。**

如果 C05 达到筛选条件，下一份协议再验证完整自适应闭环：每个 outer 都在新的 Student、optimizer 和 \(\pi\) 上重新采样、估计、更新，并考察效果是否累积或反转。

后继需要另外明确新训练 seed、完整终点、适当的固定分布参照、反馈预算，以及是否有足以支持未见来源泛化的评价面板。旧 test1147 可以提供已知 benchmark 的可比性，但不能重新命名为未曝光确认集。

如果 C05 未晋级，则根据本轮留下的证据，选择一个后继问题：

- 信号方向冲突、归一化剂量大：单独验证 C 的可靠度或幅度处理；
- 两种更新都不如 Hold：分析此时更新分布的必要性，以及一步代理与真实学习窗口的关系；
- 原始输出明确定位了早期行为失败：设计独立的监督或协议行为实验；
- 原 C 已有益，而 N 持续削弱代理价值：在已有 N/Shrink 证据上重设 N 的命题。

这份方案最终要得到的是一条可追溯的证据链：**反馈温度如何改变 C，C 如何改变经验分布，以及这个分布经过真实训练后是否改善目标效用。**旧输出分类和内部信号诊断负责解释这条链，三臂同点续训负责检验它。
