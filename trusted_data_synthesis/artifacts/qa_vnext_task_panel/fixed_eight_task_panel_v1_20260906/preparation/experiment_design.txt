## 2. 源码实现与声明相符，不是只修改了 `fit` 标志

### 2.1 资产与长度政策已经分开

`core.py::asset_binding()` 实际读取绑定目录中的资产，检查成员一致性、模板、软件版本及模型配置，并要求：


它没有把 tokenizer 声明的 131,072 当成模型位置权限。新条件又绑定了原始候选、资格、教师条件和旧 Token 数据集；新 Token 记录有独立身份，不冒用旧记录 ID。

报告中的实际读取结果为 `max_position_embeddings=32768`、`rope_scaling=null`。本次核对的是**确有这样的读取和检查路径**，不是我再次访问了服务器上的配置文件。

共享 `representation.py` 则保留了旧入口：

```python
_tokenize_candidate(...)
    -> encode_original_candidate(...,
                                 maximum_sequence_length=MAXIMUM_SEQUENCE_LENGTH)
```

旧入口仍采用历史 24,576 条件；新适配调用显式传入的新长度政策。编码、offset、原文恢复和 mask 检查没有通过这一参数变成另一套内容变换。

### 2.2 原始内容保留有实际数组检查，不只是声明

`validate_record()` 检查实际消费数组，并分别解码：

$$
\text{全部 input IDs}\rightarrow\text{完整渲染文本},
$$

$$
\text{prompt IDs}\rightarrow\text{原 prompt prefix},
$$

$$
\text{target IDs}\rightarrow\text{原 target UTF-8 内容}.
$$

同时检查 suffix、目标连续区间、labels、attention 和因果边界。对于旧 32 条 fit，`compare_historical()` 比较四个数组及非政策诊断；对于旧两条 not-fit，只核对确实存在的旧长度、渲染和边界信息，不声称比较了原来为 null 的消费数组。

报告据此将两条旧 not-fit 的 `arrays_identical` 保持为 null，而不是为追求全绿填成 true。这一处理正确。

### 2.3 完整包分母来自实际事件，没有从筛选后的行反推

`session_packages()` 的应有单元数来自历史 Session 的全部 admitted events。每个事件再连接候选和 Token 记录；缺失或不可消费的单元仍留在包内，只会使 `complete=false`。

> **不能删掉一个难以表示的 Update，然后用剩下的行数重新定义“完整会话”。**

# 四、测量设计：为 VTDO 保留正确对象，而不是只报告平均成功率

## 1. 端到端成功率按固定任务分别计算

设：

$$
Y_{i,r}
=
\mathbf1[
\text{有效 Final}
\land V_{\mathrm{QA}}
\land V_{\mathrm{trajectory}}
].
$$

两会话证据完整且可判定时：

$$
\widehat q_i=\frac{Y_{i,1}+Y_{i,2}}2.
$$

整个面板完整时：

$$
\widehat q_{\mathrm{panel}}
=
\sum_{i=1}^8\mu_{\mathrm{panel}}(x_i)\widehat q_i
=
\frac{\sum_{i,r}Y_{i,r}}{16}.
$$

报告必须同时列出八个任务的分子／分母。某个任务首次 Action 都没通过，不能被其他任务的成功抵消；但完整记录的失败仍是有效实验结果。

两个重复会话只提供有限工程观察，不足以声称稳定总体概率。不要以“2/2”替代置信程度，也不追加试次直到达到期待比例。

## 2. 广度与深度来自同一批实际会话

逐任务使用一行完整证据：

```text
注册与来源绑定
→ 本轮 Session
→ 实际 Action／Update／Claim 消费
→ QA／轨迹资格
→ 实际依赖深度
→ 投影状态
→ 原始候选与完整表示
```

深度继续分为实际结构依赖、语义操作依赖和可观察选择依赖，不使用 callback 数或解释长度替代。已有指标明确区分这些量，下一轮应复用其定义。

完整轨迹与失败前缀分别报告。尤其是 B：只有真实完成 lookup→growth→gap→absolute，才有该次完整深度三见证，不能因为任务名中含有深度扩展就预填三。

这轮主要检验**同一链路覆盖不同登记结构**，不是深度因果实验。不同任务在指标、来源、操作和输出方面同时变化，成功率差异不能仅归因于深度。

## 3. 有效性与有限商映射分开

每任务两会话，最多一个配对，全体最多八个同任务配对。只比较实际 Qualified、且现有投影支持的轨迹。

当前有限投影对有意义 reject、未解释的纠正历史或其他超域事件可能保持 `undetermined`。下一轮不应为了得到完整类数而删除这些记录，也不应将合法轨迹的投影未定回写成无效。

允许出现：

```text
Qualified = true
projection_status = undetermined
```

也允许：

```text
两个 Qualified 会话
同任务配对 = equivalent
```

**不把“至少两个商类”作为本轮通过条件。**一个任务只有一个已观察类，可以是可信的局部结果；它仍是任务面板的一部分。

只有当某任务的全部有效观察都完成映射时，才可以报告这批样本的条件频率：

$$
\widehat\pi_{\mathrm{gen}}(z\mid x_i,Y=1)
=
\frac{n_{i,z}}{m_i},
\qquad
m_i=\sum_rY_{i,r}.
$$

若 \(m_i=0\)，该条件分布为 null；若仍有未映射有效轨迹，不能删掉它们后用更小分母归一化。这些有限频率也不是最优训练权重。

## 4. 训练表示是独立维度，不能悄悄改变 \(\mu(x)\)

新正向候选仍限定为：

$$
\text{真实模型来源已验证}
\land
\text{会话 Qualified}
\land
\text{提交 admitted}.
$$

保留每次实际 messages、原 target、反馈和 State；不把十七次请求拼成一条不存在的长对话，也不从失败会话中拼接完整轨迹。

新的表示政策应对所有候选一致使用。某行仍超过 32,768 时，保留原始候选和诊断，完整包相应为不可消费；**不继续临时加长、不截断，也不删除该任务来维持表面上的全量通过。**

这里有一个直接关系到 VTDO 的问题：即使每任务都采两次，成功率不同也会使成功池的任务比例变成：

$$
\widetilde\mu_{\mathrm{success}}(x_i)
=
\frac{m_i}{\sum_km_k},
$$

它通常不等于预定的 \(1/8\)。再筛选 Token fit，还可能进一步改变比例。

因此，本轮必须分别保存：

* 登记任务边际 \(\mu_{\mathrm{panel}}\)；
* 每任务尝试与成功数量；
* 每任务可映射数量；
* 每任务完整表示包数量。

**不能把所有成功行平铺后，宣称任务边际仍然固定。**

本轮不必立即构造最终训练权重。如果某任务没有有效或完整可消费的样本，应记录该面板的全支持训练物化尚不可实现；这不否定采集实验已经正确完成，也不允许删除该任务来制造“固定边际已实现”。

# 五、下一轮怎样结束，而不是再进入接口循环

## 1. 工作流完成与科学见证分别报告

建议只设四个本轮完成对象：

| 完成对象    | 要求                           |
| ------- | ---------------------------- |
| 面板与统一条件 | 八个精确任务、十六个会话及生成／表示政策事先固定     |
| 执行与资格证据 | 不替换、不隐式修复，成功、失败、未知和未启动完整保留   |
| 分层测量    | 任务成功、实际深度、商关系、表示状态分别判断       |
| 数据衔接    | 原请求与响应可追溯；完整包、长度和任务分母没有被筛选改写 |

**不要求 16/16 成功，不要求八类各自都有两种有效行为，也不要求所有有效轨迹都能进入当前有限 Mapper。**

“八个选定任务各有至少一个完整成功见证”可以作为一项单独结果，而不是用来否定正确记录的模型失败。

## 2. 根据结果选择下一科学对象

若统一条件下已获得多类型的有效行为和完整监督包，应结束反复的接入证明，推进**更多真实任务绑定、独立评价集合与新协议下的有限分布优化对象**。现有已反复阅读和调试的来源应标记为开发用途；不能因为原文件名是 `test.json`，就将它恢复为未见盲评集。

若有效轨迹存在，但新事件导致投影未定，下一步只补充那些实际事件的有限解释，不再重做来源、Action publication 或长度适配。

若某类全部失败，依据实际首个失败位置决定是接口条件、模型提交还是任务执行问题。不要用其他类的成功补偿，也不要为获得非退化分布而换题。

若完整表示包仍不足，保留其与模型资格的区别。只有到真正固定 Student 与训练资源时，才检验 GPU 显存、forward、优化器及训练收益；**无需在这次面板采集前，把它们再加成一个新的高层门槛。**
