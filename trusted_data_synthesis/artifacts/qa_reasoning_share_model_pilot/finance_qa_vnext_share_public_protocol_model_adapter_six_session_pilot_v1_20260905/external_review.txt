# 本轮审计与后续实验方案

**审计结论：`PASS_AS_SCOPED`。本轮“模型可见状态、真实生成器回调及显式 Observation Update 的最小协议接入”可以收口。在本次审阅范围内，未发现能够直接推翻这一限定声明的 Blocking defect，无强制修订要求，也不需要再追加一次同内容的独立审计。**

本轮真正取得的进展是：**操作选择和接受更新已经通过不同回调实际提交，Host 不再把工具输出自动当成生成器接受的 Claim。**但正向生成器仍是固定策略的 fixture；这不是模型接入成功，也不是模型自主依据选择的证据。报告对这一边界区分正确。

**后续建议进入“一项带零调用准备检查的单任务真实模型接入试验”**：在同一轮完成必要的模型适配、局部控制与固定六会话试验设计，不再围绕旧 D/S 增加确定性候选或重复商审计。实际在线执行仍需新的明确授权；本答复只进行审计与方案设计。

本次已完整阅读上传报告，并独立复算数值、阶段计数与数量关系；**没有访问实验仓库、原始正式 JSON 目录或执行其 Runtime、验证器与测试**。以下分别区分报告支持的事实、本次审计判断和新提出的实验方案。

# 一、本轮审计

## 1. 当前声明：接通公开决策责任，而不是再次证明两条路线不同

本轮沿用原有 Task、四项 Evidence、三个操作及数值合同，新建的是 PublicContext、协议和会话身份。旧 D/S 的有限两类见证继续保留，没有重新测量；更早增长率差值任务的 `W=null` 也没有被改写。 

当前命题可以明确为：

> 生成器能够接收真实当前 State，通过公开 JSON 选择 Action；工具执行后，只产生 pending Observation；生成器再通过另一次回调提交接受或拒绝，Host 验证后才改变可消费 Claim 集合。

这里的两个关键条件是：

$$
\mathcal C_{\mathrm{accepted}}(s_{\mathrm{after\ action}})
=
\mathcal C_{\mathrm{accepted}}(s_{\mathrm{before\ action}}),
$$

以及在合法 accept Update 后：

$$
\mathcal C_{\mathrm{accepted}}(s_{\mathrm{after\ update}})
=
\mathcal C_{\mathrm{accepted}}(s_{\mathrm{before\ update}})
\cup\{C_{\mathrm{new}}\}.
$$

这两条是对本轮协议语义的整理表达，不是新增加的审计条件。报告明确规定：Action 输出尚不是已接受 Claim，完整 proposed Claim 必须由另一条 Update 提交，不能由 Host 自动补齐。

**本轮只需证明这个有限协议能够真实运行，不需要同时证明模型能力、一般推理修订或分布优化。**

## 2. 实现状态：三项核心机制已经被具体实例化

### 2.1 PublicState 提供了可用信息，但没有直接给出参考路线

公开上下文包含完整任务、Evidence、操作、数值规则、共同义务和答案 Schema；外层旧合同中的 measurement、路线特有前提、D/S 标签、预制节点、Oracle、旧 Final 和类数不作为公开上下文传入。

动态状态则明确区分 `accepted_claims`、`pending_observation`、当前阶段、计数、反馈和终止状态，并提供剩余预算。Request 从当前 State 及相应 Schema 构造，不替生成器选择下一个 operation 或填写 operands。 

因此，按报告所述，本轮不是：

```text
Host 给出下一正确节点
→ 生成器返回一个同意标签
→ Host 执行固定脚本
```

而是将合法提交的责任移到了回调返回值。

但需要保留一个准确限定：**当前 fixture 自己仍然具有固定策略——优先重建总额、逐步 accept、再完成比例和百分比。**Host 没有路线参数，不等于生成器已经开放探索。报告对此有明确披露。

### 2.2 Action 与 Update 的语义内容来自实际提交，而不是 Host 回填

Action 必须提交 operation、operands、parameters 和 `public_basis`。accept Update 必须提交完整 proposition，包括：

```text
value、metric、definition、subject、scope、
period、unit、currency、lineage
```

Host 核对它与实际 Observation output 的完整内容，而不是只检查一个 `accept=true`。缺失内容、数值错误或 lineage 错误都不能自动修复。 

这确实使“生成器提出并确认什么”成为可观察对象。

不过，**当前 Update 所表达的是对完整 Observation 命题的接受或拒绝，不是任意新命题推导、部分接受、旧 Claim 修订或复杂信念更新。**因此，本轮可以称为显式更新协议接通，不能据此称为一般推理更新能力已经闭合。这是范围限制，不是当前缺陷。

### 2.3 来源归属不是由公开 JSON 自报

公开提交不能添加 `origin=model`。实际来源由 GeneratorRegistration、callback 实现及 generator turn 绑定；报告还记录了实例和类方法替换的控制，而不是仅相信一个来源字符串。 

当前全部生成器提交仍记为 `deterministic_fixture`，工具 execution／Observation 为 `host_derived`。这种归属是正确的。

**这条机制将来需要扩展到真实模型适配器，但当前 fixture 的源码身份检查不能自动充当 Provider 响应来源证明。**两者是不同接入对象。

## 3. 直接反例检查：实际顺序与当前声明一致

### 3.1 七次回调确实形成三个独立的 Action／Update 对

报告记录的实际过程为：

| 阶段      | 实际发生的提交                           | 新增 accepted Claim |
| ------- | --------------------------------- | ----------------: |
| 第 1 次回调 | `relation_sum`                    |                 0 |
| 第 2 次回调 | accept 总额 Observation             |                 1 |
| 第 3 次回调 | `share_ratio`，消费已接受总额 Claim       |                 0 |
| 第 4 次回调 | accept ratio Observation          |                 1 |
| 第 5 次回调 | `scale_percent`，消费已接受 ratio Claim |                 0 |
| 第 6 次回调 | accept percent Observation        |                 1 |
| 第 7 次回调 | Final，消费已接受 percent Claim         |                 0 |

七轮各有自己的 Request、generator turn、原始公开 JSON、Submission、Receipt 和轮后 State，不是把一个返回值拆成七个阶段标签。

这直接支持本轮最重要的机制：**可消费 Claim 的形成被真正放在独立 Update 边界之后。**

独立验证还重放了七个实际公开响应，没有调用 Engine、提交解析器或准入函数重新生成结果来替代自身检查。

### 3.2 针对自动接受、错误引用和隐式修复的反例有对应控制

九个负向 preview 中，以下几项直接对应当前命题：

| 直接反例                                | 报告中的拒绝边界                            |
| ----------------------------------- | ----------------------------------- |
| pending Observation 尚未处理就执行新 Action | `admission.pending_update`          |
| 将 Observation ID 当成 accepted Claim  | `admission.accepted_claim`          |
| accept 时缺少完整 proposed Claim         | `admission.explicit_proposed_claim` |
| Claim 内容与 Observation 不同            | `admission.observed_claim_content`  |
| Update 使用旧 State 或其他 Observation    | 当前 State／Observation parent 检查      |
| 自报模型来源或用未接受对象提交 Final               | Schema／Final accepted Claim 检查      |

这些 preview 全部拒绝，且没有执行内核或提交状态更新。

**应接受这些控制在“纯准入函数”上的意义，但不把它们解释为九条真实失败会话。**本轮正式会话的实际拒绝提交和 callback 失败均为零。

### 3.3 直接路线与 reject 的 preview 不等于完整运行——但报告没有越级

同一个初始 Q0 同时准入直接 F/T 比例操作和分项求和操作，说明初始接口没有强制唯一第一步。reject Update 也有合法的 preview 结果。

但本轮没有完整执行直接路线，没有实际 commit reject，也没有观察拒绝后的重新规划。报告对此表述清楚。

所以当前应同时保留：

$$
\text{两个合法初始选择得到准入}
$$

与

$$
\text{只有一条完整正向交互被实际执行}.
$$

**这不是当前 Gate 失败的理由。**只有声称“新协议下两条完整路线均已执行”或“拒绝后恢复已验证”时，才会构成直接证据缺口；本轮没有作出这些声明。

### 3.4 数值、预算与计数独立核对一致

按报告的 50 位 Decimal 精度和既定舍入规则，本次复算得到：

$$
\frac{20397}{21813}
=
0.93508458258836473662494842525099711181405583826159,
$$

最终百分比为：

$$
\boxed{93.508458\%}.
$$

与实际 Observation 和 Final 摘录一致。 

阶段与预算关系也一致：

$$
3\ \mathrm{Actions}+3\ \mathrm{Updates}+1\ \mathrm{Final}
=7\ \mathrm{callbacks},
$$

$$
(3,3,12)-(3,3,7)=(0,0,5).
$$

会话按有效 Final 结束，没有为耗尽剩余提交预算继续调用。

测试和文件数量分别满足：

$$
13+11+10+17=51,
$$

$$
17+54=71,\qquad
100002+548046=637560+10488=648048.
$$

这些算术核对没有发现内部矛盾，但不替代原始文件哈希或源码执行核验。无执行重建只复用了既有会话，科学样本量仍为一个会话。 

## 4. Gate 与发现分级

| Gate | 本轮对象                    | 本次判断                 |
| ---- | ----------------------- | -------------------- |
| G0   | 新范围、前驱不变性和声明源码          | 接受限定 PASS            |
| G1   | 公开投影与 callback 责任       | 接受限定 PASS            |
| G2   | 一条实际生成器／Update 会话及独立 QA | 接受限定 PASS            |
| G3   | 固定状态上的直接准入控制            | 接受其 preview 范围的 PASS |
| G4   | 零外部执行与历史结论不扩张           | 接受限定 PASS            |

没有发现需要改判五项 Gate 的报告内矛盾。

**Blocking defect：`NONE_FOUND_IN_REVIEWED_SCOPE`。**
无强制修订，不重跑旧 D/S，也不重新打开两类证明。

**Scope limitation：**只有一个固定策略 fixture 会话；直接路线和 reject 仅有 preview；Update 目前是完整命题的接受／拒绝；没有 Provider 适配器或模型结果。这些限制均已披露，不否定当前最小接入命题。

**Future hardening：**一般修订语言、复杂外部工具、完整环境闭包、广泛任务和更强安全控制。不作为当前或下一小规模模型接入的额外前置门槛。

## 5. 当前允许的结论与首个未完成对象

当前可以接受：

> 固定任务能够通过公开 JSON 请求与回调完成一次真实有限交互；Action、Observation、生成器 Update 和 accepted Claim 的责任及时间关系已经分离，Host 没有通过缺失字段回填或自动接受完成该正向过程。

当前仍不能接受：

> 模型已经理解、选择或执行两种依据；七次回调体现七次独立推理；新协议已测得两类概率；显式复制并接受 Observation 已证明更强推理能力。

本轮 `new_W_share`、`new_semantic_class_count` 和模型概率保持 null 是正确的，不是把历史两类结果撤销。

**当前阶段没有剩余 Blocking defect。下一未完成对象已经是“真实模型返回值能否原样进入这个协议，并形成可验证的完整交互”，而不是继续证明 fixture 能回调。**

# 二、后续实验：单任务、单模型、固定六会话的最小接入试验

以下为新方案建议，尚未实现、冻结或执行。

建议暂命名为：

```text
finance_qa_vnext_share_public_protocol_model_adapter_and_
six_session_engineering_pilot
```

这一试验分为**同一轮内的零调用准备部分与受单独授权约束的在线部分**。不要求它们之间机械增加一次独立审计；准备检查发现具体缺陷时，才修复该缺陷。

## 1. 主问题只保留一个

> 在固定公开任务、信息、工具和协议下，真实模型能否通过自己的公开提交完成 Action、显式 Update 和 Final，且 Host 不替其决定语义内容或修复响应？

下一轮主要检验**公开协议的模型可达性**，而不是立即检验 VTDO。

两种依据路线都出现，可以成为有价值的观察；**但不应作为试验工作流通过条件**。模型只采用 D，不能据此判定协议失败，也不能为补出 S 而不断追加会话。

## 2. 固定任务与协议，不同时改动实验对象

建议沿用本轮完整 PublicContext 和以下合同：

| 项目                                           | 下一轮处理                     |
| -------------------------------------------- | ------------------------- |
| Task、F/O/T、关系 Evidence                       | 原身份与内容保留                  |
| `relation_sum`、`share_ratio`、`scale_percent` | 原语义及准入规则保留                |
| 数值精度、舍入、答案容差                                 | 原样保留                      |
| Action／Update 上限                             | 3／3                       |
| 提交上限                                         | 每会话 12                    |
| 公开响应字节上限                                     | 32,768                    |
| Update proposed Claim                        | 仍需完整提交并与实际 Observation 一致 |
| 主试验路线要求                                      | 不指定 D/S，不要求重建，不给参考执行序列    |

这些预算和提交约束来自当前已冻结协议，而不是从本轮七次实际回调倒推出来的上限。

**模型可以看到公开目标、操作合同和真实数值；不能看到旧 Final、正确答案实例、候选脚本或目标类标签。**由真实工具产生的后续 Observation 当然可以包含最终数值，这不是事先泄漏答案。

公开字段发生必要的呈现变化时，只改变新的请求呈现身份，不静默修改其语义内容。

## 3. 零调用准备：只补齐真实模型接入新增的边界

### 3.1 建立一条实际可调用的适配器链

需要把当前：

```text
request_for(State)
→ PublicRequestFixture.generate
→ 原始公开 JSON
```

接成：

```text
request_for(State)
→ 确定性消息呈现
→ 实际模型请求
→ 公开响应提取
→ 原样进入当前严格 Parser
→ Host admission / execution / update
```

这里有三项必须明确的责任。

**请求呈现与解析使用同一份权威 Schema。**直接使用 `request_for` 给出的阶段和实际 Schema，不另外手写一个近似版本；Action 阶段允许的 Action／Final 选择也应保留。

**适配器不得补齐语义字段。**不得补 operation、operand、basis、proposed Claim、citations，不得从 Observation 自动构造模型遗漏的 Update，更不得在模型失败时调用 fixture 作为备用输出。

**真实来源必须绑定到实际请求／响应。**当前固定 `PublicRequestFixture.generate` 的身份检查不能靠改名变成模型登记。需要新的适配器登记、精确请求与响应关联，以及相应验证支持；公开响应仍不得通过自报 `origin=model` 获得身份。

这项扩展只针对新接入边界，不要求重做整个 callback 安全体系。

### 3.2 两个局部完整控制足以覆盖当前尚未实际运行的关键分支

建议在新适配器的无网络测试替身中执行两条有限会话：

| 局部控制        | 提交过程                                                            | 预计计数                         |
| ----------- | --------------------------------------------------------------- | ---------------------------- |
| 直接路线        | ratio → accept → percent → accept → Final                       | 2 Action、2 Update、5 callback |
| 放弃重建结果后直接求解 | sum → reject → ratio 使用披露 T → accept → percent → accept → Final | 3 Action、3 Update、7 callback |

第二条恰好仍在当前 3 Action／3 Update 预算内。它检验的是：

> reject 真正提交后，pending 被清除、没有产生可消费总额 Claim，后续仍能从同一 Evidence universe 合法选择另一种输入。

**这不是“模型识别出错误工具结果”的实验。**当前 reject 表示 `declines`，可以放弃一个正确结果；该局部控制也不证明真实模型会重新规划。

这两条控制是在新接入链上检查新增接缝，不是重新测量旧 D/S 商类。它们应独立记为 adapter/mock 测试，不能进入在线六会话分母。

再补充非法 JSON 和 transport 失败的局部控制即可：检查没有语义修复、没有备用答案、计数和停止状态正确。不需要复制前几轮全部攻击矩阵。

### 3.3 公共失败证据必须先规定清楚

当前协议只保存通过严格公开 Schema 的原始 JSON；非法响应保存哈希与字节数，不持久化任意未解析文本。

这个策略对当前正向 fixture 没有造成缺口，但在真实模型试验中需要明确证据层级：

| 响应情况               | 可作出的核验声明                             |
| ------------------ | ------------------------------------ |
| 原始公开 JSON 已安全保存    | 可以独立重放 Parser、引用、语义和后续事件             |
| 非法文本未保存，只有哈希及接收端诊断 | 只能作为接收端记录的类型化失败观测，不能声称从原文独立复验了具体格式错误 |
| 请求或响应关联、终止证据缺失     | 保留 evidence incomplete，不能擅自补成模型失败    |

建议为每次实际调用保存：会话、轮次、State、阶段、请求身份、实际模型身份、公开响应哈希／长度、解析状态、可安全保存的错误代码、提交身份或终止状态。

**不要用哈希证明“模型究竟少了哪个字段”，也不要为了便于诊断而自动保存私有推理或任意未筛选文本。**具体保存策略需要作为新适配器合同的一部分明确；旧历史保存规则和字节不改写。

### 3.4 模型与资源配置需要实际绑定，不能从旧实验名称继承

这份报告没有提供新的 Provider 适配器、模型配置或 token 预算。因此，本次不指定未经核实的模型版本、上下文规格或价格。

准备部分需要固定一个实际可用的精确模型配置、端点、采样与推理设置、输入／输出及会话 token 上限和超时。应使用真实序列化请求核对输入规模，**32,768 字节的公开输出限制不能直接当作 token 限制**。

这些条件在首次在线调用前固定，不能看见模型输出后调整温度、Completion 预算或模型版本，仍沿用同一个正式试验身份。

## 4. 在线部分：六个中性会话，而不是两条路线各凑三条

建议预先登记六个新会话，全部采用同一任务、同一协议、同一模型配置。每个会话从独立初始 State 开始，不读取其他会话的响应作为示例。

| 项目                   | 建议范围 |
| -------------------- | ---: |
| 固定财务任务               |    1 |
| 精确模型配置               |    1 |
| 正式会话                 |    6 |
| 每会话 Action／Update 上限 |  3／3 |
| 每会话提交上限              |   12 |
| 每会话实际 Provider 尝试上限  |   12 |
| 全试验实际 Provider 尝试上限  |   72 |
| 自动网络重试／失败会话替换        |  0／0 |

**Provider 尝试计数需要独立于成功提交计数。**即使请求超时或没有形成可解析 submission，也必须消费调用预算；不能出现“没有返回合法 JSON，所以这次不计调用”的情况。

正常的协议拒绝可以依当前冻结规则反馈给模型，并允许其在剩余提交预算内继续。这属于同一会话的后续提交，不是隐式替换旧响应。明确的 transport／callback 失败则按预先规定的状态停止，不自动重发。

主试验中不加入“请采用分项重建”的定向提示。若以后确有必要研究提示条件下的 S 可达性，那是不同的生成条件，不能与本轮中性会话混合解释。

## 5. 测量目标：先分清完整交互与局部接口表现

建议逐会话记录：

```text
实际 Provider 调用和公开响应证据
各阶段提交及严格 Schema 结果
Action 准入和实际执行
Update 的接受／拒绝及 proposed Claim 一致性
accepted Claim 的产生与消费
Final、QA-valid、protocol-valid
真实终止原因和首个可定位失败
实际支持使用方式
```

### 主结果：完整公开协议成功

可为这轮新试验定义：

$$
Y_j=
\mathbf 1[
\text{有效 Final}
\land V_{\mathrm{protocol},j}
\land V_{\mathrm{QA},j}
].
$$

若六个会话均有完整、可判定的证据，则报告：

$$
\widehat q_{\mathrm{public\ protocol}}
=
\frac{\sum_{j=1}^{6}Y_j}{6}.
$$

这是**固定单任务、固定生成条件下的小规模工程观察比例**，不是旧主链的 `q_first`，不是总体金融 Agent 能力，也不承担精确概率估计的任务。

完整记录的端到端失败进入相应分母；证据缺失不能直接当作零。某阶段未到达时，其阶段条件指标保持未评估；条件分母为零时使用 null。

### 次结果：模型实际承担了哪些语义责任

至少分别报告：

* Action 的 operation、operands、parameters 和 basis 是否由模型原始响应提供；
* Update 是否由新的模型回调完整提出，而非 Host 回填；
* Final 是否消费已接受 Claim，并提供真实支持引用。

这里的“模型拥有”仅指**可归属的公开提交与实际使用关系**，不表示我们已经验证了模型内部思维过程。

### 依据路线只按实际行为描述，不预分配类别

可以记录最终分母来源，例如：

```text
disclosed_total
reconstructed_total_claim
other_or_mixed
unresolved
```

这些首先是当前会话的实际支持描述，不是调用模型前指定的目标标签。出现额外合法操作、拒绝或混合依赖时，保留完整过程，不能把所有结果强行归到旧 D/S。

本轮不必创建通用 Mapper、State Catalog 或 \(\pi(z\mid x)\)。即使观察到两种支持方式，也不能仅按路线名称自动继承旧商身份；正式类映射需明确其适用范围和实际语义对应。

# 三、下一轮怎样收口，而不是继续扩张审计

## 1. 工作流完成与模型成功分开

建议下一轮只设置四类完成条件：

| 对象      | 完成要求                                 |
| ------- | ------------------------------------ |
| 请求与身份接入 | 真实模型请求、响应及当前 State 关系完整，无 fixture 替代 |
| 本地接缝控制  | 新适配器的直接路线、reject commit 及必要失败控制正确    |
| 六会话执行证据 | 不替换、不静默重试，完整保留成功、失败和终止               |
| 验证与解释   | 公开提交可归属、成功条件明确，未到达与缺失证据不混淆           |

**不要求六个会话全部成功，也不要求两种依据路线都出现。**

但如果适配器自动填 Claim、错误输入被 Host 静默修好，或者请求／响应对应关系失真，那是新增接入机制的 Blocking defect，不能用某些会话答案正确补偿。

## 2. 各类结果的正确解释

| 观察结果                           | 可以接受的结论             | 不能据此做什么              |
| ------------------------------ | ------------------- | -------------------- |
| 至少一个完整 Qualified 模型会话          | 获得该条件下公开协议闭环的模型可达见证 | 宣称广泛能力或训练有效          |
| 六个会话都有效，但都采用直接总额               | 协议可达；本次未见证重建路线      | 宣称 S 不可达，或补样直到出现 S   |
| 两种实际依据使用均出现并有效                 | 获得更丰富的模型行为证据        | 自动赋予均匀概率或 VTDO 收益    |
| 主要失败在 Action Schema            | 当前接口生成环节是首个经验阻塞点    | 增加任务深度或扩大来源来绕过       |
| Action 正常，但 Update 经常缺字段或内容不一致 | 显式更新协议是首个经验阻塞点      | 让 Host 自动补齐后仍声称原协议通过 |
| 没有完整成功，但证据齐全                   | 接受有界模型负结果           | 把模型失败误写成实验没有执行       |
| 会话证据不完整                        | 保留 UNKNOWN，修复对应观测环节 | 删除失败会话或填入零成功率        |

尤其需要避免：看到 Update 的完整内容复制较难，就在同一次运行中把它改成单个 accept 标志。那可以是以后研究的不同协议，但它改变了模型责任，必须有新的条件身份，不能继续沿用本轮解释。

# 四、最终决定

**本轮应收口为：公开 State 与真实回调已经接通，工具 Observation 和生成器接受 Claim 已经通过独立提交分离。**

下一轮的重点应从“fixture 是否运行正确”转向“真实模型能否在不被 Host 代替的情况下完成这些提交”。建议采用上述**单任务、单模型、固定六会话**方案，并把适配器及局部状态转换检查放在同一轮的零调用准备部分，不再新增重复审计阶段。

当前报告仍为 `next_stage_authorized=false`，旧主链继续暂停；本次方案不构成实际 Provider 执行或授权消费。在线部分需另行明确授权并绑定精确配置，不能从当前协议预检的 PASS 自动推出。

```text
CURRENT_AUDIT
  = PASS_AS_SCOPED

BLOCKING_DEFECT
  = NONE_FOUND_IN_REVIEWED_SCOPE

MANDATORY_REVISION
  = NONE

CLOSED_OBJECT
  = public callback protocol and explicit Observation-to-Claim acceptance

NEXT_PRIMARY_OBJECT
  = real-model-owned public submissions and complete protocol reachability

RECOMMENDED_BOUND
  = one task, one model configuration, six sessions,
    at most 72 Provider attempts under a new authorization

OLD_MAINLINE
  = REMAINS_PAUSED
```

**下一步不需要再证明两种确定性行为存在，而需要观察：当选择、提案和接受更新真正交给模型后，哪些环节能够实现，首个实际失败又发生在哪里。**
